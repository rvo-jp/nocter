# Future Private Value Access Declarations

This document owns the implemented bounded handoff between syntax, declarations, typed bodies,
accepted private units and private instances. Language meaning belongs to the
[adopted value model](../../spec/language/value-access.md). The handoff retains its own checked
unit from source through target selection. Its native consumer uses the common Machine, ARM64 and
Mach-O products; the [entry qualification](#common-machine-body-construction) defines its limits.

## Source Scope

The syntax owner defines the bounded private goal. Checking admits explicit postfix retirement,
unmarked Copy snapshots, marked capture formation and read/edit loans from produced or
transferred values within its closed data/callable schemas. A direct marked source stays reserved
through complete invocation preparation, including selected callable adapters.
The [realization plan](../../design/compiler-realization.md) owns remaining integrated obligations.

An explicitly selected v2 package-root catalog now carries the adopted
[package metadata](../../spec/language/packages.md) through the common package decoder and physical
discovery. Root parse products, directory ownership, direct `see`, module imports, target selections
and source diagnostics become the existing immutable compile input. `ModuleSourceUnit` consumes
that exact input through its ordinary declaration/body/required-value coordinator. Contract-only
roots, complete paired headers, child/package boundaries and unused source-folder helpers retain
their existing owners. The revision-owned unit-analysis query now selects this same coordinator
for v2 input and retains accepted, rejected or incomplete syntax outcomes under exact-current source
identity. Session retains that same query branch and the original common failure report in its
exact-current envelope, without invoking checking or converting to released semantic views. Source
checking remains separate from target admission. Session can select a v2 package executable through
authored metadata and retained module headers. Native lowering consumes that checked selection for
the supported process results. Editor features, the installed standard library and CLI integration
require separate qualification. The [query owner](../../compiler/crates/nocter-compiler-computation/README.md#selected-value-access-query-scope)
defines its reuse and recovery scope.

## Implemented Handoff

```text
V2CoreUnit syntax + exact source
  -> exact-current declaration preparation
       fixed names/slots + raw source type recipes + one source catalog
       requested callable/record + transitive records -> complete immutable ready-header view
  -> dependency-scheduled ordinary typed-body preparation over ready contracts
       missing header -> declaration-owned required contracts -> iterative shared query -> retry draft
       missing constant -> ordinary checking of selected const closure -> closed execution
       unrelated headers can remain unready during required execution
       frozen values feed typing; immutable static views retain global place identity
       successful query retains its own header-prefix boundary
  -> complete reusable access-declaration query + typed queries + required frozen values
       all callable/record contracts + neutral header surface + projection recipe
  -> canonical replay of body application types + complete body data projection
       shared declaration facts and one final type authority; exact header source binding retained
  -> source-neutral control/evaluation graph
  -> reachable callable-result producers + recursive closure + identity/value-supply closure
       same graph; closed existing TypeIds, no second type authority
  -> projected initialization facts over the frozen supply operations
  -> permission-demand liveness + alternative referent/access worlds
       + exact payload contracts + logical resource/cleanup transitions
  -> definition-time const-domain checks over selected bodies and resource operations
  -> accepted private unit (all definitions validated; required values frozen)
  -> root-closed private InstanceProgram (selected concrete calls/data; no ABI or native admission)
  -> guarded private lifecycle schedules + initialization-bit recipes
  -> closed private MIR (runtime shapes, input slots, control, computation, calls and resource phases)
  -> common MachineProgram (shared layouts, ABI, body optimization, cleanup helpers and dataflow)
  -> common ARM64 lowering + Mach-O image writing
       (bounded private entry; no public CLI admission)
```

## Responsibilities

`nocter-syntax` owns recognition, exact source/tree identity, declaration-surface invalidation,
and stable locators that exclude body contents. The lowered query uses that one projection; it
does not parse source again or invent a second declaration fingerprint.

`nocter-model` owns distinct access-callable/input identities and the independent input operations, local binding
kinds, transient operation access and logical field paths. Data types are independent; access is
not a borrow-type constructor or a general coercion rank. A path contains field identities, not
source names, physical offsets or an access grant.

`nocter-declarations` owns the source-independent program, namespace, closed data authority,
ordered input identities and operations, value results, and concrete named-function
witnesses. Body-owned lexical closure keys additionally carry exact owned environment
schemas and inferred invocation contracts. They replay with body types into the same final
authority, without changing reusable headers. A flat callable input introduces a symbolic formal witness; a flat callable result
introduces a symbolic result family. Structural callable
annotations constrain these witnesses rather than introducing erased runtime datatypes. Invocation compatibility and exact input/result matching belong to declarations;
checking freezes the selected witness/view. Header freeze interns every named invocation view and
all permitted formal/result-family views in the header TypeAuthority. Body checking opens a narrow
application-type branch over that prefix; canonical replay validates lineage and owner domains
before all bodies share one final authority. Earlier body suffixes can share raw positions with
later header keys; replay uses each body's own prefix rather than a final global cutoff.
Declaration metadata and source reuse remain shared;
no consumer chooses between header and body stores as lookup fallbacks.
Reservation closure freezes the complete callable/record name and input/field identity domains
before any type normalization.
Definition construction cannot append declarations. Each requested contract loads its raw definition
and rejects missing or invalid references before publication. Requested record payloads must
establish finite containment and explicit Copy evidence before their schemas become ready.
One tagged name table survives those transitions and serves each role-specific lookup. Ready views grant only established contracts;
untyped reservations never grant body-checking admission. Complete Unit admission requires every
callable/input and record/field slot to be defined.
Admitted built-in data, finite nongeneric records and structural tuple schemas share the parsed
callable/body boundary. Data-name resolution belongs to that declaration namespace; lowering holds
no parallel type table. Declaration-owned component projection validates each selected nominal field
or tuple position against its containing data identity. Checking consumes
those schemas to certify concrete payload operations; it does not rebuild nominal type meaning.
No borrowed wrapper or released storable-type heuristic supplies a missing future contract.

`nocter-declaration-lowering` owns canonical header collection, normalization and diagnostic
projection. It reserves functions and records in namespace order and maps resolved identities to neutral
syntax locators. Its exact-current preparation supplies immutable ready declaration contexts while
checking's common readiness/value coordinator retains successful bodies and executes selected const
closures. The complete reusable query contains no current source identity, syntax ID or range.
Its [source-only supplier guards](../../compiler/crates/nocter-declaration-lowering/README.md#exact-source-evidence)
may retain selected body bytes. Binding checks the complete header surface, current locators and
any retained suppliers without repeating checking or evaluation.
The same lowering owner captures exact source evidence, including its original header view.
Checking retains paired body evidence for its own body, required values and callable-result
producers; it cannot assemble source owners and byte snapshots independently. Type annotations
have separate tagged header-source roots, including record fields before schema readiness. Those
roots are source evidence only and cannot substitute for executable expression code. The
current context has no public parts constructor; a caller cannot pair unrelated program/syntax
products or relabel released source as future source.

## Contract Facts and Limits

Every selected contract is closed before body checking consumes it. Source data-name references
resolve as selected recipes load; requested callable contracts and transitive record schemas
establish finite containment and Copy as body preparation needs them. Required execution needs
only the selected contracts and ordinarily accepted const closure; unrelated contracts can remain unready. Every
header and body must close before complete Unit admission. Source header normalization requests
computed lengths through that same coordinator, retaining selected supplier guards with its
closed type metadata. Header evidence alone grants no value/storage admission. Checking's
[listed-construction boundary](../../compiler/crates/nocter-checking/README.md#array-construction)
separately qualifies whole-array body/resource/evaluator handoffs. Its
[read-selection path](../../compiler/crates/nocter-checking/README.md#array-selection) retains evaluated
element addresses and qualifies bounded edit call inputs, scoped edit aliases and complete direct
replacement and source-proven concrete element holes. General retained-index transfer and
partial state remain gated; the
[native array consumer](../../compiler/crates/nocter-machine/README.md#private-array-execution)
owns the separately qualified stored scope and its remaining gates.
Body contents, source coordinates, declaration traversal order, and later Copy specialization cannot
change a declared input operation. Definition
order cannot renumber parameters. Reordering source declarations may invalidate a
source-surface cache entry but must preserve canonical semantic identities when recomputed.

Every callable result delivers a value of its declared data type. Parameters separately state
Read/Edit/Take, and locals separately state value mutability or scoped aliasing. Type annotations
cannot change those operations. Source/body/definition order cannot infer a new input operation.
Explicit source retirement and unmarked snapshots are selected once for value supply. An
unmarked result-dependent source retains a pending snapshot obligation until witness closure,
before initialization; insufficient Copy evidence then rejects instead of selecting an implicit
move. Explicit retirement never becomes Copy after specialization. Unmarked Copy taking inputs
snapshot rather than transfer the original. Exact payload contracts remain checking
evidence, not a generic D/S promise.

Declaration acceptance proves only header integrity. A syntax-valid body with an invalid non-Copy extraction,
invalid update, unavailable local, or unsafe backedge may rebind that same declaration program and
must later fail checking. Body typing consumes those identities/contracts and performs lexical body resolution,
structural data/operation checks, and direct-call selection. It cannot recover input operations
from body tokens, redo declaration normalization, or treat source projection as dispatch authority.
Projected initialization and referent/permission validation share a source-neutral body-flow
graph. Body typing freezes each selected place's local root, logical component keys and data TypeId;
later passes consume the selection rather than repeating member lookup. Logical resource transitions and the exact first-fragment payload contracts share those
alternative worlds. Only the complete private-unit constructor closes all body/callee assumptions;
intermediate facts cannot be treated as its accepted product.

The released compile-input/target-selection boundary rejects this future root, and no conversion
from this declaration product to the released program exists. The bounded selected-module entry
uses this same value-access authority; its implemented source, pairing, audience and orchestration
scope belongs to [declaration lowering](../../compiler/crates/nocter-declaration-lowering/README.md)
and [checking](../../compiler/crates/nocter-checking/README.md). Those component owners define the
current admitted source and runtime domains; this pipeline guide does not maintain another feature
inventory. The selected-module entry remains separate from ordinary released compiler/CLI
integration, and syntax recognition alone grants no product-level admission.


## Typed-Only Body Boundary

Checking owns one leaf query per callable. The declaration context shares the exact immutable
program authority; the query owns that authority and callable together with source-neutral body
arenas. Place reads, update/transfer operations, boundary Copy/delegation, argument preparations,
RHS-first stores, checked primitive arithmetic and structured control retain separate operations.
A deferred body is checked against its authored output, including its own fallible layer.
Its invocation has a separate future type. Ordinary nested closures do not inherit the deferred
body's permission to await. The supported process drive is described at the
[Machine handoff](#common-machine-body-construction).
The selected declaration or closure origin determines its execution kind. A symbolic callable
contract supplies no concrete constructor. Interrupted argument preparation keeps the selected
producer and result type in the typed query, while its control graph records no invocation.
An empty, directly selected construction has its own flow operation. Its logical receipt
retains the producer through owning local transfers and cancellation without an invocation.
The accepted unit qualifies storage elision from reached resource transitions for empty activations
whose uses stay local and unstarted. Native lowering omits their payload slots and transitions
while retaining control and ownership predicates. Such construction still requires runtime
execution under the const rules. Driving and escaping futures require separate evidence.
Direct and value calls store one statically selected callable and one input operation per ordered
input. Value-supply preparation can remain pending until result closure, without changing that
authored operation. A value call prepends its environment to explicit inputs; direct declaration
calls have no runtime environment input. Downstream validation consumes frozen operations rather
than reinterpreting indices against declaration parameters. A direct
place reservation is not an early read/update/transfer; explicit nested value computations execute
at their own operand point. A marked direct operand, including a selected invocation adapter,
retains retirement until complete bundle commit. The frozen input recipe names each delayed
adapter operation in materialization order; resource validation does not select adapters from
type differences. Read/edit receipt of that value uses the
caller-owned temporary path rather than surrendering ownership to the callee. A direct Copy input snapshots its selected place at preparation,
without a child read or retained source access. Copy/transfer/pending direct supply share one
graph topology; closure cannot reorder nested evaluation or cancellation. Later validation must
consume those plans, not repeat dispatch or infer intent from source punctuation. Structural
record/tuple values retain the declaration-selected component and one ordinary value operation for each
initializer in authored order. Their component values
remain owned evaluation temporaries until a single assembly step transfers them into the complete
aggregate. An interrupted initializer follows existing evaluation-frame cleanup; it cannot publish
a partially assembled record or introduce a constructor-only resource authority.

Named function references retain code identity through ordinary Copy supply, scoped aliases and
same-witness joins. A selected invocation adapter materializes a value and changes only its view;
initialization and replacement share that boundary. Environment preparation follows the same
reservation, atomic commit, cancellation and cleanup graph as explicit arguments. Exact
capture-free witness schemas justify Copy, trivial destruction and empty outside D/S; structural
annotations alone do not justify any of those payload facts. Formal inputs have no Copy evidence
and retain symbolic cleanup. Each selected argument can bind a callee formal to a named or caller
formal witness; invocation through the formal retains that semantic target. All definitions are
checked against their declared contracts, including unused/recursive bodies. The supported producer
domain includes the bounded explicit owned-capture producer, whose complete environment is
closed builtin/record/tuple data. Result-producing bodies establish one named, captured-code
or own-input relation through reachable value flow; signatures alone cannot select it. Each
selected application substitutes its actual witnesses into that relation. General dependency
footprints require further source closure. Concrete instance closure consumes
only the already selected witnesses.

Known result types and possible normal completion are independent typed facts. Interrupted
operands do not erase declared callable/record data, while the shared graph cannot evaluate an
unreached value merely because its data is known. A computed member chain retains one producer,
resolved field path and selected Copy/Move operation. Its producer executes once; later passes
consume the path without member lookup. Existing-place selection and construction use that same
field-resolution boundary. Computed selection delivers a value and cannot supply a scoped alias
or assignment target by extending a temporary's lifetime. A read/edit call may instead receive
access through the selected value's caller-owned evaluation temporary; that does not turn the
expression into an existing place or allow that temporary's direct storage to escape.

The semantic body has no source/syntax IDs, ranges, names, or symbol IDs. Exact body bytes and
body-local locators form a separate reusable source recipe. One locator projection serves the
initial checking context. Rebinding checks shared declaration-authority identity and exact own
body bytes, then resolves current origins without repeating typing. A result-closed query also
verifies its shared producer-body dependencies; changing a factory body invalidates that proof
even when the caller is unchanged. Complete-unit binding verifies this evidence once before
lending an opaque proof to body projections. Equal declarations rebuilt by an unrelated query
cannot substitute for that authority. A raw pending query can rebind its own unchanged body but
cannot enter flow or accepted-unit consumers until result closure succeeds.

No public constructor assembles a typed body or its semantic/source pairing from separate parts.
Structural failures expose their typed rule and current diagnostic; no partial typed body escapes.
A structurally valid transfer still requires initialization and conflict proofs. An ordinary
return must leave one value resource of its declared data type after frame cleanup. Passing an
intermediate query does not accept a unit. This product has no adapter to released checked
evidence. Its complete accepted Unit is consumed by the target owner's private instance closure;
typed-only evidence cannot enter that consumer.


## Flow and Initialization Handoff

Checking shares one immutable typed query into its body-flow query. The latter owns one closed
source-neutral control/evaluation graph and the fixed-point projected availability facts derived from it.
Semantic operations reference the already selected expressions, statements, locals, block exits and
call plans. No source identity, syntax node, rendered name or independently supplied declaration
program can influence this computation. Binding goes through the query's own typed source recipe;
changed authority/body is rejected before diagnostics can use stale coordinates.

Before access/resource validation, checking propagates static code/view producer facts through
this same graph's reachable successors, without depending on initialization. Actual staged
return values and prepared argument producers, rather than provisional expression types,
establish result equations. Finite monotone closure requires a named/captured-code or own-input anchor and
preserves invocation views. Named and anonymous code share return-summary terms. Each callable
result application has a caller/call-slot identity and a declaration-owned result template; its
frozen call selects the callee. Applications substitute actual bindings into reached return facts,
including callees returned by other applications, then deferred identity equalities are proved.
Templates supply no return anchor. Projection closes existing type/witness identities and freezes pending value supply
from the exact payload schema and source access. It does not repeat typing or graph construction;
known moves remain moves. Initialization then runs once over the frozen operations, followed by
access/resource validation. Producer facts do not prove owner availability and cannot replace
resource validation.

The initialization report distinguishes unreachable points, selected-value completeness and
container presence. Sparse abstract states join projected availability and preserve reaching
invalidation evidence and potential cleanup conditions without expanding shared record schemas. These are not an
access-root proof or executable cleanup schedule. The referent analysis now shares this graph and authority rather than reconstructing control or
dispatch. It preserves alternative origin worlds and staged return protection. Evaluation-frame
operations carry normal and interrupted temporary cleanup through the same graph. Logical owner
transitions are validated alongside referent survival. Executable consumers must use the closed
private-unit product rather than these intermediate reports. The development product still has no
public language-version switch or released-program adapter.


## Referent Report Boundary

The same flow query now owns read/update demand liveness and the referent/permission report.
Initialization failure is an explicit prerequisite status, not an empty access proof. Root and
creation/use identities remain semantic; exact-current diagnostics bind through the owning typed
query and locate the attempted operation, retained place/access, required use and referent declaration.
Checking distinguishes retained place identity from active read/edit grants under its
[shared access authority](../../compiler/crates/nocter-checking/README.md#shared-flow-access-and-resource-validation).

An owned answer with no outside referent can still carry D/S, and
non-owning access release differs from destroying a prepared owned resource. No consumer may
reinterpret an empty violation list as a complete accepted-body, execution or native certificate.
The exact first-fragment payload evidence is independent of R: it comes from the admitted
scalar/unit and owned-error snapshot contracts. Future dependency-bearing data cannot inherit
that evidence from ownership, Copy, or an empty referent set.

## Logical Resource and Unit Acceptance Boundary

Each reached action retains alternatives of before/after logical ownership and ordered cleanup
transitions under the same typed/control authority. The solver tracks expression, named, prepared,
retained-read-temporary and staged-result owners without dynamic execution counters. A complete
normal return preserves exactly its declared value result and no live evaluation frames. Cleanup
does not disappear when access liveness ends. A fresh value supplied to a read input retains one
temporary owner until its enclosing evaluation frame ends or unwinds. Call results are values;
they do not carry an implicit alias to an input. Computed field extraction transfers only the
selected component, leaving the source remainder in its existing evaluation frame. Copy leaves
the source complete. The same resource ledger proves result staging, read retention and remainder
cleanup; known-but-interrupted types are not resource owners.

Resource transitions use logical holder/field places and retain sparse unavailable selections.
Container presence is distinct from complete-value initialization. The ledger proves both in
each exact alternative; the initialization report joins availability for diagnostics over that
same selected graph. These products do not grant competing move or cleanup semantics. Closed
nominal cleanup retains an intact subtree as one schema operation and expands only around missing
selections. Partial drop ends the present container after cleaning its remaining fields.
Each resource transition also freezes its before/after-operation boundary. Invocation inputs and
selected adapters commit before the call; result receipt follows normal return. The source step
owner alone defines payload-bearing fields for exhaustive concrete projection. A sparse condition
projects owning-container presence and unavailable paths from the same ledger, without turning
scoped input storage into owned state or imposing physical flags.
Referent regions use the same selected field paths: parent/child paths overlap, sibling paths do
not. Source admission closes projected initialization, demand/reservation and resource validation
together; native realization remains separate.

The accepted private-unit constructor derives its membership from the declaration authority and
checks every definition and required initializer before publication, including the authored
[const body domain](../../compiler/crates/nocter-checking/README.md#constant-domain-acceptance) and
[initializer boundary](../../compiler/crates/nocter-checking/README.md#required-private-initializers). A caller cannot omit an unsafe unused
callee, combine different header generations, or construct acceptance from intermediate reports. Rebinding checks
the whole original body set before exposing any exact-current projection. No lookup, typing,
dispatch, or flow computation is repeated by that projection.

This is front-end evidence for the exact private fragment. Native instantiation, layout and code
generation establish their own admission through the handoffs below.

The v2 grammar preserves async modifiers, future type operands and await before outcome suffixes.
Contract pairing distinguishes an async declaration from an immediate implementation. The
[typed declaration contract](../../compiler/crates/nocter-declarations/README.md#future-value-declaration-boundary)
retains the deferred mode and its invocation result. Producing a future value requires its
own lifecycle evidence. A `future T` annotation on an owning local uses the same type identity
as a producer with output `T`. Body typing checks that `await` occurs in the nearest deferred body and
consumes an owned operand. The typed expression exposes one future layer's output before an outer
outcome operation. The control and resource analyses retain each local activation's selected
producer through ownership transfer. The drive consumes that receipt before execution and receives
the output through the shared normal-result transition after execution. The same construction
step commits prepared take inputs in source order to an unstarted local activation when the
input descriptor determines the layout. Closed compound inputs retain their structural cleanup
and use the ordinary value ABI when the drive supplies them to the body. A local activation can
also retain a read of an existing named place. Its ownership receipt keeps that place accessible
through moves and releases the read on cancellation or drive. For a field, the shared reservation
query supplies the original selection and its current root at commit. Intervening disjoint edits
preserve the selected region. An evaluated selection keeps the original address and performs its
bounds check during preparation. The backend transports the saved address and distinguishes it
from a take input of the same data type. A fresh input can stay in its caller-owned evaluation
slot through a local drive or cancellation. Ending that evaluation retires its storage in reverse
construction order and diagnoses a retained access whose activation would survive it.
Edit inputs use the same retained address and caller-owned temporary forms when their data has
one closed representation with no dependent text or callable channels. Construction delegates
exclusive access to the activation. The selected body updates the original initialized place
through the ordinary edit ABI, including whole and component replacement of compound data.
The replaced value's cleanup requires its own drive evidence. Unstarted cancellation releases
access without running the body. A drive invalidates caller facts whose preservation would
need a producer write footprint.
Unit acceptance retains the captured input layout for each producer at an owning holder and
qualifies non-waiting execution through reached immediate bodies and every possible local drive.
A future type in a body uses a producer selector when a reached drive has multiple producers
or a reached move or cancellation must distinguish captured inputs. Construction stores the
prepared values and any needed tag. A move with a common layout transfers its slots directly.
A move with different layouts selects the active slots before retiring the source. Cancellation
uses the original ownership transition and releases only the selected initialized inputs in
reverse order. Trivial captures require no physical release. A drive supplies the inputs to the
body and ends the activation's ownership of them.

The shared `value-modules/query-session` corpus closes an explicit checked root through physical
v2 package discovery, revision-owned analysis and session evidence before the existing instance,
lifecycle, MIR, Machine, ARM64 and image consumers. Required evaluation and the native process both
produce 42 from two same-code factory closures retaining different captured values across modules.
The native handoff consumes the session's complete Unit and the selected authored entry.

## Private Instance Closure Handoff

`nocter-target-program` consumes the complete accepted Unit and an explicit semantic root to produce
one private InstanceProgram. It retains the exact Unit/body/type authority, never a released-program
adapter or source context. An entry with unbound callback formals is not a concrete root. This
internal failure does not introduce a public CLI or target ABI rule.

Checking supplies selected declaration/captured/formal targets, formal-to-actual bindings, direct/value
invocation kind, explicit preparation actions, initialization reachability and resource obligations.
The target owner substitutes these facts into concrete instance keys and call edges. It does not
repeat name lookup, signature compatibility, body checking, access proof or Copy selection. The
source-level generic move remains selected even if its concrete named payload is Copy.

One immutable instance arena closes root reachability; recursive keys are reserved before their
edges are followed. Reached invocation commits and qualified future drives add instances.
A drive keeps its original action, candidate producers and their input channels through instance
closure. MIR dispatches on the retained selector when needed and supplies the selected stored
inputs through the ordinary body ABI. The selected body's answer enters the checked normal-result
transition. An optional answer enters the ordinary outcome graph after the drive, so propagation
and local recovery use the actual tag supplied by the selected body.
Fallible output transport has a separate admission check from backing and cleanup. An owned
outcome operation moves its active payload and retires the container on that branch. Result
projection resolves pending supplies and preserves operations already selected by typing. A
partial move obtains its physical root from the original receiving carrier while the place's
data describes the selected payload.
The selected ARM64 Darwin ABI distinguishes reads of the permanent error leaf and immutable
process-entry counts from private anonymous mappings for owned error nodes. Node creation can
trap at its backing request. An independent cleanup certificate covers releasing only the owned
mappings in the actual chain. That evidence permits reached error disposal during a drive.
An error can also pass through `throw` and `await` to the process reporter. The ordinary body ABI
passes the process context through a local drive and the process wrapper uses the closed
instance's body output for its failure status.
Source data IDs map once to concrete payload
obligations or checked unproduced structural contracts in the same declaration TypeAuthority.
The accepted Unit owns that distinction; an unproduced structural shape has no payload, cleanup or
environment to specialize. Checking rejects any reached value use of it before flow admission.
Checking owns the payload classifier; the
projection resolves a symbolic code environment to its exact cleanup contract without
inventing an owner. Closed record schemas are visited once per data identity, not expanded by path.
Consumers receive each instance with its exact checked body and those frozen maps.

The body's checking-closed result data enters that same payload projection. The target owner
never re-infers a result producer. Returned formal data uses the instance's existing binding and
payload maps. General captured environments and retained footprints still need their own source
closure. Layout, physical environment/argument realization, executable cleanup, target services,
MIR and native output are not established by this graph. Later implementation must extend this
same instance authority rather than create another call graph or infer environment shape from
parameter counts.

## Owned Capture Body Handoff

A body-owned closure schema pairs lexical code identity, ordinary environment data and the exact
invocation/input/result contract. Its typed body shares the parent's canonical program authority
and source-reuse guard. Body-local input slots identify access roots for named parameters,
anonymous parameters and capture environments alike. Formal callable identities use their actual
header parameter or lexical anonymous owner/input position; neither identity is a body-local slot. Source projection never recovers that relationship by name lookup.

Checking prepares each closure's control graph once, selects environment invocation demand from
reached operations, freezes its input authority, and runs the same initialization/access/resource
analysis and admission path used for named bodies. Unit construction checks every closure body
before publishing either body catalog. Formation transfers one complete owned environment into
one value in the existing resource ledger. Copy and cleanup consume the exact schema, not a
signature-wide assumption about callable environments.

Private instance data projection preserves an uninvoked owned environment's payload and its
environment-data obligation without adding a code instance. A code identity selects the named or
captured body independently of the value's invocation view. Its derived named source owner guards
source reuse only and cannot select a closure body. The selected complete environment uses the same private code-instance authority.

## Frozen Invocation Handoff

Checking publishes one input layout per body: an optional environment input and an ordered explicit
sequence of local slots with selected operations. Coverage and origin/operation/data consistency
are checked before complete flow admission. Root cleanup consumes this order. Named parameter
identities and closure input roles remain distinct; a consumer cannot rediscover input order from
local allocation order or an enclosing named header.

Private instances use code identity, concrete direct formal witnesses and the canonical contextual
environment as their key. A witness retains its supplied invocation view; a code instance can be
shared across views of that same full context and across runtime environment contents. Distinct
captured callable substitutions remain distinct contexts. Selected captured-code bindings use the same finite recursive interning as named code;
no captured-code registry, second call graph or source rechecking enters target closure.
Static instance sharing does not share runtime activations, environment contents or owner storage.

Each reached call edge retains its concrete instance, direct/value invocation kind, prepared-bundle
to explicit-body-input mapping, environment binding and concrete input/answer payloads. A named function
value supplies a code token without a body environment; a captured value supplies the exact ordinary
environment payload to its body slot. Body invocation and supplied view stay separate. On normal
completion the environment is retained, its remaining cleanup belongs to a consuming body, or an
adapter disposes its received post-call environment before answer delivery. A supplied Copy
snapshot is distinct from its original source owner. These recipes imply no unwind/cancellation
cleanup guarantee. Final graph freeze compares every input/answer payload with the selected callee's
concrete projections rather than inferring types or a result again.

Uninvoked values/bindings and interrupted prepared prefixes retain payload/cleanup evidence without
creating code instances. Source-selected generic
transfers do not become non-invalidating copies merely because concrete projection finds Copy.
The physical executable consumer must lower these same frozen channels, body graphs, resource steps
and normal adapter exits into environment/input/result realization. This graph grants no ABI,
physical storage, executable cleanup, MIR or native capability. Captured bodies retain actual
lexical operation domains. Checking owns callable-result application closure within those scopes;
a shared source/type root cannot replace the code identity. Extending nested environments must
preserve this distinction rather than reuse the enclosing function's operation arena.

## Private Lifecycle Schedule Handoff

The target owner's lifecycle product retains one exact InstanceProgram and its checked body
graphs. Each reachable action receives concrete resource schedules before/after its selected
operation, guarded by owning-container presence and sparse unavailable selections. Payloads
substitute through the existing instance data map; no operation, path, Copy decision or call
target is inferred again. Before bit lowering, equal source guards may merge only equal schedules
and ownership boundaries.
Different schedules under the same projected condition reject as unresolved realization, never
report-order choice.

The call operation uses its frozen body/environment channels and leaves its normally completed
answer protected. Adapter-owned environment destruction is inserted before result receipt in
the after phase; body-owned cleanup is not repeated. Trap/divergence does not execute normal
completion. Logical resource operations do not duplicate the selected source operation's value
computation or prescribe physical allocation, storage moves or an ABI.

The lifecycle schedule alone is not executable admission. Its MIR/Machine consumers realize
environment/input storage, backing deadlines, initialization predicates and fresh call activations
while preserving the same semantic owner and phase order. No global resource state is attached
to a shared code instance. General capability/dependency qualification remains open.

### Initialization Flag Encoding

Checking supplies owning-container/missing-path snapshots at body entry, before each action,
between its resource phases, and after normal completion. The target owner selects facts that
distinguish the action's remaining alternatives and emits body-local packed 64-bit tests/writes.
This does not expand nested record schemas or classify access through a data type. Complete
container absence and a present container with missing fields remain distinct observations.
Snapshot projection, rather than a second interpretation of transfer/restore rules, determines
every bit change. Blocked analysis supplies no entry evidence and cannot seed a flag layout.

One immutable bank template is copied into each fresh activation; shared code never shares
mutable flag state. Evaluate an action's tests once and retain that selection across both
phases. Apply before-writes after the complete before-step group and before starting the selected
operation. Apply after-writes only after normal completion and the complete after-step group,
including adapter cleanup and answer receipt. Trap/divergence does not execute normal writes.
No flag storage is emitted for a body without dynamic resource choices. The encoding is an
internal realization choice, not an ABI promise or a restriction on later bit/CFG optimization.

After encoding, equal operation/write sequences may share a guard across checked alternatives.
Conjunctions with equal bit keys and one complementary value merge by exact Boolean union;
bounded simplification may retain the original valid guards when its work limit is reached.
The emitted program retains physical predicates, while source conditions remain owned by the
checking report. Sharing code must not merge different flag writes or reorder resource steps.

## Private Stored Representation

The private instance graph projects produced concrete payload identities into a source-independent
runtime environment. Unproduced structural contracts have no stored representation. Original
value-field identities survive this boundary; they are never converted into published-language
field identities or reconstructed from names. Access operations remain separate from data shape.

For the bounded private fragment, the explicitly selected runtime ABI supplies scalar and error
handle layouts. Intrinsic integers use the shared numeric profile. Pointer-size isize/usize use the qualified
64-bit profile and distinct runtime roles, independently of the compiler host; fixed-width signed
and unsigned values retain their own data and stored widths. A stored `void` value selects a zero-byte, alignment-one runtime unit, distinct
from the published pipeline's completion-only runtime void. Records and tuples use
declaration/index-order member placement with each member's alignment and final aggregate padding. Machine owns the single
recursive layout calculation, checked size arithmetic and member correspondence for both pipeline
inputs. Equal offsets, including zero-byte members, do not identify logical fields.

A v2 zero-count array uses a distinct `RuntimeType::EmptyArray` stored shape. It preserves the
established element TypeId as metadata without a stored-payload reference or a demand for that
element's runtime entry. Its size is zero and alignment is one; the common Machine array layout
retains count and stride zero. This policy terminates empty containment paths, including valid
nominal cycles, without inventing an opaque type or computing an unavailable element layout.
Positive arrays use the shared homogeneous element/count shape and element geometry. The published
pipeline's `FixedArray` zero-count alignment policy remains unchanged. Equal zero-byte geometry
does not equate distinct source data identities or remove index evaluation/bounds effects.

A statically selected named function carries no runtime payload. A statically selected closure
carries only its inline environment, at offset zero; no code pointer, allocation header or erased
callable wrapper is introduced. Invocation views keep distinct type identities but do not add
payload bytes. This representation is valid only while the instance graph supplies the unique
code witness. Runtime dispatch requires a separately qualified representation.

This stored-layout boundary does not grant call ABI, activation placement, executable cleanup,
MIR or native admission. Those consumers must use the selected layouts without repeating the
calculation or recovering source semantics.

### Private Input ABI

The private input ABI keeps the checked environment input before explicit inputs, preserving
each exact body-local identity and input operation. Under the selected runtime ABI, read and
edit input operations carry one address even for zero-byte data; take carries the stored value's ordinary
Machine transport class. Access does not create a pointer/borrow data type. The captured environment
starts at carrier offset zero, while a named code token adds no body input. Adapter ownership and
post-call disposal remain in the lifecycle schedule rather than being inferred from register class.
An ordinary result uses its stored-value transport, including a zero-byte unit result. A known
signature remains typed even when its body does not return. Unproduced structural expressions
supply no runtime channel and cannot create an invocation edge. The existing Machine
register/stack/result placement algorithm serves both input products. This is an internal call
convention that may be specialized with proof; it is not a new public ABI promise or evidence of
native execution.

## Private Activation Storage Handoff

MIR's private storage lowering consumes the complete lifecycle product and freezes dense activation
slots and resource-phase storage effects. It projects reachable checked locations without creating
another source CFG, deciding ownership again or retaining checking/target storage in the result.
These requirements live in the same private MIR bodies as computation and control. The private
product remains separate from released MirProgram admission.

Value storage, address channels, prepared owning values, committed temporary backing, operand and
predicate snapshots, and protected call answers are distinct roles. A prepared slot can have
several selected callable-adapter representations; its extent accommodates those representations
without changing their data identities. Read/edit call channels bind to committed backing after
the before phase, so a preparation-time address cannot point at a retired prepared slot. Consuming
adapter cleanup addresses its received argument carrier, including post-call edits, before answer
receipt. The protected answer has separate storage throughout that cleanup.

Machine consumes these requirements through its common executable body construction below.
Scoped locals/channels hold addresses to independent backing; field and environment projections
resolve through exact runtime representations. Equal offsets do not merge logical projections,
including zero-byte payloads. Reserved bytes do not initialize a payload. Each invocation has
independent activation and initialization state.

### Complete Private MIR Bodies

Private body lowering freezes the checked reachable control graph, selected scalar computation,
address bindings and statically selected calls together with storage requirements and lifecycle
phases. No separately pairable companion or second source interpreter supplies computation.
Input slots retain the frozen signature order. Call environment projections, explicit inputs and
protected result places use the selected instance
edge, without reconstructing an adapter or its target from types.

Each action evaluates its resource guard once, performs before effects and writes, establishes
committed call bindings, computes its selected operation, and performs after effects and writes on
normal completion. Arithmetic computes before writing its destination and retains required integer
overflow/division checks. Operand snapshots remain before later operand effects. Comparisons may
normalize relation/operand order only over those completed snapshots. Short-circuit behavior stays
in the frozen graph and cannot become an eager binary operation. Branch predicates and return
answers survive their original cleanup boundaries.
Relational normalization uses the admitted intrinsic integer total orders; it supplies no rule for floating-point
or user-defined comparisons.

An ordinary result and an address channel remain distinct. The private computation contract does
not require source borrow types or a runtime function pointer. Machine consumes this closed
product without repeating checking or interpreting source operations.

### Common Machine Body Construction

Private MIR lowers through the ordinary Machine body draft, optimizer, freeze and dataflow path.
Data values and address carriers retain the same data identity with an explicit physical carrier;
an address carrier's size/class comes from the selected pointer ABI, never the referent's scalar
layout. Address slots likewise retain their referent identity separately from their stored pointer
representation. No synthetic source pointer/borrow type or substituted primitive type supplies it.

Source slots become abstract Machine stack objects; the common native frame placer remains the
owner of final stack offsets. Packed lifecycle predicates map bijectively to Machine's logical
drop-flag identities and their initial values. Native flag placement is an internal encoding, not
a source ABI. Each action selects its alternative once by control flow before either phase;
normal completion follows that selected continuation after the call. Cleanup of shared record
schemas uses one helper per concrete data identity, not an expanded tree of field paths.

On ARM64 Darwin the process-image entry admits a root with no inputs and an immediate `void`, `i32`,
or `usize` result, including the fallible forms. Its Machine wrapper reads the shared outcome tag,
uses only the selected payload, and reports and releases a failure through the common error
operations before exit. Package selection validates the authored module entry independently of
the wrapper. Checking also qualifies a deferred process drive for an empty activation with local
output backing. It follows reached invocations and original resource transitions, and requires
all selected code and cleanup to run without waiting for external progress. This can include a
local loop or recursive call. An unresolved invocation or uncertified backing receives a source
diagnostic. The native entry drives this checked body directly and consumes the output without
materializing a future value. General future construction, suspension and cancellation require
their own evidence. The default installed v2 profile remains open. Callable bodies still preserve
their full frozen input/result contracts. Native-session integration tests compile actual private
source through checking, instances, lifecycle, MIR and these existing native consumers, then
execute the images on ARM64 macOS. They cover scalar computation, scoped channels, control flow,
static callbacks and owned captures, indirect aggregate transport, zero-byte data, register/stack
argument crossing and required arithmetic traps. Closed record/tuple constants reach native code as
serialized immutable data through the model-owned frozen literal product. Their uses receive
independent values; initialization thunks do not become runtime instances. Required source array
construction/repetition, indexed reads/edits and loop computation can freeze a scalar answer before native
instance closure, including maximum-count repeated data without count expansion. Native fixtures
execute those answers as status 42; they establish compile-time array
computation with a scalar consumer, without runtime array layout or array-parameter ABI.
Immutable statics retain one place identity across bodies, with separate address bindings rather
than callable inputs or local owners. Their frozen data uses the same physical serializer without
runtime initialization. Machine owns layout, byte encoding and serialization limits, while checking owns final-data eligibility. Helper-generation tests qualify shared error/record
destruction structure. Selected runtime error constructors and their bounded executed cleanup use
the [Machine qualification](../../compiler/crates/nocter-machine/README.md#private-runtime-error-construction);
general nontrivial destruction through adapters remains unqualified. This boundary establishes correctness evidence, not a
performance claim or complete v2.0.0 support.
