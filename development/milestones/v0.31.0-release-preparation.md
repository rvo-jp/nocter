# v0.31.0 Release Preparation

**Status: release-content preparation complete; qualification pending (2026-09-03).** This record
owns the candidate identity, qualification contract, and eventual local artifact evidence.
Publication requires separate user authorization and will receive a separate immutable record.

## Release Boundary

v0.31.0 adds complete standard-output and standard-error capture to the closed synchronous
subprocess lifecycle introduced in v0.30.0. Consuming `Command.output` creates one child, drains
both finite pipes concurrently, waits for that exact child, and returns an owning `Output` with
arbitrary stdout and stderr bytes plus typed terminal status. Staged child launch reporting keeps
descriptor-setup rejection distinct from executable rejection and ordinary child exit.

The [Phase 5 review](../reviews/v0.31.0-phase-5.md) found no remaining correctness or architecture
finding. Public release notes are [`../../releases/v0.31.0.md`](../../releases/v0.31.0.md). Root
download links and the public release index remain on v0.30.0 until publication succeeds.

## Candidate Identity

The release inputs agree on `0.31.0`:

- `development/packaging/VERSION`, the sole authored release-version input;
- the `#package` version in `development/std/index.nct`;
- the archive name and installed manifest derived from `VERSION` and `RELEASE.json`;
- compiler and language-server reporting derived from the validated installed home.

The exact clean release-content commit will be recorded after this preparation is committed and
before qualification begins.

## Qualification Contract

The clean release-content commit must pass:

1. two independent complete locked workspace test runs in distinct external Cargo targets;
2. warnings-denied all-target Clippy in both external targets;
3. formatter, no-default-features checking, documentation generation and reproducibility,
   repository whitespace, and packaging-input validation;
4. the explicit public-HTTPS dependency-acquisition test;
5. checks and representative native execution for every public example against an isolated
   candidate home;
6. two independent optimized package builds with byte-identical archives and recursively identical
   installed homes;
7. fresh extraction checks for version, doctor, help, initialization, locked/offline check and
   test, deterministic graph, exact `text-banner`, `stdin-prefix`, `subprocess-status`, and
   `subprocess-output` process contracts, native run, explicit build and execution, and framed LSP
   analysis;
8. rejection after either the installed compiler or standard-library content is changed, plus
   proof that ordinary qualification commands do not mutate the installed home.

## Publication Boundary

Qualification does not tag, push, upload, edit public latest-release links, or create an immutable
publication record. A separately authorized publication must reuse the retained qualified archive
without rebuilding it, create one new annotated tag, upload exactly one archive, and verify the
public asset byte for byte. Existing published tags and assets must not be replaced.
