# v0.14.0: Specification-First Compiler Rewrite

## Goal

Build a new Nocter compiler from the public specification without consulting, executing, copying,
or behavior-matching the previous compiler. v0.14.0 is not released until the specification is
closed, the new architecture has one authority for each semantic decision, and the required public
language, standard-library, CLI, editor, and native-runtime contracts are implemented.

## Rewrite Rules

- `spec/` is the sole source of public behavior.
- A missing observable rule blocks implementation and requires a user decision.
- The archived compiler, its tests, its diagnostics, and released behavior are not oracles.
- Existing standard-library implementation details are not bootstrap semantics.
- New responsibilities receive new files or crates with acyclic dependencies.
- Compatibility adapters, fallback selection, reverse semantic lookup, and duplicate program
  indexes are prohibited.
- A phase cannot complete while its superseded authority remains active.

## Phase 0: Isolation and Specification Audit

**Status: complete.** The archived implementation is isolated, the observable specification audit
is complete, and the lexical/syntactic grammar gate is closed with a derived conformance plan.

Phase 0 removes the previous compiler from the active tree, establishes the rewrite rules, and
audits every specification chapter. Each gap is classified as:

- derivable from an existing normative rule
- an internal implementation freedom
- explicitly deferred scope
- a user-visible ambiguity requiring a decision

The phase stops for each user-visible ambiguity. The decision is written to the owning chapter and
receives valid, boundary, and invalid conformance cases before the audit continues.

### Grammar Gate

Before compiler code begins, the specification must define complete lexical and syntactic grammar
for source files, directives, declarations, types, requirements, statements, expressions,
patterns, operators, literals, construction, instances, conformances, and tests.

## Phase 1: Source and Syntax

**Status: complete (2026-08-16).** Normalized source storage, lexical projection, the complete
G001-G033 parser, syntax diagnostics, immutable syntax arenas, and lossless source projection are
implemented and qualified.

Introduce source storage, tokenization, parsing, syntax diagnostics, immutable syntax trees, and
source projections from the closed grammar. No semantic crate exists in this phase.

Completion includes accepted node-shape snapshots, syntax-rejected fixtures, semantic-boundary
fixtures, exact token-projection checks, a 256-level recursive-delimiter limit, and non-recursive
stress coverage for 5,000-layer prefix and left-associative syntax. Parsing decisions use only
tokens, jointness, delimiters, and the normative newline rules; no semantic crate or archived
implementation participates.

## Phase 2: Declarations and Structural Types

**Status: complete (2026-08-16).** The syntax-independent semantic ID, canonical symbol, normalized callable
provenance, structural type interner, immutable declaration-program spine, normalized module and
visibility model, complete typed declaration arenas, freeze-time graph-integrity validation, and
separate node/token-level bidirectional source projection are implemented. The explicit compile-
unit lowering boundary now canonicalizes and validates package, module, and physical-source
topology independently of discovery order. Every authored import now requires an explicit
discovery-owned source or module edge; source reachability/cycles and module acyclicity are checked
without path reinterpretation. Canonical declaration-surface traversal now retains exact nested
ownership and enforces the root-source-only public surface. Semantic identity
reservation and header resolution remain. Public callable contracts and private implementation
bodies are coalesced by canonical authored header, and all recursively referenceable declaration
IDs are now reserved deterministically. Exact declaration names, visibility boundaries,
declaration sites, namespace collisions, and token-level definition projections are resolved.
Generic binder identities, inherited lexical scopes, declaration-pattern reuse, contract/body
identity sharing, and exact binder projections are resolved. Authored module namespaces now resolve
direct declarations, selected aliases, module imports, visibility, and non-widening chained re-
exports in dependency order; source composition creates no semantic import. Synthetic prelude
fallback is now a separate shadowable, non-reexporting namespace layer selected by exact module
identity; standard-package modules receive no fallback and source imports of that module are
rejected. Both authored and fallback layers are retained in the immutable declaration program, so
body checking never reconstructs lookup from declaration/import iteration. Block imports remain a
checked lexical-scope responsibility rather than declaration imports. Header type syntax is now
bound once into a flat syntax-independent arena with exact
module, imported/prelude, generic, arity, `Self`, fixed-array, and structural-callable provenance
resolution. Alias applications and associated selections deliberately remain bound nodes until
requirement-aware normalization. Declaration target patterns share the same name, arity, and exact
source-projection authority and now refer directly to their allocated bare binders. Nominal
interface and structural callable capabilities reuse the same resolver and bound type arena.
Every `where` predicate and associated-type bound is now bound into a closed semantic requirement
shape, including the directed distinction between pattern refinement and general equality. The
syntax tree also represents mandatory interface-member `pub` through the common visibility node.
The structural type store now represents interface-owned `Self` by its declaring interface
identity rather than forging an implicit generic parameter. Requirement-aware normalization is
complete: aliases expand with canonical generic substitution and cycle rejection, associated
selections resolve to exact declaration identities, declaration patterns and requirements share
one evaluator, callable type origins normalize to parameter positions, opaque results retain exact
interface and associated-binding contracts, and 5,000-layer type lowering remains non-recursive.
Complete header definition now allocates every non-recursive leaf identity, defines every reserved
declaration domain, and freezes the declaration program and source index as independent immutable
values. Authored `from` contracts remain distinct from provenance that body checking must infer.
Joined public contracts and private bodies share callable and parameter identities while retaining
separate source roles. Freeze-time validation is the sole authority for declaration shape,
ownership, construction and drop attachment, complete associated bindings, opaque-result
placement, and exact compiler-selected authority over built-in surfaces. Standard authority is
stored as package and module IDs rather than recovered from a textual `std` prefix. Complete-input
ordering permutations produce the same declarations, types, and source index.

The source-backed semantic diagnostic boundary is complete. Integrity failures retain an exact
semantic subject that the separate source index projects without recreating declaration rules in
lowering. Freeze-time declaration rules distinguish authored violations from
compiler graph-integrity faults, carry stable `E0200`-`E0212` identities, and project primary and
related declaration sites through `SourceIndex`. Callable-contract violations carry stable
`E0250`-`E0253` identities and project their exact syntax subjects before reservation. Both use one
source-diagnostic envelope without merging rule selection into presentation. Authored module-
surface violations use that envelope for `E0230`-`E0232`, while malformed syntax snapshots and
inconsistent discovery inputs remain internal errors. A production facade now owns the complete
declaration pass sequence. Header name and visibility violations now preserve exact syntax subjects
and project shared namespace rules `E0240`-`E0242`; import processing reuses those rules and adds
`E0260`, `E0261`, and `E0412` for its own selected-name contracts. Import namespace bindings retain
exact local-name tokens, including aliases. Authored source-composition and module-cycle failures
now project `E0270`-`E0271`; each module edge retains its exact `use` node and cycle witnesses are
stable under input reordering. Generic binder rules now project `E0280`-`E0282` from exact stored
declaration tokens, distinguishing explicit duplicates from inherited shadowing while preserving
declaration-pattern reuse. Header type binding projects `E0290`-`E0302` from retained path segment,
argument, duplicate-name, provenance, opaque-binding, and requirement subjects; malformed bound
input remains internal. Prelude composition now reuses import rule `E0262` and the module-path
origin retained during authored import preparation; compiler-selected authority failures remain
internal. Type normalization consumes a temporary origin side index and projects `E0310`-`E0313`
and `E0320` for canonical complete alias cycles, associated selections, ambiguous callable
provenance, and projection-free general equalities after alias expansion. Definition completion
projects `E0314`-`E0319` from retained subjects. Every production-facade failure variant is
classified as either an authored rule or a compiler/discovery integrity error. Declaration-owned
G006-G010, G012-G013, and G015-G018 semantic fixtures produce identical complete diagnostics when
package and module input order is reversed.

Introduce package, module, declaration, callable, generic-parameter, body, and structural type
identities. Resolve headers into one compile-unit declaration graph and type store. Source ranges
and rendered names cannot enter semantic identity.

## Phase 3: Checked Program

**Status: complete (2026-08-17).** Every body-owned grammar form now constructs closed checked HIR,
and ownership, loans, provenance, destruction, and region semantics consume the same immutable
identities and cleanup edges.

Implement name resolution, type checking, generic requirements, conversions, dispatch contracts,
ownership, borrowing, provenance, regions, destruction, outcomes, and compiler-generated semantic
operations in body-owned checked HIR.

Current implementation includes the syntax-independent body spine, lexical identity, normalized
instance/conformance/copy/drop/construction authorities, expected-type and generic-call planning,
field/index places, ownership and cleanup flow, primitive and source-selected operators, direct and
structural callable calls, construction functions, receiver methods, named-field struct and enum
variant construction, fixed-array literals, exact generic typed-literal selection for fixed
sequence elements and decoded strings, explicit typed-literal allocation-context selection through
validated standard semantic roles, static borrowed string literals, outcome
propagation/forced unwrap, and `catch`/`otherwise` recovery. Method calls freeze
inherent, concrete conformance/default, or lexical interface dispatch and at most one explicitly
selected borrow coercion. Cleanup events distinguish statement, control-header, propagation,
store, and transfer edges; call/aggregate staging and branch-conditional temporaries share the
ordinary ownership state. Pattern control, closures, non-lexical loan escape, callable result
provenance inference, owned interpolation, exact-size typed-sequence spread, collection iteration,
authored binding annotations, and executable regions are complete. A region has one typed context
binding, one retained parent operand, one lexical body, and one ordered release target. Normal and
early exits destroy body-owned values before release; `never` termination does not invent cleanup.
The same identity controls current allocation provenance, storage escape, and the parent loan
lifetime.

Sequence literal bodies now receive a compiler-owned, non-escaping checked-HIR pack rather than an
ordinary element-typed parameter. Only pack length and consuming iteration are representable;
ordinary value use projects `E0409`. Executable signatures retain the pack's specialized element
type and parameter identity outside the ordinary runtime input list. Each reachable call site also
freezes its dense constructor item, specialized result, fixed/spread producer order, concrete spread
types, retained iteration selections, allocation selection, and per-segment residual destruction as
one executable sequence plan. Required user drop bodies enter the executable closure before MIR.
Phase 4 now lowers both caller-side pack materialization and the literal body's consuming input.

## Phase 4: Target Program, Executable Program, and MIR

**Status: complete (2026-08-18).** Target and executable-program construction and checked-body
lowering into validated MIR are complete. The closed target/toolchain snapshot
validates the standard primitive registry and selected package targets before executable
construction. Entry-driven specialization closes a deterministic graph of callable, closure,
drop, and test items, freezes concrete runtime signatures and types, and resolves every reachable
static selection without exposing a requirement to MIR. Composite comparison and index dispatch
retain named operand lanes rather than relying on step order. MIR lowering now covers scalar and
aggregate values, ordinary places, branches, direct and primitive calls, receiver and operand
coercions, comparisons, index places, outcomes, cleanup, loops, patterns, closures, regions,
callable bounds, typed strings, and static opaque results. Opaque construction and method
invocation retain one explicit representation lane from specialization through exact MIR witness
aggregates and projections, including owned, readonly, readwrite, and collection-iteration
receivers. Literal bodies now consume one dedicated MIR pack input through typed length and next
operations, and all returning paths explicitly destroy the unconsumed suffix. Callers now preserve
specified evaluation order, checked exact length, fixed/spread ownership, selected iteration, and
dense deferred destruction in one validated hidden pack argument. Interpolation now lowers through
the frozen standard owned-String constructor, text appender, and per-expression formatter
selections without a string-specific MIR operation. Its partial output uses canonical value
storage, so propagation and explicit return run ordinary cleanup while a forced trap does not.
Callable functions and compiler-owned roots share one `MirBody` CFG schema without synthetic
items. Process roots materialize all six accepted result contracts through root-only exit and
allocation-free error-reporting operations. Test targets retain one independent root per case in
declaration order and preserve empty targets. Test executable signatures are fixed to `void!`, and
`void!` success uses no fictional payload value.

Validate one target/toolchain program as the shared success boundary for `check`, `build`, and
`run`; no public check-only language subset exists. Then instantiate one entry-driven
monomorphized program graph, resolve concrete conformance dispatch once, and lower it to validated
MIR with explicit control flow, calls, moves, loans, regions, and cleanup. Library-only checking
stops at the target program and does not invent an executable entry.

## Phase 5: Machine Program and Native Target

Project MIR through the specified ABI into target-independent machine operations, deterministic
linkage, ARM64 encoding, and Mach-O output. Code generation cannot access syntax, resolver state,
or runtime names as semantic input.

**Status: in progress.** `nocter-machine` now owns the complete target-independent program consumed
by native lowering: recursive stored layouts, the immutable Nocter ARM64-Darwin ABI plan,
name-independent function linkage, content-addressed static data, concrete primitive roles,
allocation-context requirements, and validated per-function dataflow. Dense machine bodies close
all MIR storage, addresses, values, operations, packs, blocks, switches, cleanup, and terminal
behavior without retaining semantic or MIR passthrough nodes.

`nocter-arm64` owns typed instruction encoding, local branch relaxation, physical register roles,
deterministic linear-scan allocation, fixed frames, function/data fixups, and complete
materialization of the currently selected operation set. Constants, scalar operations, structural
comparisons, static and dynamic addresses, checked indexing, aggregate construction, exact memory
movement, direct and indirect callable transport, allocation-context transport, pointer/view and
memory primitives, Darwin syscalls, process termination, direct user destruction, drop flags, and
all machine terminators now execute without consulting source or semantic identities. Direct and
memory-valued block arguments each have cycle-safe parallel-copy authorities. Value switches retain
their one- or two-word subject; stored-tag switches consume the exact layout-owned byte offset.

`Arm64Program` resolves the completed function and data domains into typed fixups. The independent
Mach-O writer owns deterministic section/VM layout, native and dynamic-loader commands,
content-derived UUIDs, SHA-256 ad-hoc signing, and final bytes without invoking an assembler,
linker, or signing tool. Cross-crate conformance tests execute source-authored constants, calls,
arithmetic, comparisons, direct and memory block joins, optional tag switches, static text, large
aggregate transport, checked indexing, pointer and memory primitives, Darwin syscalls, process
exit, conditional user destruction, and compiler-generated recursive pointer destruction natively
on ARM64 macOS.

The remaining Phase 5 areas are the non-movable lexical allocation-context runtime representation
and release path, literal-pack callbacks and residual destruction, independent test-root execution,
and process-entry/I/O/error primitives. These must use the existing machine linkage, ABI, frame,
generated-destruction, and primitive-role boundaries; they may not add backend name lookup or
target-private recursive semantics.

The executable, MIR, and machine layers now preserve pointer destruction as one explicit semantic
dependency containing the concrete subject and optional destruction plan. Recursive user-drop
reachability, layout translation, validation, and hidden allocation-context propagation are closed
before target selection. Machine lowering now interns pointer plans deterministically, appends
name-independent generated linkage after the stable source-function domain, and replaces each
nonempty primitive with an ordinary direct call using the original ABI. Generated CFG handles
reverse fixed arrays without unrolling and delegates authored drops through normal function calls;
ARM64 receives no recursive destruction semantics. Literal-pack residual cleanup must next join
this same function authority.

## Completion Definition

v0.14.0 is complete only when:

- every implemented public behavior traces to one normative specification section
- no unresolved observable ambiguity remains
- the complete grammar and semantic conformance suites pass
- public examples and newly authored standard-library packages check and run
- `check`, `build`, and `run` agree on accepted programs for the same target and toolchain snapshot
- CLI and editor contracts pass protocol-level tests
- native ABI and runtime behavior pass target conformance tests
- source and declaration ordering cannot change semantic or machine results
- later phases cannot import representations owned by earlier phases to repeat decisions
- no archived implementation source, test, output, or compatibility path exists in the active tree
- clean builds are deterministic and full verification passes

Publication and release qualification require separate explicit authorization after this milestone
is complete.
