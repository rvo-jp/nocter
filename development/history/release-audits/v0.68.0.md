# Nocter v0.68.0 Publication and Audit

**Status: published and externally audited (2026-09-24).** This immutable record owns the final
qualification, publication, public-asset, performance-confirmation, and documentation-deployment
evidence for v0.68.0. Public changes are summarized in the
[English release notes](../../../releases/v0.68.0.md); language behavior remains normative only in
the [specification](../../../spec/README.md).

## Qualified Source and Artifact

The completed implementation scope, final design review, qualification, and retained-candidate
performance confirmation are recorded in:

- [`../milestones/v0.68.0.md`](../milestones/v0.68.0.md)
- [`../milestones/v0.68.0-release-preparation.md`](../milestones/v0.68.0-release-preparation.md)
- [`../reviews/v0.68.0-phase-5.md`](../reviews/v0.68.0-phase-5.md)

Release-content commit `8b14736dffecbc15d2afc83061a253e1e98da3d4` passed the complete compiler
gate in a disposable target. The gate included repository metadata, benchmark helpers, pinned
Unicode reproduction, formatting, warnings-denied all-target Clippy, every enabled locked
workspace test, no-default-features checking, warnings-denied Rust documentation, deterministic
372-page website generation, and repository whitespace validation. It included 54 Machine tests,
117 ARM64 tests, 61 analysis tests, 38 CLI tests, 62 command tests, 126 native-session tests, and
118 language-server tests.

Deterministic packaging generated the optimized compiler twice in independent temporary Cargo
targets. The compressed archives matched byte for byte, their extracted `.nocter/` homes matched
recursively, and the retained archive passed both verified fresh installation and active-home
replacement. The qualified candidate was:

- archive: `dist/nocter-v0.68.0-arm64-darwin.tar.gz`;
- byte size: 9,561,026;
- SHA-256: `36c26be4910a07bc7cb36ffbec30c36d4280f8d1a18a72da40d1775ecbc3a775`;
- compiler SHA-256: `55088c91851b198e88cb4ab1297d9913b9823b100d84b08dd1545440c393d9e0`;
- standard-library tree SHA-256:
  `fb5c772c95099f094cf5552817782f2144c4ff03c14a590dc313eb43f787d8d2`; and
- standard library: exactly 478 regular files.

The exact retained installed candidate was compared with the downloaded, digest-verified v0.67.0
release through seven complete native workloads, two warmups, and seven alternating samples.
Every observable result passed. Four executable images were 3.67–6.16% smaller and three were
unchanged. Runtime medians for the five computation-bearing workloads improved by 6.22–14.06%; the
process-pipeline and bounded-service workloads remained within 0.85% because external work and
deliberate waits dominate them.

## Post-Publication Audit

The asset was downloaded from its public release into a new disposable directory. It compared
byte for byte with the qualified local candidate, and its independently computed SHA-256 matched
both the qualification record and GitHub's asset digest. The downloaded archive extracted to a
valid Nocter home whose compiler reported release `0.68.0`, host `arm64-darwin`, and default target
`arm64-darwin`; `nocter doctor` validated the complete home and exactly 478 standard-library files.

The public latest-release endpoint resolved to `v0.68.0`. The public annotated tag resolves to the
exact publication commit recorded above, and remote `main` contained that same commit when the
audit ran.

The repository's push-triggered Compiler run `35928582162` completed successfully for the
publication commit. Its fast change-feedback gate ran in a disposable target; the scheduled and
manual full gate was intentionally not selected for this push because the release-content commit
had already passed the complete local gate before qualification.

GitHub Pages uses its Actions source. Documentation run `35928582160` completed successfully and
artifact `10779609931` deployed 372 generated pages from the publication commit. During the
post-publication audit, `https://nocter.dev/deployment.json` named source revision
`8a975e332b9a56a8e8d1aa0bbabcab9317b3e189`; the served homepage selected v0.68.0 and its exact
release asset and SHA-256.

The release asset and tag are immutable by project policy. Any correction after v0.68.0 requires a
new version, a new tag, a new qualification run, and a newly published archive; the existing tag
and asset must not be replaced.
