## Post-Publication Audit

The asset was downloaded from its public release into a new disposable directory. It compared
byte for byte with the qualified local candidate, and its independently computed SHA-256 matched
both the qualification record and GitHub's asset digest. The downloaded archive extracted to a
valid Nocter home whose compiler reported release `0.72.0`, host `arm64-darwin`, and default target
`arm64-darwin`; `nocter doctor` validated the complete home and exactly 479 standard-library files.

The public latest-release endpoint resolved to `v0.72.0`. The public annotated tag resolves to the
exact publication commit recorded above, and remote `main` contained that same commit when the
audit ran.

The repository's push-triggered Compiler run `36169449960` completed successfully for the
publication commit in 8 minutes 53 seconds. Its fast change-feedback gate ran in a disposable
target; the scheduled and manual full gate was intentionally not selected for this push because
the release-content commit had already passed the complete local gate before qualification.

GitHub Pages uses its Actions source. Documentation run `36169449963` completed successfully and
artifact `10879542350` deployed 374 generated pages from the publication commit. During the
post-publication audit, `https://nocter.dev/deployment.json` named source revision
`e2b759c5a0e5c5ebfaf4201e103cffa9976261e6`; the served homepage selected v0.72.0 and its exact
release asset and SHA-256.

The release asset and tag are immutable by project policy. Any correction after v0.72.0 requires a
new version, a new tag, a new qualification run, and a newly published archive; the existing tag
and asset must not be replaced.
