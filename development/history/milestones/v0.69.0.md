# v0.69.0: Canonical Declaration Contracts

**Status: complete (2026-09-25).** The milestone closes the existing declaration-modifier model.
It does not add a new user-facing modifier. The
[final review](../reviews/v0.69.0-declaration-contracts.md) records the closed findings,
qualification evidence, and evaluation of possible future guarantee vocabulary.

## Goal

Make every existing declaration prefix a deliberate part of one grammar and one compiler contract.
`pub`, `const`, `noalloc`, `blocking`, `async`, `primitive`, `copy`, and `default` describe different
responsibilities; the compiler must not treat their shared prefix position as proof that they have
the same semantics.

The syntax layer recognizes the canonical authored order once. Declaration lowering is the only
syntax-to-semantic projection. Checking validates bodies and compatibility from that projected
contract, while formatting and editor presentation consume the same canonical semantic facts rather
than reconstructing modifier meaning.

## Completion Definition

v0.69.0 is complete when all of the following are true:

- the normative grammar includes every supported callable prefix, including `const`;
- one syntax-owned callable-prefix recognizer serves top-level functions, construction functions,
  interface methods, and inherent methods without declaration-specific lookahead copies;
- declaration-kind policy rejects an unsupported modifier or combination without silently parsing
  it as another declaration;
- `CallableGuarantees` remains the sole structural identity for authored allocation, waiting, and
  compile-time promises, while deferred execution remains an independent declaration fact;
- callable type compatibility, interface satisfaction, contract/body joining, body validation,
  formatting, hover, completion, and diagnostics preserve those same facts;
- `primitive`, `copy`, and `default` remain authority, type-capability, and interface-body syntax
  respectively rather than being folded into the callable-effect model;
- standard-library and example source use one canonical modifier order; and
- whole-repository review finds no token-text inference, duplicate modifier policy, legacy syntax,
  or downstream reconstruction of a declaration contract.

## Canonical Categories

| Category | Source forms | Owner |
|---|---|---|
| visibility | `pub`, `pub(path)` | declaration visibility |
| compile-time availability | `const` | structural callable guarantee |
| allocation guarantee | `noalloc` | structural callable guarantee |
| synchronous-wait admission | `blocking` | structural callable guarantee |
| execution form | `async` | callable declaration execution |
| toolchain authority | `primitive` | registered bodyless declaration form |
| value capability | `copy` | nominal type declaration form |
| inherited body | `default` | interface-member declaration form |

Callable prefixes retain the canonical order `const noalloc blocking async` after visibility. The
order is grammar, not effect precedence. A primitive function places `primitive` after callable
guarantees and before `func`. Semantic validation continues to reject `async` combined with
`noalloc` or `blocking`; parsing retains enough structure to issue that semantic diagnostic.

## Phases

### Phase 0 — Specification and Authority Audit

**Status: complete.** The normative grammar now includes `const` on functions, primitive functions,
construction functions, interface and inherent methods, and structural callable types. The audit
confirmed that declaration lowering already owns the sole modifier-to-`CallableGuarantees`
projection and keeps `async` as independent execution form. Syntax recognition remains duplicated
across declaration contexts and is the Phase 1 replacement boundary.

### Phase 1 — Canonical Syntax Recognition

**Status: complete.** One syntax-owned ordered vocabulary now recognizes callable prefixes for
top-level and primitive functions, construction functions and literals, interface and inherent
methods, implicit instance call surfaces, destruction, and structural callable types. Declaration
classification and event-producing parsing consume the same recognizer. Syntax retains dedicated
modifier nodes and does not decide effects or execution semantics. The replacement removed the
context-specific `at_const_*` and `optional_*` lookahead paths.

### Phase 2 — Semantic Policy and Compatibility

**Status: complete.** Declaration lowering remains the sole syntax-to-`CallableGuarantees`
projection, and `CallableExecution` remains independent of result shape. `nocter-declarations` now
owns one closed incompatibility policy across callable kind, execution, and guarantees; checking
only attaches its violations to current source. The former asynchronous modifier rules no longer
live inside type-position validation. The policy closes impossible `const async` and unsupported
`const primitive func` promises as well as the existing `noalloc async` and `blocking async`
combinations. Contract/body joining retains exact normalized headers, while structural callable
conversion and interface satisfaction both use the model-owned directional `can_weaken_to`
relation.

### Phase 3 — Tooling and Source Migration

**Status: complete.** `nocter-language` now owns the ordered callable-modifier vocabulary, syntax
grammar categories, and context-independent modifier compatibility. Parser recognition, semantic
hover/signature presentation, and keyword completion consume that authority. This removed the
completion-only ordering matrix and corrected its rejection of supported async construction
functions. Formatting remains lossless syntax formatting and semantic highlighting remains lexical
for reserved modifiers, so neither reconstructs a callable contract. Standard-library and example
source already use the canonical order and required no compatibility migration.

### Phase 4 — Qualification and Extension Review

**Status: complete.** The complete compiler gate passed across compiler, editor, installed standard
library, every public example, native execution, package paths, no-default-features checking, and
Rust documentation. Documentation generation remained deterministic. The repository-wide modifier
inventory found no remaining local ordering or compatibility matrix. The final review rejects
redundant `noblock`, `nothrow`, `nosuspend`, and `alloc` spellings; defers ambiguous or currently
unprovable `pure` and `total`; and identifies `realtime` as the only preferred future profile after
a concrete bounded-execution proof model exists.

## Deferred Work

Adding `pure`, `realtime`, `noblock`, `nothrow`, `alloc`, `unsafe`, or another modifier is outside
this milestone until Phase 4. Linux target work also remains deferred so a second target does not
duplicate a declaration contract that is still changing.
