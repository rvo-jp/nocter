# v0.40.0 Release Preparation

**Status: qualification in progress (2026-09-07).** This record owns the release-candidate
identity, qualification contract, and retained local artifact evidence. It does not claim
publication or authorize a tag, push, upload, or public latest-release change.

## Release Boundary

v0.40.0 adds immutable canonical HTTP-family URL values, operating-system host resolution, ordered
host connection, validated HTTP/1.1 message values, bounded transport-independent framing, and a
synchronous one-request-per-connection HTTP client. Native resolver records stay inside the Darwin
adapter, HTTP framing stays independent of transport ownership, and the compiler gives URL, DNS,
and HTTP APIs no special meaning.

The [milestone](v0.40.0.md) and [Phase 5 review](../reviews/v0.40.0-phase-5.md) define the closed
implementation. Public candidate notes are
[`../../../releases/v0.40.0.md`](../../../releases/v0.40.0.md). Root download links, specification
status, and the public release index remain at v0.39.0 until separately authorized publication.

## Candidate Identity

The release inputs agree on `0.40.0`:

- `development/packaging/VERSION`, the sole authored release-version input;
- the `#package` version in `development/std/index.nct`;
- the archive name and installed manifest derived from `VERSION` and `RELEASE.json`;
- compiler and language-server reporting derived from the validated installed home.

`RELEASE.json` remains the machine authority for version-independent license, host, target, and
archive metadata. Release qualification verifies that its license agrees with the shipped legal
files and every Cargo workspace package before either package build begins.

The exact release-content commit and retained artifact evidence will be recorded only after the
clean candidate passes qualification.

## Qualification Contract

The clean release-content commit must pass:

1. independent complete compiler gates in distinct disposable Cargo targets;
2. repository metadata, benchmark-helper tests, pinned Unicode reproduction, formatting,
   warnings-denied all-target Clippy, all enabled locked workspace tests, no-default-features
   checking, and warnings-denied Rust documentation;
3. deterministic generated website reproduction and repository whitespace validation;
4. the explicit public-HTTPS dependency-acquisition test;
5. two independent optimized package builds with byte-identical archives and recursively identical
   installed homes;
6. fresh installed-home checks for version, diagnosis, help, initialization, locked/offline check
   and test, deterministic package graphs, native build, run, and direct execution;
7. every public example and its exact process contract, including DNS, TCP, UDP, timeout, URL, and
   local HTTP integration;
8. framed LSP analysis of installed public contracts and implementation sources;
9. proof that qualification commands do not mutate the installed home and that changing either the
   compiler or one standard-library source invalidates it.

The earlier complete gate on the closed implementation remains useful evidence, but release
qualification must execute against the commit carrying the final `0.40.0` identity.

## Publication Boundary

Publication remains a separate user-authorized operation. It must reuse the retained qualified
archive without rebuilding it, update public latest-release links in a separate commit, create one
annotated `v0.40.0` tag, upload exactly one asset, and verify the public download byte for byte.
