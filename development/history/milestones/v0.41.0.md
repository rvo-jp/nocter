# v0.41.0: Structured Asynchronous I/O Foundation

**Status: Phases 0-1 complete; Phase 2 is next (2026-09-08).**
The qualified v0.40.0 candidate remains isolated from this work. v0.41.0 has no release identity
until v0.40.0 is published separately.

## Outcome

v0.41.0 will make asynchronous execution one coherent language, compiler, runtime, and standard-
library capability. An ordinary program will be able to suspend an asynchronous function on a
timer or socket operation, let other runnable work progress, resume exactly once, and cancel owned
unfinished work without leaking descriptors or skipping destruction.

The release is not a syntax-only milestone. It closes only when checked source, lowered state
machines, target-independent scheduling facts, Darwin readiness, public time and network APIs,
editor behavior, native execution, and cancellation cleanup agree on one model.

HTTPS is deliberately sequenced after this foundation. Apple's current Network framework exposes
connection progress through queues and completion handlers, while Secure Transport is legacy and
requires transport callbacks. Adding HTTPS first would either introduce a temporary deprecated
transport or smuggle foreign callback ownership through the fixed-call target-service boundary.
Neither is an acceptable basis for a long-lived standard library.

## Existing Facts

- Public TCP operations are synchronous, but their private descriptors are already nonblocking.
  The private network substrate turns `would_block` into a one-descriptor readiness wait.
- Monotonic observations, finite operation deadlines, descriptor ownership, and exact interruption
  retry already have one standard-library authority.
- Nocter has no task, scheduler, reactor, wakeup, suspension, or cancellation representation.
- The target-service ABI admits fixed-arity C integer, word, and pointer values. It intentionally
  excludes callbacks, aggregate foreign values, and foreign ownership.
- Compiler-generated literal-pack callbacks are synchronous target-owned implementation details;
  they are not a general C callback ABI and must not be reused as one.

These facts make a Darwin readiness reactor feasible without changing the public FFI boundary.
They do not make modern platform TLS feasible as a synchronous wrapper over `TcpStream`.

## Core Invariants

1. The checked program owns async type and suspension meaning. MIR and later stages cannot infer an
   async call from source spelling or reconstruct borrow legality.
2. One compiler-generated state object owns every local that survives suspension. Each local has
   one initialized-state fact and one destruction path.
3. Suspending transfers control to the executor; it never copies an owning value into both the
   frame and scheduler state.
4. The executor owns task lifecycle and runnable order. The reactor owns readiness registration.
   Neither may inspect the other's internal representation.
5. A reactor registration uses a stable identity plus generation, never a pointer into movable
   task storage. A stale event therefore cannot resume a replacement task.
6. Cancellation is an ordinary ownership transition. It removes registrations before destroying
   the suspended frame and closes each owned descriptor exactly once.
7. Deadlines use the existing monotonic domain. Socket readiness and timer expiry cannot implement
   separate elapsed-time rules.
8. `async` describes suspension; a future `noblock` guarantee describes the absence of thread-
   blocking operations. Neither modifier silently implies the other.
9. Synchronous APIs remain valid and do not run a hidden global executor. Async execution begins
   only from an explicit async entry or runtime boundary.
10. LSP features consume checked async capabilities and source maps. The editor does not parse a
    second async language or inspect generated state-machine layout.

## Phase 0: Feasibility and Surface Contract

**Status: complete.**

Phase 0 has established that the existing nonblocking descriptor attempts, monotonic deadline
authority, ownership model, and target-independent lowering boundaries are reusable. It has also
established that the current trusted target-service ABI cannot honestly host Network.framework or
Secure Transport callbacks. v0.41.0 therefore begins with a callback-free readiness reactor and
leaves TLS to a later transport phase.

The adopted surface writes asynchronous production as a result type, not a callable modifier:

```nct
func fetch(url: Url): async String!
```

`async T` is a lazy, single-use owning computation. It may be stored or moved, `await` consumes it,
and destruction cancels unfinished work. `async T!` means `async (T!)`; a fallible immediate
operation returning a computation is written `(async T)!`. Calling a declaration whose normalized
outer result type is `async` creates the computation, while its body produces the inner type.
Generic substitution cannot later change an immediate declaration into a deferred declaration.

Spawned work is structured and scope-owned; the initial release has no detached task. `async` and
`noblock` remain independent because suspension and operating-system-thread blocking are distinct
facts. The complete cross-crate authority, capture-provenance, cancellation, and lowering contract
is recorded in the
[Asynchronous Computation Boundary](../../design/asynchronous-computation-design.md).

## Phase 1: Syntax and Checked Async Product

**Status: complete.**

Add lossless syntax and one checked semantic representation for `async T`, consuming `await`,
deferred callables, and the owning computation lifecycle. Extend body checking, effect closure,
provenance, cleanup, diagnostics, formatter normalization, serialization, and source maps together.

Phase 1 closes when ordinary and generic calls, success and failure results, moves, branches,
loops, captures, nested awaits, invalid contexts, and every forbidden borrow across suspension are
decided once in the checked product. No executable state machine or standard-library async API is
introduced in this phase.

The completed checked product assigns callable execution once after alias normalization, keeps
generic substitution from reclassifying immediate callables, and carries the specialized deferred
output on each checked call. Await is a consuming checked operation with contextual generic
inference across arbitrary nested async layers and outcome propagation. Pending captures and
awaited-result provenance use separate projections. Loan analysis rejects frame-internal borrows
across suspension while retaining externally owned inputs, and nested immediate closures cannot
inherit suspension authority from their enclosing deferred body. Canonical type presentation is
shared by diagnostics and editor features. Target-independent state machines remain deliberately
unsupported until Phase 2 supplies their lifecycle and destruction contract.

## Phase 2: Executable State Machines and Destruction

Lower each reachable async callable into one explicit target-independent state machine. The frame
contains only values proven live at a suspension point plus its continuation and initialization
facts. Resume, completion, failure, cancellation, and destruction are separate closed transitions.

Phase 2 closes when MIR validation can prove that every state consumes exactly its initialized
inputs, every suspension publishes one continuation, every terminal path destroys residual values
once, and Machine lowering needs no source, syntax, region, or checker lookup.

## Phase 3: Executor and Darwin Reactor

Introduce an owned single-threaded executor and a Darwin readiness reactor behind target-
independent scheduler and reactor contracts. The first reactor multiplexes nonblocking descriptors
and monotonic timers without foreign callbacks. Stable registration identities, generations,
wakeup ordering, interruption, timeout, closure, and cancellation are modeled explicitly.

Phase 3 closes when deterministic model tests cover stale events, simultaneous readiness and
timeout, cancellation at every transition, descriptor reuse, empty runnable sets, and executor
shutdown, while native loopback tests prove more than one task can make progress.

## Phase 4: Async Time and Network APIs

Add the smallest practical public async surface for sleeping, TCP connection, stream reads and
writes, listener acceptance, host candidate connection, and cancellation-safe timeouts. The async
adapters consume the same address, descriptor, resolver, error, and monotonic contracts as their
synchronous counterparts; they do not duplicate native record parsing or socket policy.

Phase 4 closes when a bounded concurrent loopback application runs through public APIs and covers
partial I/O, backpressure, timeout, peer closure, cancellation, address fallback, and deterministic
cleanup. Filesystem operations, subprocesses, TLS, UDP, and a general thread pool remain outside
this first async surface unless implementation evidence shows they share the same contract without
exceptions.

## Phase 5: Tooling, Integration, Review, and Qualification

Add complete examples and semantic-editor coverage for declarations, calls, suspension points,
inferred values, navigation, references, rename, completion, signature help, hover, semantic
tokens, and inlay hints. Review the complete area for duplicate state decisions, hidden executor
singletons, scheduler/reactor representation leaks, stale wakeups, cleanup gaps, blocking hidden
inside promised nonblocking paths, source-derived lowering, and editor-only semantics.

Qualification requires the complete repository gates, deterministic native concurrency fixtures,
installed-home execution, reproducible packaging, and a final whole-area review with no open
practical finding.

## Non-goals

- TLS or HTTPS transport
- Network.framework, foreign blocks, or a general callback ABI
- detached background tasks
- multiple executor threads, work stealing, or a `Send`/`Sync`-style type system
- asynchronous filesystem semantics or a hidden blocking thread pool
- public nonblocking descriptor manipulation
- HTTP/2, HTTP/3, WebSocket, or a production server framework
- another native target
