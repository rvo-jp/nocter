# v0.61.0: Reliable Development and Distribution

**Status: active (2026-09-19).** v0.61.0 makes ordinary source maintenance and artifact delivery
reliable before the next standard-library expansion. The latest published release remains v0.60.0.

## Goal

- make compiler regressions visible on every proposed or merged change without duplicating the
  release gate;
- bound disposable local build and release-candidate storage;
- complete comment-preserving source formatting;
- define and implement verified artifact installation after its trust and replacement contracts
  are closed in the public specification.

## Phase 0 — Repository Operability

**Status: complete (2026-09-19).** One verification entry point now owns fast and full tiers. Pull
requests and pushes to `main` run the fast tier on the supported ARM64 Darwin host; weekly and
manual jobs run the complete gate. Local release qualification retains only the current candidate,
while published artifacts remain owned by GitHub Releases and immutable release audits. The
workspace Cargo cache and obsolete local release candidates were reclaimed.

## Phase 1 — Comment-Preserving Formatting

**Status: complete (2026-09-19).** Formatter trivia ordering and anchoring are independent of token
layout. Formatting preserves exact comment text and kind, comment order, and syntax-owned
documentation attachment. Candidate reparse verifies all four properties before a file may be
replaced. The published `E0601` code remains reserved rather than being reassigned. The complete
disposable compiler gate passed after the formatter and CLI contracts changed.

## Phase 2 — Verified Artifact Installation

**Status: specification closure pending.** Before implementation, the public contract must decide
the artifact trust input, local-versus-remote acquisition boundary, installation destination and
replacement transaction, and failure recovery behavior. Existing manifest content validation is
an integrity mechanism and must not be described as artifact authenticity.

## Completion Gates

- the complete disposable compiler gate passes;
- documentation generation and external-site build pass;
- formatter conformance covers leading, trailing, inline, multiline, ordinary, item-documentation,
  and file-documentation comments;
- the installed-artifact qualification exercises the adopted installation transaction;
- a final review finds no duplicate verification command authority, unbounded generated-output
  lifecycle, comment-specific parser fork, or ambiguous trust claim.
