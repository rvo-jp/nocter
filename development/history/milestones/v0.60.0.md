# v0.60.0: Streaming Compression and Safe Archives

## Goal

Turn the existing byte codecs, fixed-capacity storage, checksum state, byte streams, and path
contracts into one safe compressed-archive pipeline. Nocter must be able to inspect and extract a
gzip-compressed tar archive without an external `gzip`, `tar`, zlib, or second transport model.

The milestone begins with decoding and reading. Compression strategy and archive creation remain
separate later work: a correct streaming decoder has bounded state and deterministic progress,
whereas a useful encoder additionally owns match finding and compression policy.

## Completion Definition

v0.60.0 is complete when all of the following are true:

- one allocation-free DEFLATE engine accepts fragmented input and bounded output while reporting
  exact input consumption and output production;
- stored, fixed-Huffman, and dynamic-Huffman blocks share one bit-order, history-window, and symbol
  validation authority;
- malformed trees, invalid distances, incomplete input, exhausted output, and completed streams
  remain distinct outcomes without text-backed control flow;
- one gzip layer validates headers, optional fields, concatenated members, CRC-32, and uncompressed
  size through existing checksum and byte-codec contracts;
- one tar reader exposes bounded entry metadata and body streams without allocating a complete
  entry or creating another external I/O abstraction;
- extraction rejects absolute paths, parent traversal, unsupported special files, duplicate output
  paths, and configured size-limit violations before publishing unsafe filesystem state;
- blocking and asynchronous adapters drive the same compression and archive state machines rather
  than repeating format decisions;
- a practical application inspects or safely extracts a `.tar.gz` stream under explicit input,
  output, entry-count, and path limits;
- native, standard-library, editor, documentation, installation, and packaging gates pass; and
- whole-repository review finds no duplicate bit reader, Huffman builder, checksum, archive-header,
  path-normalization, or transport-specific decode authority.

## Responsibility Boundaries

`std/compress` owns compressed representation, decoder state, history, and progress classification.
It does not own files, sockets, deadlines, archive paths, or extraction policy. Input and output
remain caller-owned slices; the decoder retains only state required between calls.

`std/archive` owns tar headers, entry boundaries, archive metadata, and safe relative archive
paths. It does not own DEFLATE, gzip framing, filesystem publication, or transport progress.

`std/checksum` remains the only CRC-32 authority. `std/bytes` remains the only multi-byte scalar
authority. `std/io` remains the only blocking and asynchronous byte-transport contract. `std/path`
and `std/fs` remain the path and filesystem authorities.

The extraction application owns policy: accepted entry kinds, resource limits, destination
selection, temporary publication, and cleanup. These decisions are not embedded in tar parsing.

## Phases

### Phase 0 — Progress and State Authority

Status: complete.

- freeze the decoder progress model, terminal-state rules, and resource-limit ownership;
- implement and test one allocation-free LSB-first bit reservoir for every DEFLATE block kind;
- prohibit decoder retention of caller input and output slices; and
- define incomplete-input and exhausted-output outcomes without recoverable-error text conventions.

### Phase 1 — DEFLATE Core

Status: complete.

- decode stored, fixed-Huffman, and dynamic-Huffman blocks;
- validate canonical trees, literal/length symbols, distances, and end-of-block state;
- preserve one 32 KiB history authority across arbitrary input and output fragmentation; and
- prove identical output and terminal classification for every tested chunk partition.

One allocation-free decoder now owns the complete stored, fixed-Huffman, and dynamic-Huffman state
machine. Canonical tables are built into caller-owned fixed storage only after complete validation;
symbol decoding consumes no incomplete prefix; and one 32 KiB ring is the sole history authority.
Native execution covers whole-buffer and one-byte input/output partitions, overlapping copies,
history wrap beyond 32 KiB, exact progress, malformed block/tree/distance cases, and sticky success
and failure terminals.

### Phase 2 — Gzip Members

Status: complete.

- parse bounded headers and optional fields;
- validate method, flags, header termination, CRC-32, and modulo-2^32 output size;
- support concatenated members without conflating trailing invalid data with completion; and
- expose one gzip decoder over the Phase 1 engine.

One allocation-free gzip decoder now parses fixed and optional headers, verifies optional header
CRC-16 values through the shared CRC-32 transition, delegates payload representation exclusively to
the raw-DEFLATE decoder, and validates trailer CRC-32 and modulo-2^32 output size. Explicit
`member_finished` and transport-EOF operations preserve concatenated-member boundaries without
guessing whether absent input means completion. Native execution covers byte-at-a-time input and
output, every optional header field, concatenation, integrity damage, reserved flags, invalid
payloads, truncation at each framing region, exact progress, and sticky terminal states.

### Phase 3 — Tar Entries

Status: complete.

- parse and validate checksummed 512-byte headers;
- expose regular-file and directory metadata plus bounded entry-body progress;
- normalize archive paths without filesystem access; and
- skip padding and unsupported entry kinds without retaining complete bodies.

One allocation-free POSIX ustar reader now owns header assembly, checksum and octal validation,
entry boundaries, body ranges, padding, and the two-block end marker. It retains only one normalized
UTF-8 relative path and metadata record; bodies remain exact ranges of caller input. Path
normalization rejects absolute paths, parent components, empty results, malformed UTF-8, and ustar
capacity overflow before publishing an entry. Native execution covers byte-at-a-time headers and
bodies, regular files, directories, observable unsupported kinds, padding, terminal markers, and
distinct malformed and truncated regions.

### Phase 4 — Transport Composition

Status: complete.

- adapt gzip and tar progress to `BlockingReader` and `Reader` without format-specific transports;
- preserve backpressure, cancellation, and bounded scratch storage;
- keep deadlines in existing timed-reader composition; and
- prove blocking and asynchronous fragmentation equivalence.

One transport-independent gzip cursor now drives both owning `BlockingReader` and `Reader`
projections. A separate tar event cursor accepts either standard reader per operation, so tar owns
neither source type nor deadline policy. Both cursors retain one bounded reusable input allocation,
validate reported read counts, and commit asynchronous input only after the awaited refill
completes. Late gzip failures are deferred until already-produced output has been observed.

Transport-driven tar completion drains its source after the in-band end marker. Consequently a
gzip-composed archive cannot report success before the outer member trailer, CRC-32, size, and EOF
have been validated. Native blocking and asynchronous pipelines use one-byte source, decode,
archive, and body fragments and produce identical entry metadata and content.

### Phase 5 — Safe Extraction Application

Status: complete.

- add one complete `.tar.gz` inspection or extraction package;
- require explicit resource limits and safe destination-relative paths;
- publish files only after their complete content has passed framing and integrity checks; and
- cover truncation, checksum damage, path traversal, duplicate paths, and excessive declarations.

The `archive-inspect` package now composes a bounded blocking source, `BlockingGzipReader`, and
`TarStream` without recreating compression or archive decisions. Its explicit policy bounds
accepted compressed bytes, every decoded transport byte, declared body bytes, entry count, and
normalized path length.
It rejects traversal through the tar authority, duplicate normalized paths, unsupported entry
kinds, nonempty directories, and every configured limit. A single rejected sentinel byte
distinguishes an input exactly at its limit followed by EOF from an excessive stream.

The application retains only bounded decode storage plus bounded entry metadata. It publishes no
line of output until the tar end marker, complete gzip trailer, and transport EOF have all passed,
so late checksum or framing damage cannot expose a partial report. Declared tests exercise
one-byte source fragmentation, truncation, damaged gzip integrity, every resource limit, traversal,
duplicates, unsupported entries, and decoded data following the tar marker; the repository-owned
process contract also executes the complete application against a real file.

### Phase 6 — Editor, Review, and Qualification

Status: complete.

- qualify public and implementation sources through the complete editor surface;
- run compiler, standard-library, native, documentation, installation, and packaging gates;
- review all representation and responsibility boundaries; and
- prepare v0.60.0 only after the installed practical application passes.

The real `archive-inspect` package now crosses hover, declaration and implementation navigation,
member completion, semantic highlighting, and inferred-type hints from one complete checked
generation. The repository-wide gate executes its declared tests and process contract through the
installed standard-library declarations together with the raw decoder, gzip, tar, and blocking and
asynchronous composition suites.

The final authority review found no second bit reservoir, Huffman builder, CRC-32 transition, tar
parser, path normalizer, or transport-specific format state machine. Its only gate findings were
stale audit metadata: the closed standard dependency catalog did not yet name the four intentional
transport and storage edges added in Phase 4, and one command-test match repeated an identical
empty-output arm. The catalog now records those edges and the redundant arm is merged. Compiler,
native, editor, documentation, formatting, and integrity gates pass. v0.60.0 is ready for the
separate release-preparation change that assigns and qualifies the release identity.

## Explicit Non-goals

ZIP, encryption, cryptographic authentication, symbolic archive schemas, host-endian APIs,
filesystem-preserving device nodes, and compression-ratio optimization are outside v0.60.0.
Archive creation and a general-purpose DEFLATE encoder require a separate application-driven
milestone rather than hidden scope inside decoding.
