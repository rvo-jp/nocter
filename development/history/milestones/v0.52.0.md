# v0.52.0: Compile-Time Callable Evaluation

## Goal

Allow ordinary, explicitly capable Nocter callables to participate in compile-time evaluation while
preserving one checker, one constant-value authority, deterministic target-independent execution,
and the same runtime semantics for those callables.

## Completion Definition

v0.52.0 is complete when all of the following are true:

- `const func` and `const method` declare one authored compile-time-callable capability;
- the capability participates in callable identity, compatibility, declaration completion,
  interface conformance, formatting, diagnostics, and semantic presentation;
- ordinary checking is the sole producer of all type, control-flow, operation, and dispatch
  decisions used by compile-time calls;
- a checking-owned exhaustive projection converts eligible checked bodies into source-independent
  compile-time callable plans;
- semantic construction resolves constant values, static values, array lengths, and callable
  specializations through typed dependency-query strata, then publishes one immutable
  compile-time program authority;
- constants and immutable statics can call eligible functions and methods without a syntax-reading
  evaluator or a second checker;
- evaluation supports scalar values, static text, tuples, and fixed arrays, with deterministic
  recursion and work limits;
- allocation, ambient state, mutable aliasing, destruction, blocking, and asynchronous operations
  are rejected through operation capability rather than declaration-name rules;
- the standard library uses the feature for real scalar derivation helpers instead of keeping a
  demonstration-only API;
- compiler, LSP, formatter, standard-library, installed-toolchain, and public-example gates pass;
- a whole-repository review finds no optional constant placeholder, duplicate value table,
  source-level body interpreter, or caller-correctness precondition in this area.

## Phases

### Phase 0 — Dependency and Value-Domain Audit

Status: complete.

- trace every current constant, static, fixed-array-length, and checked-body dependency;
- identify concrete standard-library consumers;
- define authored capability, checked projection, evaluation plan, and value ownership separately;
- record the semantic query required to break the existing declaration/checking stage cycle.

The audit found that constants are currently evaluated during declaration lowering before any
callable body is checked. Adding calls to the syntax-owned expression planner would therefore
create a second checker. The adopted design replaces fixed stage ordering for compile-time facts
with identity-keyed dependency queries and keeps the evaluator downstream of ordinary checking.
The complete boundary is documented in
[`development/design/compile-time-callable-design.md`](../../design/compile-time-callable-design.md).

### Phase 1 — Authored Capability and Declaration Model

Status: complete.

- add one compile-time-callable capability to semantic callable contracts;
- parse and normalize canonical `const` callable modifiers without conflating constant declarations;
- enforce one-way capability weakening and contract/body agreement;
- integrate formatter, AST, diagnostics, hover, completion, and semantic tokens.

`CompileTimeGuarantee` is now an independent axis of `CallableGuarantees`. The shared
syntax-to-contract projection consumes one `CompileTimeModifier` for module functions,
construction functions, methods, interface methods, and structural callable types. Contract
joining and interface conformance therefore use the same directional compatibility relation:
compile-time capability may be forgotten, while a runtime-only callable cannot acquire it.
Canonical formatting and semantic presentation render `const` before the runtime guarantee
modifiers, and completion follows that authored order. Constant declarations retain their distinct
`const NAME: Type` parse identity.

### Phase 2 — Checked-Body Plan Projection

Status: complete.

- define the closed callable-plan representation in `nocter-constant-evaluation`;
- project eligible checked operations exhaustively from canonical checked bodies;
- retain selected callable and specialization identities without lookup inputs;
- diagnose unsupported operations and enforce deterministic evaluation budgets.

The closed callable-plan model and checking-owned projection are implemented. Program finalization
projects the complete callable arena once and publishes one identity-indexed
`CompileTimePlanTable` inside `CheckedProgram`; consumers cannot request projection or pair a body
with a callable themselves. Plan construction validates every body-node, parameter, local, and
direct-call edge before publication. It lowers scalar values, readonly inputs, immutable locals,
primitive arithmetic and comparisons, tuples, fixed arrays, blocks, conditionals, returns, and
already-selected direct calls. Unsupported operations become source-neutral projection rules and
are projected once to `E0421` through canonical body-node origins. Deterministic evaluation limits
are expressed in semantic operation steps and source-call depth, independent of host time or
instructions.

### Phase 3 — Semantic Dependency Queries

Status: complete.

- separate constant identity/type declarations from evaluated value ownership;
- introduce one semantic construction authority with typed dependency-query strata for array
  lengths, values, bodies, and callable plans;
- detect real dependency cycles and publish no partial semantic product;
- replace embedded constant payloads in checked operations with stable constant identities.

The shared dependency-query core is implemented and current constant evaluation now uses it. Each
key has exactly one absent, active, or completed state; active re-entry returns the exact cycle,
failed branches erase their active state, and completed diamond dependencies are reused. Constant
plans freeze their declared reference edges once during planning. The query resolves every edge
before evaluating short-circuit control flow, preserving the language rule that an initializer
cannot hide a dependency cycle in an unselected branch, while removing the former separate
dependency-order DFS. Completed values are allocated once behind shared immutable handles, and the
query authority cannot be cloned into a competing cache. Checked bodies now distinguish intrinsic
literal payloads from declaration
references: a reference retains `ConstantId` through compile-time projection and target
reachability. `ExecutableProgram` freezes only the values required by its closed item set, and MIR
resolves those identities exclusively through that table. Declaration records retain metadata
only. A sparse structural table supplies the early fixed-array type boundary, while checked
finalization later owns the dense constant/static value table. Array lengths use dense
`ConstantExpressionId` keys and request structural constants through one memoized authority.
Callable plan ownership is specialization-based rather than declaration-slot-based:
checking projects every eligible body once into a shared operation recipe, including unreached
generic bodies, and one query transforms only its type edges for every reachable closed
`CompileTimeCallTarget`. Generic substitutions are represented by evaluator-domain type shapes
instead of store-relative `TypeId`; multiple call sites share one completed specialization, and
recursive source call graphs close without being misdiagnosed as construction cycles. Declaration
values and callable plans are intentionally completed in ordered, non-reentrant strata: checking
cannot observe unfinished declaration types, and declaration lowering cannot reopen checker state.
Finalization joins the exact shared value table and closed specialization table into one immutable
`CompileTimeProgram`, so every downstream consumer receives the complete pairing through one
authority and cannot assemble or recompute either side.

### Phase 4 — Compile-Time Calls and Value Expansion

Status: complete.

- admit direct function and method calls in constant and static initializers;
- support scalar values, static text, tuples, and fixed arrays end to end;
- preserve target-defined numeric behavior through the existing evaluator authority;
- add standard-library scalar derivation consumers and cross-module conformance fixtures.

The closed callable executor is implemented. Plans now retain specialized parameter and result
shapes, and execution validates every call boundary, local binding, operation result, and final
result without reopening declarations. One executor owns deterministic step/depth budgets and a
completed-call cache. Recursive calls, nested selected calls, malformed arguments, and width
violations are covered directly. Constant-expression evaluation and callable execution share one
scalar arithmetic/comparison/conversion authority rather than maintaining parallel semantics.
Constant and static initializer values are now produced only from their ordinary checked
expression bodies. Their zero-parameter initializer plans execute through the same closed-plan
executor as callable bodies, so direct function calls, readonly method calls, and generic helpers
reachable only from an initializer work without extending the header expression planner.
Immutable static values now preserve tuple structure through planning, semantic validation,
executable closure, machine layout, and data encoding instead of flattening or rejecting it.
Executor control is represented as a value or one function-level interruption. Returns and
unreachable paths propagate through every parent operation uniformly; a discarded conditional or
an argument expression cannot accidentally consume a nested return.
Existing standard-library scalar policy is now the first real consumer: buffer-capacity
normalization, URL byte classification, and Gregorian-calendar derivation retain their runtime
implementations while publishing closed compile-time plans. Exercising the UTC code exposed and
fixed an inclusive-comparison projection error: the checker represents `>=` as reversed `<` plus
the symmetric `==` step, and projection now preserves that selected meaning without requiring the
irrelevant equality direction to match. Projection also rejects step-local coercions explicitly
instead of silently treating a selected conversion as primitive comparison work.
Declaration metadata no longer embeds or exposes its value authority through
`DeclarationProgram`. Declaration lowering publishes a sparse `StructuralConstantTable` containing
only scalar values admitted before type normalization. It never evaluates immutable statics and
does not treat that table as the final value authority. Checked finalization constructs and
validates one dense `DeclarationValueTable` for every constant and static after all initializer and
callable plans are closed.
Constants and immutable statics now own expression-form semantic body identities. Their exact
source roots pass through the same projection catalog, lexical resolver, and ordinary typed-body
checker as block implementations. Declaration validation proves the reciprocal identity and body
form, so the remaining evaluator join can consume selected checked operations without locating or
retyping initializer syntax.
Checked initializer bodies project to zero-parameter compile-time plans. Their selected call edges
seed the shared callable-specialization query, which also closes generic helpers reached only from
an initializer. `CompileTimeProgram` retains the initializer plans by semantic body identity and
their execution produces the sole final declaration-value authority.
Checked-source integration now covers static text borrows and tuple and fixed-array results through
the same executor-to-frozen-value adapter. The aggregate tests verify exact closed shapes rather
than constructing evaluator values manually, so projection and execution cannot drift while each
passes only its own unit tests.
Header evaluation is now deliberately restricted to structural constants required by fixed-array
types. Optional planning is transactional: an ordinary initializer outside that early subset
publishes neither a partial value nor a source projection and is handled later by its checked body.
Only an actual type-shape dependency turns structural ineligibility into a declaration error.
Constant and static metadata are defined from reserved declaration identities, never from the
presence of an evaluated payload.
Final value-table construction requires every early structural constant to equal the value
produced by its checked initializer plan. The required bootstrap duplication therefore cannot let
a fixed-array type and the corresponding published constant acquire different meanings. Program
preparation also closes borrowed receiver value types before body checking, so const-method plan
availability is independent of whether the implementation happens to read `self`.

### Phase 5 — Review and Qualification

Status: planned.

- remove the closed-expression-only call prohibition and superseded adapters;
- review all compiler stages for duplicate checking, value lookup, dependency traversal, and source
  reinterpretation;
- run complete compiler, editor, documentation, standard-library, native, installation, and
  deterministic packaging gates;
- qualify v0.52.0 only after the standard library exercises the shipped capability.

## Deferred Work

Compile-time heap allocation for `String`, `Vec`, `Map`, and `Set`; mutable compile-time state;
procedural generation; reflection; constant generics; and composite execution guarantees such as
`realtime` remain outside v0.52.0.
