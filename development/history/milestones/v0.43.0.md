# v0.43.0: Authenticated TLS and HTTPS

**Status: active; Phase 0 complete, Phase 1 in progress.**

## Outcome

v0.43.0 will add authenticated secure transport and make the existing HTTP client usable with
`https` URLs without duplicating HTTP parsing, request policy, response framing, connection
ownership, or asynchronous lifecycle semantics.

The [Secure Transport Boundary](../../design/secure-transport-design.md) owns the cross-layer
constraints and Darwin provider selection. Network.framework is the selected modern TLS provider;
the existing Darwin TCP stream and listener implementation will be replaced before HTTPS is
enabled, so plain and secure streams cannot retain competing connection engines.

## Phase 0: Provider and Executable Boundary

**Status: complete.**

The Darwin SDK and runtime were inspected against the existing descriptor, reactor, target-service,
ARM64, and Mach-O contracts. Secure Transport composes with the existing transport model but its
public API stops at TLS 1.2 and is deprecated. Network.framework supplies modern TLS 1.3 but owns a
parallel connection and scheduling model. An embedded provider requires a native object-linking and
security-maintenance foundation that Nocter does not currently have.

The independent executable prerequisite is complete. Trusted imports now retain Security and
CoreFoundation library identities; Mach-O derives a canonical library sequence once and uses it for
load commands, bind ordinals, layout, and deterministic identity. A generated native image binds
both frameworks, creates a TLS context, releases it, and exits successfully.

Network.framework was selected because it provides the supported TLS 1.3 and system-trust contract
without a bundled third-party runtime. The broader TCP migration is accepted as part of v0.43.0;
Secure Transport and an embedded TLS runtime are excluded.

## Phase 1: Closed Network Adapter Foundation

**Status: in progress.**

Define one fixed target-service ownership and progress contract. Runtime imports now distinguish
function symbols from data symbols, and ARM64/Mach-O retain both kinds without losing their loader
meaning. A generated executable obtains Network.framework's default protocol-configuration block,
constructs secure TCP parameters, releases them, and exits without an external linker.

Complete the compiler-owned fixed Block ABI, callback mailbox, dispatch ownership, and
reactor-visible wake bridge. Source declarations must not expose native handles, callback pointers,
provider status codes, or general foreign ABI construction.

The fixed Block ABI is now represented by one runtime schema and one ARM64 materializer. Descriptor
identity is typed, a descriptor cannot disagree with the admitted one-pointer capture shape, and
the signature must be canonically NUL-terminated. Native generated-image qualification passes a
captured configuration block to Network.framework and observes its mailbox write.

The callback boundary was then simplified before implementation: an owned Unix datagram socketpair
is both the bounded mailbox and the reactor wake source. One runtime schema owns the fixed 40-byte
event. A generated executable passes the compiler block to a serial dispatch queue, sends from its
callback thread, and receives the complete event through the descriptor. This removes shared queue
state, locks, callback-side allocation, and a separate wake protocol.

Provider-object transfer and cancellation lifetime are now qualified against an actual secure TCP
connection. Callback errors cross the channel at +1 and are released by the receiver. Receiving the
final cancelled state is deliberately not the release fence because the callback sends before it
returns. The receiver next completes `dispatch_sync_f` on the same serial queue; only that second
step permits release of the connection, parameters, endpoint, queue, and channel. The remaining
Phase 1 work is to expose these mechanisms through one closed compiler-owned adapter operation
surface with explicit permanent channel-failure behavior.

## Phase 2: Plain TCP Migration

Move public TCP streams and listeners to the closed adapter while preserving their established
ownership, timeout, synchronous, asynchronous, and stable-error contracts. Remove the superseded
TCP descriptor implementation after equivalent native qualification passes. UDP retains its
datagram-specific descriptor substrate.

## Phase 3: Synchronous `std/tls`

Add a unique TLS stream, authenticated client handshake, reads, complete writes, clean close,
system and custom trust configuration, stable errors, and deterministic negative tests.

## Phase 4: Asynchronous TLS

Drive the same provider state through existing descriptor readiness and absolute deadlines.
Cancellation removes readiness ownership before releasing the TLS stream and underlying descriptor.

## Phase 5: HTTPS

Teach the existing HTTP client to select a private plain or secure connection while preserving one
request policy, decoder, cursor, response owner, and `(async Response!)!` immediate/deferred split.

## Phase 6: Qualification and Security Review

Qualify hostname mismatch, unknown and expired roots, truncated records, handshake timeout,
cancellation, ownership transfer, deterministic local HTTPS, editor behavior, examples, packaging,
and the complete repository gates. Do not use a public Internet service as ordinary test evidence.
