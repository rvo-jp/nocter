# v0.43.0: Authenticated TLS and HTTPS

**Status: active; Phases 0-2 complete, system-trust portions of Phases 3-4 and Phase 5 implemented.**

## Outcome

v0.43.0 will add authenticated secure transport and make the existing HTTP client usable with
`https` URLs without duplicating HTTP parsing, request policy, response framing, connection
ownership, or asynchronous lifecycle semantics.

The [Secure Transport Boundary](../../design/secure-transport-design.md) owns the cross-layer
constraints and Darwin provider selection. Network.framework is the selected modern TLS provider;
the existing Darwin TCP stream and listener implementation will be replaced before HTTPS is
enabled, so plain and secure streams cannot retain competing connection engines.

## Phase 0: Provider and Executable Boundary

**Status: complete.**

The Darwin SDK and runtime were inspected against the existing descriptor, reactor, target-service,
ARM64, and Mach-O contracts. Secure Transport composes with the existing transport model but its
public API stops at TLS 1.2 and is deprecated. Network.framework supplies modern TLS 1.3 but owns a
parallel connection and scheduling model. An embedded provider requires a native object-linking and
security-maintenance foundation that Nocter does not currently have.

The independent executable prerequisite is complete. Trusted imports now retain Security and
CoreFoundation library identities; Mach-O derives a canonical library sequence once and uses it for
load commands, bind ordinals, layout, and deterministic identity. A generated native image binds
both frameworks, creates a TLS context, releases it, and exits successfully.

Network.framework was selected because it provides the supported TLS 1.3 and system-trust contract
without a bundled third-party runtime. The broader TCP migration is accepted as part of v0.43.0;
Secure Transport and an embedded TLS runtime are excluded.

## Phase 1: Closed Network Adapter Foundation

**Status: complete.**

Define one fixed target-service ownership and progress contract. Runtime imports now distinguish
function symbols from data symbols, and ARM64/Mach-O retain both kinds without losing their loader
meaning. A generated executable obtains Network.framework's default protocol-configuration block,
constructs secure TCP parameters, releases them, and exits without an external linker.

Complete the compiler-owned fixed Block ABI, callback mailbox, dispatch ownership, and
reactor-visible wake bridge. Source declarations must not expose native handles, callback pointers,
provider status codes, or general foreign ABI construction.

The fixed Block ABI is now represented by one runtime schema and one ARM64 materializer. Descriptor
identity is typed, a descriptor cannot disagree with the admitted one-pointer capture shape, and
the signature must be canonically NUL-terminated. Native generated-image qualification passes a
captured configuration block to Network.framework and observes its mailbox write.

The callback boundary was then simplified before implementation: an owned Unix datagram socketpair
is both the bounded mailbox and the reactor wake source. One runtime schema owns the fixed 40-byte
event. A generated executable passes the compiler block to a serial dispatch queue, sends from its
callback thread, and receives the complete event through the descriptor. This removes shared queue
state, locks, callback-side allocation, and a separate wake protocol.

Provider-object transfer and cancellation lifetime are now qualified against an actual secure TCP
connection. Callback errors cross the channel at +1 and are released by the receiver. Receiving the
final cancelled state is deliberately not the release fence because the callback sends before it
returns. The receiver next completes `dispatch_sync_f` on the same serial queue; only that second
step permits release of the connection, parameters, endpoint, queue, and channel. Backend lowering
consumes these mechanisms through one closed compiler-owned adapter operation surface.

The adapter dependencies and event-transfer failure policy are now closed as well. Runtime roles
are the only authority for loader symbol, kind, library, and Block signature. The ARM64 channel
emitter retries only interrupted complete-record transfer; short records, EOF, and permanent
failure abort because a lost ownership-bearing event cannot be recovered safely. Both generated
callback tests consume that emitter rather than carrying independent retry or failure logic.

## Phase 2: Plain TCP Migration

**Status: complete.**

Move public TCP streams and listeners to the closed adapter while preserving their established
ownership, timeout, synchronous, asynchronous, and stable-error contracts. Remove the superseded
TCP descriptor implementation after equivalent native qualification passes. UDP retains its
datagram-specific descriptor substrate.

The operation authority and full plain-TCP import/callback vocabulary are now frozen. One checked
owner lifecycle rejects cross-family operations and makes release reachable only after a typed
final cancellation state and the serial-queue barrier. ARM64 lowering must now consume that
contract for connection operations, then listener operations, before the public owners change.
ARM64 now has one complete typed import view over the runtime catalog, and the native connection
qualification consumes that view instead of redeclaring its own symbol subset. Callback-channel
imports deduplicate into the same canonical pointer slots. Connection and listener state events
also share one production callback emitter; the native lifecycle qualification no longer carries a
second retain-and-transfer implementation in its test code.

The fixed native owner record and runtime-checked ARM64 transitions are complete. The native
connection qualification now releases endpoint and parameter temporaries at creation, publishes
only the provider object, queue, channel, and lifecycle tag, and consumes the common terminal
cleanup emitter after the cancellation event and queue barrier.

Production callback emission now covers connection receive, connection send, and accepted
connections as well as owner state. Each callback retains every non-null payload with the matching
Network or dispatch family before one complete channel transfer; no completion callback may publish
a borrowed provider object.

Plain outbound connection construction is now a production adapter operation rather than native
test scaffolding. It accepts a numeric Darwin socket address, creates the callback channel, serial
queue, address endpoint, plain-TCP parameters, provider connection, state handler, and queue
association, and publishes the fixed owner record only after the complete graph exists. Every
partial failure follows the same reverse-order cleanup ladder. The native lifecycle qualification
uses this constructor directly, then starts, cancels, observes the final event, crosses the queue
barrier, and releases the owner.

The source-independent owner representation now crosses the frontend and backend without a native
word array in standard source. One private `NetworkOwner` primitive type is resolved to a closed
runtime-storage role during declaration lowering; Target validates its empty unique semantic
contract, and Machine takes its 40-byte aligned layout solely from the runtime ABI schema.

The terminal connection lifecycle is production code as well. Start, cancellation, final-state
observation, serial-queue quiescence, and release are fixed ARM64 callable targets; the native
generated-image qualification invokes those same targets rather than rebuilding their transitions
inside the test. Quiescence validates the owner first, completes `dispatch_sync_f`, and only then
commits the state that permits resource release.

Callback events remain entirely behind the target boundary instead of borrowing the owner record's
coincident dimensions or acquiring a source-visible storage identity. Production event targets
validate lifecycle before exposing the reader or receiving one complete record into private target
storage.

Construction, event receipt, and terminal lifecycle are now returned as one atomic ARM64 plain-
connection target set. The lowerer cannot acquire a constructor without also acquiring the only
targets capable of draining and safely releasing its owner.

Connection-state event interpretation is now production-owned. One target receives the complete
record into private stack storage, validates its event kind and closed provider state, extracts and
then releases an optional retained provider error, clears the consumed record, and advances the
owner's final-state fence only for a valid cancelled event. It returns only normalized state,
error-domain, and error-code words. The native qualification no longer reads callback-event lanes,
releases provider errors, or claims the final-state transition itself.

The complete plain-connection lifecycle now crosses the source primitive boundary. Eleven closed
primitive roles bind creation, start, callback descriptor observation, receive and send initiation,
ordered event receipt, effective local and remote address copying, cancellation, queue quiescence,
and terminal release to the production target set. Target contract
validation identifies the opaque owner through the runtime-storage registry rather than its source
spelling. ARM64 collects primitive use once, validates the source ABI against the runtime schemas,
and supplies the same target identities to immediate and deferred functions. A standard-library
native test exercises the entire source-to-Network.framework cancellation lifecycle.

Effective-address projection is now closed as well. Production targets copy the current local or
remote endpoint through one checked path, accept only complete Darwin IPv4 and IPv6 record pairs,
release both retained provider objects in reverse order, and return only caller-owned bytes plus
their length. Standard source converts those bytes through the existing target-independent
`NetworkAddress` boundary, and a native loopback test qualifies both directions.

The production transfer starters and their callback identities are now one atomic target family.
Receive installs the fixed retained-payload callback over the owner's independently lived mailbox
writer. Send first asks dispatch to copy the borrowed source bytes into system-owned storage, then
submits that owner with the fixed completion callback and releases the local dispatch reference.
Neither operation lets a source borrow or stack Block outlive its call.

One connection event consumer now owns the shared callback order. It accepts connection-state,
receive-completion, and send-completion records from the same mailbox, validates their closed
shapes, normalizes and releases provider errors and content contexts, maps dispatch data only long
enough to copy it into caller storage, and clears the private record after ownership is consumed.
The private Darwin source boundary receives only five native-object-free words and caller-owned
bytes. Separate state and transfer consumers are deliberately absent because they could not safely
predict which callback kind arrives next. A generated loopback test sends and receives real bytes
through the production primitive family, then cancels, drains to the final state, crosses the queue barrier,
and releases the owner.

`NetworkOwner` now belongs to the target-independent network model below both policy and the Darwin
adapter. This keeps the module dependency direction acyclic: high-level network policy depends on
the adapter, while the adapter depends only on the shared model. Compiler fixtures consume the
declaration-lowering runtime bindings directly instead of rediscovering primitive declarations by
walking the checked graph.

A provider-independent listener owner now mirrors the connection lifecycle without exposing a
native listener, accepted connection, callback Block, or provider port. The listener event consumer
adopts each accepted provider connection into its own closed owner before source can observe it.
Synchronous and asynchronous acceptance share the same ordered event authority, absolute deadline,
terminal cancellation fence, and stable failure mapping.

Public `TcpStream` and `TcpListener`, numeric and resolved connection paths, synchronous and
asynchronous transfers, timeouts, effective addresses, half-close, close, and destruction now use
the provider owners exclusively. A waiting establishment event retains its provider failure and is
classified as one failed candidate, so ordered address fallback cannot be captured by the
provider's implicit retry loop. Existing connections may still wait for provider recovery.

The superseded synchronous and asynchronous TCP descriptor policy and its raw stream-syscall test
fixtures have been deleted. The remaining descriptor owner, target operations, and retry engine
serve UDP only. Twenty-nine standard network native cases plus public async TCP and HTTP loopback
fixtures qualify equivalent behavior across the migration.

## Phase 3: Synchronous `std/tls`

Add a unique TLS stream, authenticated client handshake, reads, complete writes, clean close,
system and custom trust configuration, stable errors, and deterministic negative tests.

The system-trust client path is implemented. It preserves the requested hostname across ordered
address fallback, requires TLS 1.2 or newer, and reuses the provider stream owner for decrypted
reads, complete plaintext writes, addresses, timeout configuration, shutdown, close, and
destruction. One deadline starts before resolution and is never restarted per candidate. A native
fixture verifies that the complete compiler and runtime path rejects a plain local peer with the
stable `std.net.tls_failed` code. Custom trust configuration and deterministic authenticated
success fixtures remain before this phase is complete.

## Phase 4: Asynchronous TLS

Drive the same provider state through the existing callback-event descriptor and absolute
deadlines. Cancellation observes the final provider state and callback-queue barrier before
releasing the TLS stream owner.

System-trust asynchronous establishment and transfer are implemented. Resolution retains the
existing immediate/deferred result split, while the deferred computation owns the hostname storage,
resolved candidates, and shared deadline. Establishment, reads, and writes consume the same ordered
event authority and owner lifecycle as synchronous TLS; no parallel async connection engine exists.
The local plain-peer fixture qualifies both synchronous and asynchronous rejection. This phase
remains open until the custom-trust surface and positive authenticated fixture establish the final
configuration and cancellation contracts.

## Phase 5: HTTPS

**Status: implementation complete; authenticated success qualification depends on Phase 3 custom
trust.**

Teach the existing HTTP client to select a private plain or secure connection while preserving one
request policy, decoder, cursor, response owner, and `(async Response!)!` immediate/deferred split.

The transport selection and ownership boundary is implemented. One private `ClientTransport` sum
is the only HTTP component that distinguishes TCP from authenticated TLS. Synchronous and
asynchronous request writes, response-head reads, body reads, close, and destruction consume that
common contract; the request encoder, response decoder, framing state, and public `Response` do not
inspect the URL scheme. `https` preserves the same immediate resolution failure and deferred
transport failure split as `http`. A local plain-peer fixture verifies that both synchronous and
asynchronous HTTP select TLS and preserve `std.net.tls_failed` rather than sending plaintext.
HTTPS supplies a NUL-terminated `http/1.1` protocol identifier through the TLS-owned ALPN boundary;
the same native fixture inspects the complete ClientHello record and rejects a missing protocol.
No HTTP code constructs native TLS options or exposes the package-internal ALPN entry points.

## Phase 6: Qualification and Security Review

Qualify hostname mismatch, unknown and expired roots, truncated records, handshake timeout,
cancellation, ownership transfer, deterministic local HTTPS, editor behavior, examples, packaging,
and the complete repository gates. Do not use a public Internet service as ordinary test evidence.
