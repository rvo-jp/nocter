# v0.56.0 Release Preparation

**Status: published and externally audited.** This record owns the release-candidate identity,
qualification contract, and retained local artifact evidence. The immutable publication evidence
is recorded in [`../release-audits/v0.56.0.md`](../release-audits/v0.56.0.md).

## Release Boundary

v0.56.0 generalizes `from` into one value-provenance contract across callable results, parameters,
receivers, annotated locals, and structural callable identity. Declaration lowering resolves
source names once into semantic parameter identities; checking proves one shared containment
relation; analysis and editor features project that checked contract without reconstructing source
semantics.

Synchronous and asynchronous lending iterators tie each associated item to the active receiver
call. `std/scan` uses the contract for allocation-free cursors and reusable byte and UTF-8 windows,
while HTTP query decoding borrows from the retained request target or decoder scratch storage. The
practical HTTP service consumes those lent values without an implicit ownership copy.

The [milestone](v0.56.0.md) owns the completed implementation. The [closure
review](../reviews/v0.56.0-phase-5.md) records the reopened presentation correction, final authority
audit, and complete repository gate. Public candidate notes are
[`../../../releases/v0.56.0.md`](../../../releases/v0.56.0.md). Root downloads, specification
publication status, and the public release index now select v0.56.0.

## Qualification Contract

The clean release-content commit must pass:

1. the complete compiler gate in a disposable Cargo target;
2. repository metadata, performance helpers, pinned Unicode reproduction, formatting,
   warnings-denied all-target Clippy, every enabled locked workspace test, no-default-features
   checking, and warnings-denied Rust documentation;
3. deterministic out-of-tree website generation and repository whitespace validation;
4. two independent optimized package builds with byte-identical archives and recursively identical
   installed homes;
5. fresh installed-home checks for version, diagnosis, help, initialization, locked/offline check
   and test, deterministic graphs, native build, run, and direct execution;
6. every public example and the exact filesystem, streaming, network, HTTP, TLS, process, task,
   lending, persistent-connection, and graceful-service contracts;
7. interactive LSP initialization, dynamic capability registration, hover, completion, navigation,
   edited-source diagnostics, recovery, and shutdown against installed public and implementation
   sources;
8. proof that qualification commands do not mutate the installed home and that changing either the
   compiler or one standard-library source invalidates it.
