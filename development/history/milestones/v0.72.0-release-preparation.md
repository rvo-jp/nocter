# v0.72.0 Release Preparation

**Status: qualification pending (2026-09-26).** This record owns the v0.72.0 release-content
identity, qualification contract, and retained local artifact evidence. Publication and its public
audit remain separate steps, both explicitly authorized for this release.

## Release Boundary

v0.72.0 makes path-sensitive bounds and integer-arithmetic proof a checking-owned semantic product.
Checked operations retain a closed disposition, checked execution uses it for `notrap`, MIR and
Machine transport it without re-proof, and ARM64 implements complete runtime fallback checks. The
standard slice API adopts only the guarantees proved through this full path.

The [v0.72.0 milestone](v0.72.0.md) owns the implementation scope. Its five reviews record the
safety-disposition boundary, flow domain, dynamic bounds proof, arithmetic runtime closure, and
standard-library adoption. Public candidate notes are
[`../../../releases/v0.72.0.md`](../../../releases/v0.72.0.md).

## Candidate Identity

The release inputs agree on `0.72.0`:

- `development/packaging/VERSION`, the sole authored release-version input;
- the `#package` version in `std/index.nct`;
- the archive name and installed manifest derived from `VERSION` and `RELEASE.json`; and
- compiler and language-server reporting derived from the validated installed home.

`RELEASE.json` remains the machine authority for version-independent license, host, target, and
archive-layout metadata. The release-content commit and retained archive identity are filled only
after qualification runs from a clean committed tree.

## Qualification Contract

The clean release-content commit must pass:

1. the complete compiler gate in a disposable Cargo target;
2. repository metadata, performance helpers, pinned Unicode reproduction, formatting,
   warnings-denied all-target Clippy, every enabled locked workspace test, no-default-features
   checking, and warnings-denied Rust documentation;
3. deterministic out-of-tree website generation and repository whitespace validation;
4. two independent optimized package builds with byte-identical archives and recursively identical
   installed homes;
5. verified fresh installation and active-home replacement from the retained archive, followed by
   installation diagnosis, recursive identity comparison, and transaction-cleanup confirmation;
6. fresh installed-home checks for version, help, initialization, locked/offline check and test,
   deterministic graphs, native build, run, and direct execution;
7. every public example plus the complete process, filesystem, network, TLS, HTTP, durable-state,
   configuration, service, checked-arithmetic, structural-guarantee, and flow-proof contracts;
8. interactive LSP initialization, dynamic capability registration, semantic queries,
   edited-source diagnostics, recovery, and shutdown; and
9. proof that qualification commands do not mutate the installed home and that changing either the
   compiler or one standard-library source invalidates it.

## Publication Boundary

Publication must reuse the exact retained qualified archive without rebuilding it. The annotated
tag, single GitHub Release asset, latest-release endpoint, downloaded installed home,
push-triggered workflows, and source-identified Pages deployment require a separate
post-publication audit. The tag and asset are immutable by project policy; any correction requires
a new release identity.
