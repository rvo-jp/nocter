# v0.44.0: Explicit Asynchronous Producers and Future Values

**Status: Phases 0-3 complete; Phase 4 planned.**

## Outcome

v0.44.0 separates callable execution from value type syntax. `async` explicitly marks a function
or method whose invocation creates deferred work, while `future T` is the structural owning value
produced by that invocation. The compiler will no longer infer execution from the normalized outer
constructor of a result type.

The change is intentionally source-breaking. The removed `async T` type spelling and result-driven
producer classification receive no compatibility parser, alias, migration mode, or fallback
lookup.

## Phase 0: Contract and Authority Replacement

**Status: complete.**

- Freeze modifier grammar, future type precedence, callable and interface matching, entry behavior,
  ownership, provenance, primitive boundaries, and invalid combinations in `spec/`.
- Update the cross-crate asynchronous-computation contract so declaration syntax is the sole input
  to execution classification and the type store is the sole owner of future identity.
- Inventory every source, standard-library, editor, target, and backend consumer of the old model.

Completion requires regenerated public documentation, no current-contract reference that presents
`async T` as a type, and repository checks passing.

## Phase 1: Frontend and Declaration Model

**Status: complete.**

- Parse and format `async func`, `async method`, and `future T` with one syntax-tree shape.
- Replace `Async` type identities with `Future` identities throughout the semantic model.
- Lower callable execution directly from the declaration modifier and validate admitted declaration
  categories and interface matches without inspecting result shapes.
- Delete result-normalization classification and its alias/generic exceptions.

Completion requires focused lexer, parser, formatter, declaration-lowering, validation, and
presentation tests, including immediate functions that return futures and asynchronous functions
that produce nested futures.

## Phase 2: Checking and Executable Pipeline

**Status: complete.**

- Make call checking construct `future Output` solely from the frozen deferred execution fact.
- Make body checking consume the declared output directly and keep `await` dependent on both the
  enclosing execution capability and an owned future operand.
- Carry the unchanged closed execution fact through target, MIR, Machine, ARM64, entry adaptation,
  capture provenance, cancellation, and runtime ABI boundaries.
- Remove every downstream result-shape inference or old-type compatibility path.

Completion requires immediate forwarding, nested futures, interface dispatch, ownership failures,
entry execution, native suspension, cancellation, and no-allocation boundaries to pass.

## Phase 3: Standard Library, Examples, and Editor Surface

**Status: complete.**

- Migrate every current standard-library and example declaration to the new canonical syntax.
- Preserve intentional immediate fallible setup around future values with explicit parentheses.
- Update hover, completion, inlay, semantic-token, navigation, and diagnostic expectations from the
  same semantic presentation authority.
- Remove stale public prose and formatter output using the old spelling.

Completion requires every compiler-checked standard module and public example to parse, check, and
run under the new contract, plus complete LSP semantic tests.

## Phase 4: Qualification and Review

**Status: planned.**

- Run the complete compiler, standard-library, examples, documentation, and native asynchronous
  qualification gates from clean external targets.
- Review for duplicate execution authorities, result-type reclassification, source-text inference,
  compatibility remnants, and reverse dependencies.
- Prepare publication only after the old model is absent from current source and generated docs.

Completion requires a clean worktree, passing release gates, and a review with no unresolved
release-blocking findings.
