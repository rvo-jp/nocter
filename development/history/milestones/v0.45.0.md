# v0.45.0: Enforceable Asynchronous I/O and Structured Tasks

**Status: Phases 0 through 2 complete; Phase 3 is in progress.**

## Outcome

v0.45.0 makes every `future T` safe to drive without synchronously waiting for external progress.
It identifies synchronous waiting through the positive `blocking` effect, closes that effect
through bodies and indirect calls once, then uses the resulting foundation to normalize practical
asynchronous APIs and expand structured task composition.

The design does not create `noblock future T`, infer safety from an `_async` suffix, or equate
nonblocking execution with bounded execution time. `noalloc`, blocking behavior, deferred
execution, and result provenance remain independent facts.

## Phase 0: Contract and Effect Inventory

**Status: complete.**

- Define the universal future drive invariant and the exact synchronous-wait boundary in `spec/`.
- Add the `blocking` callable effect, its canonical syntax, structural callable relation,
  interface rule, named-callable contract rule, closure inference rule, and invalid
  implicit-operation cases.
- Inventory standard-library and primitive entries that can wait for descriptors, files, clocks,
  processes, threads, name resolution, or contended synchronization.
- Define separate primitive facts for constructor-call blocking behavior and returned-future drive
  safety so no later stage reconstructs either fact.

Completion requires one normative owner for each public rule, generated documentation, an explicit
primitive migration inventory, and no unresolved user-visible semantic choice.

Phase 0 completed on 2026-09-11. The specification now makes drive safety universal to `future T`
and reserves `blocking` for the positive synchronous-wait effect. The cross-crate inventory found
two boundaries that later implementation must not hide: generic `SyscallN` roles are conservatively
blocking because their runtime arguments cannot certify safety, and the Network.framework release
barriers synchronously wait on a dispatch queue and therefore must leave future drive and
cancellation paths. Documentation generation, its deterministic navigation test, the registered
diagnostic vocabulary test, and repository diff checks pass.

## Phase 1: Syntax and Semantic Effect Authority

**Status: complete.**

- Parse, format, lower, serialize, and present `blocking` on admitted declarations and structural
  callable types.
- Extend the checked effect authority with a monotone synchronous-wait analysis over direct calls,
  interface dispatch, callable witnesses, closures, recursive groups, and destruction.
- Validate named nonblocking contracts, inferred closures, async bodies, implicit callable forms,
  and interface implementations from that one result. Phase 2 binds closed primitive-role facts
  while migrating the affected standard-library declarations.
- Carry no blocking classification into MIR or Machine; those stages consume already accepted
  future and call edges.

Phase 1 completed on 2026-09-11. `blocking` now has one syntax node and one semantic guarantee
dimension shared by declarations and structural callable types. Checking collects the existing
selected call, closure, and destruction graph once, closes allocation and blocking effects in the
same monotone fixed point, and publishes one immutable `CallableEffects` table. Nonblocking named
callables, asynchronous bodies, implicit destruction, closure witnesses, and interface
implementations are checked against that authority. Semantic presentation renders the authored
contract and does not derive modifiers from inferred body effects. Compiler workspace library
tests, focused lowering and presentation tests, formatting, documentation generation, and
repository diff checks pass.

## Phase 2: Standard-Library API Normalization

**Status: complete.**

- Mark synchronous filesystem, terminal, time, process, resolver, network, TLS, and HTTP paths from
  the Phase 0 inventory.
- Make asynchronous operations the canonical base-name surface where a blocking twin exists, and
  use an explicit `_blocking` suffix for the synchronous twin.
- Move recoverable setup into the asynchronous result where ownership permits, avoiding unnecessary
  `(future T!)!` public layers and wrapper-only `_async` declarations.
- Preserve one codec, state machine, timeout authority, and error-selection implementation behind
  both execution surfaces.

The first Phase 2 boundary changes replace source-selected Darwin numbers for page mapping, page
release, descriptor close, hash-seed filling, wall-clock observation, and timeout waiting with
closed semantic primitive roles. The target backend now owns their ABI constants, fixed flags, and
native time layouts. The public time surface uses asynchronous `sleep` as its canonical name and
the explicit `sleep_blocking` name for synchronous waiting. Network callback consumption now has
distinct blocking receive and nonblocking try-receive roles; the latter owns Darwin
`MSG_DONTWAIT` and `EAGAIN` classification and is the only receive operation used while driving
futures. The synchronous dispatch release barrier remains open because it cannot satisfy the
universal future drive invariant merely by adding a source modifier. Connection and listener drop
now consume their owner through a distinct disposal primitive that immediately submits terminal
cleanup to a global worker queue. Failed operations, observed cancellation, explicit close, and
implicit destruction use the same transfer; public wrapper destruction relies on structural field
cleanup rather than restating it. The worker drains ownership-bearing callbacks, crosses the
owner's serial release barrier, and releases the native resources. Explicit synchronous network
operations and their authored `blocking` contracts remain to be normalized. Numeric listener
setup now also has an executor-safe future: it transfers the owner into `StreamListener` before
its first readiness suspension, consumes provider events through nonblocking try-receive, and uses
the common disposal path on cancellation or failure. Host-based asynchronous TCP, TLS, and HTTP
setup no longer invoke the synchronous resolver before producing a future. One owned validated
host/service endpoint crosses the public factory boundary; Network.framework performs resolution
and connection while the future is driven, and the operation deadline begins inside that future.
Numeric and host endpoint constructors are distinct closed primitive roles sharing one provider
owner lifecycle rather than source-selected ABI behavior. The synchronous resolver now carries an
explicit `blocking` contract from the private Darwin adapter through public host resolution, TCP,
TLS, and HTTP entry points. The target-service catalog is the source-independent authority for
whether `getaddrinfo` and `freeaddrinfo` may wait, and target closure rejects source contracts that
disagree with that catalog.

Every registered primitive declaration is now checked against the closed runtime catalog's exact
blocking classification. Generic syscall and synchronous provider-receive roles are explicitly
blocking; drive-safe future constructors and all remaining nonwaiting roles must remain
unqualified. Synchronous filesystem, stream I/O, process, network, TLS, and HTTP contracts now
propagate the same fact through their private helpers, compiler fixtures, initialized programs,
and public examples instead of relying on caller knowledge.

Host-based asynchronous TCP and TLS connection plus asynchronous HTTP send now expose one deferred
`future T!` outcome. Input validation, endpoint ownership, request preparation, provider resolution,
and transport failure occur while that computation is driven; no API presents an immediate
fallible wrapper around a second fallible future. The implementation uses ordinary async callable
contracts rather than bodyless future-returning adapters, so callable execution and capture
provenance remain owned by the checked declaration model.

Phase 2 completed on 2026-09-11. Public asynchronous TCP, TLS, and HTTP operations now own the
canonical base names, including `net.connect_tcp`, `TcpStream.read`, `tls.connect`, `Client.send`,
and `Response.read_to_end`. A synchronous twin uses the explicit `_blocking` suffix throughout
constructors, stream methods, the shared `Reader` and `Writer` contracts, examples, and semantic
tooling. Timeout variants retain `_with_timeout` as the operation qualifier, before any
`_blocking` execution qualifier. Private provider and protocol helpers may retain implementation
names that distinguish their substrate role; those names do not form a second public API. The
standard library still has one transport owner and one HTTP decoder behind both execution
surfaces. Complete language-server, native-session, package-example, compiler-workspace,
documentation, formatting, lint, and repository-diff gates pass.

## Phase 3: Structured Task Composition

**Status: in progress.**

- Requalify `task.join` under the universal future invariant.
- Add bounded race and deadline composition with explicit winner/elapsed values and deterministic
  loser cancellation.
- Add nonblocking time suspension without a second scheduler or process-global executor.
- Prove exact-once cancellation, output consumption, capture destruction, and nested wait-interest
  forwarding on the native target.

The first Phase 3 boundary adds `task.race` over two same-output computations. The compiler-owned
pair lifecycle shares ordered polling and wait-interest forwarding with `task.join`, selects the
left child on a same-step tie, cancels the loser before completion, and retains the winner output
until consumption. Machine owns only the raw structural result offsets; ordinary standard-library
code converts `(bool, T)` into the public `Race<T>` enum. Pair cancellation now admits a completed
but unconsumed child, closing the lifecycle case exposed when a race cancels a partially completed
nested join.

## Non-goals

v0.45.0 does not add detached tasks, copyable task handles, a process-global executor, general
threading, parallel CPU execution, `realtime`, `nosuspend`, bounded-work analysis, or a second
future type. It does not treat allocation, long computation, or recoverable failure as blocking.
