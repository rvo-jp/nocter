# v0.71.0: Guaranteed Structural Operations

**Status: release candidate.** This milestone lets generic code preserve immediate execution
guarantees through operators, borrow coercions, and expansion instead of losing them at a
structural requirement boundary. Its release identity and artifact qualification are owned by the
[release-preparation record](v0.71.0-release-preparation.md).

## Goal

Make execution guarantees compositional across every implicit operation that a generic body can
perform. A requirement is the sole source contract for the generic body; concrete specialization
must prove that the selected operation and any implicit coercions meet it. Syntax, normalization,
proof, checked execution facts, and editor presentation must share one guarantee model.

## Completion Definition

v0.71.0 is complete when:

- structural operator, borrow-coercion, and expansion predicates accept canonical `noalloc notrap`
  prefixes and no unrelated callable modifiers;
- duplicate structural prerequisites combine independent guarantees without making declaration
  order authoritative;
- stronger admitted facts imply weaker requirements through one shared directional rule;
- concrete operations and all implicit coercions are checked against the requested guarantees;
- generic body execution reads the guarantee from capability evidence without redispatching;
- formatting, hover, completion, diagnostics, normative grammar, and architecture documentation
  expose the same contract;
- checked arithmetic gives standard code a useful trap-free numeric foundation; and
- the standard library publishes only guarantees proved by the complete compiler gate.

## Phases

### Phase 0 — Structural Guarantee Foundation

**Status: complete.** The shared structural predicate representation now carries canonical
`noalloc notrap` guarantees from syntax through normalization, directional implication, concrete
selection, and checked execution. Formatter, hover, completion, and normative documentation use
the same model. Positive, rejection, weakening, and prerequisite-composition tests close the
boundary.

### Phase 1 — Checked Arithmetic and Standard Adoption

**Status: complete.** Every built-in integer now exposes `noalloc notrap` checked addition,
subtraction, and multiplication. The `u64` and `i64` implementations are the two arithmetic
authorities; narrower integers and target-width integers widen, use those authorities, verify the
destination range, and narrow. Package-private capacity arithmetic was removed, and allocation,
collection, codec, process, HTTP, storage, and text code now use the type-owned methods.

Standard `String` and `Vec` borrow coercions and borrowed `Vec` expansion publish the same
guarantees. Their proof reaches the closed raw-view primitive facts rather than trusting a wrapper.
Native numeric and duration tests cover overflow, underflow, signed minimum asymmetry, target-width
results, and the migrated duration implementation.

### Phase 2 — Qualification

**Status: complete.** The complete source-tree gate passed across compiler, standard-library,
examples, documentation, native execution, and editor behavior. The
[final review](../reviews/v0.71.0-structural-guarantees.md) found and closed a general
owned-receiver selection defect, stale standard dependency-review edges, and a stale native test
inventory. It confirmed one duplicate-requirement composition law, no source-text semantic
inference, no generic-body redispatch, no compatibility fallback, and no remaining v0.70
structural-guarantee limitation.

Release identity, deterministic archive assembly, and installed-artifact qualification remain a
separate release-preparation operation. They must run from the final clean release-content commit
rather than being represented by this implementation gate.

## Deliberate Limits

This milestone does not add `realtime`, asynchronous drive-time trap guarantees, value-sensitive
overflow proofs, or unchecked indexing. Built-in bounds-checked indexing remains potentially
trapping. An omitted modifier remains an intentionally weaker public requirement even when a
particular implementation is inferred to have a stronger body fact.
