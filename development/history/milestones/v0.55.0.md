# v0.55.0: Erased Callables and Practical HTTP Applications

## Goal

Add one explicit, owning runtime callable-erasure model and use it to build deterministic HTTP
routing and complete practical applications over the existing streaming service lifecycle.

## Completion Definition

v0.55.0 is complete when all of the following are true:

- `any func`, `any &func`, and `any &+func` are distinct sized types whose callable contracts,
  guarantees, result provenance, ownership, and destruction survive erasure;
- concrete closure erasure is an explicit checked allocation operation and indirect invocation is
  selected once before Target, MIR, Machine, and ARM64 consume it;
- erased callables work in fields, variants, aliases, generic arguments, parameters, locals, and
  named results without changing static callable specialization;
- request targets expose validated path and query structure without reparsing raw target text in
  each application layer;
- one deterministic router owns method and path-pattern selection, typed route parameters, and
  readonly repeatable erased handlers without hidden task or connection ownership;
- response conveniences derive from the existing `Responder` and `ResponseWriter` transitions
  rather than introducing a second framing or persistence authority;
- one complete application exercises static, parameter, missing, malformed, streaming, timeout,
  persistent-connection, and graceful-shutdown paths using only public APIs;
- compiler, editor, standard-library, native, documentation, installation, and packaging gates
  pass;
- whole-repository review finds no implicit callable boxing, duplicated dispatch, source-name
  runtime lookup, second target parser, hidden task registry, or caller-correctness lifecycle
  precondition.

## Phases

### Phase 0 — Erased Callable Contract

Status: complete.

- freeze source syntax, ownership, allocation, provenance, effect, destruction, and ABI rules;
- add a distinct semantic type and checked erasure/invocation operations;
- preserve existing statically witnessed `func` behavior unchanged;
- reject silent erasure at ordinary call arguments.

The adopted boundary is documented in
[`development/design/erased-callable-design.md`](../../design/erased-callable-design.md).

### Phase 1 — Closed Runtime Dispatch

Status: complete.

- close concrete erasure descriptors in `ExecutableProgram`;
- lower explicit construction, indirect invocation, ownership transfer, and destruction through
  MIR and Machine;
- implement the target-independent machine operation and ARM64 indirect call;
- qualify capture-free, borrowed-capture, owned-capture, readwrite, consuming, fallible, future,
  cancellation, and guarantee-weakening cases.

### Phase 2 — Request Target Values

Status: complete.

- separate path and query once from the already validated request target;
- add percent-decoding and explicit malformed-target errors without implicit Unicode assumptions;
- expose borrowed query iteration and owned decoded values where ownership is required;
- retain the original target spelling without a second parsing authority.

### Phase 3 — Deterministic Routing

Status: complete.

- add exact and named-segment route patterns with one construction-time validation pass;
- reject duplicate or ambiguous routes before serving;
- select method, path pattern, and route parameters deterministically;
- store heterogeneous readonly handlers through `any &func`.

### Phase 4 — Application Responses

Status: complete.

- add small response constructors and common content metadata over the existing response planner;
- provide explicit not-found, method-not-allowed, and handler-error application policies;
- preserve streaming output, backpressure, deadlines, connection disposition, and unique responder
  ownership.

### Phase 5 — Practical Application and Qualification

Status: active.

- build a complete routed application with bounded application-owned task admission;
- exercise route parameters, query values, streamed request and response bodies, keep-alive,
  timeout, malformed input, handler failure, and graceful shutdown;
- qualify hover, completion, declaration navigation, diagnostics, native execution, packaging, and
  deterministic documentation;
- perform a whole-repository authority and lifecycle review before release preparation.

## Deferred Work

General `any Interface` objects, inline erased environments, user-selected allocators for callable
erasure, middleware stacks, automatic request-body decoding, automatic response serialization,
HTTP/2, HTTP/3, WebSocket framing, and concurrent pipelining remain outside this milestone.
