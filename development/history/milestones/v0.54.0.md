# v0.54.0: Streaming and Persistent HTTP Services

## Goal

Make long-running HTTP/1.1 services practical with bounded memory, transport backpressure,
sequential persistent connections, and explicit shutdown while preserving one framing authority
and one uniquely owned connection through every request and response state.

## Completion Definition

v0.54.0 is complete when all of the following are true:

- one transport-independent body cursor owns decoded-body progress, completion, pending input, and
  retained overread bytes for both client responses and server requests;
- an incoming server request exposes its body incrementally through ordinary asynchronous reader
  contracts instead of collecting the complete body before handler entry;
- response bodies may be written incrementally with fixed-length or chunked framing and transport
  backpressure, while the existing owned-body response remains a derived convenience;
- response completion returns the connection only when request framing, response framing, and
  connection policy prove that reuse is safe;
- HTTP/1.1 keep-alive processes requests sequentially without executing pipelined requests or
  discarding already received bytes;
- explicit body finalization, response finalization, timeout, cancellation, peer failure, and
  destruction each close or transfer the stream exactly once;
- server shutdown stops admission and drains application-owned handler tasks without a hidden
  task registry, connection semaphore, or detached computation;
- one runnable application transfers a body larger than its fixed transport buffers and exercises
  connection reuse, backpressure, bounded admission, and graceful shutdown;
- compiler, editor, standard-library, native, documentation, installation, and packaging gates
  pass;
- review finds no duplicate completion flag, second framing decision, full-body allocation in the
  streaming path, caller-correctness precondition, or response capability that aliases an
  unfinished request body.

## Phases

### Phase 0 — Ownership and Framing Model

Status: complete.

- trace body decoding, pending input, connection closure, timeout, and response authority through
  the existing synchronous client, asynchronous client, and one-request server;
- define a single body-cursor authority independent of transport and client/server policy;
- define request-body, responder, response-writer, and reusable-connection transitions before
  adding public declarations;
- reject designs that split one stream between body and response owners or require callers to
  prove an internal completion flag.

The audit found that the response client already decodes bodies incrementally, while the server
drives the same decoder into a complete `Vec` before entering the handler. Client response storage
also mirrors the decoder's terminal state in a separate Boolean. The adopted model replaces both
drivers with one cursor whose decoder state is the sole completion authority and whose pending
range survives every ownership transfer.

An accepted connection transfers into one incoming request owner. That owner implements ordinary
asynchronous reading and retains the stream until a consuming body-finalization operation has
drained any unread bytes. Only finalization can produce the unique responder. Completing a response
either returns one reusable connection or closes it; failure and cancellation never publish a
partially reusable state. The complete boundary is documented in
[`development/design/streaming-http-service-design.md`](../../architecture/runtime/http-service.md).

### Phase 1 — Canonical Body Cursor and Incoming Streaming

Status: complete.

- replace response-local decoder, pending range, scratch storage, and completion duplication with
  one transport-independent body cursor;
- make incoming requests own that cursor and expose `Reader` and `TimedReader` behavior;
- make consuming body finalization drain unread bytes and transfer exactly one responder;
- retain bytes beyond the current body for a later sequential request instead of rejecting safe
  transport overread.

Client responses and server requests now embed the same private `BodyCursor`. It owns the selected
decoder, retained input range, unread offset, and fixed transport scratch storage; `BodyState` is
the only completion and failure authority. The response-local completion Boolean and the separate
response-progress wrapper were removed.

`ServerConnection.read_request` now transfers the stream into an `IncomingRequest` as soon as its
head is complete. The request implements `Reader` and `TimedReader`. Consuming `finish_body` drains
unread bytes and is the sole transition to `Responder`; body failure remains a distinct terminal
state and can never be mistaken for response-safe completion. Cursor tests cover fragmented fixed
bodies, retained overread, empty destination storage, and persistent failure. Native loopback tests
cover partial body consumption followed by draining and response authority. The public examples
and editor reference test use the new transition.

### Phase 2 — Streaming Response Output

Status: complete.

- make `ResponseHead` the shared validated response metadata value;
- add fixed-length and chunked response writers over ordinary `Writer` and `TimedWriter` contracts;
- reject overflow, premature finish, forbidden body status, and reserved framing fields before
  exposing a reusable connection;
- implement the owned-body response path through the same response plan and writer transitions.

`ResponseHead` now owns authored and parsed response metadata. One private response planner rejects
reserved fields, forbidden payload statuses, invalid lengths, and limit violations before output,
then freezes fixed-length or chunked framing. `ResponseWriter` implements ordinary and timed writer
contracts, commits state only after complete transport progress, owns bounded chunk spelling, and
rejects overflow, premature finish, repeated failure, and excessive chunked output.

`OutgoingResponse` now embeds `ResponseHead`; its responder operation begins a fixed writer, writes
the borrowed complete body, and finishes that same transition. The former complete-response
encoder was deleted. Unit tests cover frozen wire heads and pure output-state validation; native
loopback tests cover fixed convenience output and multi-fragment chunked output; the asynchronous
example and editor reference test use the streaming writer API.

### Phase 3 — Sequential Persistent Connections

Status: complete.

- select HTTP/1.1 persistence once from validated request fields and server response policy;
- return a connection only after complete request consumption and complete response emission;
- parse retained pipelined bytes only after the prior response finishes;
- preserve explicit close and operation-deadline behavior without a connection pool.

The request-head decoder now selects one private connection disposition while it owns validated
fields. HTTP/1.1 defaults to reuse; every comma-separated `Connection` token is validated, and any
`close` token makes the exchange terminal. The response planner consumes this semantic decision
without reparsing fields. Applications may force the same terminal plan before response output
through `Responder.close_after_response`.

Completed fixed and chunked writers return `ServerConnection?`. Presence transfers the exact TCP
stream, retained unread input range, and reusable transport scratch allocation as one private
`ConnectionInput`; absence means the completed response advertised and performed closure. A
native loopback test sends two requests in one transport write, proves the second request is not
parsed until the first response returns the connection, and then closes through the second
request's policy. No pool, concurrent pipeline executor, or second persistence decision was added.

### Phase 4 — Graceful Service Lifecycle

Status: complete.

- stop listener admission without invalidating already accepted connection owners;
- drain application-owned `TaskGroup` handlers under an explicit deadline;
- prove that cancellation and destruction retire every request reader, responder, writer, and
  persistent connection exactly once;
- add process-signal observation only if the complete reference service demonstrates that an
  application-owned shutdown trigger cannot express the required lifecycle.

No new HTTP shutdown owner was required. Consuming `Server.close` already retires listener
admission independently of every accepted connection. The bounded service now closes admission
first, moves its application-owned handler `TaskGroup` into one result-consuming drain future, and
bounds that complete drain with one `task.with_timeout` deadline. Completion returns every handler
outcome; expiry destroys the drain future and structurally cancels all children still owned by its
group.

A native lifecycle fixture constructs each linear owner before transferring it into a suspended
handler: `IncomingRequest`, `Responder`, `ResponseWriter`, and a response-returned
`ServerConnection`. Deadline cancellation closes the peer in every state. A separate successful
case closes the listener before driving its accepted handler and proves that the handler can still
complete its response and be observed by the drain. Process signals were not added because an
ordinary application trigger expresses the complete lifecycle without changing ownership.

### Phase 5 — Application, Tooling, and Qualification

Status: complete.

- build one complete streaming service using only public APIs and fixed-size transfer buffers;
- exercise a body larger than each buffer, a reused connection, a forced close, timeout, malformed
  framing, and shutdown with active handlers;
- verify hover, completion, declaration navigation, implementation navigation, and diagnostics for
  the new typestates;
- perform whole-repository review and deterministic release qualification.

The public service application now exercises the complete lifecycle through ordinary contracts. A
raw loopback peer sends a 32 KiB body and a second pipelined request in one transport write. The
handler consumes the body through a 1 KiB buffer, emits a 32 KiB chunked response through the same
bounded transfer size, receives the reusable connection only after writer completion, and then
decodes the retained request and forces terminal response policy. Independent peers verify
malformed connection framing and idle request timeout. Admission remains bounded by a two-child
application-owned `TaskGroup`; consuming the server stops admission before the remaining group is
drained under one deadline.

The editor reference scenario resolves hover, completion, declaration, and implementation through
the checked public typestates, then edits the application to use a consumed server owner and
observes the expected diagnostic from a new semantic generation. Native application execution,
the complete compiler gate, deterministic out-of-tree documentation, repository metadata, and
diff integrity pass. The [Phase 5 review](../reviews/v0.54.0-phase-5.md) records the final authority
audit and qualification evidence. Release identity and packaged-image reproducibility remain the
separate release-preparation boundary.

## Deferred Work

HTTP/2, HTTP/3, protocol upgrade, CONNECT tunnels, WebSocket framing, request routing, middleware,
automatic serialization, connection pooling, and concurrent pipelined execution remain outside
this milestone. They require independent public contracts and must not be approximated through
hidden state in the HTTP/1.1 service lifecycle.
