# v0.49.0 Release Preparation

**Status: qualification in progress (2026-09-13).** This record owns the release-candidate
identity, qualification contract, retained local artifact evidence, and publication boundary.

## Release Boundary

v0.49.0 completes structured process I/O across synchronous and executor-safe execution. One
child-owner model now supports inherited, null, and piped standard streams; transferable generic
byte endpoints; exact terminal observation; nonblocking observation; termination; cancellation;
and nonblocking abandonment cleanup. Closed status and output operations are conveniences over the
same launch, endpoint, observation, and cleanup authorities.

The release also removes generated website HTML from the repository. Authored documentation and
static inputs remain on `main`, while GitHub Actions builds one source-identified Pages artifact
outside the source tree.

The [milestone](v0.49.0.md) owns the completed implementation. The [final process
review](../reviews/v0.49.0-phase-7.md) and [documentation artifact
review](../reviews/v0.49.0-documentation-artifact.md) record the closed models and implementation
gates. Public candidate notes are [`../../../releases/v0.49.0.md`](../../../releases/v0.49.0.md).
Root downloads, specification publication status, and the public release index remain at v0.48.0
until publication.

## Candidate Identity

The release inputs agree on `0.49.0`:

- `development/packaging/VERSION`, the sole authored release-version input;
- the `#package` version in `development/std/index.nct`;
- the archive name and installed manifest derived from `VERSION` and `RELEASE.json`;
- compiler and language-server reporting derived from the validated installed home.

`RELEASE.json` remains the machine authority for version-independent license, host, target, and
archive-layout metadata. Release qualification verifies that its license agrees with the shipped
legal files and every Cargo workspace package before either package build begins.

The exact release-content commit and retained artifact evidence will be recorded only after the
clean candidate passes qualification.

## Qualification Contract

The clean release-content commit must pass:

1. the complete compiler gate in a disposable Cargo target;
2. repository metadata, benchmark helpers, pinned Unicode reproduction, formatting,
   warnings-denied all-target Clippy, every enabled locked workspace test, no-default-features
   checking, and warnings-denied Rust documentation;
3. deterministic out-of-tree website generation and repository whitespace validation;
4. two independent optimized package builds with byte-identical archives and recursively identical
   installed homes;
5. fresh installed-home checks for version, diagnosis, help, initialization, locked/offline check
   and test, deterministic package graphs, native build, run, and direct execution;
6. every public example and the exact structured-process contracts, including generic blocking and
   async pipe transfer, simultaneous output beyond pipe capacity, cancellation, timeout, and child
   cleanup;
7. framed LSP analysis of installed public contracts and implementation sources;
8. proof that qualification commands do not mutate the installed home and that changing either the
   compiler or one standard-library source invalidates it.

The completed implementation gates remain useful evidence, but release qualification executes
again against the commit carrying the final `0.49.0` identity.

## Publication Boundary

Publication must reuse the retained qualified archive without rebuilding it, update public
latest-release links in a separate commit, fast-forward `main`, switch GitHub Pages to its Actions
source, create one annotated `v0.49.0` tag, upload exactly one asset, verify the public download byte
for byte, verify the source-identified Pages deployment, and record the immutable audit.
