# v0.59.0: Integrity-Checked Binary Records

## Goal

Turn the v0.58.0 scalar byte foundation into safe processing for variable-width and
integrity-checked binary records. Complete input, incomplete input, numeric overflow, and
non-canonical representation must remain distinct semantic outcomes. Existing cursors, fixed and
dynamic storage, and blocking and asynchronous I/O remain the only position, ownership, and
transport authorities.

## Completion Definition

v0.59.0 is complete when all of the following are true:

- one public prefix-decode result carries a decoded value and consumed width or distinguishes
  incomplete, overflowed, and non-canonical input without a text-backed error convention;
- fixed-width signed integer codecs preserve exact two's-complement representations in both byte
  orders without weakening lossless numeric-conversion rules;
- explicitly named unsigned base-128 and ZigZag signed codecs accept only canonical encodings and
  never publish a partial value or output prefix;
- one independent `std/checksum` responsibility provides allocation-free one-shot and incremental
  CRC-32 with reproducible static data and no cryptographic claim;
- `scan.ByteCursor`, `fixed.ByteBuffer<N>`, and dynamic byte storage consume the same codec results
  and keep their state unchanged after incomplete, invalid, or insufficient-capacity operations;
- a practical append-only record package detects truncated headers and payloads, non-canonical
  lengths, excessive declared lengths, checksum mismatches, and trailing corruption while
  preserving every preceding complete record;
- blocking and asynchronous fragmented reads recover identical records from the same wire image
  without a second framing, checksum, or endian implementation;
- native, standard-library, editor, documentation, installation, and packaging gates pass; and
- whole-repository review finds no duplicated decode classification, cursor transaction, checksum
  table, framing decision, or source-level representation reinterpretation.

## Responsibility Boundaries

`std/bytes` owns scalar representation and the prefix-decode result. It may report how many bytes a
complete scalar consumed, but it does not own cursor position, record limits, framing, storage, or
external I/O.

`std/checksum` owns CRC-32 state transition and finalization. It does not own record layout,
transport progress, authentication, cryptography, or corruption-recovery policy.

`std/scan.ByteCursor` remains the sole borrowed forward-position authority. Variable-width cursor
methods inspect the remaining view, advance exactly the reported width only after a decoded result,
and remain unchanged for every other result.

`std/fixed.ByteBuffer<N>` remains the bounded staging authority. Variable-width append first proves
the complete encoded width fits, then commits exactly that width. `Vec<u8>` owns dynamic growth,
while `std/io` owns blocking and asynchronous transport.

Record framing belongs to the practical record package. A generic `FrameReader` or schema system is
not standardized until more than one independent application demonstrates the same contract.

## Phases

### Phase 0 — Prefix Decode Authority

Status: complete.

- define one generic result for decoded value and width, incomplete input, overflow, and
  non-canonical input;
- specify transactional cursor behavior for every variant;
- give formatting, hover, completion, navigation, and semantic highlighting one ordinary nominal
  source declaration; and
- add native fixtures that prove each variant retains its exact payload and identity.

### Phase 1 — Portable Integer Completion

Status: complete.

- add exact signed 16-, 32-, and 64-bit bit-pattern conversion and fixed-width byte codecs;
- add explicitly named unsigned base-128 and ZigZag signed codecs;
- reject overlong, unterminated, and overflowing encodings before cursor advance; and
- preserve output bytes when the complete encoding does not fit.

### Phase 2 — Data Integrity

Status: complete.

- add `std/checksum` with one-shot and incremental CRC-32;
- generate or verify one canonical lookup table from the published polynomial;
- cover standard vectors, arbitrary chunk boundaries, empty input, and repeated finalization; and
- document that CRC detects accidental corruption but does not authenticate data.

### Phase 3 — Cursor and Storage Composition

Status: complete.

- integrate variable-width decode with `ByteCursor` without a second cursor state;
- integrate transactional encode with `ByteBuffer<N>` and dynamic byte storage;
- validate complete declared lengths before allocation or cursor mutation; and
- keep scalar conversion, checksum state, storage growth, and transport progress independent.

### Phase 4 — Integrity-Checked Record Application

Status: complete.

- build an append-only record package with magic, version, canonical length, payload, and CRC-32;
- read the same wire image through blocking and asynchronous fragmented inputs;
- retain every preceding valid record when the tail is incomplete or corrupt; and
- cover truncation at every field boundary, excessive lengths, non-canonical lengths, checksum
  mismatch, multiple records, and exact deterministic bytes.

The completed `examples/binary-record` package assigns wire emission, parsing, and transport
adaptation to separate source responsibilities behind its root contract. One record is exactly 23
bytes: magic, version, one canonical ULEB128 payload width, the 12-byte payload, and a big-endian
CRC-32. The public executable writes two records, reads the same image through two-byte
asynchronous fragments, and validates the decoded tail and final value. Declared tests reuse the
same decoder through one-byte blocking fragments, classify every shorter prefix, reject
non-canonical and excessive lengths before payload interpretation, and retain the first record
after second-record checksum or trailing corruption. Command integration fixes the exact 46-byte
image and runs all four declared cases.

### Phase 5 — Editor, Review, and Qualification

Status: complete.

- qualify public and implementation sources through the complete editor surface;
- run compiler, standard-library, native, documentation, installation, and packaging gates;
- review for duplicate decode, endian, checksum, cursor, framing, and stream authorities; and
- prepare v0.59.0 only after the installed practical application passes.

The completed qualification exercises the real binary-record package across hover, completion,
definition, implementation, semantic highlighting, and inlay hints. The disposable-target compiler
gate also runs its process contract and declared tests through installed standard declarations.
Whole-area review found no duplicate endian, prefix classification, checksum, cursor, framing, or
transport-specific decode authority. The one integration omission was the closed standard-library
dependency catalog: it now records the intentional `checksum -> internal/safety` and `vec -> bytes`
edges and continues to reject any unreviewed or stale edge. Native qualification also updates its
closed selected-case inventory for the intentional signed-representation test. The complete
evidence and authority trace are recorded in the
[v0.59.0 Phase 5 review](../reviews/v0.59.0-phase-5.md).

## Explicit Non-goals

Compression, cryptographic hashing, message authentication, encryption, schema generation,
host-endian APIs, unaligned typed views, a generic framing framework, and symbolic constant
arithmetic are outside v0.59.0. CRC-32 is an accidental-corruption check and must not be presented as
a security boundary.
