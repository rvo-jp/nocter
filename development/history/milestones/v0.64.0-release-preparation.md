## Candidate Identity

The release inputs agree on `0.64.0`:

- `development/packaging/VERSION`, the sole authored release-version input;
- the `#package` version in `std/index.nct`;
- the archive name and installed manifest derived from `VERSION` and `RELEASE.json`; and
- compiler and language-server reporting derived from the validated installed home.

`RELEASE.json` remains the machine authority for version-independent license, host, target, and
archive-layout metadata. Qualification verifies that its license agrees with the shipped legal
files and all Cargo workspace packages before either package build begins.

The release-content commit is `a5944bbea8c6ed7ba691a78df46b2dae77e4edb1`. Documentation-only
qualification evidence recorded afterward is not an artifact input.

## Qualification Contract

The clean release-content commit must pass:

1. the complete compiler gate in a disposable Cargo target;
2. repository metadata, performance helpers, pinned Unicode reproduction, formatting,
   warnings-denied all-target Clippy, every enabled locked workspace test, no-default-features
   checking, and warnings-denied Rust documentation;
3. deterministic out-of-tree website generation and repository whitespace validation;
4. two independent optimized package builds with byte-identical archives and recursively identical
   installed homes;
5. verified fresh installation and active-home replacement from the retained archive, followed by
   installation diagnosis, recursive identity comparison, and transaction-cleanup confirmation;
6. fresh installed-home checks for version, help, initialization, locked/offline check and test,
   deterministic graphs, native build, run, and direct execution;
7. every public example and retained application-specific native output contract, including the
   structurally validated random content-identity example;
8. interactive LSP initialization, dynamic capability registration, semantic queries,
   edited-source diagnostics, recovery, and shutdown; and
9. proof that qualification commands do not mutate the installed home and that changing either the
   compiler or one standard-library source invalidates it.
