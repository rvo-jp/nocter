# v0.58.0: Binary Data and Protocol Foundation

## Goal

Make bounded binary formats practical without creating a second cursor, stream, or buffer model.
`std/bytes` owns only the mapping between scalar values and byte sequences. Existing `std/scan`
cursors own forward input position, `std/fixed.ByteBuffer<N>` owns bounded staging, and `std/io`
owns external byte transport.

## Completion Definition

v0.58.0 is complete when all of the following are true:

- one public byte-codec contract covers unsigned integers and IEEE floating-point values in both
  big-endian and little-endian order;
- decoding is allocation-free, rejects short input without partial semantic results, and composes
  with `scan.ByteCursor` rather than introducing another input-position authority;
- encoding is allocation-free, rejects short output without modifying any byte, and accepts any
  mutable byte slice, including a `fixed.ByteBuffer<N>` spare region;
- `ByteBuffer<N>` provides one transactional append boundary that commits either a complete encoded
  value or no bytes, without reimplementing byte order;
- dynamic `Vec<u8>` and external `io.Writer` paths consume the same canonical encoded bytes rather
  than owning separate integer codec rules;
- at least one complete binary-format example exercises decoding, bounded encoding, file transport,
  malformed input, capacity exhaustion, and exact round trips;
- native, standard-library, editor, documentation, installation, and packaging gates pass; and
- whole-repository review finds no duplicated byte-order implementation, cursor authority, partial
  write contract, or source-level layout reinterpretation.

## Responsibility Boundaries

`std/bytes` owns pure value/byte conversion. It does not own stream progress, allocation, file or
socket I/O, buffering policy, framing, or a schema language.

`std/scan.ByteCursor` remains the sole public borrowed forward cursor. Codec helpers decode an exact
slice or an exact `ByteWindow`; advancing a cursor remains an explicit caller decision.

`std/fixed.ByteBuffer<N>` remains the sole fixed-capacity byte owner. Its codec-facing operation
borrows spare storage, encodes into that storage, and commits only after complete success.

`std/io` remains the stream contract. Stream helpers stage complete fixed-width encodings through
the same `std/bytes` operations; they do not repeat arithmetic or host-endian assumptions.

## Phases

### Phase 0 — Contract and Failure Atomicity

Status: complete.

- freeze module ownership and exact public signatures;
- define endian naming and supported scalar domains;
- prove that failed fixed-width encode and decode operations have no partial observable result; and
- add semantic fixtures for composition with borrowed and fixed-capacity storage.

### Phase 1 — Canonical Scalar Codecs

Status: complete.

- implement unsigned 16-, 32-, and 64-bit codecs in both byte orders;
- implement IEEE binary32 and binary64 codecs by delegating through their public bit contracts;
- keep arithmetic in one private implementation family; and
- cover boundaries, non-symmetric byte patterns, signed zero, infinities, and NaN payloads.

### Phase 2 — Cursor and Fixed-Capacity Composition

Status: complete.

- add exact cursor decoding without a second cursor representation;
- add transactional fixed-buffer encoding without exposing uncommitted bytes;
- prove unchanged cursor and buffer state after insufficient input or capacity; and
- preserve provenance through selected byte windows.

### Phase 3 — Dynamic and Stream Composition

Status: complete.

- connect codecs to dynamic byte collection and blocking/asynchronous writers;
- use one fixed-size staging representation for stream writes;
- preserve the complete-write contracts already owned by `std/io`; and
- avoid adding buffering or framing policy to the codec module.

### Phase 4 — Practical Binary Application

Status: complete.

- add one runnable bounded binary-format package;
- validate exact round trips and malformed or truncated input;
- demonstrate allocation-free field encoding with explicit capacity; and
- document when applications should choose slices, fixed buffers, vectors, or streams.

### Phase 5 — Editor, Review, and Qualification

Status: active.

- verify hover, completion, navigation, formatting, and diagnostics for the public contract;
- run compiler, standard-library, native, documentation, installation, and packaging gates;
- review the complete compiler and library integration for duplicate authorities and hidden host
  assumptions; and
- prepare v0.58.0 only after the practical application passes from a clean installation.

## Deferred Work

Signed integer bit-pattern conversion, variable-length integers, checksums, compression,
cryptography, schema generation, host-endian APIs, unaligned typed views, and symbolic constant
arithmetic remain outside this milestone unless the practical application proves one is required.
Protocol-specific framing belongs to its protocol module rather than `std/bytes`.
