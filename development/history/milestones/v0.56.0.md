# v0.56.0: Lending APIs and Zero-Copy Foundations

## Goal

Generalize `from` from a callable-result-only clause into one value-provenance contract and use it
to express lending APIs without named lifetime parameters. Complete the compiler, editor, and
standard-library foundations needed for zero-copy iteration, parsing, buffered windows, and
protocol decoding.

## Completion Definition

v0.56.0 is complete when all of the following are true:

- one `from` rule applies to callable results, parameters, receivers, and annotated local values;
- a contract names existing value bindings rather than declaring lifetime variables, and stores
  resolved semantic identities rather than source spellings;
- callable headers reserve the receiver and every parameter before resolving any provenance
  clause, so forward references and mutually dependent constraints do not depend on source walk
  order;
- input contracts are part of structural callable compatibility and survive aliases, closures,
  erased callables, interface requirements, and generic substitution;
- call checking proves each constrained argument's provenance is contained by its named source
  arguments before a call can execute;
- body checking uses the same constraint graph when proving result, assignment, and local-binding
  provenance, without replacing a parameter's own origin with a less precise source origin;
- lending iteration and mutable lending iteration can return an associated item tied to the active
  receiver call without generic associated types or Rust-style named lifetimes;
- at least one parser/window API and one protocol-decoding path retain borrowed data without an
  ownership copy;
- formatter, hover, signatures, navigation, semantic tokens, diagnostics, and inlay hints present
  authored contracts from checked identities rather than reconstructing source text;
- compiler, editor, standard-library, native, documentation, installation, and packaging gates
  pass; and
- whole-repository review finds no result-only compatibility path, order-dependent origin lookup,
  duplicated provenance solver, or downstream reinterpretation of a checked value contract.

## Phases

### Phase 0 — Unified Value Contract

Status: complete.

- freeze grammar and semantics for result, parameter, receiver, and local-binding clauses;
- define simultaneous header resolution, containment, cycles, static/independent values, and
  consume-and-return provenance transitions;
- establish one compiler authority for normalized value-provenance constraints.

### Phase 1 — Declaration and Structural Callable Model

Status: complete.

- parse every value-contract position with one syntax node;
- resolve declaration inputs only after receiver and parameter identities are reserved;
- include normalized input constraints in structural callable identity and compatibility;
- remove result-specific names and wrappers whose responsibility is now general.

### Phase 2 — Provenance Checking

Status: complete.

- validate argument constraints at direct, interface, closure, and erased-callable invocation;
- use one simultaneous constraint graph for body assumptions and contract validation;
- check annotated local initializers and assignments through the same containment operation;
- retain precise argument identity when mapping a constrained callable result.

### Phase 3 — Lending Interfaces

Status: next.

- add readonly and readwrite lending iterator contracts whose item result is `from self`;
- integrate generic associated item types, interface prerequisites, `for`, and `for await`;
- prove mutation exclusion while a yielded item remains live.

### Phase 4 — Zero-Copy Standard APIs

Status: planned.

- add borrowed text/byte windows and parsing cursors;
- adopt lending decoding where owned copies are unnecessary;
- keep owned convenience APIs as explicit ownership boundaries rather than hidden fallbacks.

### Phase 5 — Editor, Application, and Qualification

Status: planned.

- complete canonical formatting and semantic presentation for every contract position;
- exercise zero-copy parsing and protocol decoding in a practical application;
- run the complete release gate and adversarial authority review.

## Deferred Work

Named lifetime or origin parameters, abstract outlives predicates, generic associated types,
variant-dependent public provenance, movable direct self-references, and in-place operations that
change an existing owner's provenance set remain outside this milestone. A provenance-changing
operation consumes its owner and returns the new value instead.
