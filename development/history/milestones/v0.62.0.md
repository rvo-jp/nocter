# v0.62.0: Structured Command-Line Applications

**Status: release preparation (2026-09-20).** v0.62.0 replaces repeated raw process-argument
indexing in ordinary applications with one explicit command-line schema, one parser, and help text
derived from that same schema. All implementation phases are complete; v0.61.0 remains the latest
published release until explicit publication.

## Goal

- keep `std/process` authoritative for immutable operating-system arguments and decoding failure;
- make `std/cli` authoritative for option, positional, and command grammar;
- classify each supplied argument once and retain one owned parsed result;
- derive usage and help from the exact schema used by parsing; and
- prove the API through representative repository applications rather than a parser-only fixture.

## Phase 0 — Contract and Responsibility Model

**Status: complete.** Defined the public schema, result, error, presentation, and process-adapter
boundaries before implementation. The parser must not print, terminate the process, interpret
application values, inspect source text, or duplicate operating-system argument storage policy.

## Phase 1 — Options and Positional Arguments

**Status: complete.**

Implement long and short flags, value options, the `--` option terminator, required and optional
positionals, stable failure categories, schema validation, and a caller-supplied argument entry
point used by deterministic tests.

## Phase 2 — Presentation from the Parsing Schema

**Status: complete.**

Generate compact usage and complete help from the same immutable definitions selected by parsing.
Help rendering returns an owned string; application code alone decides whether to print or exit.

## Phase 3 — Nested Commands and Repeated Values

**Status: complete.**

Add explicit subcommand selection and schema-selected repetition policy without introducing
reflection, compiler-known declarations, or a second parsing path.

## Phase 4 — Application Adoption

**Status: complete.**

Move representative archive, filesystem, JSON, text, and HTTP examples away from raw argument
counts and indexes. Preserve their existing exit-status and operational contracts while making
their accepted invocation visible in one schema.

## Phase 5 — Review and Qualification

**Status: complete.**

Review the complete implementation for duplicated recognition, parser/help disagreement,
`std/process` representation leakage, hidden I/O or exit behavior, order-dependent schema
selection, and wrappers that carry no responsibility. Run the complete compiler and documentation
gates before release preparation.

## Completion Gates

- parser, result queries, usage, and help consume one schema authority;
- every accepted token is classified once and no result query reparses source spelling;
- malformed schemas and invocations fail through stable `std.cli.*` categories;
- representative applications use the public API and preserve exact native behavior;
- no compiler special case or new source syntax is required; and
- the complete disposable compiler gate and final responsibility review pass.
