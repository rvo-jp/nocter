# v0.38.0: Floating-Point Foundation and Practical Numeric APIs

**Status: active; Phases 0 through 2 complete; Phase 3 underway.** v0.38.0 adds `f32` and `f64` as complete language values and
connects them to native execution, numeric text, formatting, and JSON without treating a host
floating-point implementation as compiler authority.

The active cross-crate contract is
[`development/design/floating-point-design.md`](../../design/floating-point-design.md). Current
released behavior remains defined by `spec/` until each adopted behavior is implemented and moved
into the public specification.

## Phase 0: Semantic and Representation Contract

Define literal syntax and contextual typing; IEEE value, arithmetic, comparison, and NaN behavior;
explicit conversions; total-order separation; stored layout; Machine register classes; the target
constant-evaluation authority; standard numeric APIs; and the responsibility boundary from source
through native code and editor presentation.

**Status: complete.** The adopted design separates ordinary comparison from the `TotalOrder`
contract, assigns typed result bits to one target evaluator, and makes Machine the sole owner of
general versus floating-point transport. It rejects lexer-side host parsing, semantic-type recovery
inside ARM64, and float-specific exceptions in generic sorting.

## Phase 1: End-to-End Language and Native Execution

Implement `f32` and `f64` across tokens, syntax, formatter, diagnostics, built-in types, contextual
literal checking, constants, operations, conversions, CheckedProgram, MIR, Machine layout and ABI,
ARM64 floating-point registers and instructions, and executable validation. Replace the current
total-order assumption attached to structural `<` with the adopted comparison rules and the
standard `TotalOrder` boundary. Keep one typed constant and one transport decision through the
pipeline.

This phase closes only when scalar and aggregate float values, mixed general/float calls, spills,
returns, constants, control flow, NaN, infinity, signed zero, subnormals, and unsupported forms pass
source, semantic, ABI, and native tests.

**Status: complete.** The lexer retains one value-free floating token grammar; the type and runtime
tables contain closed `f32`/`f64` identities; and one target-parameterized arbitrary-precision
integer evaluator converts decimal spellings to typed IEEE bits without host floating-point
parsing. Checked bodies, MIR, and Machine retain those bits. Machine layout is the sole owner of
stored size, alignment, aggregate placement, and scalar transport class. ARM64 consumes that class
through independent general and floating virtual-register banks, independent argument banks,
class-local spilling, typed constants, arithmetic, partial comparison, calls, returns, aggregate
fields, and generic memory primitives. Native execution qualifies `f32`, `f64`, a ninth floating
stack argument, a call-crossing spill, `Vec<f64>` storage, lossless integer-to-float conversion, and
`f32`-to-`f64` widening. The checked comparison plan now represents inclusive comparison as
short-circuited strict comparison plus equality, evaluates source operands once, and preserves NaN
incomparability through native execution. One target-bearing constant plan now evaluates decimal
literals, arithmetic, remainder, comparison, integer conversion, and `f32` widening through a
bits-only software IEEE evaluator; header constants, recursively frozen statics, and native uses
retain its exact result bits. Qualification covers source diagnostics, semantic typing, stored and
ABI layout, independent exhausted general/floating argument banks, returns, call-crossing spills,
aggregate storage, control flow, compile-time/runtime agreement, NaN, infinities, both zero signs,
and representable subnormals through native execution.

## Phase 2: Practical Numeric Library

Add compiler-checked `f32` and `f64` declarations and ordinary source implementations for
classification, sign, rounding, bit conversion, parsing, shortest round-trippable formatting,
checked conversion, and total comparison. Add the shared comparison contract and migrate sorting
to `TotalOrder`. Reuse one parsing authority and one generation authority across direct methods and
`Format`.

This phase closes only when both ordinary and recoverable allocation paths work, public declaration
files remain readable contracts, implementation files contain the algorithms, and source/native
tests cover boundaries rather than host-library coincidence.

**Current foundation:** `from_bits` and `to_bits` are the sole representation primitives. Ordinary
Nocter source implements allocation-free classification, sign inspection, and absolute value from
those exact bits. Public infinity and NaN constants use the target constant evaluator. Native tests
cover payload preservation, signed zero, subnormals, normal values, infinities, module-constant
method receivers, directed rounding, ties-to-even rounding, and representation-based total
comparison. Checked integer conversion rejects fractions, non-finite values, and range loss before
target conversion; checked `f64` narrowing likewise rejects finite overflow and nonzero underflow.
The exact `u64` wide-arithmetic surface now exposes the high half of a full product, fixed-width bit
composition, wrapping arithmetic, rotation, and leading-zero count for the decimal algorithms.
One arbitrary-precision source parser consumes complete decimal and canonical non-finite text,
rounds the exact rational value directly to binary32 or binary64 with ties to even, and rejects
finite overflow and nonzero underflow. Native boundaries cover midpoints, subnormals, normal
extrema, non-finite values, signed zero, redundant zeroes, and invalid grammar.
`TotalOrder` now separates algebraic totality from the structural availability of `<`,
and in-place sorting requires that explicit promise. One fixed-capacity Dragon generator now
compares exact IEEE rounding intervals without intermediate allocation and emits the shortest
round-trippable decimal spelling. Type-owned ordinary and recoverable methods, `Format`, and
interpolation all route through that generator. Canonical tests cover notation thresholds,
non-finite values, signed zero, format integration, allocation failure, IEEE extrema, adjacent
representations, and a deterministic 512-value binary64 sample. Phase 2 is complete.

## Phase 3: Application Integration, Tooling, and Qualification

Integrate finite floating-point values with JSON, interpolation, and practical examples. Qualify
hover, completion, signature help, definition, references, rename, semantic tokens, inlay hints,
formatting, recovery, installed-home behavior, package and single-file commands, native execution,
documentation generation, packaging, and the complete compiler gate.

Review the complete change for duplicate literal parsing, host-dependent constant folding, semantic
type recovery in Machine or ARM64, mismatched ABI classification, operator/total-order conflation,
numeric text duplication, editor-only meaning, stale unsupported-float paths, and compatibility
fallbacks. Prepare publication only after this review is clean.

**Current progress:** `std/json.Number` now converts finite `f32` and `f64` values through the sole
shortest-decimal generator and projects an exact retained token through the sole runtime decimal
parser. Optional absence represents non-finite input or numeric range loss; the recoverable
constructors retain allocator failure as the distinct outer outcome. Native tests cover binary32,
binary64, signed zero, maximum finite magnitude, non-finite rejection, range rejection, and
recoverable allocation success. JSON retains its exact token as the representation authority; no
JSON-specific float scanner or formatter was introduced. A complete single-file example now
crosses parsing, arithmetic, interpolation, JSON conversion, generation, native compilation, and
execution. Framed editor tests use one complete and one recovering float source to qualify method
hover, definition, references, rename, signature help, semantic tokens, inlay hints, and completion
through the ordinary semantic authority. Source formatting preserves floating literal spelling and
formats the surrounding numeric expression through the shared syntax-owned formatter.

## Completion Definition

v0.38.0 is complete when an ordinary program can calculate, parse, format, interpolate, pass,
return, store, compare, and JSON-round-trip finite `f32` and `f64` values through native execution;
can deliberately observe and classify IEEE exceptional values; and receives consistent compiler
and editor behavior for invalid code. Compile-time and runtime results agree under one target
contract, Machine owns the complete register-class decision, and ordered generic consumers do not
mistake floating-point partial comparison for a total order.

## Non-goals

- decimal, arbitrary-precision, complex, or SIMD numeric types
- implicit numeric promotion
- C ABI floating-point interoperability
- locale-dependent numeric text
- configurable rounding environments
- transcendental functions without an adopted accuracy contract
- `noblock`, `realtime`, or another callable guarantee
- another native target
