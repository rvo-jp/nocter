# v0.72.0: Flow-Proven Safe Operations

**Status: active.** This milestone makes value-sensitive safety proof a checking-owned semantic
product. Later stages transport and validate admitted proof instead of rediscovering it from
constants, machine layout, or generated instructions.

## Goal

Let ordinary checked Nocter code prove that selected operations cannot trap while preserving one
authority for every conclusion. The checker derives local facts from typed values and control flow,
freezes the disposition on the checked operation or place, and uses the same fact for `notrap`
validation. MIR and Machine carry that decision without a second proof system.

## Completion Definition

v0.72.0 is complete when:

- source-visible bounds and arithmetic proofs are derived only by checking;
- branch-local facts refine operations and joins retain only facts valid on every incoming path;
- checked semantics record whether a safety check is required, proven unnecessary, or proven to
  trap;
- execution analysis consumes the recorded disposition instead of re-evaluating expressions;
- MIR and Machine transport the disposition without inference or reinterpretation;
- ARM64 consumes the closed Machine disposition without target-owned range analysis;
- `notrap` accepts useful value-sensitive code only when the complete checked path is proven safe;
- no unchecked indexing, compatibility fallback, source-text inference, or duplicate backend proof
  authority is introduced; and
- compiler, native, standard-library, editor, and documentation gates pass from one clean commit.

## Phases

### Phase 0 — Safety-Disposition Boundary

**Status: complete.** Checking now owns the three-way
bounds disposition for direct fixed-array indexing: runtime check required, proven in bounds, or
proven to trap. Checked execution facts consume it, MIR transports it, and Machine preserves it
while resolving only the index representation. Machine neither strengthens nor revalidates the
checking-owned state. Focused checker, MIR, Machine, and `notrap` tests close each boundary. The
[Phase 0 review](../reviews/v0.72.0-phase-0.md) records the cross-stage authority audit and
qualification evidence.

### Phase 1 — Flow Fact Domain

**Status: complete.** Checking now owns an integer-range environment keyed by stable parameter and
immutable-local identities. Primitive comparison meaning is normalized once in checked semantics,
branches refine copied states, and joins retain only facts true for every reachable continuation.
Every control construct isolates or joins the environment explicitly. Mutable and aliasable storage
is excluded rather than relying on implicit invalidation. The
[Phase 1 review](../reviews/v0.72.0-phase-1.md) records the control-flow and authority audit.

### Phase 2 — Bounds Proof Across Control Flow

**Status: complete.** Dynamic fixed-array, slice, and string indexing consume the shared fact
environment and are accepted by `notrap` only on a proven path. Slice and string lengths are
identified through validated toolchain semantic roles rather than names. While false exits and
explicit `break` paths join through the same state model; facts about mutable or different storage
remain inadmissible. The [Phase 2 review](../reviews/v0.72.0-phase-2.md) records the proof boundary
and loop audit.

### Phase 3 — Checked Arithmetic Proof

**Status: active.** Reuse the fact domain for integer range obligations. First close the existing
native runtime-check gap for normal arithmetic, then make the operation disposition, execution trap
fact, and emitted check consume one checking-owned decision. Conservative runtime checks remain
when proof is incomplete.

### Phase 4 — Standard Adoption and Qualification

**Status: planned.** Apply only proved guarantees to practical standard APIs, run the complete gate,
perform a cross-stage authority review, and prepare the deterministic release artifact.

## Deliberate Limits

This milestone does not add unchecked operations, user-authored proof assertions, dependent types,
SMT solving, or target-specific safety rules. Failure to prove safety keeps the runtime check; it is
not a compilation error unless an authored `notrap` contract requires the proof.
