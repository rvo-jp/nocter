# v0.40.0: Synchronous Internet Client Foundation

**Status: active; Phases 0-1 complete, Phase 2 next (2026-09-07).**

v0.40.0 completes one end-to-end user outcome: an ordinary Nocter program can parse an absolute
HTTP URL, resolve its host through the operating system, connect over synchronous TCP, send a
bounded HTTP/1.1 request, and consume a correctly framed response. The active cross-responsibility
contract is [`development/design/internet-client-design.md`](../../design/internet-client-design.md).

Implemented public behavior remains defined only by `spec/` and checked standard-library contracts.
This milestone records adopted scope and completion evidence; it does not make planned APIs
available early.

## Phase 0: Architecture and Trusted Target Services

Audit the existing network, I/O, allocation, error, target ABI, ARM64, and Mach-O boundaries. Add a
private, closed catalog for fixed-arity operating-system service calls so the Darwin adapter can use
the system resolver without introducing public FFI or network vocabulary into semantic IR.

Phase 0 closes when target closure validates each trusted declaration once, Machine carries a
source-independent foreign-call plan, ARM64 and Mach-O divide call selection from import encoding,
unsupported signatures fail before code emission, an imported test function executes natively, and
ordinary primitive/syscall programs remain byte-stable where their input has not changed.

Phase 0 completed with one compiler-owned target-service catalog, exact source-private standard
declaration bindings, target-closure ABI validation, closed MIR descriptors, dense Machine import
and runtime-call ABI identities, ARM64 indirect imported calls, and deterministic Mach-O function
binding. The initial catalog uses Darwin's system `getaddrinfo` and `freeaddrinfo` symbols with an
honest C-integer/pointer signature; it exposes neither arbitrary FFI nor resolver vocabulary to
generic compiler stages. A native imported-function image executes successfully, the bundled
standard package crosses target closure, the complete compiler workspace passes tests and strict
Clippy, and the pre-existing zero-timeout UDP qualification now establishes readiness without a
scheduler race.

## Phase 1: URL Values

Add `std/url` with parsed absolute RFC 3986 values, exact components, canonical generation,
relative-reference resolution, equality, hashing, formatting, recoverable allocation, and HTTP
request-target projection. Recognize `http` and `https`, reject non-ASCII registered names until an
IDNA contract exists, and keep transport policy out of the URL module.

Phase 1 closes when grammar boundaries, percent escapes, dot segments, default ports, IPv4, IPv6,
registered names, relative resolution, canonical round trips, allocation failure, and editor
features are covered without reparsing source text in consumers.

Phase 1 adds one immutable canonical `Url` representation and keeps parsing, relative resolution,
component projection, equality, hashing, formatting, and HTTP request-target generation over that
representation. The module accepts only absolute HTTP-family URL values, keeps IDNA and transport
policy outside its boundary, and distinguishes absent from present-empty query and fragment values.
One private typed attempt separates invalid input from recoverable allocator failure without
changing the public uniform `error` model. RFC 3986 normal and abnormal dot-segment cases, authority
replacement, canonical address formatting, default-port removal, round trips, injected failures for
every recoverable operation, and URL-driven hover, navigation, signature help, and completion pass.
The storage constructor is the sole authority for the private layout; parsers and resolvers do not
retain source text or assemble that layout independently.

## Phase 2: System Resolution and Host Connections

Add system name resolution to `std/net`. Preserve usable OS result order, copy only logical
`SocketAddress` values, release every native result exactly once, remove exact duplicates, map
stable errors, and connect candidates under one monotonic operation deadline.

Phase 2 closes when numeric bypass, localhost IPv4/IPv6 results, invalid names, empty results,
native failure, recoverable allocation, candidate fallback, deadline sharing, and all cleanup paths
are verified without an external command or public Internet dependency.

## Phase 3: HTTP/1.1 Message and Framing Core

Add validated methods, statuses, header names, header values, requests, responses, and one
transport-neutral HTTP/1.1 codec. Select body framing exactly once and enforce finite syntax and
buffer limits before allocation.

Phase 3 closes when fixed-length, chunked, close-delimited, bodyless, informational, trailer,
partial-input, premature-EOF, overflow, conflicting-length, unsupported-coding, and smuggling-prone
cases have exact tests. The codec must know neither DNS nor TCP ownership.

## Phase 4: Synchronous HTTP Client

Connect parsed URLs, host resolution, TCP, and the shared codec through one owned client/response
lifecycle. Support ordinary methods, validated headers, bounded byte request bodies, streaming
response reads, timeouts, deterministic closure, and stable contextual errors. Reject HTTPS before
network work until TLS exists.

Phase 4 closes when a local fixture covers hostname resolution, request targets, Host generation,
request bodies, all response framings, slow and truncated peers, limits, timeout, unfinished-body
cleanup, and sequential independent requests. v0.40.0 deliberately sends one request per connection
and does not claim redirects, replay, or pooling.

## Phase 5: Integration, Tooling, Review, and Qualification

Add complete single-file and package examples plus standard-library behavior guides. Verify source
checking, native execution, formatting, hover, completion, signature help, definition, references,
rename, semantic tokens, inlay hints, installed-home behavior, and deterministic documentation.

Review the complete change for duplicate URL parsing, custom-DNS drift, native ABI leakage,
repeated target-service selection, resolver leaks, per-candidate timeout restart, duplicate HTTP
framing, unbounded allocation, ambiguous message acceptance, transport/codec coupling, and
editor-only meaning. Qualify and retain the release candidate only after this audit is clean.

## Completion Definition

v0.40.0 is complete when a released Nocter program can fetch one deterministic local `http://` URL
by host name and stream its valid HTTP/1.1 response through public standard-library APIs. Each URL,
resolver, descriptor, deadline, HTTP framing, foreign ABI, and import-encoding decision has one
authority, and no compiler stage interprets URL, DNS, or HTTP semantics.

## Non-goals

- TLS and HTTPS transport
- public arbitrary FFI
- browser WHATWG URL behavior or IDNA
- automatic redirects, cookies, proxying, decompression, authentication, or connection pooling
- HTTP server APIs, HTTP/2, HTTP/3, WebSocket, or async I/O
- another native target
