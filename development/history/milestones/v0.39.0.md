# v0.39.0: Synchronous Network I/O Foundation

**Status: release qualification in progress (2026-09-07).**
v0.39.0 establishes target-independent numeric addressing and practical synchronous TCP and UDP
over one descriptor, deadline, target-adapter, and error model. The active cross-responsibility
contract is [`development/design/network-io-design.md`](../../design/network-io-design.md).

Implemented public behavior remains defined only by `spec/` and the checked standard-library
contracts. This milestone records adopted scope and completion evidence; it does not make planned
APIs available early.

## Phase 0: Network Semantic and Target Contract

Define address values and canonical text, descriptor ownership and cleanup, TCP stream behavior,
UDP datagram boundaries and truncation, monotonic deadlines, stable errors, and the target/ABI
boundary. Audit the existing primitive, I/O, time, pointer, and target capabilities before changing
source or compiler code.

**Status: complete.** The adopted design keeps sockets out of compiler representations, makes
`std/net` the public authority, assigns descriptor and deadline policy to one private substrate,
and confines native address and polling layout to the selected target adapter. The existing generic
syscall arities, pointer operations, `Duration`/`Instant`, built-in error, and stream contracts are
sufficient. No parser, checker, MIR, Machine, or ARM64 feature is required for the foundation.

## Phase 1: Numeric Address Values

Add compiler-checked IPv4, IPv6, IP, and socket-address declarations with allocation-free parsing,
canonical formatting, equality, hashing, and deterministic ordering. Keep exact declarations in
`std/net/index.nct`, algorithms in implementation sources, and native socket records absent from
public representations.

This phase closes when edge-case source and native tests cover complete parsing, canonical text,
IPv6 compression ties, bracketed socket addresses, invalid input, equality, hashing, and formatting
integration without duplicate scanners or generators.

**Status: complete.** `std/net` now exposes opaque copyable IPv4, IPv6, IP, and socket-address
values backed only by logical bytes and ports. Allocation-free parsers consume complete input;
canonical generators are shared by direct string conversion and `Format`; equality, hashing, and
ordering use the same logical representation. Five native standard-library tests cover parser
boundaries, RFC 5952 compression selection, projection and ordering, `Format`/`Hash` integration,
and unambiguous socket-address text. Review found and closed the eight-component trailing-`::`
boundary before completion.

## Phase 2: Shared Socket Substrate and TCP

Implement target adapters for socket creation, logical/native address conversion, connection,
binding, listening, acceptance, local/peer addresses, shutdown, close-on-exec, broken-pipe
suppression, polling, and raw-error classification. Build one private descriptor and readiness engine
on that contract, then expose owned TCP streams and listeners over it. Phase 2 establishes the
readiness seam; finite deadline accounting enters with the first public timeout in Phase 4.

This phase closes when client/listener loopback tests cover connection, peer and local addresses,
port-zero binding, bidirectional streaming, partial transfer, EOF, interruption, shutdown, explicit
close, destruction, and every partial-construction cleanup path. TCP must conform to existing
`Reader` and `Writer` semantics without copying their policy.

**Status: complete.** `std/internal/net/model` now owns the logical target-boundary values shared by
policy and adapters without a dependency cycle. `std/internal/net` owns the sole descriptor state,
close-once cleanup, interruption retry, readiness waits, and complete-stream-write policy.
`std/internal/net/darwin` alone owns Darwin socket and polling records, constants, byte order,
syscalls, descriptor configuration, IPv6-only behavior, close-on-exec, and broken-pipe suppression.
`std/net` exposes move-only `TcpStream` and `TcpListener` values with stable public errors and the
existing `Reader`/`Writer` contracts. Nine native tests now cover both address families, effective
port-zero addresses, peer/local identity, bidirectional bytes, EOF after shutdown, terminal
idempotent close, bind-failure cleanup, and stable address-conflict errors. Finite deadline state is
intentionally added in Phase 4 when a public timeout first exists; TCP already crosses the same
readiness seam that deadline accounting will extend.

## Phase 3: UDP Datagrams

Expose owned UDP sockets over the same descriptor, address, target, deadline, and error substrate.
Preserve one-message boundaries and report source, copied length, and truncation explicitly; do not
conform UDP to byte-stream interfaces.

This phase closes when loopback tests cover unconnected and connected sends, zero-length datagrams,
exact receive, truncation, multiple messages, address families, close, and error cleanup without a
UDP-specific retry loop.

**Status: complete.** `UdpSocket` now reuses the Phase 2 descriptor owner, connect/bind transitions,
readiness waits, logical address conversion, Darwin configuration, and stable network-error
mapping. `DatagramRead` keeps source address, copied length, and truncation together; UDP does not
implement byte-stream interfaces. Five additional native loopback tests cover unconnected and
connected operation, exact bytes and source identity, explicit truncation followed by a distinct
message, zero-length datagrams, IPv6, peer reporting, and terminal close. Darwin `recvmsg` layout
and message flags remain confined to the target adapter, while one shared descriptor policy owns
all wait and cleanup decisions.

## Phase 4: Public Timeout and Socket Options

**Status: complete and reviewed (2026-09-07).**

Expose the smallest portable timeout and option surface justified by TCP and UDP use. Convert each
relative `Duration` to one monotonic absolute deadline and route connect, accept, stream I/O, and
datagram I/O through the shared engine. Keep platform option encodings private and reject options
without portable semantics.

This phase closes when immediate, finite, interrupted, partial-progress, and expired cases use the
same deadline authority and do not restart a timeout during retries. IPv6-only behavior,
reuse-address behavior where exposed, and effective local-address reporting are deterministic.

Phase 4 adds finite connection, acceptance, stream-read, stream-write, datagram-connect,
datagram-send, and datagram-receive timeouts. `SocketDescriptor` retains only portable relative
configuration. A new package-private deadline policy samples `Instant` once per operation and is
the sole authority for remaining-time projection. The Darwin adapter receives only one bounded
poll interval and reports readiness, interruption, timeout, or native failure without deciding
retry policy.

Eighteen native network tests now include finite TCP accept and read expiration, finite UDP receive
expiration, configuration observation and clearing, timeout-bounded loopback connection, and the
zero-timeout/ready-data boundary. The [Phase 4 review](../reviews/v0.39.0-phase-4.md) records the
responsibility and verification audit. No reuse-address option is exposed because v0.39.0 has no
portable API requirement that justifies it.

## Phase 5: Integration, Tooling, and Qualification

**Status: complete and reviewed (2026-09-07).**

Add practical loopback examples and qualify source checking, native execution, formatting, hover,
completion, signature help, definition, references, rename, semantic tokens, inlay hints, package
and single-file workflows, installed-home behavior, documentation generation, and the full compiler
gate.

Review the complete change for duplicate address parsing, duplicated retry loops, raw descriptor or
ABI leakage, wall-clock deadlines, UDP/stream conflation, raw errno leakage, unclosed partial
constructors, editor-only meaning, and compatibility fallbacks. Publication preparation begins only
after that review is clean.

Phase 5 adds `network-address.nct` as an explicit single-file numeric-address program and
`network-loopback` as a complete package. The package selects kernel-assigned ports, exchanges TCP
bytes and one UDP datagram entirely over IPv4 loopback, and observes `std.net.timed_out` without an
external service. The public-example registry makes both workflows part of ordinary native
compilation and exact process-output qualification; the installed-home system-example gate executes
the loopback package through the distributed standard library.

The package's implementation source drives a focused semantic-editor matrix covering hover,
completion, signature help, definition, implementation navigation, references, rename, semantic
tokens, and inlay hints. The [Phase 5 review](../reviews/v0.39.0-phase-5.md) records the complete
authority audit and source-tree verification evidence. Release-only gates are tracked separately
in the [release-preparation record](v0.39.0-release-preparation.md).

## Completion Definition

v0.39.0 is complete when an ordinary Nocter program can parse and format numeric IPv4 and IPv6
socket addresses, exchange TCP byte streams, exchange boundary-preserving UDP datagrams, apply
monotonic synchronous timeouts, and diagnose failures through stable public errors on loopback.
Exactly one private subsystem owns descriptors and deadline policy, exactly one target adapter owns
native layouts and constants, and no compiler stage interprets network concepts.

## Non-goals

- DNS, service-name resolution, URLs, HTTP, WebSocket, or TLS
- asynchronous networking, public nonblocking sockets, or `noblock`
- multicast, broadcast, ancillary messages, interface enumeration, or IPv6 zone identifiers
- Unix-domain or raw sockets
- another native target
