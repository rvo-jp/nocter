# v0.49.0: Structured Process I/O

**Status: Phase 2 complete; Phase 3 next.**

## Outcome

v0.49.0 completes process execution as one structured synchronous and asynchronous facility.
Commands can launch an owned child, explicitly select inherited, null, or piped standard streams,
transfer pipe endpoints into generic byte I/O and buffering, await or synchronously observe exact
termination, request termination, and safely abandon an unobserved child without blocking the
executor or leaking a zombie. Closed status and output operations become conveniences over that
same ownership model.

## Phase 0: Contract and Migration Closure

**Status: complete.**

- Inventory current command preparation, launch reporting, pipe ownership, blocking polling,
  output capture, finite input, wait classification, and future cancellation boundaries.
- Fix the process, endpoint, cancellation, abandonment, execution-name, and error-precedence
  contracts before implementation.
- Determine whether the current runtime wait vocabulary can observe process completion without
  blocking or periodic polling.
- Prove that public pipe types can use ordinary `Reader`, `Writer`, `BlockingReader`,
  `BlockingWriter`, and generic buffers without compiler recognition.

Phase 0 completed on 2026-09-12. The existing synchronous implementation already provides sound
prepared launch storage, close-on-exec reporting, normalized descriptor ownership, fair finite
input/output progress, and exact-child status classification. Those responsibilities remain useful
but are currently joined inside a terminal blocking session. The generated async process root uses
`poll`, whose closed wait vocabulary covers only descriptors and deadlines and cannot observe child
completion. Async wrappers over the current loop would therefore block or require periodic probes.

The adopted [cross-component design](../../design/structured-process-io-design.md) gives process
completion one runtime-contract interest, moves the generated Darwin root to a unified native event
mapping, gives `Child` one generation-qualified ownership identity, and requires unobserved children
to transfer to a nonblocking abandonment authority. Public pipe endpoints use the existing generic
byte contracts. Existing async method, future ownership, interface, structured-task, tuple, error,
and provenance semantics are sufficient; no source-language syntax change or process-name
recognition is required.

The local macOS SDK confirms an exact native basis: `EVFILT_PROC`, `NOTE_EXIT`, the packed
`kevent64_s` record, `SYS_kqueue`, and `SYS_kevent64`. These constants remain target-owned and do
not enter standard source or the target-independent runtime contract.

## Phase 1: Unified Runtime Wait Interests

**Status: complete.**

- Add generation-qualified process completion to the target-independent reactor vocabulary and
  the sole runtime ABI encoder.
- Replace the host Darwin reactor's descriptor-only adapter with one native mapping for descriptor,
  timer, and process events.
- Replace the generated ARM64 Darwin root's temporary `pollfd` mapping with the same semantic
  event model.
- Prove duplicate registration rejection, cancellation cleanup, stale-event rejection, process
  exit wakeup, mixed-interest ordering, and ABI round trips.

Phase 1 completed on 2026-09-12. `ReactorInterest` and its sole numeric encoder now include process
completion. The host Darwin adapter and generated ARM64 process root both project descriptor
directions, process exit, and fixed deadlines onto `kqueue`/`kevent64`; the generated root no
longer constructs `pollfd` records. One runtime-contract schema owns the `kevent64_s` layout and
constants used by both implementations.

Native changes retain opaque, non-reused identities and delivered generated events are accepted
only after their token, filter, subject, and semantic source record agree. Darwin's
exit-before-registration `ESRCH` race becomes immediate readiness without collecting status.
Descriptor/timer/process native tests, cancellation and replacement tests, ABI round trips, and
complete generated-image conformance cover live and already-exited processes.

## Phase 2: Child and Abandonment Ownership

**Status: complete.**

- Introduce the exact process-owner record and compiler-owned abandonment target service.
- Keep explicit wait responsible for exit-status observation and abandonment responsible only for
  terminate-and-reap cleanup.
- Make cancellation and destruction transfer ownership without waiting on the executor thread.
- Cover normal exit, signal exit, already-exited abandonment, repeated PIDs, transfer failure, and
  executor shutdown.

Phase 2 completed on 2026-09-12. `std/process` now creates one private `ChildOwner` immediately
after every successful parent-side fork. Terminal observation consumes that owner and disarms it
only after an exact exit or signal result. Any remaining owner enters one closed
`process_abandon` primitive during destruction; no compiler stage recognizes the source type or
its fields.

The ARM64 Darwin service sends SIGKILL synchronously before transferring the unreaped PID to a
private dispatch worker. The worker alone blocks in `wait4`, retries interruption, requires the
exact PID, releases its target-owned record, and fails closed on any lost-ownership invariant.
Ordinary observed commands allocate no cleanup record. Generated native tests cover ordinary and
signal observation, already-exited commands, repeated failed launches followed by success, and an
actual live child whose dropped owner is terminated and reaped without blocking its caller.

## Phase 3: Public Spawn and Pipe Values

**Status: planned.**

- Add `Stdio`, `ProcessIo`, `Child`, `ChildStdin`, `ChildStdout`, and `ChildStderr` contracts.
- Add canonical async and explicit blocking spawn and observation operations.
- Transfer each configured endpoint at most once and close every untaken endpoint through its
  owner.
- Implement async and blocking byte interfaces through one endpoint state, without pipe-specific
  buffering.

## Phase 4: Generic Transfer and Lifecycle Operations

**Status: planned.**

- Add one generic byte-copy policy over ordinary reader and writer contracts for each execution
  surface.
- Add exact wait, nonblocking observation, graceful termination, and forced termination.
- Qualify partial progress, EOF, broken pipe, cancellation, endpoint destruction, and child
  observation under structured task composition.

## Phase 5: Closed Operation Migration

**Status: planned.**

- Rebuild status, finite-input output capture, and their blocking twins over the shared launch,
  endpoint, and observation authorities.
- Remove the old terminal command-I/O session and every obsolete wrapper after migration.
- Preserve fair concurrent progress and one public failure precedence without a second polling
  loop.
- Rename synchronous operations to the `_blocking` convention without compatibility aliases.

## Non-goals

- shell parsing or implicit `PATH` search;
- process groups, terminal control, pseudo-terminals, or daemonization;
- arbitrary numeric signal APIs;
- asynchronous regular-file or directory operations;
- asynchronous item iteration or generators;
- compatibility aliases for the previous synchronous process operation names;
- targets other than `arm64-darwin`.
