# v0.70.0: Trap-Free Callable Contracts

**Status: active.** This milestone adds the independently useful `notrap` guarantee without
combining it with allocation, waiting, recoverable failure, or asynchronous execution.

## Goal

Let APIs publish and structurally require that immediate execution cannot enter a Nocter safety
trap. The compiler must prove the promise over the same checked execution graph that already owns
allocation and synchronous-wait facts. A primitive declaration may rely only on its closed runtime
role, and editor presentation must reproduce the authored contract without inference or source-text
reconstruction.

## Completion Definition

v0.70.0 implementation is complete when:

- `notrap` is accepted in canonical `const noalloc notrap blocking` order on every immediate
  callable surface that can own a source contract;
- `CallableGuarantees` is the sole structural identity and weakening authority for trap freedom;
- one positive fixed-point fact covers direct checked traps, selected calls and operations,
  callbacks, closures, and implicit destruction;
- bodyless callables are conservative, while registered primitives validate authored `notrap`
  against compiler-owned runtime evidence;
- recoverable `T!` flow and explicit process termination remain distinct from safety traps;
- `notrap async` is rejected until `future T` can retain a drive-time trap guarantee;
- formatting, hover, completion, diagnostics, normative grammar, and compiler architecture expose
  the same contract; and
- the complete compiler gate and documentation build pass from disposable output directories.

## Phases

### Phase 0 — Contract and Grammar

**Status: complete.** The language-owned modifier vocabulary, syntax grammar, declaration lowering,
structural callable model, compatibility relation, and semantic presentation now carry one
independent trap guarantee.

### Phase 1 — Transitive Proof

**Status: complete.** Checked execution facts now include a source-trap lattice dimension. The
least fixed point covers direct checked operations, calls, callable values, closures, and ownership
cleanup. Contract violations retain the checked source operation that introduced the fact.

### Phase 2 — Trusted Boundaries and Qualification

**Status: in progress.** Primitive runtime roles now carry explicit source-trap evidence, and target
validation rejects a trapping primitive that claims `notrap`. Dedicated process-abort and
process-exit primitive roles distinguish termination from safety traps without name matching or
whole-wrapper fact suppression. Remaining work is the complete repository gate,
generated-documentation check, and final design review.

## Deliberate Limits

`notrap` does not promise successful allocation, normal process continuation, bounded execution,
absence of recoverable `error`, operating-system survival, or immunity to invalid compiler/runtime
representations. It is not currently a property of driving `future T`; asynchronous trap contracts
require a future milestone with a representation that retains that evidence.
