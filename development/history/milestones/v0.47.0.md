# v0.47.0: Canonical Asynchronous Byte I/O

**Status: Phase 0 complete; Phase 1 planned.**

## Outcome

v0.47.0 gives executor-safe byte streams one generic public contract. Unqualified `Reader` and
`Writer` become the canonical asynchronous interfaces, synchronous code uses explicit
`BlockingReader` and `BlockingWriter` contracts, and ordinary whole-stream and text adaptation is
implemented once as async interface defaults rather than once per concrete transport.

## Phase 0: Contract and Migration Inventory

**Status: complete.**

- Fix interface naming, execution kinds, receiver access, result and capture ownership, and default
  algorithm behavior before changing public declarations.
- Inventory every standard, example, compiler fixture, semantic-editor assertion, and behavior
  guide that currently uses `Reader` or `Writer`.
- Separate portable byte semantics from transport-specific timeout, readiness, framing, and close
  policy.
- Prove that existing async interface validation and dispatch are the only compiler mechanisms
  needed; do not add standard-name recognition.

Completion requires one cross-module design authority, an exact migration set, checked async
interface/default-method probes, formatting, deterministic documentation, and repository checks.

Phase 0 completed on 2026-09-11. The migration inventory contains the `std/io` declarations and
bodies, file buffers, filesystem helpers, JSON generation and its private sink adapter, TCP, TLS,
HTTP response bodies, nine public example source files, four native-session fixture families, and
the semantic-editor reference source. The adopted names follow the already-released concrete API
rule instead of adding an `Async` prefix to the canonical surface. A focused checker probe proves
that a generic async function can await a default async interface method which itself awaits a
required method twice. Existing witness matching already rejects an immediate method returning a
future as an async implementation, so the standard migration requires no parser, resolver,
checker, lowering, or editor special case.

## Phase 1: Explicit Synchronous Contracts

**Status: planned.**

- Rename the existing interfaces to `BlockingReader` and `BlockingWriter` without aliases.
- Migrate `File`, file buffers, filesystem helpers, JSON generation, concrete network and TLS
  witnesses, public examples, native fixtures, and editor expectations in one closed change.
- Keep every synchronous wait and `_blocking` method contract unchanged.

Completion requires the complete standard source and public examples to contain no old synchronous
interpretation of `Reader` or `Writer`.

## Phase 2: Canonical Async Interfaces and Defaults

**Status: planned.**

- Add async `Reader.read` and `Writer.write` requirements.
- Add generic async whole-stream, UTF-8, flush, text, and line defaults.
- Preserve invalid-read-count, partial-write, EOF, failure, cancellation, allocation, and UTF-8
  behavior through one portable implementation.
- Exercise generic async default dispatch and mismatched synchronous witnesses in compiler and
  native tests.

## Phase 3: Transport Conformance and Deduplication

**Status: planned.**

- Make TCP and TLS implement both explicit blocking and canonical async contracts.
- Make HTTP `Response` implement both reader contracts.
- Delete response-specific ordinary collection and route its timeout variants through only the
  concrete timeout primitive plus shared collection policy.
- Keep transport timeout methods outside the base interfaces.

## Phase 4: Application and Tooling Integration

**Status: planned.**

- Add a complete public program whose generic async byte algorithm works across more than one
  concrete reader or writer.
- Cover native interface dispatch, cancellation, EOF, failure, UTF-8 validation, and exact output.
- Qualify hover, completion, signature help, navigation, semantic tokens, and inlay hints through
  the ordinary checked contracts and implementation sources.
- Update the sole I/O, network, TLS, and HTTP behavior authorities without duplicating signatures.

## Phase 5: Whole-Area Review and Release Readiness

**Status: planned.**

- Review for compatibility aliases, duplicate collection loops, source-name inference, concrete
  type branches, blocking operations reachable from futures, recomputed witness selection, reverse
  dependencies, and caller-trust contracts.
- Run the complete compiler, documentation, standard-library, public-example, formatting, and
  repository gates.
- Stop before changing release identity or publishing.

## Non-goals

- asynchronous regular-file or directory operations;
- a blocking-worker pool, detached tasks, threads, or parallel execution;
- timeout or cancellation policy in the base byte interfaces;
- generic datagram I/O through stream interfaces;
- seek, random access, vectored I/O, or memory mapping;
- effect-polymorphic interface methods;
- compatibility aliases for the previous synchronous interface names.
