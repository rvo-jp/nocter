# v0.36.0: Wall-Clock Time and UTC Calendar

**Status: complete and publication authorized (2026-09-06).** v0.36.0 adds one coherent civil-time
capability on top of the
existing monotonic `Duration` and `Instant` foundation. It introduces normalized Unix wall-clock
observations, validated proleptic-Gregorian UTC values, canonical RFC 3339 interchange, and
filesystem modification times without making calendar policy compiler behavior.

The exact standard-library declarations belong to `development/std/time/index.nct`. The longer
observable contract belongs to `development/std/time/README.md`.

## Phase 0: Public Contract and Authority

Define the `SystemTime` and `UtcDateTime` domains, normalization, ranges, comparison, conversion,
RFC 3339 profile, failure codes, target boundary, filesystem integration, tooling presentation,
and explicit non-goals. Target-specific standard source obtains raw wall-clock fields through the
existing generic syscall boundary; calendar arithmetic, parsing, generation, and public errors
remain ordinary standard-library behavior.

## Phase 1: Wall-Clock Acquisition and Normalized Instants

Add the ARM64 Darwin standard-library wall-clock adapter, normalized signed Unix seconds plus
nanoseconds, construction and observation, equality and ordering, normalization arithmetic, source
checking, native execution, and target-boundary tests. No source-visible `noblock` promise is
introduced.

## Phase 2: UTC Gregorian Calendar

Implement one shared conversion authority between normalized system time and validated UTC
components. Qualify leap years, month lengths, the Unix epoch, dates before the epoch, the year
0000 and 9999 boundaries, nanosecond preservation, and rejected out-of-range conversions.

## Phase 3: RFC 3339 Interchange

Parse uppercase RFC 3339 timestamps with `Z` or numeric minute offsets and zero to nine fractional
digits. Normalize accepted offsets into UTC. Reject leap-second spellings because the POSIX-style
`SystemTime` domain cannot represent them bijectively. Generate one canonical UTC spelling with
uppercase `T` and `Z`, no fractional field for zero nanoseconds, and exactly nine fractional digits
otherwise. Ordinary and recoverable allocation entry points share one parser and generator.

## Phase 4: Filesystem and Practical Integration

Expose file modification time through `fs.Metadata` using the same `SystemTime` type. Add a
complete runnable example that observes the wall clock, inspects a file timestamp, performs UTC
conversion, and emits canonical RFC 3339 text.

## Phase 5: Tooling and Stabilization

Qualify formatting, hover, completion, signature help, navigation, semantic highlighting,
installed-home behavior, native execution, target rejection, and generated documentation. Review
the complete change for duplicate calendar arithmetic, ABI reinterpretation, source-text semantic
recovery, authority reversal, and wrappers that bypass an owner contract.

## Completion Definition

v0.36.0 is complete only when an ordinary program can observe wall-clock time, convert it to and
from validated UTC calendar components, parse and generate the adopted RFC 3339 profile, and read a
filesystem modification time through one shared public instant type. Every conversion and format
uses one standard-library calendar authority; the compiler and target backend do not know calendar
or RFC 3339 semantics.

## Non-goals

- local time and daylight-saving rules
- the IANA time-zone database
- locale-dependent presentation
- leap-second tables or preservation
- async timers, scheduling, and periodic timers
- `noblock`, `realtime`, or another callable guarantee
- another host or target
