# v0.64.0: Application Encoding and Identity

**Status: released and externally audited (2026-09-20).** Release-content commit
`a5944bbea8c6ed7ba691a78df46b2dae77e4edb1` passed the complete gate and deterministic artifact
qualification. Annotated tag `v0.64.0` resolves to publication commit
`fd7df74721f29e8fa650b3527e94923321671839`; the
[publication audit](../release-audits/v0.64.0.md) owns external evidence.

## Goal

Turn Nocter's byte, text, and cryptographic-entropy foundations into one practical application-data
layer. Programs must be able to encode arbitrary bytes, compute stable content digests, and create
or exchange opaque identifiers without compiler-owned formats or application-local codecs.

The implementation belongs in checked standard-library source. Compiler primitives remain limited
to operations ordinary Nocter source cannot express, so encodings, SHA-256 policy, UUID layout,
and textual presentation do not become target knowledge.

## Completion Definition

v0.64.0 is complete when all of the following are true:

- strict lowercase hexadecimal and RFC 4648 Base64 codecs provide allocating convenience and
  caller-owned allocation-free operations from one decision core;
- standard padded Base64 and URL-safe unpadded Base64 remain distinct explicit contracts rather
  than an input-guessing mode;
- malformed input and insufficient destinations never expose partially decoded output as success;
- one incremental SHA-256 authority supports arbitrary chunking and a fixed 32-byte digest value;
- digest equality, bytes, lowercase text, parsing, formatting, and hashing share that value's
  canonical representation;
- UUID values own exactly 16 bytes, parse and render one canonical spelling, participate in
  equality, ordering, formatting, and hashing, and create version-4 values from `std/random`;
- random and identifier contracts state their actual synchronous-waiting effect consistently;
- complete compiler, editor, native, public-example, documentation, and packaging-metadata gates
  pass without duplicate public codec, digest, UUID, or random-source authorities.

## Responsibility Boundaries

`std/hex` owns hexadecimal alphabet, validation, exact size arithmetic, encoding, and decoding.
Other standard modules may consume this contract but do not retain local hexadecimal codecs for
the same complete-byte representation.

`std/base64` owns the standard padded and URL-safe unpadded RFC 4648 profiles. It validates one
selected profile strictly and never accepts a mixed alphabet or guesses padding policy.

`std/digest` owns SHA-256 block state, padding, finalization, and the opaque `Sha256Digest` value.
Compiler-side content integrity remains a host-tool responsibility and cannot be called from a
Nocter program or used as the standard-library implementation.

`std/uuid` owns UUID byte layout and canonical lowercase hyphenated text. Version-4 creation
depends only on the public random-byte contract; it does not acquire entropy independently.

## Phases

### Phase 0 — Contract and Correctness Foundation

**Status: complete.** Module ownership, public profiles, failure vocabulary, exact-size rules, and
the cross-module dependency graph are frozen. The v0.63.0 random effect surface was audited and
the current contract now states that the bounded Darwin entropy operation does not carry Nocter's
`blocking` effect before UUID construction depends on it.

- define owned and caller-owned codec surfaces without two policy implementations;
- assign digest bytes, text, equality, formatting, and hashing to one opaque value;
- define UUID parsing, rendering, and version-4 generation over that value model; and
- prove the module graph remains acyclic and compiler-independent.

### Phase 1 — Hexadecimal and Base64 Codecs

**Status: complete.** Strict codecs, deterministic tests, shared internal ASCII digit helpers that
remove existing URL, JSON, and network duplication, and checked documentation are implemented.

### Phase 2 — Incremental SHA-256

**Status: complete.** The allocation-free streaming state and opaque digest pass published vectors,
every block-padding boundary, chunking-independence checks, and the shared formatting, hashing,
equality, ordering, byte, and canonical-text contracts.

### Phase 3 — UUID and Random Tokens

**Status: complete.** Canonical UUID values and version-4 generation now compose the public random
contract. URL-safe tokens compose the same entropy contract with canonical Base64 without becoming
a second entropy or encoding authority.

### Phase 4 — Adoption, Review, and Qualification

**Status: complete.** Practical public adoption now exercises SHA-256, UUID version 4, and URL-safe
tokens through installed standard-library contracts. The remaining complete-byte hexadecimal copy
in HTTP request-target handling was replaced by the package-internal ASCII authority. The final
review found no duplicate application-facing codec, digest, UUID, or entropy authority, and the
complete verification matrix passes. Exact release inputs remain a separate release-preparation
step.

## Non-goals

v0.64.0 does not add encryption, signatures, password hashing, key storage, deterministic random
streams, permissive Base64 decoding, arbitrary UUID versions, or a compiler cryptography
primitive. Constant-time behavior is not promised without an independently enforceable execution
contract.
