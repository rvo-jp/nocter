# v0.48.0: Generic Buffered Byte I/O

**Status: Phase 0 complete; Phase 1 next.**

## Outcome

v0.48.0 makes buffering follow the execution model established by v0.47.0. Unqualified
`BufReader<R>` and `BufWriter<W>` become generic executor-safe adapters over `Reader` and `Writer`.
Synchronous code uses explicit generic `BlockingBufReader<R>` and `BlockingBufWriter<W>` adapters.
No buffer type is tied to `File`, and no transport reimplements portable buffering, line, or flush
policy.

## Phase 0: Contract and Migration Closure

**Status: complete.**

- Inventory the existing file-specific blocking buffers, every consumer, and the generic language
  capabilities needed by their replacements.
- Fix names, generic constraints, ownership, EOF, partial progress, UTF-8, flush, failure,
  cancellation, and terminal-state behavior before changing declarations.
- Prove that ordinary generic types, interface constraints, async callables, and static dispatch are
  sufficient; do not add compiler recognition of standard-library buffer names.
- Keep asynchronous regular files, worker threads, process pipes, detached tasks, and a generic
  item-stream abstraction outside this milestone.

Phase 0 completed on 2026-09-12. The current `std/io/buffer` types were confirmed to be concrete
`File` owners despite their unqualified names and despite v0.47.0 assigning unqualified byte-I/O
names to executor-safe contracts. Existing standard generic adapters prove that a nominal generic
type can own or borrow an interface-constrained value without runtime dictionaries. Existing async
interface/default dispatch proves that buffer operations need no parser, checker, lowering,
runtime, or editor special case.

The adopted ownership and transition contract is:

- each buffer uniquely owns its underlying source or destination;
- reader state owns unread bytes and any incomplete line prefix across calls;
- EOF is stable and later reads return zero or absence without touching the source;
- a read failure or invalid UTF-8 line makes the buffered reader terminal because input may already
  have been consumed;
- cancellation while awaiting more input preserves already accepted line bytes and leaves no
  initialized scratch bytes visible as input;
- a writer accepts bytes into its private buffer and publishes them only through its underlying
  writer contract;
- flush enters a terminal state before awaiting the destination, because cancellation or failure
  can follow an externally visible prefix whose length is unknown;
- successful flush clears retained bytes and restores the open state; failed or cancelled flush
  cannot be retried;
- destruction discards unflushed bytes and destroys the uniquely owned underlying value without
  hiding a fallible operation;
- a successful explicit `finish` flushes and returns the underlying destination by value.

## Phase 1: Explicit Generic Blocking Buffers

**Status: planned.**

- Replace `BufReader` and `BufWriter` with `BlockingBufReader<R>` and
  `BlockingBufWriter<W>` without aliases.
- Constrain behavior through `BlockingReader` and `BlockingWriter` instead of storing `File`.
- Preserve bounded refill, line normalization, reusable destination, explicit flush, terminal
  failure, and zero-capacity normalization.
- Migrate standard source, public examples, native fixtures, documentation, and semantic-editor
  expectations in one closed change.

## Phase 2: Canonical Generic Async Buffers

**Status: planned.**

- Add `BufReader<R>` over `Reader` and `BufWriter<W>` over `Writer`.
- Implement buffered reads, line reads, reusable line destinations, complete writes, flush, and
  finish with cancellation-safe state transitions.
- Share pure capacity, byte-copy, line-validation, and error construction policy between execution
  surfaces without sharing their control loops.
- Qualify immediate and suspended progress, partial transport work, EOF, cancellation, error, and
  destruction through native execution.

## Phase 3: Portable State-Machine Qualification

**Status: planned.**

- Exercise both memory-backed and transport-backed readers and writers through the same generic
  adapters.
- Cover UTF-8 scalars split across arbitrary reads, CRLF and unterminated lines, zero progress,
  impossible counts, flush failure after a visible prefix, cancellation, and exact-once cleanup.
- Prove that an operation never retries an ambiguous output prefix or exposes scratch
  initialization as received input.

## Phase 4: Application and Tooling Integration

**Status: planned.**

- Add one complete asynchronous line-oriented application over TCP or TLS and reuse the same
  buffering contract over a second concrete stream.
- Migrate synchronous examples to the explicit blocking names.
- Qualify hover, completion, signature help, navigation, semantic tokens, and inlay hints through
  ordinary generic and interface semantics.
- Update the sole standard I/O behavior guide without duplicating declarations.

## Phase 5: Whole-Area Review and Release Readiness

**Status: planned.**

- Review for file-specific remnants, compatibility aliases, execution-name inversion, duplicate
  buffering loops, transport branches, repeated dispatch, cancellation holes, reverse
  dependencies, and caller-trust contracts.
- Run the complete compiler, standard-library, examples, documentation, formatting, and repository
  gates.
- Stop before changing release identity or publishing.

## Non-goals

- asynchronous regular-file or directory operations;
- a blocking-worker pool, threads, detached tasks, or parallel execution;
- independently owned subprocess pipes;
- seek, random access, vectored I/O, or memory mapping;
- a generic `Stream<T>` or asynchronous iterator language feature;
- compatibility aliases for the old file-specific `BufReader` and `BufWriter` names.
