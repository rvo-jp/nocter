# v0.46.0 Release Preparation

**Status: qualification in progress (2026-09-11).** This record owns the release-candidate
identity, qualification contract, retained local artifact evidence, and publication boundary. No
tag, push, upload, or public latest-release change is authorized by preparation alone.

## Release Boundary

v0.46.0 completes UDP as an executor-safe networking surface. One `UdpSocket` owner supports
immediate setup and address observation, canonical asynchronous transfers, explicit asynchronous
deadlines, and clearly named blocking twins. Closed target operations keep one nonwaiting datagram
attempt out of the generic blocking syscall boundary, while standard source remains the sole owner
of retry, timeout, truncation, and public failure policy.

The [milestone](v0.46.0.md) owns the completed implementation and Phase 5 review. Public candidate
notes are [`../../../releases/v0.46.0.md`](../../../releases/v0.46.0.md). Root download links,
specification publication status, and the public release index remain at v0.45.0 until an explicitly
authorized publication commit.

## Candidate Identity

The release inputs agree on `0.46.0`:

- `development/packaging/VERSION`, the sole authored release-version input;
- the `#package` version in `development/std/index.nct`;
- the archive name and installed manifest derived from `VERSION` and `RELEASE.json`;
- compiler and language-server reporting derived from the validated installed home.

`RELEASE.json` remains the machine authority for version-independent license, host, target, and
archive-layout metadata. Release qualification verifies that its license agrees with the shipped
legal files and every Cargo workspace package before either package build begins.

The exact release-content commit and retained artifact evidence will be recorded only after the
clean candidate passes qualification.

## Qualification Contract

The clean release-content commit must pass:

1. the complete compiler gate in a disposable Cargo target;
2. repository metadata, benchmark-helper tests, pinned Unicode reproduction, formatting,
   warnings-denied all-target Clippy, every enabled locked workspace test, no-default-features
   checking, and warnings-denied Rust documentation;
3. deterministic generated website reproduction and repository whitespace validation;
4. two independent optimized package builds with byte-identical archives and recursively identical
   installed homes;
5. fresh installed-home checks for version, diagnosis, help, initialization, locked/offline check
   and test, deterministic package graphs, native build, run, and direct execution;
6. every public example and its exact process contract, including asynchronous UDP, TCP, TLS, HTTP,
   structured cancellation, timeout, and terminal ownership;
7. framed LSP analysis of installed public contracts and implementation sources;
8. proof that qualification commands do not mutate the installed home and that changing either the
   compiler or one standard-library source invalidates it.

The completed Phase 5 gate remains useful evidence, but release qualification executes again
against the commit carrying the final `0.46.0` identity.

## Publication Boundary

Publication must reuse the retained qualified archive without rebuilding it, update public
latest-release links in a separate commit, create one annotated `v0.46.0` tag, upload exactly one
asset, and verify the public download byte for byte. Those actions require explicit authorization.
