**Status: candidate identity selected; artifact qualification pending.** This record owns the

## Release Boundary

v0.54.0 completes the bounded HTTP/1.1 service lifecycle. Client responses and incoming server
requests share one transport-independent body cursor, server handlers read request bodies
incrementally, and response writers stream fixed-length or chunked output under transport
backpressure. A connection is returned only after request consumption, response completion, and
the selected persistence policy prove that sequential reuse is safe.

Graceful shutdown remains application-owned: closing the listener stops admission, while one
deadline-bounded `TaskGroup` drain owns every accepted handler until completion or structural
cancellation. The complete public service transfers 32 KiB bodies through 1 KiB application
buffers, retains a pipelined request for later sequential processing, forces terminal policy, and
checks malformed framing plus idle timeout.

The [milestone](v0.54.0.md) owns the completed implementation. The [closure
review](../reviews/v0.54.0-phase-5.md) records the final authority audit and complete repository
gate. Public candidate notes are
[`../../../releases/v0.54.0.md`](../../../releases/v0.54.0.md). Published-version surfaces continue
to select v0.53.0 until publication succeeds.

## Candidate Identity

The release inputs agree on `0.54.0`:

- `development/packaging/VERSION`, the sole authored release-version input;
- the `#package` version in `development/std/index.nct`;
- the archive name and installed manifest derived from `VERSION` and `RELEASE.json`;
- compiler and language-server reporting derived from the validated installed home.

`RELEASE.json` remains the machine authority for version-independent license, host, target, and
archive-layout metadata. Qualification verifies that its license agrees with the shipped legal
files and all Cargo workspace packages before either package build begins.

The exact release-content commit and measured artifact identities will be recorded after clean-tree
qualification. A later documentation-only evidence commit is not an artifact input.

## Qualification Contract

The clean release-content commit must pass:

1. the complete compiler gate in a disposable Cargo target;
2. repository metadata, benchmark helpers, pinned Unicode reproduction, formatting,
   warnings-denied all-target Clippy, every enabled locked workspace test, no-default-features
   checking, and warnings-denied Rust documentation;
3. deterministic out-of-tree website generation and repository whitespace validation;
4. two independent optimized package builds with byte-identical archives and recursively identical
   installed homes;
5. fresh installed-home checks for version, diagnosis, help, initialization, locked/offline check
   and test, deterministic graphs, native build, run, and direct execution;
6. every public example and the exact filesystem, streaming, network, HTTP, TLS, process, task,
   persistent-connection, and graceful-service contracts;
7. interactive LSP initialization, dynamic capability registration, hover, completion, navigation,
   edited-source diagnostics, recovery, and shutdown against installed public and implementation
   sources;
8. proof that qualification commands do not mutate the installed home and that changing either the
   compiler or one standard-library source invalidates it.
