# v0.46.0: Asynchronous Datagram I/O

**Status: Phase 0 complete; Phase 1 next.**

## Outcome

v0.46.0 completes UDP as a first-class executor-safe networking surface. The same `UdpSocket`
owner supports immediate setup, canonical asynchronous send and receive, explicit async deadlines,
and clearly named blocking twins without exposing descriptor modes or weakening the v0.45.0
blocking-effect model.

## Phase 0: Contract and Target Inventory

**Status: complete.**

- Classify UDP operations by actual external waiting rather than by their current generic syscall
  implementation.
- Fix the public execution and naming model before implementation.
- Define the closed target-operation boundary required to prove immediate datagram attempts
  nonblocking.
- Define cancellation, timeout, datagram atomicity, truncation, and empty-message behavior.
- Reject duplicate socket owners, blocking wrappers disguised as futures, and mutable timeout
  inheritance in async APIs.

Phase 0 completed on 2026-09-11. The adopted design keeps bind, numeric peer selection, and address
observation immediate; makes send, send-to, and receive canonical asynchronous operations; gives
their synchronous twins `_blocking`; and applies configured timeouts only to the synchronous
surface. Generic syscall roles remain blocking. A finite set of closed datagram roles becomes the
only authority that may certify one native attempt as nonblocking.
