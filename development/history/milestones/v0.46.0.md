# v0.46.0: Asynchronous Datagram I/O

**Status: implementation complete; release qualification in progress.**

## Outcome

v0.46.0 completes UDP as a first-class executor-safe networking surface. The same `UdpSocket`
owner supports immediate setup, canonical asynchronous send and receive, explicit async deadlines,
and clearly named blocking twins without exposing descriptor modes or weakening the v0.45.0
blocking-effect model.

## Phase 0: Contract and Target Inventory

**Status: complete.**

- Classify UDP operations by actual external waiting rather than by their current generic syscall
  implementation.
- Fix the public execution and naming model before implementation.
- Define the closed target-operation boundary required to prove immediate datagram attempts
  nonblocking.
- Define cancellation, timeout, datagram atomicity, truncation, and empty-message behavior.
- Reject duplicate socket owners, blocking wrappers disguised as futures, and mutable timeout
  inheritance in async APIs.

Phase 0 completed on 2026-09-11. The adopted design keeps bind, numeric peer selection, and address
observation immediate; makes send, send-to, and receive canonical asynchronous operations; gives
their synchronous twins `_blocking`; and applies configured timeouts only to the synchronous
surface. Generic syscall roles remain blocking. A finite set of closed datagram roles becomes the
only authority that may certify one native attempt as nonblocking.

## Phase 1: Closed Datagram Target Operations

**Status: complete.**

- Add the finite operation roles and exact effect classifications to the runtime contract.
- Bind each role to one standard declaration through the standard profile.
- Move Darwin syscall identities, fixed invocation flags, and carry/error normalization behind
  ARM64 lowering while keeping native record ownership in the target-specific standard adapter.
- Reject missing, duplicate, mismatched, or unsupported datagram role bindings before MIR.
- Remove generic syscall use from the datagram adapter rather than retaining compatibility wrappers.

Completion requires target-contract, Machine, ARM64, native execution, architecture, formatting,
and diff checks with no source-path or primitive-name inference.

Phase 1 completed on 2026-09-11. Ten closed roles now cover descriptor opening and configuration,
bind, peer selection and status, connected and addressed sends, receive, and local/peer address
observation. The ARM64 backend owns fixed Darwin calls and invocation flags; the standard Darwin
adapter owns socket-address/message records, retries, malformed-result classification, and
descriptor cleanup. Generic syscall entry remains only for the synchronous `poll` wait and is no
longer reachable from an immediate datagram attempt. Removing its last UDP consumer also removed
the otherwise-unused `Syscall5` role, declaration, contract, and backend dispatch rather than
retaining a mandatory compatibility surface.

## Phase 2: Shared Synchronous and Asynchronous Policy

**Status: complete.**

- Refactor one datagram attempt model beneath both execution surfaces.
- Drive async waits through descriptor readiness or readiness-plus-deadline futures.
- Keep interruption retry, timeout selection, error normalization, and truncation in standard
  source.
- Prove that cancellation removes wait interests without closing or duplicating the socket.

Phase 2 completed on 2026-09-11. One provider-independent attempt reducer now gives ready,
interrupted retry, readiness wait, normalized failure, source address, and truncation their sole
standard-source meaning. Synchronous loops consume that model through blocking `poll`; asynchronous
loops consume it through descriptor-readiness futures and one optional fixed monotonic deadline.
Every transfer holds an exclusive descriptor borrow, while cancellation owns only the logical wait
registration. Reactor qualification proves that cancelling the last waiter leaves the same native
descriptor open and reusable by a replacement waiter.

## Phase 3: Public UDP Surface

**Status: complete.**

- Make immediate setup and observation nonblocking contracts.
- Add canonical async send, send-to, and receive operations with explicit timeout variants.
- Rename synchronous transfer twins with `_blocking` and migrate all standard tests and examples
  without aliases.
- Update declaration documentation and the sole network behavior guide.

Phase 3 completed on 2026-09-11. `send`, `send_to`, and `receive` now expose the canonical async
surface with explicit `_with_timeout` variants; `send_blocking`, `send_to_blocking`, and
`receive_blocking` are the only synchronous transfers. Bind, numeric peer selection, and address
observation are immediate contracts and no longer reach a blocking poll. Existing standard tests
and the synchronous network example use only the new `_blocking` names, and the active network
design plus behavior guide no longer describe asynchronous UDP as open work. No compatibility
aliases retain the previous synchronous spellings.

## Phase 4: Tooling and Native Integration

**Status: complete.**

- Exercise bidirectional IPv4 and IPv6 datagrams, connected and explicit destinations, empty and
  truncated messages, readiness, timeout, cancellation, close, and error paths natively.
- Add a complete public asynchronous UDP example with an exact process contract.
- Qualify hover, completion, signature help, navigation, semantic tokens, and inlay hints through
  the ordinary checked semantic query path.

Phase 4 completed on 2026-09-11. Native qualification now drives real IPv4 and IPv6 loopback
descriptors through explicit-destination and connected transfers, empty and truncated datagrams,
readiness suspension, timeout cancellation, post-cancellation reuse, and closed-socket failure.
The public `async-udp` package has an exact zero-output process contract. Its ordinary checked
package analysis also drives hover, completion, signature help, contract and implementation
navigation, semantic tokens, and inlay hints without an editor-only UDP model.

## Phase 5: Whole-Area Review and Release Readiness

**Status: complete.**

- Review for generic-syscall remnants, duplicate retry or timeout loops, reverse dependencies,
  recomputed effect facts, caller-trust contracts, and stale synchronous-only documentation.
- Run the complete compiler, documentation, example, formatting, and repository gates.
- Stop before changing the release identity or publishing.

Phase 5 completed on 2026-09-11. The whole-area review confirmed one-way authority from closed
runtime roles through source bindings, target validation, Machine operations, ARM64 materialization,
and private standard adapters. Immediate and async datagram attempts cannot reach the remaining
generic blocking `poll`; sync and async orchestration share one retry, deadline, failure, source-
address, and truncation policy without sharing incompatible wait mechanics. Native source fixtures,
editor assertions, and two unrelated scheduler-sensitive HTTP timeout fixtures were corrected at
their qualification boundaries. The complete repository gate passes. See the
[Phase 5 final review](../reviews/v0.46.0-phase-5.md) for authority, findings, and evidence.

The [release-preparation record](v0.46.0-release-preparation.md) owns the candidate identity,
artifact qualification, and publication boundary.
