# v0.52.0 Release Preparation

**Status: candidate qualification in progress.** This record owns the release-candidate identity,
qualification contract, retained local artifact evidence, and publication boundary. Publication
must reuse the retained qualified archive without rebuilding or replacing it.

## Release Boundary

v0.52.0 adds checked compile-time callable evaluation. An explicit `const` modifier promises that
a function, method, construction function, or callable type can execute during semantic
construction. The same declaration and implementation remain available to ordinary runtime calls.

Constant and immutable-static initializers now enter the ordinary semantic body pipeline. The
checker owns name resolution, typing, generic specialization, operator selection, ownership, and
dispatch exactly once; a closed evaluator executes only those frozen decisions. Scalar values,
static text, tuples, and fixed arrays cross the complete checked-plan and native-data boundary.

Declaration lowering retains a separate sparse structural-constant table solely for fixed-array
type construction. Checked finalization publishes the one dense constant/static value table and
proves that every duplicated structural bootstrap value agrees with its checked initializer.

The [milestone](v0.52.0.md) owns the completed implementation. The [closure
review](../reviews/v0.52.0-phase-5.md) records the final boundary corrections and complete compiler
gate. Public candidate notes are [`../../../releases/v0.52.0.md`](../../../releases/v0.52.0.md).
Root downloads, specification publication status, and the public release index remain at v0.51.0
until publication.

## Candidate Identity

The release inputs agree on `0.52.0`:

- `development/packaging/VERSION`, the sole authored release-version input;
- the `#package` version in `development/std/index.nct`;
- the archive name and installed manifest derived from `VERSION` and `RELEASE.json`;
- compiler and language-server reporting derived from the validated installed home.

`RELEASE.json` remains the machine authority for version-independent license, host, target, and
archive-layout metadata. Qualification verifies that its license agrees with the shipped legal
files and all Cargo workspace packages before either package build begins.

The qualified release-content commit and retained artifact identities will be recorded only after
the clean candidate passes every gate.

## Qualification Contract

The clean release-content commit must pass:

1. the complete compiler gate in a disposable Cargo target;
2. repository metadata, benchmark helpers, pinned Unicode reproduction, formatting,
   warnings-denied all-target Clippy, every enabled locked workspace test, no-default-features
   checking, and warnings-denied Rust documentation;
3. deterministic out-of-tree website generation and repository whitespace validation;
4. two independent optimized package builds with byte-identical archives and recursively identical
   installed homes;
5. fresh installed-home checks for version, diagnosis, help, initialization, locked/offline check
   and test, deterministic package graphs, native build, run, and direct execution;
6. every public example and the exact filesystem, streaming, network, HTTP, TLS, and process
   contracts, including the bounded asynchronous file-report success and failure paths;
7. framed LSP analysis of installed public contracts and implementation sources;
8. proof that qualification commands do not mutate the installed home and that changing either the
   compiler or one standard-library source invalidates it.
