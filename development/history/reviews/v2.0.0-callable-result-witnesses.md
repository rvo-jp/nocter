# v2.0.0 Named Callable Result Witnesses

## Scope

This checkpoint extends the private value-binding front end and its existing static instance
product. Flat callable results now retain a named code witness through returned factory calls,
explicit and block-final returns, invocation adapters, local values/aliases, conditional joins,
replacement and anchored recursive equations. It grants no public CLI, ABI, MIR or native admission.

The sole language rules are the [callable result contract](../../spec/language/callables.md#statically-witnessed-callable-results)
and [bounded grammar](../../spec/language/syntactic-grammar.md#bounded-value-binding-fragment).
The [cross-stage contract](../../architecture/pipeline/value-access-declarations.md) and owning
crate READMEs describe the current responsibilities; this record preserves qualification evidence.

```text
func increment(value: i32): i32 { value + 1 }
func make(): func(i32): i32 { increment }
func forward(): func(i32): i32 { make() }
func run(): i32 {
    let action = forward()
    action(1)
}
```

The returned environment is an ordinary owning value. Its exact named producer proves Copy and
trivial cleanup; the structural result signature alone proves neither. Formal callback inputs
remain checked without inheriting those properties from a known caller.

## Authority Review

- Header normalization uses one value-slot syntax/definition/publication path for inputs and
  results. Symbolic result families and their permitted views are interned before header freeze.
  Checking selects existing named keys in that same immutable TypeAuthority; no body type store
  or downstream contract search is introduced.
- Body typing records result constraints and exact identity equalities without erasing witnesses.
  A query with unresolved results cannot enter the public flow boundary. Conditional Copy plans
  remain intermediate evidence until the exact established producer schema proves them.
- The existing selected control graph and initialization report are built once. Static producer
  flow follows actual evaluations, bindings, replacement, conditional forwarding and staged return
  values over reachable edges. It does not infer a producer from a provisional expression type.
  Its code/view facts are separate from availability and owner responsibility; they cannot prove
  that a moved or dropped value is usable.
- Finite producer sets close across result-producing functions. One established named producer is
  required; different code identities and unanchored equations reject. Invocation views survive
  the relation, and deferred join/replacement identities are proved before projection.
- Identity projection updates the existing body arenas and call/binding targets, then access and
  resource validation consume the same graph/initialization. Preparation actions and control IDs
  do not change. Successful closure here proves capture-free Copy schemas; supporting a move-only
  result later requires resolving supply before initialization rather than reusing that assumption.
- Closed queries share producer-body source evidence. Editing a factory body invalidates a closed
  caller query even if its own bytes and headers are unchanged. Complete Unit binding verifies
  the dependencies once and lends a private proof to all body projections. No stale source
  projection or retyping fallback is admitted.
- The target owner consumes checking-closed result identities and the body's resolved result data
  through its existing instance/call/payload graph. It performs no second result inference. Only
  reachable invocation commits add instances; interrupted calls still retain known types without
  inventing result owners or executable edges.

## Findings and Counterexamples

A provisional conditional type can mention a named branch that never executes. Treating that
TypeId as a producer would falsely anchor this relation:

```text
func make(): func(i32): i32 {
    if false { increment } else { make() }
}
```

Actual producer flow leaves this equation unanchored. The corpus also rejects the local-binding
variant and a named local overwritten by `make()` before return. A dynamic conditional with a
reachable named branch remains an anchor; both expression and explicit-return recursion pass.

Equal signatures do not make two returned functions interchangeable. Distinct explicit returns,
factory joins and replacements reject. `once` cannot be upgraded to `func`; a fixed `mut`
environment cannot be invoked through update access. Copying a proved named result preserves the
original owner, while dropping an owner with a live alias still fails access validation.

The staged-result test proves that the returned function survives automatic cleanup of a taking
error input, with one result owner and no duplicated disposal. Interruption tests distinguish
known contract mismatch from runtime non-reachability, and exclude uncommitted factory/result
calls from the instance graph.

## Verification

The production source corpus contains 231 cases: 119 accepted units, 98 checking rejections,
8 header rejections and 6 syntax rejections. This checkpoint adds 42 sources: 23 accepted,
17 checking rejections and 2 header rejections. All 225 syntax-valid sources have lossless parser
snapshots; declaration tests validate 217 header-valid units independently of body acceptance.
Existing snapshots and manifest verdicts are preserved.

Five focused checking integration tests inspect proof gating, closed targets/data, Copy versus
move, staged cleanup, recursive anchors and source-dependency invalidation. Three additional
source-backed target tests inspect the same instance graph, interrupted reachability and the
separation between proved result Copy and generic formal transfer.

Affected library checks pass: checking 708, declarations 49, model 43, declaration lowering 144
and syntax 144. After the producer-flow review, all 708 checking tests, the current header/syntax
corpus and 15 private target tests pass. Warnings-denied workspace all-target Clippy validates
API compatibility. Formatting, documentation generator tests, an external documentation build
and whitespace checks pass. LSP and native runtime suites do not consume this private path and
are not claimed as feature evidence.

## Remaining Work

Later extension: [deferred value supply](v2.0.0-deferred-value-supply.md) removes the
conditional-Copy initialization ordering described above. This checkpoint's evidence remains
unchanged; current contracts and next work belong to the crate READMEs and handoff.


Input-dependent result relations need call-application identities and substitution. A single
family keyed only by the returning function would conflate `forward(first)` with
`forward(second)`; simply permitting formal producers is unsound. Potentially move-only
returned environments also require Copy-versus-move resolution before initialization and exact
view/dependency/cleanup evidence. These are extensions to the same authorities, not signature
lookup or runtime erasure fallbacks.

Captured environments, general R/D/S and retained-state/write footprints, physical environment
and argument realization, ABI, executable cleanup, MIR and native output remain separate work.
No performance result follows from this static closure. The [handoff](../../TODO.md) owns the
next concrete task.
