# v0.49.0 Phase 2 Child Ownership Review

**Result: complete with no open Phase 2 defect.** Every successful parent-side fork now creates one
private standard-library child owner. Exact observation or fail-stop abandonment consumes the sole
reaping obligation.

## Findings Closed During Implementation

### A raw PID did not carry cleanup authority

The prior synchronous command path passed a `usize` PID through launch and wait functions. Correct
cleanup depended on every caller reaching the wait. `ChildOwner` now acquires the PID immediately
after fork, retains an active state, and invokes abandonment from destruction unless terminal
observation disarmed it.

### Destruction could not perform a blocking reap

The source owner calls one nonblocking primitive. Its Darwin target sends SIGKILL before returning,
then transfers the exact unreaped PID to a private dispatch worker. Only that worker blocks in
`wait4`. Allocation failure, unavailable dispatch infrastructure, an unexpected wait error, or a
different returned PID aborts instead of losing the unique cleanup obligation.

### Completion ABI validation assumed every result was a value

The first native qualification rejected the abandonment call because the shared register validator
treated `void` as a zero-word returned value. The machine contract represents it as
`MachineResultAbi::Completion`. The validator now handles completion explicitly and still rejects a
zero-width value pretending to be completion.

### The owner and raw subprocess sources briefly formed a visibility cycle

Only the owner consumes raw fork and wait facts. The redundant reverse `see` was removed, leaving
raw process transitions independent of ownership policy and the owner dependent only on their
private declarations.

## Responsibility Review

- `nocter-runtime-contract` owns the closed process-abandon primitive role and Darwin service import
  catalog.
- `nocter-standard-profile` maps that role to one private standard declaration; it does not infer a
  source type name.
- `std/process` owns `ChildOwner`, active/disarmed state, wait classification, and the decision to
  abandon during destruction.
- `nocter-target-program` owns the source-independent primitive signature and target constraint.
- `nocter-arm64` owns forced termination, asynchronous worker transfer, exact `wait4`, imports, and
  native failure policy. It receives only a PID and cannot inspect standard-library storage.
- The reactor continues to wake process-completion futures without reaping or decoding status.
