Date: 2026-11-09. Scope: finite nongeneric record declarations, structural construction and existing-place field operations
in the private value-binding front end. This extends the
[bounded front-end checkpoint](v2.0.0-value-binding-front-end.md),
[schema checkpoint](v2.0.0-nominal-payload-schemas.md) and

It does not qualify native execution or the full language.

## Source Behavior

The owning [bounded grammar](../../../spec/language/syntactic-grammar.md#bounded-value-binding-fragment),
[value rules](../../../spec/language/value-access.md) and
[nominal payload contract](../../../spec/language/structs-and-enums.md#future-direction-v2-0-0-nominal-value-payloads)
remain normative. The production private path now accepts records as callable inputs/results and
resolves local/input-rooted field chains, including grouped selections. Structural values initialize
all declared fields exactly once, with component Copy-or-move selected in authored order.

```text
struct Pair {
    first: error
    second: error
}

func first(take pair: Pair): error {
    pair.first
}

func pair(take a: error, take b: error): Pair {
    Pair { second: b, first: a }
}
```

In `first`, the result is moved before cleanup destroys `second` and ends the remaining container.
In `pair`, the initializer produces `second` before `first`, while the completed result retains
its declaration-owned schema order. Whole-value
use after extraction fails; a writable field can be restored before returning the complete record.
Explicit `drop pair` can end a present partial record without reconstructing moved components.
Nested fields, scalar compound updates, explicit `copy struct`, branch/loop restoration, and
disjoint call/alias accesses use the same path. Parent/child and identical-field accesses still
overlap. Copy is selected from the component schema and never inferred merely because a field is
read or a record contains Copy fields.

Header rejection covers unknown data names, recursive containment, invalid Copy requests and
duplicate fields. Body and flow rejection distinguish unknown fields, wrong data, unavailable
selected values, missing containing storage, fixed-value updates and overlapping permissions.
Defining records after their users does not change name availability.

## Authority Review and Refactoring

Data-name resolution, schemas, field identity and Copy evidence belong to the single private
declaration program. Lowering reserves all names before definitions and delegates data resolution
to that owner. Its syntax-only header extraction, semantic definition construction and diagnostic
projection have separate modules; none maintains a second type namespace.

Body typing resolves a field chain once into one selected-place identity, root local, field path
and data TypeId. Its mutable interning index does not survive publication. Initialization, access,
call reservations and resource handling consume those selections without repeating member lookup.
Only the final selected place is interned, avoiding redundant prefix places for long chains.

Projected initialization uses sparse joined availability for use diagnostics and fixed points.
The resource ledger retains exact alternative ownership/cleanup states. These are different
derived facts over one selected control graph: initialization cannot replace an alternative
cleanup proof, and the ledger cannot grant permission. Both distinguish complete selected values
from present ancestor containers. Referent regions compose the selected field path with alias
origins, so siblings can be independent without overlooking parent/child conflicts.

The resource payload module is named `resources::payload`, replacing the misleading `places`
name: it owns sparse unavailable payload regions and cleanup frontiers, not source-place lookup.
Owning local survival is read directly from the ledger instead of being duplicated in the scoped
alias-value map. Construction keeps completed component values as expression owners in the same
evaluation frame, then transfers them through one `Step::Assemble`. A return/break/continue before
completion cleans those values in reverse production order through the existing frame exits;
there is no parallel incomplete-constructor ledger or fabricated whole-record destruction.
Assembly records selected field/source pairs, and validates all transfers before publishing any
change. Empty and nested records use that same transition. The typed value boundary is named for
value supply rather than function returns, since component construction consumes the same rule. Rebinding preserves the exact declaration authority and rejects changed record
headers through the full neutral header surface; no separate record-header recipe is retained.

## Remaining Work

This fragment constructs records, receives them through inputs and can manipulate or return
them. It cannot yet select a field directly from a computed value. Temporary component extraction,
Copy-or-move and remainder cleanup are the next source integration boundary. Indexing, generic/interface/callable and dependency-bearing payloads, user destructors,
outcomes, async, public modules, target layout and executable/native realization remain separate.

There is no CLI language switch, released-program conversion, native result or speedup claim.
The handoff owns the next concrete work; crate READMEs and the
[cross-stage boundary](../../architecture/pipeline/value-access-declarations.md) own current
implementation contracts rather than this review.
