## Source Behavior

The owning [bounded grammar](../../spec/language/syntactic-grammar.md#bounded-value-binding-fragment),
[value rules](../../spec/language/value-access.md) and
[nominal payload contract](../../spec/language/structs-and-enums.md#nominal-value-payloads)
remain normative. The production private path now accepts records as callable inputs/results and
resolves local/input-rooted field chains, including grouped selections. Structural values initialize
all declared fields exactly once, with component Copy-or-move selected in authored order.
A computed field chain evaluates its producer once and delivers the selected component as a
value; aliases, assignment and edit-input supply still require existing storage.

```text
struct Pair {
    first: error
    second: error
}

func first(take pair: Pair): error {
    pair.first
}

func pair(take a: error, take b: error): Pair {
    Pair { second: b, first: a }
}

func first_result(take a: error, take b: error): error {
    pair(a, b).first
}
```

In `first`, the result is moved before cleanup destroys `second` and ends the remaining container.
In `pair`, the initializer produces `second` before `first`, while the completed result retains
its declaration-owned schema order. In `first_result`, only `first` moves out of the call result;
its remaining `second` stays in the original evaluation frame until cleanup. Whole-value use after extraction fails; a writable field can be restored before returning the complete record.
Explicit `drop pair` can end a present partial record without reconstructing moved components.
Nested fields, scalar compound updates, explicit `copy struct`, branch/loop restoration, and
disjoint call/alias accesses use the same path. Parent/child and identical-field accesses still
overlap. Copy is selected from the component schema and never inferred merely because a field is
read or a record contains Copy fields.

Header rejection covers unknown data names, recursive containment, invalid Copy requests and
duplicate fields. Body and flow rejection distinguish unknown fields, wrong data, unavailable
selected values, missing containing storage, fixed-value updates and overlapping permissions.
Defining records after their users does not change name availability.

## Authority Review and Refactoring

Data-name resolution, schemas, field identity and Copy evidence belong to the single private
declaration program. Lowering reserves all names before definitions and delegates data resolution
to that owner. Its syntax-only header extraction, semantic definition construction and diagnostic
projection have separate modules; none maintains a second type namespace.

Body typing resolves a field chain once into one selected-place identity, root local, field path
and data TypeId. Its mutable interning index does not survive publication. Initialization, access,
call reservations and resource handling consume those selections without repeating member lookup.
Only the final selected place is interned, avoiding redundant prefix places for long chains.
The `selection` module replaces the narrower `place_typing` module and owns one member-chain
split and field resolver for both existing places and computed values; construction uses the same
resolver. A computed path freezes its producer, complete resolved path and Copy/Move action in
one typed operation, without extracting intermediate containers or reopening field lookup later.
Copy evidence is selected from the component, even when its containing record is move-only.

The earlier `ValueType` enum conflated a result's type with whether evaluation could reach it.
An interrupted call or constructor discarded a known record type, which would have required a
second shape-recovery walker or unnecessary source annotations for computed selection. Result
access and possible normal completion are now independent private facts in one typed product.
Calls, structural values, operators and compatible branches preserve known data while a control
exit still produces no runtime resource. A pure exit with no result shape cannot invent fields.
Existing structural type constraints remain checked, including known-but-interrupted results;
flow and resource consumers require an actual possible continuation. No operation kind or
callable input is inferred from this control fact.

Projected initialization uses sparse joined availability for use diagnostics and fixed points.
The resource ledger retains exact alternative ownership/cleanup states. These are different
derived facts over one selected control graph: initialization cannot replace an alternative
cleanup proof, and the ledger cannot grant permission. Both distinguish complete selected values
from present ancestor containers. Referent regions compose the selected field path with alias
origins, so siblings can be independent without overlooking parent/child conflicts.

The resource payload module is named `resources::payload`, replacing the misleading `places`
name: it owns sparse unavailable payload regions and cleanup frontiers, not source-place lookup.
Owning local survival is read directly from the ledger instead of being duplicated in the scoped
alias-value map. Construction keeps completed component values as expression owners in the same
evaluation frame, then transfers them through one `Step::Assemble`. A return/break/continue before
completion cleans those values in reverse production order through the existing frame exits;
there is no parallel incomplete-constructor ledger or fabricated whole-record destruction.
Assembly records selected field/source pairs, and validates all transfers before publishing any
change. Empty and nested records use that same transition. The typed value boundary is named for
value supply rather than function returns, since component construction consumes the same rule. Rebinding preserves the exact declaration authority and rejects changed record
headers through the full neutral header surface; no separate record-header recipe is retained.

## Verification

The [shared production manifest](../../compiler/tests/fixtures/value-bindings/README.md) now has
113 sources: 58 accepted units, 46 checking rejections, 4 header rejections and 5 syntax rejections.
The field integration added 34 sources, construction 21, and computed selection 28. All 108
syntax-valid sources have reviewed lossless parser snapshots; the original snapshots are unchanged.
Syntax, declaration and unit tests consume the same per-source expectations and actual production
entry points. No auxiliary parser or source-text checker supplies a semantic verdict.

Seven additional source-to-unit tests inspect exact selected operations and resource transitions:
field result staging before sibling cleanup, aggregate/component Copy, no duplicate destruction
after partial drop, both replacement cleanup alternatives after a branch, record-header cache
invalidation, exact outside-update field paths, and a 64-level shared schema. The last test selects
one deepest field with one typed place and 65 intact sibling disposals/container ends, without
expanding the exponentially larger conceptual payload tree.

Four construction integration tests inspect authored field mapping versus completed declaration-
order cleanup, reverse production-order cleanup on an early return without assembly, nested
obligation transfers without duplicate destruction, and a scalar snapshot before a later update.
The source corpus additionally covers conditional construction and return/break/continue paths,
read supply of a fresh record, and invalid/reused components. A focused ledger test rejects missing,
duplicate, wrong-owner and already-consumed component selections without changing any owner or
publishing a partial step, then validates complete assembly.

Six computed-selection integration tests inspect single evaluation and result staging before
sibling cleanup, preserved complete scalar/nominal Copy sources, read-temporary and source-remainder
cleanup order, interrupted known types without selected resources, exact unknown-field/type
messages and source focus, and another 64-level shared schema. That last test freezes one computed
path and emits only 65 sibling disposals/container ends; it does not expand the conceptual tree.
The production corpus also rejects computed aliases/updates, grouped read-alias extraction,
unknown fields on interrupted sources, wrong known-result annotations and reuse of consumed
inputs. It accepts call, structural, conditional and grouped roots through ordinary value supply.

## Remaining Work

This fragment constructs records, receives them through inputs, selects fields from existing
places and computed values, and manipulates or returns their values. Indexing, generic/interface/
callable and dependency-bearing payloads, user destructors, outcomes, async, public modules, target
layout and executable/native realization remain separate. The next bounded task is monomorphic
callable contracts and exact noncapturing callable schemas before captured environments and
retained-state obligations are admitted; the handoff owns its concrete work order.

There is no CLI language switch, released-program conversion, native result or speedup claim.
The handoff owns the next concrete work; crate READMEs and the
[cross-stage boundary](../../architecture/pipeline/value-access-declarations.md) own current
implementation contracts rather than this review.
