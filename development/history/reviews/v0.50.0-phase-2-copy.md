# v0.50.0 Phase 2 Identity-safe Copy Review

Date: 2026-09-14

## Result

The canonical and explicitly blocking filesystem surfaces now copy a complete byte stream with
bounded memory. Both open the source and destination first, compare the identities of those exact
descriptors, and truncate only after proving that the endpoints are different files. Same-path,
symbolic-link, and hard-link aliases therefore fail without destroying the source bytes.

## Authority Review

- `DarwinFileOperation::Identity` is the sole asynchronous operation identity. Its closed job
  contract requires a live file owner, no path operand, worker-owned target storage, and a portable
  device-and-inode result.
- `DarwinFileAccess::CopyDestination` is distinct from create-and-truncate. The generated worker
  owns its target open flags, while standard source selects only the semantic access role.
- The generated worker decodes Darwin `stat` storage before publishing two integer facts. Standard
  source cannot inspect a target record or reconstruct an inode offset.
- `std/io` owns descriptor identity observation and the shared equality predicate. `std/fs` owns
  only the copy policy: open, compare, truncate, and delegate transfer to the existing `io.copy`
  algorithm.
- The blocking twin performs the same descriptor-based decision without driving an executor. It
  uses the same public error mapping and the same generic byte-copy implementation.
- `DarwinSystemCall::ALL` closes the compiler-owned syscall-number set. The uniqueness check can no
  longer silently omit a newly added filesystem call.

## Failure and Ownership Review

Destination creation is observable before identity checking when the destination did not exist,
but no existing contents are truncated before the check. After successful identity validation,
copy is deliberately non-transactional: a later source or destination failure may leave a
truncated partial destination. The public contract states that behavior and does not imply flush.

The asynchronous identity job moves the file owner into the bounded worker and restores it from
completion before mapping success or failure. Cancellation and abandonment use the existing
retirement authority; no caller pointer or path spelling survives submission. Every ordinary file
open now requests close-on-exec, preventing a live library descriptor from leaking through a
successful process replacement.

## Verification

Focused verification covers the closed runtime schemas, primitive registry, generated ARM64
operation family, host conformance, complete native asynchronous copy with a symbolic-link
self-alias, complete native blocking copy with direct self-copy, unchanged source bytes after
rejection, authored standard-source checking, and semantic-editor hover over the public contract.
