# v0.60.0 Phase 4 Transport-composition Review

**Result: complete with no open Phase 4 finding (2026-09-19).** Blocking and asynchronous gzip
readers and tar event drivers now compose through the existing byte-reader interfaces while format
decisions remain in one cursor per representation.

## Authority Review

- `GzipDecoder` remains the sole gzip framing, integrity, member, and DEFLATE authority.
- `GzipCursor` owns only buffered input position, transport EOF, terminal projection, and the rule
  that initialized output precedes a late format error.
- `TarReader` remains the sole ustar header, entry, body, padding, and path authority.
- `TarCursor` owns only source fragments, caller-output projection, and outer-source completion.
- Blocking and asynchronous files perform their respective refill operation and consume the same
  cursor attempt. Neither branches on gzip flags, DEFLATE symbols, tar headers, or entry kinds.
- Read-count validation remains owned by `std/io`; CRC-32 remains owned by `std/checksum`.

The tar transport API accepts its reader on each operation instead of storing a concrete or
borrowed transport. This keeps one `TarStream` usable with either standard reader contract and
prevents archive storage from acquiring source ownership, deadline, or cancellation policy.

## Correctness Findings Closed During Implementation

The first composition returned archive completion immediately after the second zero block. That
could leave a gzip trailer unread and therefore report success before CRC-32 and size validation.
The final cursor records the in-band tar end separately, discards any remaining tar transport
bytes, and publishes `finished` only after the supplied reader reaches EOF. A damaged outer trailer
is now observed after every valid inner entry and body byte instead of being hidden by the archive
marker.

An owning generic tar wrapper also made the archive representation depend on moving a potentially
large nested decoder owner. The final API retains only archive state and receives a reader borrow
per operation. This is a smaller contract, preserves transport replacement, and lets timeout
adapters compose without another wrapper or deadline field.

## Progress and Failure Review

- Both adapters allocate one reusable bounded input vector at construction; zero capacity becomes
  one byte.
- Decoder input and caller output are never retained across calls.
- Async cursor state changes only after an awaited source refill succeeds.
- Source errors and invalid read counts are returned by their owning I/O boundary.
- Gzip data invalidity is distinct from an impossible decoder-progress report.
- A late gzip trailer failure is deferred only when the same call initialized output, preserving
  the standard reader contract without losing bytes.
- Terminal success and failure are sticky, and empty caller output cannot consume body data.

## Evidence

Native sessions compose one-byte blocking and asynchronous sources through gzip and tar with
one-byte decoder and body buffers. They assert identical metadata and body bytes, repeated gzip
EOF, deferred trailer failure, invalid source counts, and rejection of a damaged outer trailer
after the complete inner tar body has been observed. The raw incremental gzip and tar sessions
continue to pass independently.

`cargo fmt --all -- --check`, `git diff --check`, the current standard-library checker, the focused
native sessions, and the out-of-tree documentation build form the Phase 4 gate.
