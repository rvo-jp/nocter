# v0.65.0 Phase 6 Practical Stateful-service Review

**Result: complete with no open Phase 6 finding (2026-09-21).** The complete service exercises the
v0.65.0 stack through installed standard-library contracts, and the final review found one owner
for each shared-storage, readiness, application-data, routing, session, logging, and lifecycle
decision. Exact release inputs remain a separate release-preparation boundary.

## End-to-End Path

The HTTP service creates one `Router<ServiceState>`. Its state owns the request timeout, session
cookie policy, and `Mutex<Vec<Event>>`; the router lends that exact state to a selected handler
without a global registry or hidden clone. Concurrent clients cross the server admission bound and
task group. The user route decodes a path parameter and query value, accepts or issues a session,
records one event with a redacted session field, and returns the session through the explicit HTTP
cookie policy. Shutdown stops admission, observes every retained handler, recovers the router
state, projects the retained event through `std/log` and `std/json`, and verifies both the event
shape and absence of the bearer spelling.

This is an application composition test rather than a second implementation of any participating
policy. The example does not own a session parser, event renderer, route matcher, wakeup loop, or
service scheduler.

Process pipes and synchronization notifications remain distinct descriptor owners over the common
Darwin descriptor adapter. They do not import each other's representation. The compiler has no
recognized name for mutexes, channels, cancellation, sessions, routing, or logging.

## Corrected Findings

The synchronization guide promised that immediate operations allocate only during construction,
but sender and receiver cloning, non-waiting channel operations, cancellation mutation and
inspection, and `ServiceScope.stop` did not expose checked `noalloc` contracts. The missing
contracts were not merely presentation defects. `SharedWrite<T>` retained an additional
`SharedCell<T>` owner, so destroying a write projection could be the last-owner path for an
arbitrary `T`. The projection now stores only the header and value pointers and is bounded by the
borrow provenance of `SharedCell.try_write`. Its destructor can only release the lock and is
therefore structurally `noalloc`. A negative semantic test proves that an owner cannot move while
the derived mutex guard remains live.

Notification signaling previously acquired a write projection solely to reach the write
descriptor. `NotificationHandle` now caches both descriptor identities while its shared
`Notification` owner keeps them live. Signaling uses the cached descriptor and the one Darwin retry
policy without acquiring coordination state. This removes an unnecessary dependency on exclusive
projection and makes best-effort signaling truthfully `noalloc`; notification bytes remain hints,
and every consumer still rechecks its semantic state after waking.

The channel used unchecked arithmetic for cloned endpoint counts although shared owner counts
already failed closed on overflow. Both counters now use the same checked arithmetic authority and
abort on an impossible representation overflow. The test-only public owner-count accessor was
removed: tests now observe ownership through clone, exclusion, mutation, and final behavior rather
than exposing an internal counter as a second contract.

The complete service initially asserted only the number of retained events. It now performs the
observable operation for which the event exists: structured JSON projection. The final check proves
the expected event name and redacted value are present and that the incoming bearer spelling is
absent.

The Phase 5 wall-clock correction also exposed a backend-wide ABI invariant. A Darwin kernel
syscall emitter must initialize every argument in the compiler-owned kernel ABI, including output
pointers omitted by a public C wrapper; ambient register values can never become accidental kernel
arguments. The backend documentation now records this contract explicitly.

The full parallel native suite exposed a host-load assumption in the existing process-termination
test. It slept for one second and then sent a signal, so a delayed child could receive the default
disposition before installing its kqueue source. The launcher now inherits a harmless disposition,
publishes its own readiness before `exec`, and delivers the signal repeatedly within a finite
deadline until the Nocter process exits. The test therefore synchronizes through observable state
and no longer treats elapsed host time as proof of runtime initialization.

## Structural Review

Source inspection found no duplicate shared allocator, owner counter, notification pipe, polling
wait, HTTP percent decoder, route selector, session representation, redaction renderer, logger
registry, or process-global service state in the milestone scope. Standard-library dependency
validation records the channel's checked-arithmetic edge explicitly. No compiler primitive or
lowering branch identifies the new public types by spelling.

The important lifetime boundary is mechanical rather than conventional. `SharedWrite<T>` cannot
keep a mapping alive itself and therefore cannot outlive the `SharedCell<T>` from which it was
projected. The declared `from self` provenance is checked at an application boundary; moving the
mutex owner while its guard remains usable is rejected with `E0397`. Callers do not have to know
the pointer layout or remember a release precondition.

## Evidence

Focused semantic tests accept the public `noalloc` contracts and reject a mutex owner move while a
guard remains live. A native integration test crosses two-slot backpressure with three FIFO values,
final sender closure, two serialized mutex mutations, and cancellation caused by source
destruction. The installed-standard-library example suite runs the complete HTTP service, including
loopback clients, structured event projection, redaction, graceful shutdown, and final state
recovery. The complete compiler, editor, native, standard-library, documentation, example,
formatting, and repository-integrity gates pass.

## Conclusion

Phase 6 closes one vertical service foundation rather than appending isolated APIs. Responsibilities
consume only the contracts below them: synchronization does not know executor queues, HTTP does not
know shared-memory layout, sessions do not know cookie syntax, logging does not discover request or
process context, and the example does not reimplement their decisions. Release preparation can now
freeze and qualify exact v0.65.0 inputs without another implementation phase.
