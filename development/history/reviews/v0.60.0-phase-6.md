# v0.60.0 Phase 6 Editor, Authority, and Qualification Review

## Scope

This review closes the streaming-compression and safe-archive milestone. It covers the raw DEFLATE
engine, gzip framing and integrity, POSIX ustar observation, blocking and asynchronous transport
composition, the bounded `archive-inspect` application, editor projection, the reviewed standard
dependency graph, and whole-repository qualification.

## Findings and Resolution

### The reviewed dependency graph omitted transport-composition edges

The whole-workspace gate rejected `archive -> io`, `archive -> vec`, `compress -> io`, and
`compress -> vec` as unexpected. All four are intentional Phase 4 edges. Compression and archive
format state remain transport-independent; their public adapters implement the existing reader
contracts and retain bounded reusable input in ordinary vectors. The exact dependency audit now
names those edges. It remains a closed equality check, so neither a new hidden dependency nor a
stale reviewed edge can pass silently.

### Command test output classification repeated one identical branch

Warnings-denied Clippy found that `async.nct` used a separate empty-output match arm beside two
other examples with the same result. The cases now share one arm. No lint allowance, output
special case, or production wrapper was added.

### Archive editor behavior needed an application-level contract

Unit and native tests proved execution but did not show that one checked application generation
projected both compression and archive APIs across editor features. The language-server scenario
now opens the real `archive-inspect` package. Hover presents the specialized gzip and tar
contracts, definition selects each public `index.nct`, implementation selects the corresponding
transport source, completion uses checked `TarStream` members, semantic tokens cover the policy,
source, and application files, and inlay hints use retained checked body types. The server has no
archive-specific query or source-text fallback.

## Authority Review

`std/internal/deflate` is the sole LSB-first reservoir and canonical Huffman-table authority.
`std/compress` owns raw decoder state, the 32 KiB history ring, gzip member framing, and format
progress. Gzip integrity delegates every CRC-32 transition to `std/checksum`; the POSIX tar header
sum remains an archive-format field and does not duplicate CRC behavior.

`std/archive` alone parses tar headers, tracks bodies and padding, interprets entry kinds, and
normalizes bounded relative paths. The application consumes that normalized path and owns only
resource limits, duplicate rejection, accepted kinds, retained report metadata, and delayed public
output. It neither reparses headers nor repeats path normalization.

One gzip cursor and one tar cursor classify format progress independently of transport. Blocking
and asynchronous adapters differ only in how they request input; both commit a validated count
into the same cursor after a completed read. Deadlines, cancellation, files, and sockets remain in
their existing I/O owners. `LimitedSource` is application policy for accepted compressed bytes,
not another gzip or transport interpretation.

Search and call-site review found no second bit reader, Huffman builder, checksum transition,
archive-header parser, path-normalization decision, full-entry buffer, external `gzip` or `tar`
process, or transport-specific decoder. Downstream responsibilities consume public progress and
reader contracts rather than inspecting another layer's representation.
