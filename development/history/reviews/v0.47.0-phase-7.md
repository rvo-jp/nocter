# v0.47.0 Phase 7 Source Snapshot Identity Closure

## Scope

This review covers source ingestion, reusable parsing, source-backed syntax helpers, package
decoding, target selection, compile-input construction, declaration lowering, constant planning,
and checking. It asks whether stale or independently created source and syntax values can compare
equal through a reused local index, whether an API depends on its caller to pair those values
correctly, and whether any later stage silently repeats target selection to repair inconsistent
input.

## Root Finding

`SourceId` previously contained only a zero-based `u32` map index. Two independent `SourceMap`
values therefore both issued `SourceId(0)`. A syntax tree from one compiler generation could pass
the source check of another map whose first entry had unrelated bytes. `NodeId` similarly contained
only that source ID and a node-arena index, so independent parses of the same source could lend nodes
to each other.

Most production CLI and LSP paths happened to remain coherent because reusable parsing compared
exact normalized text before rebinding. The public and cross-crate contracts did not encode that
fact. Literal decoders, package decoding, declaration projection, constant planning, target
selection, and alternate compile-input construction accepted pieces separately and therefore
relied on callers to preserve an undocumented generation invariant.

The stronger IDs then exposed a second concrete defect: package resolution already retained each
root source and its syntax tree, but discovery parsed that root again when it became a module
source. The two trees shared bytes and a source ID but had independent node arenas. Later semantic
projection worked only because the old `NodeId` treated equal local indexes as equal. Discovery now
selects the sole retained tree and rejects a missing or duplicate retained tree as an inconsistent
snapshot. It performs no second parse.

## Identity Model

`SourceId` now packs a local source index and an opaque process-unique issuance identity into one
64-bit value. A map lookup validates the complete identity. Independent identity domains cannot
alias. Compiler computation owns one `SourceIdentityDomain` and carries it on its unforgeable
source-revision token into package resolution. Maps in that revision family reuse a complete ID
only while the physical name and normalized text remain unchanged. Any content transition issues a
new identity, including a later restoration of earlier text.

The distinction is required by the query model. A document-version-only transition is allowed to
reuse source-backed semantic results, so issuing unrelated IDs for equal current source values
would pair reused semantics with an unresolvable current map. Conversely, restoring earlier bytes
must not revive their old source projection. The exact-current query fingerprint therefore includes
the complete process-local source IDs as well as paths and bytes. This preserves metadata-only reuse
and invalidates every source-backed branch across a content transition. The syntax provider remains
responsible only for syntax; it does not own or expose the identity domain.

Every independently built syntax tree also receives an opaque identity. `NodeId` packs that tree
identity and its node index beside the source ID, retaining the previous two-word size on 64-bit
targets. Cloning or rebinding the same immutable parse product preserves tree identity; parsing the
same source independently creates another identity. `SyntaxTree::node` and other ownership checks
therefore reject foreign nodes instead of interpreting their coincident index.

Opaque issuance fields are excluded from `Debug`, `Display`, diagnostics, and canonical semantic
surfaces. `SourceId` ordering uses the current map index before its opaque foreign-value
tiebreaker, so integrity cannot make semantic ordering depend on process allocation history. The
identity-domain debug view is also opaque and cannot disclose the retained source corpus.
Workspace equivalence tests compare diagnostics through their observable path, range, code,
message, notes, help, and repair projection. They do not equate the internal source and node
authorities issued by independent compiler owners.

## Contract Changes

`nocter-syntax` now publishes `BoundSyntax`, the sole proof that a `SourceFile` and `SyntaxTree`
describe the same exact source identity. Source-backed string decoding and declaration projection
accept that proof. Package decoding and constant planning carry it across their public boundary;
their consumers convert construction failure to their existing typed integrity errors.

`TargetSelection` owns the selected compilation target and the exact multiset of syntax root IDs.
Its activity maps retain complete `NodeId` keys rather than reducing them to source-and-index pairs.
Activity queries also reject membership in a reparsed or foreign tree by treating the node as
inactive; they no longer assume that every caller has already selected the node's tree.
`CompileUnitInput` validates the target, syntax roots, and membership of every tree in its exact
source map once while constructing its immutable owned form, then exposes the stored decision
without another traversal. A selection also rejects duplicate trees for one physical source.
Declaration-lowering
resolution maps likewise retain complete nodes. The unused
`from_target_selection` constructor and the target-mutating `with_target` rebuilding path were
removed, leaving one supplied-selection model.

The discovery boundary consumes package resolution's retained source/syntax pair directly. A
package root therefore has one syntax authority from declaration decoding through module discovery,
and the source-syntax provider is invoked only for sources not already present in that graph.

## Adversarial Evidence

Regression tests prove that:

- independent identity domains issue unequal IDs at the same local index and reject each other's
  lookups;
- maps in one revision family retain IDs for unchanged values, replace IDs after a content change,
  and do not resurrect an earlier ID when text is restored;
- independent revision domains do not alias even for equal source names and bytes;
- independently parsed trees for one source reject each other's node IDs, while a tree clone keeps
  the original identity;
- `BoundSyntax` rejects a source and tree from independent maps;
- target selection rejects an independent source map and does not match a reparsed tree for the
  same source;
- activity selected from one parse cannot activate a node from another parse;
- compile input rejects a selection created from another source generation.
- compile input rejects a selection and syntax tree that agree with each other but belong to a
  foreign source map;
- source ordering remains current-map order when reused identities were issued in another order;
- identity-domain debug output does not expose admitted paths or source text;
- discovery performs one parse for a package root and preserves that exact root `NodeId` in the
  discovered unit.
- unchanged LSP diagnostics and rename edits resolve against the current document version without
  losing source identity;
- an edit followed by restoration of the original invalid text publishes a new current diagnostic
  rather than reusing its stale source projection.
- incremental and fresh compiler owners produce equal observable diagnostics without requiring
  their process-local source or tree authorities to alias.

The focused source, syntax, target-selection, compile-input, declaration-lowering, discovery, and
language-server suites pass. The complete release-verification workflow also passes in a disposable
target directory: repository metadata and performance helpers, Unicode mutation and reproducibility
checks, fresh all-workspace Clippy with warnings denied, every workspace and all-target test,
the no-default-features build, and rustdoc with warnings denied.

## Review Conclusion

No production source-backed semantic decoder found in the reviewed area still accepts an
independent source/tree pair. No target-selection or declaration-resolution key found in the
semantic path discards the syntax-tree identity. Remaining source/index tuples are deterministic
ordering or source-neutral serialization projections; they do not recover ownership or semantic
selection.

Low-level tree navigation continues to accept a tree and node because both belong to the syntax
responsibility, but the tree now detects a foreign node identity. Cross-responsibility APIs use
proved bindings or typed validation instead of assuming correct caller pairing.
