# v0.67.0 Phase 2 Indexed Store-state Review

**Result: complete with no open Phase 2 finding (2026-09-23).** Store lookup and traversal now use
one retained representation without making hash placement persistent or observable.

## Authority Review

`StoreState` exclusively owns retained entries, insertion order, reusable slots, and the transient
index. The index owns only seeded hash probing and hash-to-slot candidate membership. It cannot
read keys, decide equality, determine persistence order, or encode storage. Exact byte equality is
confirmed by `StoreState`, and snapshot encoding walks the same insertion-order chain exposed by
the public lending cursor.

Snapshot recovery constructs `StoreState` once. Duplicate-key rejection is an ordinary failed
insertion into that state, so recovery does not build a temporary map, discard it, and later
reconstruct lookup authority. Ordinary get, set, replace, remove, iteration, commit, and compaction
do not scan all retained entries or rebuild the index.

The index reports duplicate or missing slot membership instead of silently accepting an invalid
caller transition. `StoreState` converts those impossible transitions to the standard invariant
abort. This keeps structural invariants inside the owning implementation rather than relying on
every caller to preserve undocumented index rules.

## Observable Contract

`Store.entries()` returns a lending cursor in deterministic insertion order. Each item borrows its
key and value directly from the retained state; no entry bytes are copied and advancing the cursor
requires the previous yield to be dead. Removal followed by insertion reuses storage while placing
the new entry at the logical tail. The durable snapshot remains byte-for-byte independent of the
randomized index layout.

## Qualification

The standard Store tests execute through native compilation and cover snapshot recovery, duplicate
keys, indexed replacement and removal, slot reuse, insertion-order traversal, equal-hash candidate
membership, and tombstone reuse. The complete durable Store application test covers public lending
traversal before commit and after recovery, removal, replacement, and slot reuse. Formatting,
workspace tests, documentation generation, and repository checks complete the phase gate.
