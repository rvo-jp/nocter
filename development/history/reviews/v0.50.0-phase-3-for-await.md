# v0.50.0 Phase 3 `for await` Review

Date: 2026-09-14

## Result

Phase 3 is complete. Nocter now consumes the compiler-selected `AsyncIterator` contract through a
first-class `for await` statement. The implementation does not preserve a compatibility lowering
to a spelled `next` call and does not create a second async runtime protocol.

## Authority Boundaries

- Syntax records `ForAwaitStatement` separately from synchronous collection and range iteration.
  The asynchronous grammar therefore cannot be reinterpreted as a range, argument pack, or
  expansion loop later.
- Body checking owns source consumption, exact interface-method selection, associated `Item`
  resolution, result-shape validation, and the enclosing failure-propagation plan.
- `TypedIterationStep` is the one common acquisition/dispatch/item contract shared by synchronous
  and asynchronous iteration. `TypedAsyncIteration` adds only the checked outer failure layers.
- Target dependency discovery records that frozen selection. MIR accepts the checked step and
  never queries the standard library or performs method lookup.
- MIR's asynchronous loop module owns control-flow construction but delegates future suspension,
  fallible ABI projection, optional payload binding, cleanup, and destruction to their existing
  authorities.

## Ownership and Cancellation

The source is evaluated once and owned by the loop. Every header creates the checked readwrite
receiver, invokes one deferred step, suspends, propagates failure, and distinguishes a present item
from exhaustion. A move-only named source still requires explicit `move`; async iteration has no
expansion fallback.

Review added an explicit cancellation-order assertion and exposed one real boundary error: the
loop-owned iterator exists before entry into the body scope, so ordinary scope transfer cleanup did
not yet classify it as an inner lifetime. The corrected loop-header transfer contract consumes that
iterator first, then applies the existing outer transfer cleanup. MIR cancellation consequently
releases the pending child future before destroying the iterator and remaining parent state.
Checked suspension storage also retains the iterator's materialized address while the child holds
its mutable receiver.

## Tooling and Validation

The formatter preserves and canonicalizes `for await`. LSP validation covers complete semantic
analysis, loop-binding hover, lexical completion, definition navigation, and semantic tokens. The
native filesystem test now traverses `WalkDir` through `for await`, proving parser through ARM64
execution over the installed standard library.

Validation completed with:

- full compiler workspace tests, including network-enabled integration tests;
- all 543 `nocter-checking` library tests;
- focused syntax, formatter, MIR, LSP, and native `WalkDir` tests;
- workspace `cargo clippy --all-targets -- -D warnings`;
- `cargo fmt --check` and `git diff --check`;
- deterministic documentation generation and publication-boundary tests.

No remaining Phase 3 defect was found. Phase 4 may build bounded streaming adapters on this single
checked iteration and suspension contract.
