# v0.68.0 Phase 4 Native Workload Review

**Result: complete with no open Phase 4 finding (2026-09-24).** The optimized Machine product was
exercised through seven complete compiler-produced ARM64 applications. The comparison observed
ordinary installed compilers and native processes; no benchmark-only compiler, standard-library,
or execution path exists.

## Measurement Authority

[`native-run.js`](../../benchmarks/native-run.js) builds every workload through `nocter build`,
records the executable byte length and SHA-256 identity, alternates compiler order, validates every
observable result after timing, and retains each measured round and order position. Its deterministic
inputs record exact byte lengths and digests. The existing installed-home identity authority records
the compiler, manifest, and standard-library tree; benchmark code cannot call a private compiler
crate or inspect Machine internals.

The retained comparison used two warmups and seven samples per compiler and workload on macOS
25.6.0, Apple M1 ARM64, 8 logical CPUs, 8 GiB memory, and Node.js 20.10.0. Repository commit
`0009b826ac107ee957de2840d83fba711b365e27` was clean. The published v0.67.0 compiler digest was
`4771263ed39549a5207ec4fda35831529775bca1e653511bb35f9dce6f5e1812`; the candidate digest was
`0f41bea09599bb973dc8d40b79cde9f8699b73357fd809e2c2b41f4b07bb745d`. Both installed homes used
standard-library tree `52090bf785b060a3fd59ae974c46a14692274d2ead5aed2e0ffe3b7a8c89759d`.

Release metadata intentionally remained at v0.67.0 during pre-release measurement. The candidate
label, repository identity, compiler digest, and distinct manifest digest identify the measured
compiler without prematurely changing v0.68.0 release metadata.

## Results

Negative deltas are improvements. Runtime values are the median wall-clock milliseconds from seven
alternating samples.

| Workload | v0.67.0 bytes | Candidate bytes | Size delta | v0.67.0 ms | Candidate ms | Runtime delta |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| line frequency | 181,760 | 181,760 | 0.00% | 226.408 | 211.627 | -6.53% |
| JSON normalization | 313,856 | 297,344 | -5.26% | 576.381 | 535.638 | -7.07% |
| archive inspection | 2,410,880 | 2,262,272 | -6.16% | 14.322 | 12.484 | -12.83% |
| binary record | 215,040 | 215,040 | 0.00% | 3.231 | 2.983 | -7.68% |
| subprocess pipeline | 198,400 | 198,400 | 0.00% | 147.913 | 147.294 | -0.42% |
| async HTTP | 745,312 | 712,288 | -4.43% | 7.885 | 7.347 | -6.82% |
| HTTP service | 1,801,488 | 1,735,440 | -3.67% | 1,042.540 | 1,040.648 | -0.18% |

The compute-, collection-, parsing-, and compression-heavy cases improved by 6.53–12.83% at the
median. Three programs retained the same aligned image size; four fell by 3.67–6.16%. Process and
service workloads remained effectively flat because child-process or fixed timeout/service work
dominates their runtime. No measured median or executable size regressed.

## Coverage and Conclusion

The matrix covers synchronous and recoverable execution, allocation, Map/Set use, JSON and binary
parsing, gzip/tar decompression, blocking and asynchronous filesystem I/O, process pipelines,
timeouts and cancellation, loopback networking, HTTP streaming, durable state, and structured
service shutdown. The complete compiler library gate independently passed, including 118 LSP tests
and 126 native-session tests. Correctness therefore does not depend on the benchmark validator.

The evidence does not justify another target-specific optimization in Phase 4. Remaining flat
workloads are dominated by external I/O or deliberate waits, while the workloads affected by
generated computation already show material improvement. Phase 5 can review authority boundaries,
determinism, and release qualification without introducing benchmark-driven production behavior.
