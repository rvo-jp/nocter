# v0.71.0 Guaranteed Structural-operation Review

**Result: complete with no open implementation finding (2026-09-25).** Generic equality,
ordering, indexing, borrow coercion, and expansion now retain authored `noalloc notrap` guarantees
through one structural-requirement model. Concrete selection proves those requirements, while a
generic body consumes the frozen capability evidence without repeating selection or inspecting
source text.

## Authority Review

The review traced each guarantee through its complete ownership chain:

- `nocter-language` owns the shared callable-modifier vocabulary and the structural grammar's
  admitted subset;
- syntax preserves admitted modifier nodes without assigning semantic meaning;
- declaration lowering projects declaration and predicate modifiers through one
  `project_callable_guarantees` function;
- `CallableGuarantees` owns guarantee identity, independent requirement composition, and the sole
  directional weakening relation;
- requirement normalization combines duplicate predicates before capability selection, so source
  order cannot decide which guarantee survives;
- capability evidence retains the normalized predicate selected for a generic body;
- checked execution reads structural guarantees directly from that evidence instead of
  redispatching; and
- concrete dispatch resolves the eventual implementation once for specialization and verifies the
  selected operation and every implicit coercion against the same requested contract.

Formatter, completion, hover, and diagnostics consume syntax identities or normalized semantic
contracts. No semantic consumer recognizes guarantee spelling in source text, reconstructs a
structural contract from presentation output, or lets a target backend infer a missing guarantee.

## Closed Findings

Three concrete defects were found and closed during qualification:

- owned-receiver selection treated physical storage ownership as the ability to supply an owned
  value. A copyable field reached through a borrow could therefore not call a value-receiver method.
  Selection and materialization now share the explicit `can_supply_owned` fact: copyable borrowed
  places produce a checked copy, while move-only borrowed places remain rejected;
- removal of obsolete `std/internal/mem` capacity helpers left stale dependency-review edges. The
  review graph now describes the actual standard-library imports; and
- the native recoverable-allocation inventory still expected the pre-checked-arithmetic test count.
  Its explicit count now includes the four numeric regression cases.

The receiver correction is not a checked-arithmetic exception. It repairs the general method
contract used by checking, interruption recovery, and member completion, and its regression tests
cover both the newly valid copyable case and the still-invalid move-only case.

## Standard-library Foundation

All ten built-in integer types expose `noalloc notrap` checked addition, subtraction, and
multiplication. `u64` and `i64` own the arithmetic implementations; narrower and target-width types
widen, call those authorities, validate their destination range, and narrow. Standard-library
capacity, offset, duration, codec, collection, process, storage, and text code use those type-owned
operations instead of maintaining a package-private arithmetic layer.

`String` and `Vec` borrow coercions and borrowed `Vec` expansion publish structural guarantees only
where their complete primitive path proves them. Bounds-checked indexing remains potentially
trapping, and no wrapper is trusted merely because its body currently appears simple.

## Deliberate Limits

The structural grammar does not admit `const`, `blocking`, or `async`: these predicates describe
an immediate implicit operation, not a declaration body, a permission to wait, or future driving.
`notrap async`, value-sensitive overflow proofs, unchecked indexing, and a composite `realtime`
profile remain outside this milestone. An unqualified requirement remains weaker even when one
particular implementation happens to prove stronger facts.

## Qualification

The fast compiler gate passed from a disposable target, covering repository metadata, performance
helpers, pinned Unicode reproduction and mutation checks, formatting, warnings-denied Clippy, and
all fast-tier workspace tests. The slow suites then passed against the same source boundary: 38 CLI
tests, 62 command tests including the loopback-network public examples, 126 native-session tests,
and 118 language-server tests. No-default-features workspace checking and warnings-denied Rust
documentation also passed.

Documentation generation remains deterministic and writes outside the repository. Deterministic
archive assembly and installed-artifact qualification are intentionally not claimed here: they
require the final release identity and clean release-content commit and therefore belong to the
separate release-preparation record.
