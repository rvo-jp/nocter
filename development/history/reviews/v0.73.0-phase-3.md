# v0.73.0 Phase 3 Review: Borrowed Range Construction

**Result: complete with no open finding (2026-09-30).** Borrowed slice and UTF-8 range operations
now publish `notrap` only after complete source bodies pass checking and their narrow representation
primitives agree with compiler-owned runtime facts.

## Contract Boundary

The implementation has three explicit layers:

1. ordinary source validates ordering, source length, and UTF-8 scalar boundaries;
2. recoverable checked arithmetic derives byte offsets without admitting integer wrap; and
3. package-private primitive roles project already validated storage into a borrowed view.

The primitive runtime profile is the sole authority for execution facts. `pointee_size`, borrowed
UTF-8 byte projection, and string subview projection were already classified as allocation-free,
nonblocking, and free of source traps by that exhaustive profile. Their source declarations now
publish the matching `notrap` guarantee, and target-program contract validation rejects any future
primitive declaration that claims stronger facts than its role owns.

No public raw-address operation was introduced. Raw view constructors remain package-private, and
the public result retains the source view's provenance.

## Slice Range Proof

`[T].get_range` checks `start <= end` and `end <= self.len()` as separate exits. The first surviving
path proves `end - start`; the subtraction is evaluated before entering a raw-pointer call. This
ordering is a contract boundary rather than an optimizer hint: a raw pointer is an opaque alias
carrier, so the place-sensitive flow model intentionally discards relational facts when it crosses
such a call.

Element-byte multiplication and base-address addition use `checked_mul` and `checked_add`.
Unrepresentable address arithmetic therefore returns `none` instead of relying on a target wrap or
a backend proof. The target receives an ordinary already-checked primitive call and does not repeat
the source range decision.

## Text Range Proof

`str.is_char_boundary` now handles `index >= len` in one guard. The continuing path has the exact
strict length relation required by byte indexing. The zero boundary remains a direct success, and
all other in-range positions inspect only a proven byte.

`str.get_range` first proves bound order, then validates both UTF-8 boundaries, then forms the
subview through the one private primitive boundary. `str.bytes`, `is_char_boundary`, and
`get_range` expose matching `noalloc notrap` declarations and implementations.

  — passed with every physical standard body checked through target selection.
- `cargo test -p nocter-native-session standard_str_contract_crosses_native_tests --quiet` — passed
  13 native cases, including full UTF-8 ranges, rejected split encodings, terminal empty slice
  ranges, and reversed slice bounds.
- `cargo test -p nocter-checking --lib --quiet` — 633 tests passed.
- `cargo clippy -p nocter-checking -p nocter-native-session --all-targets -- -D warnings` — passed.
- `node development/site/test-generation.js` and an external documentation build — passed and
  generated 374 pages.
- `cargo fmt --all -- --check` and `git diff --check` — passed.

The first complete check also confirmed that relational facts are not silently retained across an
opaque raw-pointer call. Range length is deliberately materialized before that boundary; weakening
alias invalidation to make this body pass would have made unrelated mutable-pointer calls unsound.

## Remaining Work

Phase 4 can now adopt the same proof boundary in iterators, scanners, and other borrowed observers.
Generic comparison-based traversal remains qualified only when its selected operation contracts
also publish the required guarantees.
