# v0.49.0 Phase 4 Generic Transfer and Child Lifecycle Review

**Result: complete with no open Phase 4 defect.** Generic transfer now composes ordinary byte
interfaces across both execution surfaces, while child observation and termination extend the
single Phase 2 owner instead of creating another PID, polling, or cleanup authority.

## Findings Closed During Implementation

### Terminal observation needed durable ownership state

A nonwaiting `wait4` can reap the child before the public `Child` is consumed. Treating that result
as a transient return value would make repeated observation and later wait attempt to reap the same
PID again. The private owner now stores one closed state tag and terminal value. Every observation
path reads that record first, and only the transition from pending may call the target observer.
Destruction transfers abandonment only from the pending state.

### Termination must not imply observation

Graceful and forced termination now request target actions without consuming the child or changing
its reaping state. `ESRCH` means the request no longer has a live target, but it does not prove that
this owner has reaped its exact child. Wait or destruction therefore remains mandatory ownership
policy. Signal numbers and the Darwin syscall stay in two exact ARM64 roles; standard source cannot
select an arbitrary signal or kernel operation.

### Generic copy needed one bounded policy, not process buffering

`io.copy` and `io.copy_blocking` depend only on the corresponding reader and writer contracts.
They share capacity, count validation, overflow policy, initialized-prefix projection, and
allocation behavior. The loops differ only where their interface calls differ: one awaits
executor-safe operations and the other admits blocking. Process endpoints remain ordinary
implementations and gain no process-specific copy or buffering state.

## Responsibility Review

- `std/io/transfer.nct` owns bounded generic transfer policy and no descriptor or process fact.
- each reader and writer owns its partial progress, failure, and cancellation semantics.
- `std/process/child_owner_darwin.nct` owns the sole exact-child PID, terminal cache, signal request,
  observation, and abandonment transition.
- public `Child` methods translate private wait outcomes to `ExitStatus` and never expose PID or
  target signal constants.
- runtime roles name closed termination meanings; the standard profile maps declarations; target
  validation owns signatures; ARM64 selection owns Darwin syscall and signal encoding.

No compiler stage recognizes `Child`, `ExitStatus`, or `io.copy`. No source caller must coordinate
two status records or remember to reap after a failed observation. No copy implementation reaches
inside a concrete stream.

## Evidence

- complete bundled-standard discovery, checking, target validation, and native materialization;
- generated blocking and asynchronous copies from a real child pipe into independent generic
  writers;
- a live child observed pending, gracefully terminated, observed and cached twice, then consumed
  by exact wait;
- a second live child forcibly terminated and observed as signal 9;
- runtime-role uniqueness, source-location, target-contract, ARM64 selection, standard-dependency,
  compiler, documentation, formatting, and repository gates.
