# v0.46.0 Phase 5 Asynchronous Datagram I/O Final Review

**Result: implementation and source-tree qualification complete with no open practical v0.46.0
finding (2026-09-11).** UDP now has one closed native-attempt vocabulary, one standard-source
progress policy, and separate blocking and suspending wait adapters beneath one public socket
owner.

## Authority and Dependency Audit

The final implementation has these single authorities:

1. The runtime primitive catalog owns the finite datagram roles and their allocation, blocking,
   and future-drive classifications. Neither source profiles nor backends infer effects from names.
2. The standard profile binds each role to one declaration identity and exact source location. It
   does not own syscall numbers, native flags, or adapter records.
3. Target-program construction validates complete role coverage and freezes the concrete callable
   signatures before Machine lowering. Later layers cannot repeat declaration selection.
4. ARM64 Darwin lowering owns the target syscall identities, fixed nonblocking flags, argument
   placement, and kernel carry/error normalization. Standard source cannot issue a generic syscall
   for a datagram attempt.
5. The private Darwin standard adapter owns socket-address records, message records, descriptor
   cleanup, and conversion between native results and the shared attempt vocabulary.
6. The provider-independent UDP layer owns interruption retry, readiness requests, deadline
   selection, normalized failures, source-address results, empty messages, and truncation. Blocking
   and async surfaces consume those results through different wait mechanisms without duplicating
   their meaning.
7. The task runtime and reactor remain the only suspension, readiness-registration, timeout, and
   cancellation authorities. A pending UDP computation owns only its exclusive socket borrow and
   logical wait; cancellation neither closes nor duplicates the descriptor.
8. Checked semantic products remain the sole editor authority. UDP hover, completion, signature
   help, navigation, tokens, and hints use the ordinary package query path and contain no protocol-
   or backend-specific inference.

The only generic syscall still reachable in the UDP implementation is the synchronous blocking
wait's `poll`. It is intentionally classified as blocking and is not reachable from an immediate
attempt or async wait. The separate sync and async loops repeat only orchestration required by
their different execution contracts; both delegate result interpretation and deadline creation to
the same policy operations.

## Findings Corrected During Review

The review and complete gate corrected four qualification defects:

- The native UDP test embedded a large source string in Rust, obscuring the tested program and
  exceeding the repository's test-body size rule. The program now lives in the compiler source-
  fixture tree and the native harness only supplies execution infrastructure.
- One language-server test combined every UDP feature assertion in a single oversized function.
  It now opens and analyzes the package once, then delegates navigation/call assertions and local
  source-feature assertions to narrow helpers. No second analysis or editor model was introduced.
- An existing HTTP backpressure test used a 20-millisecond whole-request deadline and assumed the
  timeout would occur specifically while writing the body. Under parallel load it could expire
  during connection or head transmission. Its loopback peer now explicitly reads and validates
  the request head, then stops consuming bytes for longer than a one-second request deadline. The
  observed failure phase is therefore fixture-owned rather than scheduler-dependent.
- Another HTTP timeout test sent an intentionally abandoned connection, head-timeout request,
  body-timeout request, and truncated response through one listener while assuming accept order.
  It also began 20-millisecond deadlines before its peer had observed the relevant request. The
  abandoned operation now has an independent endpoint, and each timeout starts with a one-second
  deadline whose peer delay begins only after the complete request head arrives. Connection
  scheduling can no longer select which HTTP phase the test observes.

The public async UDP example was also rewritten by the canonical Nocter formatter after the
runnable-example gate detected layout drift.

Searches across current source and documentation found no compatibility alias for the superseded
synchronous names, no second datagram error normalizer or timeout clock, no source-text primitive
inference, no UDP-specific editor path, and no native descriptor ownership exposed to public
standard declarations.
