# v2.0.0 Variadic Input Contracts

## Status and Ownership

Adopted on 2026-11-09 under the user's delegated v2.0.0 design/work authority. This review
records alternatives, consequences and future conformance obligations. The normative owner is
[Variadic Inputs and Argument Expansion](../../spec/language/variadic-inputs.md); the
[grammar](../../spec/language/syntactic-grammar.md#argument-expansion) owns recognition.
The private compiler and its 283 production corpus cases remain unchanged. No compiler,
executable, capture, evaluator, ABI or native qualification follows from this document.

## One Argument Sequence, No Implied Container Type

The preceding assembly draft allowed final ordinary/keyed packs but did not define what their
body binders meant. Converting every pack to an owned array would snapshot/move read arguments
and need a new allocation/backing contract. Converting it to a particular slice type would
silently select a capability API and contiguous range representation. Neither follows from
the declared per-input read/edit/take operations.

The selected binder denotes the supplied argument sequence. Read/edit entries may map to
scattered caller places; take entries own received components. Index/count/forward/capture use
that one checked entry map. They do not acquire ordinary bare-name value construction, a dynamic
`[T]` definition, whole-pack replacement or a generic parameter-pack mechanism.

A pack is one formal identity with entry/component paths. Invocation counts do not change
its callable type. Static specialization and physical gathering remain implementation choices
that must preserve those checked identities, effects and cleanup. A name-only pack header
also fixes the former optional-ellipsis grammar's unsupported repeated tuple/discard binder.
Tuple-valued elements remain available and can be decomposed normally inside the body.

```text
func forward(... take jobs: Job): void {
    submit(...jobs)
}
```

Assuming a move-only Job and a matching submit, input receipt owns each Job. Forwarding reserves
each transfer and commits only after the complete destination bundle is ready. The original
pack's count remains but its transferred entries are unavailable. Returning cleans only its
remaining values, not Jobs now owned by submit. Read forwarding instead delegates existing
access; it cannot consume the original Jobs merely because the destination wants ownership.

## Keyed Does Not Mean a Map or Named Fixed Arguments

```text
func fields(... take entries: Key: Value): void
```

Each direct `key: value` contributes one ordered pair, with key prepared first. The same input
operation applies to both. Duplicate keys survive without Eq/Hash requirements or implicit
collision policy. `entries[index]` uses an ordinal, even when Key is usize. A map implementation
can later consume this contract and apply its own checked insertion/failure semantics.

Making keys implicitly read-only would hide a different contract inside take/edit. Treating
the colon as a fixed-parameter label would add lookup-dependent call syntax and another argument
style. The selected target already identifies the final pack and the required K/V data.
An ordinary tuple-valued pack and a keyed pack remain different callable contracts.

The integrated header audit also fixes an origin-attachment ambiguity: a trailing callable
element type could consume the same from as the enclosing edit pack. The common grammar now
attaches to the nearest open callable result. Group the complete type for an enclosing relation,
as in `... edit entries: Key: (mut(): void) from source`. Resolving which header contains source
must never select the parse. This rule also governs ordinary higher-order inputs/results and
future-wrapped trailing callables; a repeated from is not a second spelling for grouping.

## Expansion Uses the Receiving Contract Once

Built-in argument expansion accepts another pack or a fixed array. It contributes to a final
pack after the fixed inputs, and cannot splice fixed arity or silently call a user iterator.
Allowing runtime-length expansion to satisfy fixed inputs would require runtime arity failure;
allowing only some statically known carriers there would add a second mapping rule to this
checkpoint. A fixed prefix remains explicit. General user expansion/iteration can be designed
together rather than guessing their protocol from the ellipsis spelling.

The receiving ordinary pack supplies one value/access per source entry. A keyed receiving pack
requires pairs and supplies key/value separately. Explicit expansion can adapt pairs to a keyed
tail and keyed entries to an ordinary pair-valued tail. This is an explicit argument preparation
operation, not type equality or a callable-kind adapter.

If a source pair has a Copy key and non-Copy value, keyed take snapshots the key and reserves
the value. Ordinary take of its non-Copy pair transfers the entire pair. These different
component boundaries must be frozen before availability checking. Searching the alternatives
to preserve a later source use would break declaration authority.

An expansion source evaluates once at its written position, and all its entries are prepared
before the next contribution. Direct non-Copy sources remain reserved until invocation;
Copy taking components snapshot at preparation. Earlier nested constructors/calls keep their
completed transfers when later preparation fails. A spread of a read Copy array is still an
access, not an implicit snapshot chosen to permit a later conflicting mutation.

## Capturing Without a Mandatory Intermediate Collection

```text
func make_submitter(... take jobs: Job): once(): void {
    (jobs;) { submit(...jobs) }
}
```

The existing value-capture segment can capture the sequence's count and component values.
Non-Copy owners move at closure formation; Copy snapshots retain carried dependencies. The
resulting environment owns remaining-entry cleanup if never called or partially consumed.
Reading, editing and extracting choose func/mut/once by the existing invocation rules; merely
owning the captured sequence is insufficient to select once.

Rejecting pack capture would require an intermediate container just to retain received Jobs,
potentially imposing a source allocator/failure API that closure environment storage does not
require. Creating an implicit first-class array from every bare pack name would instead hide
ownership behind ordinary data syntax. The selected rule uses the already explicit capture
operation, with per-component supply, and leaves bare-name data construction unsupported.
Unlisted captures use the same checked inference without an escape-driven ownership upgrade.

Capture frames and async producer frames preserve the one entry schema; they do not share a
second owner ledger or postpone the transfer until drive/invocation. Required physical backing
and progress effects still need independent proof. Read/edit captures retain actual outside
roots; capturing a range of accesses does not make it independent or Copy.

## Origins and Cleanup

`from items` bounds the pack's input subtree, translating each entry to its actual root/carried
dependencies. The one formal source does not require a new lifetime annotation for every actual
argument. An explicit edit-pack bound covers all components and reachable writes. Unknown
aliases remain possible unless the selected operation/bundle proves disjointness.

Normal/recoverable take cleanup visits reverse entry order and value before key; it skips
transferred components. Results are protected before cleanup. Unstarted async cancellation
disposes already received values; pending cancellation uses actual remaining initialization.
Read/edit delegation begins at producer construction, and a stored future cannot retain a
caller temporary whose evaluation extent ended. Completion/cancellation bounds remain distinct.
Empty and zero-sized entries do not change these obligations by byte-size reasoning.

## Future Conformance Obligations

These are required cases, not passed compiler tests:

| Case | Required observation |
| --- | --- |
| Zero or many tail contributions under one signature | One formal pack identity, same callable type |
| Two/nonfinal packs; tuple/discard pack header | Reject malformed binder contract without flattening inputs |
| Pack name collides with a fixed name or tuple leaf | Reject duplicate header binding in the common namespace |
| Named keyed callable type versus one-colon ordinary pack | Preserve S15's syntax, independent of name lookup |
| Contextual take/edit used as a pack binding/type name | Recognize the complete grammar position, without operation/name lookup fallback |
| Trailing callable from versus grouped callable type followed by enclosing from | Bind to the syntactic owner, reject unknown inner names and ungrouped double-from escape |
| Pack/closure omitted mode versus explicit edit/take | Default read or selected contextual completion; no body-based named-input mode |
| Expected keyed closure with no annotation; explicit one-/two-type annotation | Inherit omitted shape/data; reject incompatible asserted shape |
| Index operator with a variadic/keyed index head | Reject outside its one ordinary index-input contract |
| Unknown generic type with empty tail | Require unique type evidence; do not invent a type from emptiness |
| Exact-type read Copy entry followed by conflicting later mutation | Retain original-place reservation; no inferred snapshot |
| Read outcome injection from Copy/fresh versus direct non-Copy source | Construct an admitted wrapper temporary; reject an implicit consuming read conversion |
| Copy taking entry followed by mutation | Retain prepared snapshot |
| Duplicate read roots versus conflicting edit/non-Copy take roots | Read sharing can remain; validate the complete exclusive/transfer bundle |
| Same actual storage through distinct entry/key/value paths | Logical ordinals alone do not establish disjointness |
| Keyed direct contribution | Prepare key before value, preserve duplicate keys and source order |
| Produced key/value in an edit tail versus immutable existing place | Lend the owned temporary under the later input protocol; never snapshot an immutable place to repair edit |
| Colon in fixed prefix or tuple as direct keyed entry | Reject alternate named/pair argument style |
| Built-in expansion of fixed array/pack | Evaluate source once; freeze count/root map; prepare ascending entries |
| Mixed direct and expanded contributions with later failure | Preserve exact preparation order, reservations and completed nested moves |
| Spread before required fixed inputs or to non-variadic target | Reject; no runtime arity failure or signature re-selection |
| Tuple/string/arbitrary container spread | No guessed iterator, user expansion or dynamic `[T]` semantics |
| Pair sequence into keyed tail; keyed source into tuple-valued ordinary tail | Record explicit receiving-shape adapter without equating callable types |
| Pair with Copy key and non-Copy value | Keyed take snapshots/transfers separately; ordinary take transfers whole pair |
| Read/edit source expanded into non-Copy take | Reject missing ownership; copying descriptor cannot repair it |
| Computed array expanded to read/edit/take | Respect value/place category and caller temporary lifetime |
| Non-Copy owning-array spread followed by source use/drop | Retain actual missing elements and skip them at remainder cleanup |
| Zero source count | No element transfers/effects invented; source expression still evaluates |
| Accumulated count exceeds target usize after an entry | Checked trap before the next entry/step/contribution/commit; evaluated required CTFE fails compilation |
| len after partial transfer, read of hole, replacement of hole | Original count remains; reject unavailable read; allow valid restoration |
| Dynamic index changed after extraction | Cleanup uses frozen original position and actual root map |
| Bare pack local/return/drop/whole alias | Reject non-data binder use, without manufacturing a container |
| Explicit value capture from owning/read-Copy/read-non-Copy pack | Move, snapshot, or reject under source-context evidence |
| Captured pack never called, read repeatedly, updated, partly consumed | Preserve environment invocation inference and remaining-entry cleanup |
| Capture formation followed by later interrupted capture | Earlier executed component moves remain; clean captured prefix in reverse order |
| Inferred access capture escapes its actual roots | Reject; no inferred move/owner extension merely to make escape valid |
| Heterogeneous callable witnesses with equal signatures | No implicit erasure/dynamic witness join |
| Result dependent on dying take entry versus forwarded carried outside root | Reject dead direct storage; preserve valid outside dependencies |
| One formal pack as sole eligible result origin | Elide conservatively over its entry subtree, without merging actual roots |
| Edited pack bound violated by an unindexed component/outside write | Check the complete promised post-state, not body-use subset |
| Read/take pack from bound with incompatible incoming carried roots | Reject the incoming obligation, without interpreting it as edited post-state |
| Async read/edit pack construction then later drive/cancellation | Retain activation, roots and distinct phase state relations |
| Async take pack cancelled before drive/after partial transfer | Clean exactly received/remaining components in reverse order |
| Stored future with temporary read entries versus immediate await | Preserve caller-frame lifetime; no implicit owning promotion |
| Pack operations in const domain | One ordinary body/domain/evaluator authority, no runtime fallback |

Freeze pack kind, component boundaries, formal entry paths, actual prepared sources, supply
choices, capture mapping, origin/state transitions and exact cleanup under the checked program.
Downstream executable/MIR/ABI/editor consumers may not reconstruct them from names, text, arity
or source syntax. Exercise interruption, overlapping roots, partial restoration, cancellation
and capture disposal before target realization.

## Verification and Next Work

Documentation generation, an explicit external site build, links/whitespace and the combined
owning/draft grammar inventory are the checkpoint gates. They cannot establish parser
unambiguity, dynamic pack/capture safety, native vararg calling, evaluator execution or speedup.
No language-server test of an unconsumed private path counts as implementation evidence.

The documentation generator tests and external build at `/tmp/nocter-variadic-site` passed,
preserving 376 published pages. A read-only combined grammar inventory found 157 V2 productions
with no duplicate definitions or unresolved V2 references. Links and whitespace are also checked;
these observations are documentation evidence only.

Next close general expansion/iteration, typed literal entries and coercion with their capability/
backing schemas, then remaining lexical/expression/control and package/platform subjects. The
unclosed `[T]` and library APIs remain explicit gates rather than pack implementation shortcuts.
