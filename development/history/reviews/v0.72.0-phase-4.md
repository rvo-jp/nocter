# v0.72.0 Phase 4 Standard Adoption and Qualification Review

**Result: complete with no open implementation blocker (2026-09-26).** The physical standard
library adopts only guarantees that the completed v0.72.0 proof model can establish. Release
identity, deterministic archive qualification, publication, and external audit remain release
preparation work.

## Standard Adoption

The borrowed slice API now publishes `noalloc notrap` for:

- `len` and `is_empty`;
- non-owning pointer observation;
- checked readonly and readwrite element access; and
- first-element access through the checked operation.

The declarations and implementation bodies carry the same contracts. Whole-standard compilation
validates every body rather than trusting the contract file. The checked accessors test the index
against the same slice length before direct indexing, so the checking-owned path fact discharges the
bounds trap. `first` delegates only to that proved accessor.

Borrowed text length, emptiness, and pointer observation also publish `noalloc notrap`; each is a
direct wrapper around a runtime-role-certified primitive. Text range construction and slice range
construction deliberately remain unqualified because their current bodies contain additional
pointer or arithmetic obligations beyond the Phase 4 adoption proof.

## Authority Review

The reviewed path is directional:

1. checking derives integer ranges, same-view length relationships, and path-local refinements;
2. each checked index or arithmetic operation stores a closed disposition;
3. checked execution analysis consumes that stored disposition for `notrap` validation;
4. MIR converts the disposition without examining source expressions;
5. Machine converts it without examining checked or MIR operands; and
6. ARM64 emits or omits the specified check without performing range analysis.

Search and call-site inspection found no target-side constant proof, source-text inference,
operation-name fallback, or second bounds/arithmetic decision table. MIR's `InternalInvariant`
state is confined to compiler-generated arithmetic and cannot represent a source proof. Machine
effect classification consumes the closed disposition only to preserve trapping operations during
optimization.

## Focused Qualification

The physical standard-library target crossed discovery, declaration lowering, complete checking,
MIR lowering, Machine lowering, and ARM64 selection with the new authored contracts. The focused
native-session standard test passed. Phase 0 through Phase 3 already cover disposition formation,
conservative control-flow joins, runtime fallback checks, static traps, and native arithmetic trap
behavior. Documentation generation and the complete compiler and installed-artifact gates are
repeated during release preparation from the clean release-content commit.

No compatibility spelling, unchecked operation, hidden caller precondition, or backend-owned proof
authority was introduced.
