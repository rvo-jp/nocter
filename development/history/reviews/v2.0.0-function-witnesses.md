## Implemented Source Boundary

The owning [future callable rules](../../spec/language/callables.md#named-function-witnesses)
and [bounded grammar](../../spec/language/syntactic-grammar.md#bounded-value-binding-fragment)
remain normative. A reference to a named function can supply a local value, retaining that exact
code identity. A local structural annotation checks the input operations/data and result and can
select a permitted invocation view:

```text
func update(edit value: i32): void { value += 1 }

func run(): i32 {
    var action: mut(edit i32): void = update
    var value = 1
    action(value)
    value
}
```

The checked call still targets `update`. The `mut` view requires writable environment access even
though this particular function has no captures. Plain `let action = update` retains the reading
invocation view. Named witnesses have exact Copy evidence: supplying a `once` instance copies the
witness rather than invalidating its original. Explicitly dropping the original still makes it
unavailable. This is ordinary Copy supply, not permission to invoke a consumed move-only closure.

Local annotations are constraints on concrete witnesses, not runtime-erased datatypes. Two named
functions with equal signatures remain different witnesses. Same-witness branches and replacement
are supported; heterogeneous branches and replacement reject instead of inventing erased dispatch.
Aliases can retain a matching view but cannot construct a changed one. A restricted view cannot
recover a stronger contract by looking through to the original declaration.

The bounded parser rejects structural callable headers, anonymous closures, capture lists, packs,
retained-state clauses and erased callables. The full future specification describes broader
contracts; those are not implemented merely by accepting this local annotation form.

## Authority and Resource Review

- The declaration program owns each concrete witness and interns all named invocation views at
  header freeze in its existing TypeAuthority. Body annotations cannot change header type
  availability or force a second body-owned type store. Projection preserves code identity/view.
- The declaration owner matches structural constraints and validates invocation adapters. Checking
  projects typed mismatch domains instead of maintaining another signature/compatibility policy.
- The ordinary value boundary materializes Copy-or-move before adapting a view. Initialization and
  assignment share that boundary and one atomic resource transition; alias creation does not
  silently adapt a referent.
- A call through a value prepares its environment first, followed by explicit inputs. Each selected
  input plan carries its operation. Resource validation consumes that operation without reopening
  declaration parameters or guessing an index offset. Direct declaration calls use the same plan
  machinery and need no runtime environment input.
- Environment permission, full-bundle commit, interrupted preparation, retained temporaries and
  cleanup use the existing graph and resource ledger. No function-specific owner/liveness registry
  or erased indirect-call product was introduced.
- Capture-free named-witness payloads alone justify Copy, trivial destruction and empty outside
  D/S. These are exact schema facts, not an inference from an arbitrary `func` annotation or an
  unknown environment. General callable contracts still need witness/dependency propagation.
- Review also found duplicated nominal field/generic-storage traversal in the two existing loan
  queries. They now share one traversal helper while preserving their different handling of
  unresolved generics. The checking library suite covers the refactor.
- The released declaration validator rejects private witness keys. Released body recipes and
  target/runtime representation boundaries cannot translate them, and editor presentation cannot
  invent a label for them through the released session product. Shared type visitors handle only
  intrinsic leaf facts; they do not admit the private program into the released pipeline.

A tempting structural-function-pointer representation was rejected: it would discard the witness
before specialization and make arbitrary callback environments appear independent/Copy without
proof. The selected concrete witness keeps both static dispatch and future specialization open.

## Verification Evidence

The production corpus now contains 149 sources: 76 accepted whole private units, 63 checking
rejections, 4 header rejections and 6 syntax rejections. All 143 syntax-valid inputs have lossless
structural snapshots; declaration tests freeze 139 header-valid units independently of body
acceptance. The 36 added sources cover local receipt, annotations and exact mismatch domains,
Copy and aliases, invocation views, recursive/computed calls, joins/replacement, taking inputs,
interruption, drop and retained permissions. Previously tracked parser shapes remain unchanged.
The manifest is the sole per-source expectation catalog.

Four additional source-to-unit tests inspect semantic evidence beyond acceptance: environment-first
update reservations with the exact static target, the explicit taking input's shifted commit index,
Copy preparation before dropping the original, and cancellation without invocation/result receipt.
Declaration/model tests check mismatch domains, identity/view preservation, Copy and restricted-view
compatibility; another test proves released declaration admission rejects private witness keys.

The affected library suites pass: model 41, declarations 48, declaration lowering 143, syntax 144
and checking 696 tests. Warnings-denied workspace Clippy checks all targets, including shared model
consumers. Documentation generator tests and an external site build validate the authored Markdown.
LSP and native runtime suites are not evidence for this private source path and were not run for
this extension. There is no performance claim or executable qualification.
