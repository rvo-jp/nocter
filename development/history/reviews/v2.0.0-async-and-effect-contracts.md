# v2.0.0 Async Phases, Cancellation and Inferred Effects

## Status and Owners

The adopted owners are [async computations](../../spec/language/asynchronous-computations.md),
[execution effects](../../spec/language/execution-effects.md),
[deferred origin bounds](../../spec/language/memory-and-regions.md#deferred-completion-and-cancellation-bounds)
and [staging syntax](../../spec/language/syntactic-grammar.md#asynchronous-staging).
This review records choices, counterexamples and future proof/source cases. It is not another
language authority, an implemented effect solver, async compiler acceptance, ABI qualification
or a runtime/performance result. Published contracts and the private compiler are unchanged.

The delegated designer resolved these model/source roles under existing authorization. No new
keyword, cancellation qualifier, effect parameter or user approval is required. The previous
same-bound-on-all-cancellation assumption was an internal model choice, not a separately selected
user source spelling; its correction below preserves the adopted placement of from clauses.

## Audit Findings

### Default Is a Role Prefix on One Ordinary Head

The earlier assembly independently repeated const/async/function/method heads for interface
operations and put default inside that modifier sequence. Reuse the ordinary head productions
instead: `default async method ...` and `default const method ...`. Removing default leaves
exactly the existing declaration head. Keep one order, not a choice of equivalent source styles.
This changes an unimplemented envelope, not released or private-fragment acceptance.

### Completion Cannot Be Promised before a Lazy Body Runs

Earlier edited-state text required the same final origin bound on cancellation as on completion.
For an unstarted lazy producer this can be impossible:

```text
// Assume Holder's schema carries outside dependencies and clear actually removes them.
async func forget(edit holder: Holder from static): void {
    holder.clear()
}
```

At construction holder still has its incoming dependencies. Cancelling before the first drive
cannot establish static-independent state without running unstarted body statements, resetting
state implicitly or imposing a hidden incoming precondition. Those would contradict laziness,
the ordinary meaning of an edit postcondition, or the no-rollback rule.

The selected model gives completed normal/recoverable paths the authored bound B. Pending
cancellation permits Entry union B after cleanup. The default B already preserves Entry, so
ordinary omitted clauses do not gain new direct-retention permissions. A narrower explicit
completion bound becomes usable after await without falsely claiming the same state after an
unstarted drop. The union is a conservative relation over dependency-slot alternatives, not
copied storage, resurrected access or simultaneous duplicate exclusive capabilities.

Retaining the old same-bound rule would reject useful lazy reset operations for a reason unrelated
to actual memory safety. Adding a second source cancellation clause would require repeating
information derivable from the existing entry/completion contracts. Allowing arbitrary input
retention on cancellation would weaken declaration readability. Entry union B instead preserves
the old state without authorizing a new direct view absent from B. A suspended prefix that cannot
meet it needs genuinely checked source cleanup or is invalid; no reset is synthesized.

### Ready Output Is a Different State Transition

A ready future has completed the producer, but still owns its unconsumed output. If that output
is a guard, its destructor can update an outside owner. It is unsound to treat whole-future
disposal as just Entry union B or to infer empty effects from output ownership.

The future schema composes pending cancellation with the separate completed-state/output-cleanup
path. Delivered output retains its capabilities and transitions after await too. Child/guard
cleanup must happen while all roots it uses are valid. A missing output-write schema is an
admission gap, not proof of no write. No body search or target reselection is delegated to
lowering to recover it.

Unstarted cancellation can also run the cleanup of owned input/capture values. Its footprint
must include their checked outside-state effects even without a body statement. The void-output
forget example retains entry state because its input is only an edit access, not because all
unstarted future cancellation is effect-free.

### Effects Need Phases, Not Replacement Modifiers

Creation, drive, normal cleanup, pending cancellation and ready-output disposal have separate
effects. A waiting immediate future factory is unsafe inside a parent's drive even if its
returned future has a safe body. Runtime-managed error/frame storage counts as backing, and
release can wait through its chosen backend. Noalloc-style facts cannot stand in for those proofs.

Conditional facts follow concrete callback witnesses, type cleanup schemas and invocation
adapters. They can be discharged without authored effect bounds and without changing a generic
body's selected transfer into a Copy. Unknown remains unknown. Every actual future needs drive/
release evidence even if never awaited; an interrupted result needs no invented environment.

An external-state polling cycle can synchronously wait despite immediate individual observations.
The proof must account for dependence on external progress or an actual suspension/independent
return argument. CPU-only divergence is different: no-wait is not a fairness, cancellation-latency
or time-bound promise. In particular a divergent active drive cannot be concurrently destroyed
as though the future had reached a quiescent cancellation state.

### Read Still Does Not Mean Snapshot

An async read input retains source access even for a scalar. A fresh operand's owner stays in the
caller evaluation frame; an immediate await can keep that frame alive across suspension. Storing
the future beyond that temporary is invalid. The ordinary remedy is a sufficiently live named
owner or intentional take input, not a hidden value capture or automatic lifetime extension.

Take inputs transfer at creation, not first drive. Edit delegation also begins at creation,
preventing conflicting caller uses while deferred work retains access. Required backing precedes
the producer's commit, without rolling back effects of earlier argument computations. An
immediate recoverable factory has its own different commit/failure contract; async cannot add
an unadvertised outer failure layer for construction.

## Future Source and Proof Obligations

These are specified future cases, not tests passed by the bounded private compiler.

| Case | Required behavior |
| --- | --- |
| async declaration with a fallible output | Call produces future of the outcome; body throw runs only when driven |
| Immediate helper returning a future | Run its immediate effects now; do not infer async from its result |
| Type-owned async construction | Check the deferred payload constructs Self; no receiverless utility loophole |
| const async, anonymous async closure, async primitive/drop/operator | Reject unsupported staging position/combination |
| default async method versus async default method | Reuse the ordinary head under a default role prefix; reject the alternate order |
| Await in a nested ordinary closure | Reject rather than capture the enclosing async permission |
| await operation()? versus await (factory()?) | Preserve output versus constructor extraction order |
| Stored future with a needed read temporary | Reject escape of the caller's evaluation frame |
| Immediately awaited read temporary | Keep the parent evaluation owner through child completion/cancellation |
| Scalar read input while its root changes | Reject conflict; do not invent snapshot semantics |
| Take input, then drop unstarted future | Source transfer remains performed; clean captured value once without running body |
| Owned input guard changes outside state on unstarted cancellation | Compose its checked cleanup footprint; do not infer identity from the unstarted phase |
| Deferred edit, followed by a conflicting caller edit | Reject while the future retains its delegation |
| Interrupted preparation before async commit | Preserve reserved source; clean prepared values; do not undo earlier nested moves |
| Recoverable immediate factory fails after receiving a take value | Apply its own committed-input contract, not the producer's precommit rule |
| forget from static completes | Establish the declared independent state before delivering output |
| Same operation cancelled before first drive | Preserve Entry; do not claim completion or run clear |
| New direct buffer view survives suspension/cancel but is absent from B | Reject the cancellation footprint even if eventual completion clears it |
| Source-authored guard clears that view on cancellation | Check cleanup order/footprint; no generated rollback |
| Pending cancellation leaves an external edit partly initialized | Reject, independently of its allowed dependency envelope |
| Ready guard output writes an outside owner on drop | Compose its cleanup transition after B, independently of pending cancellation |
| Output view points into destroyed producer-local storage | Reject despite output ownership or eliminated frame fields |
| Callback witness or destructor/backend can wait | Reject the affected async production/use with its concrete cause |
| Allocating cleanup is proved non-waiting | Do not require Copy or noalloc as a substitute |
| Child construction can wait but child drive is safe | Reject construction in the parent's drive |
| Polling loop has only immediate observation calls | Still prove independence from external progress or suspend |
| CPU-only divergent loop | Do not claim bounded work or preemptive cancellation from non-waiting |
| Body/backend changes an inferred fact | Invalidate dependent certificates and diagnose affected safety-sensitive uses |
| Drop unstarted future with fallible output | No fabricated body failure or successful completion |
| Cancel ready future before source output delivery | Dispose under the owning cancellation contract; do not return that output |
| Delivered child failure later discarded by a composition | Preserve its failure-loss warning; wrapping/fusion cannot recategorize delivery |
| Frame backing is removed or release backend changes | Preserve semantic roots, source operation choices and recheck actual phase effects |

  with the development contracts excluded from navigation/search/publication.

- Read-only grammar inventory across the owning syntax chapter and remaining assembly: 151 V2
  productions, no duplicate definitions and no unresolved V2 references.

Documentation-generator tests, an external site build and whitespace/link checks qualify this
documentation boundary only. The combined owning grammar/remaining draft inventory checks named
V2 productions for duplicates/missing references, not parsing ambiguity, type soundness or
executable cancellation. No new production compiler fixture or runtime test is claimed.

Full control/enum patterns, literal/pack/coercion contracts, lexical and package/platform source,
library task/async-iteration APIs and entry scheduling remain separate closure work. Compiler
implementation additionally needs conditional effect/dependency solvers, quiescent-state/frame
proofs and native lifecycle realization under the same authority. Preserve the current 283-case
private corpus and its own acceptance scope; these examples do not extend it.
