# v0.72.0 Phase 2 Bounds Proof Across Control Flow Review

## Scope

This review covers dynamic fixed-array and view indexing, standard length identity, loop exits, and
the authority boundary from checking through native lowering.

## Findings and Remediation

### Closed — View length could not be identified without a spelling exception

The flow domain can prove `index < length`, but an ordinary `values.len()` call did not state that
its result was the receiver view's length. Matching `len`, `slice_len_raw`, or a module path inside
the checker would have made physical standard-library structure a semantic input.

The closed toolchain contract now binds the exact public slice and string-view length methods.
`StandardSemanticTable` validates each declaration as a public readonly, allocation-free method
with the required receiver and `usize` result. Flow analysis consumes only the resolved callable
identity. Runtime primitive roles remain independent implementation boundaries.

### Closed — Constant-only ranges could not describe a view bound

`SafetyFlowState` now has two orthogonal fact forms: integer intervals against constants and
relations between an index identity and one storage identity's length. The relation records only
the conclusions required by bounds checking: below length or at-or-above length. Branch negation
is normalized once from `PrimitiveComparisonRelation`; joins intersect symbolic facts.

Direct places are admitted only when their root is a parameter or immutable local and their path
contains at most borrow dereferences. Field projections, aliases, captures, mutable locals, and
coerced receivers remain conservative. A bound from one view cannot prove indexing another.

### Closed — Loop handling discarded valid exits and could not represent breaks

Every loop frame now records the safety state at each syntactically reachable `break`. A `while`
adds its false-condition edge; an infinite loop has only explicit break exits; potentially
zero-iteration collection and range loops retain their entry edge. All exits use the same join as
ordinary branches. The tracked identities cannot mutate, so no loop-local fixed-point shortcut is
required.

## Evidence

- checker tests admit branch, terminal-path, while-exit, and break-exit proofs;
- negative tests reject join leakage, loop-body leakage, mutable locals, and a length fact applied
  to different storage;
- standard semantic tests accept the exact view-length contract and reject a missing `noalloc`
  guarantee;
- the physical standard profile passes a command-level package check with both new roles;
- checking, MIR, Machine, toolchain-contract, and standard-profile tests pass;
- warnings-denied Clippy passes for every touched stage and ARM64.

## Result

Checking remains the sole proof producer. Standard discovery supplies identity, not proof logic;
MIR and Machine transport each frozen disposition; ARM64 consumes it. Phase 3 can extend the same
flow environment to arithmetic only after the always-on runtime arithmetic contract is closed.
