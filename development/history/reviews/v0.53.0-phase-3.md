# v0.53.0 Phase 3 HTTP Server Lifecycle Review

## Scope

This review covers the public server typestate, accepted-connection ownership, incremental request
decoding, response encoding, shared HTTP field and framing state, the loopback application, and the
boundary between `std/http` and `std/net`.

## Findings and Resolution

### Connection states are distinct owned capabilities

`Server` owns only the listener. `ServerConnection` owns one accepted stream before request
decoding, and consuming `read_request` transfers that stream into exactly one `Responder` beside
the owned request. Consuming `respond` writes and closes it. No public state flag permits a second
read or response, no task is detached, and failure or cancellation destroys whichever state still
owns the stream.

### Field syntax and framing evidence have one authority

The first implementation draft shared `Content-Length` and `Transfer-Encoding` interpretation but
left nearly identical field-line scan loops in the request and response decoders. That would have
allowed aggregate limits or malformed-line policy to diverge. The completed design instead gives
`FieldBlockState` sole ownership of the line cursor, retained fields, aggregate bounds, and framing
evidence. Request and response decoders own only their different start-line state and final framing
selection.

The response decoder still owns informational-response sequencing because requests have no such
state. The body decoder remains the single authority for fixed, chunked, bodyless, and
close-delimited progress. Server request collection drives that decoder without reinterpreting its
state.

### Wire encoding is shared without destination effects

Request and server-response head encoding use one byte append, decimal spelling, field emission,
reserved-field policy, and bounded-capacity implementation. Their protocol-specific functions own
only start-line spelling and generated-field selection. The reserved-field policy is a closed enum,
so callers cannot create contradictory boolean combinations or classify failures by comparing
public error strings.

### Buffering is finite and owned by one lifecycle

Request heads are bounded before continued protocol-controlled growth. Complete request bodies are
bounded by the same `Limits` carried from `Server`; chunk metadata and trailers retain the existing
line, count, and aggregate bounds. Scratch storage is fixed-size and request body storage has one
owner. Any already-buffered bytes following the first complete request are rejected rather than
silently retained as an unsupported pipeline.

Response heads are fully validated and capacity-checked before the first write. Statuses that
forbid bodies reject non-empty body state. The responder alone adds connection closure and length
fields, so user fields cannot establish a second framing interpretation.

### HTTP does not know transport internals

The server uses only public `TcpListener`, `TcpStream`, and `SocketAddress` contracts. It does not
inspect descriptors, readiness interests, executor state, native network failures, or provider
representations. Conversely, `std/net` contains no HTTP parser, body framing, server typestate, or
message limit. No compiler-recognized server abstraction was added.

## Deferred Boundaries

Accept, request-read, and response-write timeout operations belong to Phase 4. Application-owned
connection and task limits also remain there. Their absence does not introduce an implicit timeout,
detached work, or unbounded codec buffer in Phase 3; it leaves a deliberately smaller public
operation set. Keep-alive, pipelining, upgrades, tunnels, and streaming message bodies remain
explicitly outside the current milestone.

## Evidence

- authored-standard discovery, syntax, visibility, dependency, and complete body checking;
- complete bundled-standard target-session compilation;
- request parsing at every single input-fragment boundary;
- Host, framing ambiguity, bodyless response, reserved-field, and capacity boundary cases;
- native installed-standard execution of the public async HTTP client/server loopback application;
- deterministic documentation generation and repository whitespace validation.

## Result

No open Phase 3 finding remains. Listener ownership, accepted state, request parsing, body decoding,
response encoding, and final connection closure each have one authority. Each responsibility uses
another only through its declared operation boundary, and neither request nor response processing
recomputes a decision made by shared codec state.
