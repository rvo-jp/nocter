# v0.49.0 Documentation Artifact Migration

## Result

The authored documentation, build mechanism, and deployment output now have disjoint ownership.
`main` retains only authored Markdown, published Nocter sources, shared assets, website-only static
inputs, and the generator. Generated HTML is neither a source input nor a tracked repository tree.

## Authority and Deployment

- Authored files retain their existing repository authorities. The deployment workflow does not
  rewrite or mirror them.
- `build-docs.js` is the sole projection from published sources to website paths. It requires an
  explicit output directory disjoint from the source repository.
- `OutputTransaction` owns atomic replacement only within that caller-owned output directory. It
  no longer stages or restores output inside the repository.
- Pull requests validate the generator and build the complete site without uploading it. Pushes or
  manual runs on `main` upload the complete build as one GitHub Pages artifact.
- Only the deployment job receives `pages: write` and `id-token: write`; source checkout and build
  retain read-only repository permission.
- `deployment.json` and repository-source links identify the exact commit supplied by the workflow.
  A deployed page can therefore be traced to its complete authored source revision.

The repository's Pages source must be switched to **GitHub Actions** during the main-branch
cutover. Generated branches and a tracked `docs/` tree are not part of the new model.

## Findings Corrected During Migration

An initial lexical path check rejected ordinary in-repository output but could treat macOS `/var`
and `/private/var` aliases as different trees. Output validation now canonicalizes the nearest
existing ancestor before checking both containment directions. It rejects an output inside the
repository and an output that contains the repository, preventing both generated-source pollution
and destructive replacement of a source ancestor.

The README logo previously pointed into generated output and briefly occupied a separate root
asset authority during migration. Its one authored copy now lives with the other static inputs
under `development/site/static/assets/`; the repository README consumes that source directly and
the generator copies the enclosing static tree into the artifact once.

## Qualification

- adversarial generation from independent timestamp domains produces byte-identical output;
- missing, in-repository, source-ancestor, and ambiguous output selection are rejected;
- stale output is removed by complete atomic replacement;
- the artifact contains all 278 pages, static files, the shared logo, `CNAME`, and exact deployment
  identity;
- every published page remains reachable through structural navigation;
- private source and historical publication boundaries remain enforced;
- workflow YAML parses, documentation links validate, and repository whitespace checks pass.

The migration removes 287 generated files and about 10 MB from the checked-out source tree. Prior
generated objects remain in immutable Git history, but main-branch review churn and future Git
growth from website output stop here.
