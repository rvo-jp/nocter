# v0.43.0 Phase 6 Secure Transport Final Review

**Result: implementation and source-tree qualification complete with no open practical v0.43.0
finding (2026-09-10).** Authenticated TLS and HTTPS now cross one Network.framework connection,
event, trust, deadline, and terminal-ownership model without exposing native objects or duplicating
HTTP policy.

## Authority and Ownership Audit

The final implementation has these single authorities:

1. The runtime contract owns every native import identity, ABI schema, callback-event shape, owner
   lifecycle, and closed primitive role. ARM64 materializes those operations but cannot invent a
   second provider contract.
2. The Darwin target adapter owns Network.framework and Security-framework interaction. Standard
   source receives only opaque owners, normalized events, caller-owned bytes, addresses, and
   booleans; native handles, metadata, callbacks, and provider status codes do not escape.
3. The provider-independent internal network layer owns stream connection progress, deadlines,
   ordered events, cancellation, queue quiescence, and terminal release. Plain TCP and TLS use the
   same owner and event authority.
4. `std/tls` owns authentication policy: minimum TLS version, requested hostname, system trust,
   optional custom-root augmentation, ALPN configuration, and negotiated-protocol validation.
   Custom roots extend rather than replace the platform trust store.
5. `std/http` owns URL-scheme transport selection and otherwise consumes one private transport
   sum. Request encoding, response decoding, framing, cursor state, and response ownership neither
   inspect TLS internals nor maintain secure-transport variants.
6. The checked public contracts remain the sole editor authority. Hover, navigation, completion,
   and hints expose `Client`, `TrustAnchor`, and their public members without projecting private
   HTTP trust policy or native TLS declarations.

The verification callback evaluates the provider-created trust, so its hostname policy and
certificate-validity policy remain intact. Every callback path reaches one completion invocation.
Temporary CoreFoundation and Security objects are released on every acquisition branch. Terminal
owner cleanup cancels the native connection, observes its final event, crosses the serial-queue
barrier, releases the connection and callback context, and only then releases queue and channel
state.

Deferred TLS establishment owns the copied hostname, ALPN identifier, custom-root bytes, resolved
candidates, and one absolute deadline. Once a native connection exists, the suspended frame owns
the ordinary stream owner. Existing MIR cancellation plans and executor destruction invoke the
same terminal lifecycle; TLS does not carry a private cancellation engine.

## Findings Corrected During Review

The final review corrected three concrete defects instead of preserving compatibility paths:

- A Mach-O qualification test still used the superseded network configuration callback role after
  TLS configuration gained its own closed vocabulary. The test now lives in the TLS configuration
  responsibility and consumes `DarwinTlsCallbackRole`, so the old role cannot become a second
  declaration authority.
- The `std/tls` dependency on `std/ptr` was reviewed rather than copied into a TLS-local pointer
  conversion. `std/ptr.from_ref` remains the single safe borrow-to-pointer authority and exposes no
  native provider object, so the dependency is intentional.
- HTTPS advertised `http/1.1` in ClientHello but did not verify the selected application protocol.
  A server could therefore complete authentication without agreeing to the protocol consumed by
  the HTTP codec. The runtime contract now defines one closed negotiated-protocol operation; the
  Darwin target inspects retained TLS metadata while native objects are alive and returns only a
  boolean. The shared network connection path enforces it for synchronous and asynchronous TLS,
  and HTTP supplies the exact `http/1.1` requirement.

Searches and boundary review found no second trust evaluator, hostname verifier, certificate-
validity policy, ALPN parser, HTTP codec, connection-event consumer, timeout clock, callback
ownership path, or TLS-specific editor inference. Native failure details remain private and every
public authentication or protocol-negotiation failure normalizes to `std.net.tls_failed`.

## Security and Integration Evidence

Deterministic local fixtures qualify system-trust rejection, custom-root acceptance, hostname
mismatch, an unknown root, malformed trust material, expired certificates under custom trust,
truncated TLS records, silent-peer handshake timeout, plain-peer rejection, synchronous and
asynchronous cancellation, and authenticated HTTPS. A separate authenticated server deliberately
selects no ALPN; both synchronous and asynchronous HTTPS reject it, while the positive custom-trust
server selects `http/1.1` and completes through the same HTTP decoder.

The existing `http-get` example uses the ordinary `Client` path and documents authenticated system
trust. Editor qualification resolves the custom-trust API exclusively through public HTTP and TLS
contracts. No ordinary test depends on a public Internet service.
