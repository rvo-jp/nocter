# v0.52.0 Phase 5 Compile-Time Evaluation Closure Review

Date: 2026-09-15

## Result

The implementation and architecture review is complete. Ordinary checking is the only authority
for initializer and callable body semantics. Declaration lowering retains only the scalar
structural constants required to construct types, while checked finalization produces the one
dense constant/static value table consumed by target selection, lowering, and editor presentation.

Fresh installed-toolchain qualification remains a release-preparation gate. v0.52.0 must first
receive one clean release-identity commit so deterministic packaging can bind the candidate to the
exact source tree.

## Findings and Remediation

### An early value table could be mistaken for the final authority

Declaration construction previously allocated slots for every constant and static, filled some of
them before checking, and later completed the same table. That shape exposed an optional final
value authority to recovery and checking, made metadata definition depend on successful early
evaluation, and encouraged consumers to treat phase absence as a value state.

The old completion adapter and optional slots are removed. `StructuralConstantTable` is a sparse,
constant-only construction input; `DeclarationValueTable` is a dense checked product containing
every constant and immutable static. A narrow `ConstantValueLookup` capability lets partial editor
products present available constants without acquiring static-value or construction authority.
The final table validates its complete declaration domain, recursive value shapes, and equality
with every early structural result before publication.

### Initializers bypassed ordinary body semantics

Constants and statics formerly depended on a header expression evaluator that could not consume
selected calls. Extending that evaluator would have duplicated name resolution, type checking,
generic specialization, and dispatch.

Every initializer now owns an expression-form `BodyId` and follows the shared source projection,
name resolution, typed-body checking, and checked-plan projection pipeline. Finalization executes
zero-parameter initializer plans through the same closed executor as `const` callable bodies.
Generic functions and readonly methods reached only by an initializer are specialized from frozen
checked decisions; no evaluator reads syntax or performs lookup.

### Receiver-type availability depended on incidental body use

Receiver declarations store the nominal owner and capability rather than an already-borrowed
value type. The previous body-local construction interned the effective borrow only when a body
mentioned `self`. A valid `const method` that did not read its receiver could therefore reach plan
projection without the receiver type existing in the sealed store.

`Parameter::value_type_contract` now exposes the structural parameter contract, and program
preparation interns every effective parameter value type before sealing the type authority.
Checking and later consumers use the read-only `Parameter::value_type` lookup. Plan availability no
longer depends on source-body access patterns.

### Constant/static metadata had a second declaration walk

Constant and static definitions were collected from the early value maps and sorted in dedicated
passes before the ordinary declaration-definition pass. This made successful evaluation a hidden
precondition for metadata and gave declaration order two owners.

The canonical declaration pass now defines constant and static metadata directly from reserved
identities. Structural evaluation contributes only values. The obsolete all-values definition
walks and sorting are gone.

### A rejected structural definition mutated its builder

The sparse table initially used `BTreeMap::insert` before reporting a duplicate identity. Ignoring
the returned error and continuing would replace the first accepted value, violating the repository
rule that a failed transition publishes no state change.

Definition now uses the occupied/vacant entry boundary and mutates only a vacant identity. A test
attempts a conflicting second definition, finishes the program after the rejection, and proves
that the first value remains canonical.

### Completion modifiers encoded policy as independent booleans

Callable-modifier completion carried four booleans whose legal combinations were implicit. The
current warnings-denied toolchain rejected that representation, and another modifier would have
multiplied the states.

Completion now carries the explicit ordered set of permitted keywords plus the independently
conditional `async` capability. Filtering reads that policy directly instead of reconstructing it
from flag combinations.

## Repository-Wide Boundary Review

Searches and call-site inspection confirmed:

- the restricted header evaluator handles only scalar structural constants and fixed-array
  lengths; it does not evaluate statics or checked calls;
- speculative structural planning uses private resolution state and publishes no source
  projection when the initializer is outside the structural subset;
- constant and static declaration records contain metadata and initializer body identity, never
  evaluated payloads;
- all final values are executed from checked initializer plans and joined once into
  `CompileTimeProgram` with the closed callable-specialization table;
- checked constant references retain `ConstantId`; executable closure and MIR consume the frozen
  value table instead of copying or recomputing declaration values;
- structural bootstrap evaluation is the only intentional duplicate execution, and final-table
  construction requires byte-for-byte semantic value equality with the checked result;
- recovery and analysis depend on `ConstantValueLookup`, not on concrete value-table layout or
  phase-specific optional slots;
- missing plans, types, declaration identities, and value shapes are typed integrity failures,
  not permissive fallbacks;
- compile-time execution consumes typed operations, selected call targets, and the compilation
  target only; it cannot inspect syntax, resolve names, or select dispatch;
- no closed-expression-only call prohibition, old value-completion module, duplicate final value
  table, or source-level callable interpreter remains in the active compiler.

No further issue with current impact or an obvious near-term failure mode was found in this area.
Executor caches remain execution-local by design; they do not become mutable state in the
immutable checked program.
