# v2.0.0 First Access Validation Slice

## Status and Authority

This record bounds the first front-end implementation task after the broad
[readiness audit](v2.0.0-implementation-readiness.md). It is a development work contract, not a
second language authority. The owning future
[grammar fragment](../../../spec/language/syntactic-grammar.md#first-access-validation-fragment),
[value-access rules](../../../spec/language/value-access.md), and
[assignment/flow rules](../../../spec/language/bindings-and-initialization.md#future-direction-v2-0-0-assignment-and-flow)
define source meaning. Current released behavior remains unchanged.

S11's `&place` is adopted. Its semantics, bounded function/body grammar, source requirements,
and finite delegation/init model are recorded. The syntax implementation checkpoint below now
uses production syntax, declaration processing, typed bodies, source-neutral flow and named-slot
initialization, permission-demand liveness, alternative referent/access worlds, exact first-fragment
payload evidence and logical ownership/cleanup transitions. The complete private-unit constructor
now accepts the nineteen positive corpus units and checks every definition. General dependencies,
full-language composition, target realization and native execution remain unimplemented for this
future fragment. No further human spelling decision blocks this particular slice.

## Boundary and Deferred Composition

The first accepted product is checked front-end evidence for one supplied private module, not a
native executable, package-discovery replacement, or alternate public language version.

| Included | Required distinction |
| --- | --- |
| Named private functions and direct named calls | Declaration identity and complete I/U/X contracts selected before operand permissions |
| `bool`, `i32`, `void`, opaque `error` | Scalar/unit Copy versus move-only error; no error construction needed |
| Inferred/annotated scalar locals and discard | Existing place read versus fresh X, explicit transfer, or supplied U |
| `&place`, `^place`, grouping | Immediate delegation versus ownership extraction; no direct call assertions under grouping |
| Primitive arithmetic/comparison/logical operations | Fresh scalar X; short-circuit edges; existing checked numeric semantics |
| Whole-place assignment and explicit drop | RHS-first state, conditional old cleanup, definite initialization |
| If results, while/loop, break/continue, return | Alternative worlds, backedge fixed point, last uses, normal cleanup then handoff |

Nominal fields/indexes/ranges, destructors, tuples/patterns, generic evidence, aliases and compound
type trees, structural/erased callables, closures, async/outcomes, module contracts, CTFE, effects,
standard-library migration, ABI and native execution remain separate closure/implementation tasks.
This temporary task boundary must never become a restriction of the full language. In particular,
using scalar values here does not establish that owning values generally have empty D/S.

The `V2CoreUnit` parse goal is for development conformance. It does not make bodies legal in
`index.nct`, add a user-selectable compatibility flag, or permit current `&`/`&+` borrow meanings
to coexist with future update semantics in one accepted program. A final v2.0.0 product must
remove transitional authorities rather than retain two checking paths.

## Adjacent Product Obligations

Before changing production crates, read their current contracts and derive narrow changes from
these owning rules. Do not add a parallel compiler or source-text semantic oracle in the corpus.

1. **Syntax owns recognition.** Preserve prefix operator and operand trees, type qualifier
   positions, full function headers, grouping, statement boundaries, and structural direct-marker
   violations. Retain invalid non-place operands/targets for focused checking. No name/type
   lookup decides the parse. Add lossless shape assertions for this corpus in the owning syntax
   tests, including zero/one/many edges, newlines, grouping, and recovery.
2. **Declarations own contracts.** Publish one immutable identity/type/permission for each input
   and output, independent of source spelling and optimizer representation. Validate declarations
   before bodies, including unique names and result-origin eligibility. No std function lookup,
   heuristic Copy flag, or callee-body inspection supplies a missing contract.
3. **Checking owns actions and flow.** Separate the stored access permission of a named value
   from its natural initializer operation and its eligibility under a selected boundary. Record
   Copy, explicit transfer, delegation, reservation and commit as checked actions, not a later
   backend guess. Calculate source last-use/cleanup liveness, initialization and access alternatives
   to a conservative fixed point. Validate every loop/return/short-circuit edge and cleanup.
4. **Accepted evidence is complete.** Each selected call has checked operands, result access,
   and cleanup obligations; each transfer has a valid initialized owner; each U access has a live
   writable parent. Rejected or unsupported source cannot leak a partially accepted product.
   Diagnostics identify the attempted action, conflicting source/retained access, and relevant
   later use or backedge. Do not invent exact public codes before updating their owner.
5. **Consumers use decisions.** Later products receive identities and checked operations without
   rereading syntax, reselecting a callable, inferring permission from `&` text, or reconstructing
   liveness. Native acceptance waits for owning target/layout/cleanup and checked-operation
   contracts; front-end acceptance alone is not executable qualification.

The current architecture remains authoritative for stage direction. A concrete Rust product or
crate API is not declared by this review. Update the relevant crate README and adjacent boundary
contract together when an implementation responsibility actually changes.

### Fixed-Point Argument and Limits

A reached slot represents either initialized, uninitialized, or the union of both. An unreached
point is absent, rather than seeded with a fictitious maybe state. Parameters seed initialized
holders; new local slots seed uninitialized. Binding and complete X assignment strongly initialize;
transfer/drop/committed direct X arguments remove ownership; scope exit releases holders and
records conditional owned cleanup. Compound use is checked after its RHS. A commit checks all
reserved preconditions before removing any X ownership, so internal argument order cannot fabricate
an intermediate uninitialized state during the atomic commit.

Each edge merges all reaching states. Transfers are monotone over this finite lattice, and
invalidation evidence is drawn from a finite set of graph action locations. The worklist therefore
converges without an arbitrary iteration budget. Diagnostics are collected only after convergence;
a successful first iteration cannot justify the backedge. The source tests exercise these rules,
but this argument is not a mechanized general memory-safety proof.

The report describes named slots, not referent validity, alternative access worlds, R/D/S payload
relations, reservation conflicts or executable cleanup. The next validator must compute source
access liveness and surviving roots from this same graph, protect staged results through actual
cleanup, reject the four remaining corpus cases and additional alias/reservation cases, and preserve
the valid last-use/alternative-U examples. Neither this checkpoint nor a passing initialization
report closes the first access slice or supplies native acceptance.

### Selected Demand and Handoff Rules

An access does not retain exclusive authority for future reads alone. Demand propagates through
bindings, conditional answers, prepared inputs and returns. Explicit update creation itself still
requires exclusive eligibility, even when the resulting access will be unused. A later U argument,
U result or mutation keeps exclusivity needed. Removing a dead intermediary reparents its children
without changing their roots or granting stronger authority. Source types and already-selected
operations remain fixed. Negative contrasts verify that adding a later update retains the earlier
exclusion; they do not silently strengthen a read declaration.

A review found that merely retaining the old U actor for a pending I call unnecessarily excluded
compatible parent reads. The reservation now retains its identity protection and only the read
authority the call needs. Cancellation-only use keeps the prepared prefix, but releasing a
non-owning capability does not dereference its root. Actual resource destruction is different and
remains pending. An explicit ownership transfer in a return expression still cannot change a
merely reserved place before that reservation is cancelled.

Every invocation checks its complete bundle before changing ownership. Existing-place reservations
are not activated as early I/U accesses, whereas computed accesses are already active. Duplicate X,
U/U and I/U bundles are rejected without declaration fallback. A child that ends during preparation
can permit activation afterward. Header result-origin candidates form alternative worlds, rather
than simultaneous exclusive accesses. Output access is reparented without retaining callee parameter
storage; returning a local/consumed root fails its stable bound before ordinary exit cleanup.

### Payload Closure and Scope

R, D and S remain separate. The bounded data domain is exactly `bool`, `i32`, `void` and the opaque
built-in `error`. The first three have trivial destruction and empty carried dependencies. The
owning error snapshot/storage contract guarantees a private immutable failure graph, no access to
construction views and no caller-managed region requirement. Its handle remains move-only and
owns graph release. A sealed exhaustive concrete payload certificate records those facts; it does
not derive independence from Copy, ownership, or an empty R set. Any future nominal, aggregate,
generic, closure, future or region-dependent shape must obtain its own dependency evidence.

This resolves the first-fragment D/S obligation from its actual data contracts rather than adding
a speculative general dependency solver or reading released compiler/standard-library internals.
The private goal still has no error constructor, user destructor, allocation API, fallible outcome
or suspended execution. Their effect/dependency proofs are not certified by this checkpoint.

### Selected Evaluation and Ownership Rules

A review found that a fresh X call operand could supply I only when Copy was available. Reading a
fresh move-only value does not require duplication. The checker now selects a distinct owned-read
preparation action. Explicit evaluation frames keep the owned temporary through the enclosing
statement, condition or block-result evaluation. Its R identity is a temporary root, not a local
invented to rescue a dangling result. A discarded access can finish before that temporary is
destroyed; a saved access used in a later statement or returned out of the function fails. No
source syntax changes or implicit Copy/clone are introduced.

The shared forward solver now retains logical owners beside access worlds, independent of access
liveness. The owner map and ordered evaluation stacks use finite existing holder identities;
no runtime token counter, unbounded event history or arbitrary iteration cutoff participates in
the fixed point. Each action records before/after ownership alternatives and its ordered steps.
Receiving a callee result is distinct from constructing a fresh value and does not acquire another resource.
Named R survival reads the owner map directly; there is no second survival index.

Preparing a computed X input moves its obligation into the prepared prefix; successful invocation
transfers it to the callee. An interrupted invocation destroys prepared owned arguments in reverse
order. Merely reserved named owners survive cancellation, and earlier explicit moves are not rolled
back. I input temporaries stay caller owned until evaluation cleanup. Nested evaluation, call and
lexical frames close in nesting order; staged and forwarded X results leave the destroyed frame.
Primitive operand/condition snapshots consume only admitted trivial payloads. Compound assignment
retains checked arithmetic; no optimization proof is inferred from this ownership accounting.

Replacement uses the RHS-completed state. Conditional alternatives dispose exactly the old owner
actually present, and `value = ^value` has none to dispose. U assignment either updates the named
owning root or records disposal/replacement of the initialized caller input payload. Every normal
return has empty evaluation frames and exactly the X result owner, or none for I/U. Paths that
trap or diverge do not acquire source unwinding or an eventual-cleanup guarantee.

The transition report is source neutral and retains guards as ownership-state alternatives, not
a flattened unconditional destruction list. A target consumer must realize those transitions,
error-storage disposal and checked primitive operations under its layout/runtime contract. No
released checked-program adapter, CLI language switch, native consumer or executable cleanup
qualification is added. Whole-unit source reuse verifies all original body bytes and the same
header authority before exposing any current-source projection.

### Counterexamples and Validation

New source tests contrast prepared ownership with named reservation, cancellation with invocation,
discarded temporary access with saved/returned access, and conditional replacement with a
self-transfer. They cover U replacement into local and external roots, loop ownership restoration,
nested condition exit, whole-unit rejection of unsafe unused callees, mutually recursive ownership
forwarding, and exact-current whole-unit rebinding. Direct invalid-state tests reject duplicated
ownership, double destruction, repeated transfer and a missing owned result. These are finite-domain
invariants and adversarial conformance tests, not a mechanized general soundness proof.
