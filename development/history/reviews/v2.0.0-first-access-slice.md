# v2.0.0 First Access Validation Slice

## Status and Authority

This record bounds the first front-end implementation task after the broad
[readiness audit](v2.0.0-implementation-readiness.md). It is a development work contract, not a
second language authority. The owning future
[grammar fragment](../../../spec/language/syntactic-grammar.md#first-access-validation-fragment),
[value-access rules](../../../spec/language/value-access.md), and
[assignment/flow rules](../../../spec/language/bindings-and-initialization.md#future-direction-v2-0-0-assignment-and-flow)
define source meaning. Current released behavior remains unchanged.

S11's `&place` is adopted. Its semantics, bounded function/body grammar, source requirements,
and finite delegation/init model are recorded. The syntax implementation checkpoint below now
uses the production parser. Declaration/body checking, full-language composition, and native
execution remain unimplemented for this future fragment. No further human spelling decision
blocks this particular slice.

## Boundary and Deferred Composition

The first accepted product is checked front-end evidence for one supplied private module, not a
native executable, package-discovery replacement, or alternate public language version.

| Included | Required distinction |
| --- | --- |
| Named private functions and direct named calls | Declaration identity and complete I/U/X contracts selected before operand permissions |
| `bool`, `i32`, `void`, opaque `error` | Scalar/unit Copy versus move-only error; no error construction needed |
| Inferred/annotated scalar locals and discard | Existing place read versus fresh X, explicit transfer, or supplied U |
| `&place`, `^place`, grouping | Immediate delegation versus ownership extraction; no direct call assertions under grouping |
| Primitive arithmetic/comparison/logical operations | Fresh scalar X; short-circuit edges; existing checked numeric semantics |
| Whole-place assignment and explicit drop | RHS-first state, conditional old cleanup, definite initialization |
| If results, while/loop, break/continue, return | Alternative worlds, backedge fixed point, last uses, normal cleanup then handoff |

Nominal fields/indexes/ranges, destructors, tuples/patterns, generic evidence, aliases and compound
type trees, structural/erased callables, closures, async/outcomes, module contracts, CTFE, effects,
standard-library migration, ABI and native execution remain separate closure/implementation tasks.
This temporary task boundary must never become a restriction of the full language. In particular,
using scalar values here does not establish that owning values generally have empty D/S.

The `V2CoreUnit` parse goal is for development conformance. It does not make bodies legal in
`index.nct`, add a user-selectable compatibility flag, or permit current `&`/`&+` borrow meanings
to coexist with future update semantics in one accepted program. A final v2.0.0 product must
remove transitional authorities rather than retain two checking paths.

## Adjacent Product Obligations

Before changing production crates, read their current contracts and derive narrow changes from
these owning rules. Do not add a parallel compiler or source-text semantic oracle in the corpus.

1. **Syntax owns recognition.** Preserve prefix operator and operand trees, type qualifier
   positions, full function headers, grouping, statement boundaries, and structural direct-marker
   violations. Retain invalid non-place operands/targets for focused checking. No name/type
   lookup decides the parse. Add lossless shape assertions for this corpus in the owning syntax
   tests, including zero/one/many edges, newlines, grouping, and recovery.
2. **Declarations own contracts.** Publish one immutable identity/type/permission for each input
   and output, independent of source spelling and optimizer representation. Validate declarations
   before bodies, including unique names and result-origin eligibility. No std function lookup,
   heuristic Copy flag, or callee-body inspection supplies a missing contract.
3. **Checking owns actions and flow.** Separate the stored access permission of a named value
   from its natural initializer operation and its eligibility under a selected boundary. Record
   Copy, explicit transfer, delegation, reservation and commit as checked actions, not a later
   backend guess. Calculate source last-use/cleanup liveness, initialization and access alternatives
   to a conservative fixed point. Validate every loop/return/short-circuit edge and cleanup.
4. **Accepted evidence is complete.** Each selected call has checked operands, result access,
   and cleanup obligations; each transfer has a valid initialized owner; each U access has a live
   writable parent. Rejected or unsupported source cannot leak a partially accepted product.
   Diagnostics identify the attempted action, conflicting source/retained access, and relevant
   later use or backedge. Do not invent exact public codes before updating their owner.
5. **Consumers use decisions.** Later products receive identities and checked operations without
   rereading syntax, reselecting a callable, inferring permission from `&` text, or reconstructing
   liveness. Native acceptance waits for owning target/layout/cleanup and checked-operation
   contracts; front-end acceptance alone is not executable qualification.

The current architecture remains authoritative for stage direction. A concrete Rust product or
crate API is not declared by this review. Update the relevant crate README and adjacent boundary
contract together when an implementation responsibility actually changes.

## Source Conformance Product

The [corpus](../../compiler/tests/fixtures/v2-access/README.md) currently contains 44 inputs:
19 expected accepted units, 19 checked rejections, and six syntax rejections. Its manifest records
one unique primary source projection for each rejection. They are private module fragments, not
complete runnable packages and not current compiler fixtures selected by an automatic glob.

Important contrasting pairs include:

| Accepted requirement | Rejected requirement |
| --- | --- |
| U call reservation permits a later temporary read | An earlier `let edit = &value` already excludes that parent read |
| U parent updates after its read child's last use | U parent updates before the child's later read |
| X call from a read Copy access takes a snapshot | X call from an existing Copy owner still consumes it |
| `value = ^value` restores the moved slot | Compound assignment reads a slot consumed by its RHS |
| Both conditional branches supply X | A plain I place branch and a fresh X branch have no inferred common mode |
| Explicit expected X copies a scalar branch | Expected X cannot implicitly move a move-only source |
| Every continuing loop path restores ownership | A `continue` skips restoration, or a short-circuit path consumes before a joined use |
| Joined U alternatives access one root per path | Parent access conflicts with an active U child |
| Explicit transfer inside computed `if` operand | Direct call `(^value)` assertion hidden under grouping |

The inventory command validates registration, shapes, and source projections only. The owning
Rust syntax tests now validate parsing/rejection and shapes; compiler semantic acceptance,
checked rejection, and declaration input-order invariance remain pending. No Python parser is
introduced. Parsing a `check-reject` input is required and does not establish semantic acceptance.

## Syntax Implementation Checkpoint

`nocter-syntax` now implements `ParseGoal::V2CoreUnit` inside its production parser, sharing the
lexer, event/tree construction, token identities, newline rules, bounded nesting, and recovery.
It uses a distinct root and dedicated access-type, update, transfer, and unit nodes. It never calls
a released borrow/type/expression production as fallback. Ordinary `lex` and the released
`SourceFile` goal retain their earlier meaning; `^` punctuation is admitted by the future goal only.
There is no public CLI/source-version switch.

All 44 manifest inputs enter the actual syntax tests: 38 parse with reviewed lossless node-shape
snapshots, and six reject with source projections. Separate tests cover zero/one/many list and
operator edges, delimiters/newlines, comparison chains, grouping, nested computed operands,
callable-operand prefix restrictions, token subdivision, bounded recursion, lossless recovery,
and rebinding reusable syntax into another source identity. This does not close later type/name
rules or prove exhaustive full-language grammar coverage.

Direct call assertions use a typed `UnmarkedCallOperand` expectation rather than inventing a
contextual source keyword. The diagnostics projection emits `E0120` at the prefix, including
under grouping; the future owning diagnostic section defines that projection. Actual non-place
prefix operands still parse for later checking.

The released target-selection boundary now rejects a future core root with `InconsistentSyntax`.
It previously ignored a non-`SourceFile` root, which could leave its items absent and permit an
empty selection. A regression test verifies rejection, unchanged builder state, and acceptance
of a subsequent real source. Released formatting rejects the future root before spacing rules
run. These guards prevent an apparently successful mixed-language/empty program while semantic
migration is incomplete.

Focused validation passes 204 unit tests across syntax, target selection, diagnostics, and source
tooling, plus their doc tests and warnings-denied Clippy. The complete compiler gate was run;
its general workspace, CLI, and command stages passed. Its native suite passed 131 cases and
failed `public_tls_and_https_reject_plain_peers_and_https_advertises_http1` when an image exited
with status 1, so that invocation was **not** a clean full-gate pass.

The exact TLS case then passed alone, and all 12 `network_and_tls` cases passed together with
four test threads, without changing runtime code or weakening the test. The original output
does not identify its returned error code; do not claim that scheduling or a timeout caused it.
The fixture's one-second deadline is a possible investigation point, not an established cause.
The stopped gate's remaining stages were completed separately: all 118 language-server tests,
workspace `--no-default-features` checking, and warnings-denied workspace Rust documentation
passed. Documentation generator tests/build and fixture inventory validation also passed.

This is a verified syntax implementation checkpoint with a recorded non-reproduced native-test
failure, not a clean one-pass full-compiler or release qualification. Preserve that distinction
in follow-up work rather than hiding the failed invocation behind successful reruns.

```sh
cargo test --locked --manifest-path development/compiler/Cargo.toml -p nocter-syntax -p nocter-target-selection -p nocter-diagnostics -p nocter-source-tooling
```

The next implementation boundary is declaration identity/type/permission construction and body
checking for this goal. Do not reinterpret the new nodes through released borrow lowering or
claim that the 19 expected semantic rejections are already implemented.

## Finite Access-Flow Exploration

The [flow exploration](v2.0.0-access-flow-check.py) enumerates two whole owning roots, initialized
or uninitialized, and two access identities with I/U delegation parents. Explicit end events
assume a previously calculated last use; the script does not calculate source liveness. Read
siblings may coexist; U requires a writable parent and excludes unrelated overlapping accesses.
A child restricts its parent; ending a leaf restores only that parent's surviving authority.
A live access requires an initialized surviving root and an acyclic delegation chain.

It reaches 56 states and checks 364 transitions, rejecting 1,428 action attempts. Universal
checking across predecessor pairs accepts 1,640 join operations. Five invalid-state and five
invalid-transition mutants test dead/dangling roots, cycles, I-to-U upgrade, conflicting siblings,
parent update/read conflicts, and incorrect transfer state. Four selected loop scenarios check
reinitialization, a second-iteration failure, zero iterations, and restoration only on an exit.

The independent invariant checks use graph ancestry and initialized roots; they are still part
of a small executable model, not a mechanized preservation/progress proof. Root reservation and
result staging remain in their separate explorations. This model has no fields/ranges, D/S payload
graph, actual destructor execution, source CFG/liveness, callable effects, or asynchronous state.
The source fixtures are not parsed or executed by it. Its finite results cannot justify deleting
any general compiler validation gate.

## Entry and Completion Gates

This checkpoint supplies the grammar/semantics and distinguishing source inputs needed to start
bounded syntax/declaration/checking implementation. Implementation must preserve a coherent
language boundary; it cannot quietly mix released std contracts or borrow meanings into v2.0.0.
Do not wait for every optimization experiment or a full-language mechanized proof to start this
bounded task, and do not describe the task as a complete v2.0.0 migration.

The slice completes only when its production parser/declaration/checker consume the manifest,
assert accepted semantic actions and lossless syntax shapes, reject the other cases at the right
stage with local evidence, and cover every included grammar edge. Add combinations that invalidate
an initially accepted action after a join or later last use. Check discovery/declaration order
independence through actual owning APIs. Review that no fallback to the released model or duplicate
semantic authority remains in that accepted product. Run the focused owning tests and required
compiler gates then; documentation/model checks alone cannot close implementation.

Afterward extend the same model through projections/nominals and public contract matching, then
callable/generic/outcome/async composition. Keep native lifecycle and optimization evidence as
separate gates. No performance number follows from completing a source checker.
