# v0.49.0 Phase 1 Unified Runtime Wait Review

**Result: complete with no open Phase 1 defect.** The semantic wait vocabulary, host adapter, and
generated ARM64 wait root now implement one descriptor/timer/process model.

## Findings Closed During Implementation

### `pollfd` could not represent the adopted contract

The generated root no longer supplements `poll` with process-specific sleeps or status probes.
It builds compact Darwin changes from semantic records, submits them through `kevent64`, waits for
descriptor or process events with the nearest fixed deadline, and validates every delivered event
before publishing readiness.

### Process exit can precede native registration

Darwin returns `ESRCH` when a process exits before a new process filter is installed, including an
unreaped child. Treating that as a hard registration failure would make ordinary fast children
racy. Both adapters now convert only a validated process-change `ESRCH` into immediate readiness.
They do not call `waitpid`, decode status, or poll periodically; the future's owner retains exact
observation authority.

### Native ABI facts had two potential homes

`DarwinEventAbiSchema` is the sole record-layout and event-vocabulary authority. The narrow host
FFI crate validates the SDK binding against it, while generated lowering encodes from it. The host
reactor knows safe filters and tokens but no raw pointers; the task runtime knows semantic
interests but no Darwin values.

### The unfinished process API briefly widened an internal helper

The first implementation declared a package-visible `wait_process_completion` wrapper before any
other standard module consumed it. The standard declaration audit rejected that speculative
surface. Phase 1 now exposes only the compiler-owned primitive at its exact private source; Phase 2
will add the first cross-module operation together with its child-ownership contract.

## Responsibility Review

- `nocter-runtime-contract` owns semantic variants, numeric tags, round trips, and target ABI
  schema.
- `nocter-darwin-event-queue` is the sole audited host unsafe boundary and owns native pointer,
  buffer, descriptor, and interrupted-call safety.
- `nocter-darwin-reactor` owns logical-to-native registration projection and never owns or reaps a
  process.
- ARM64 change construction, wait orchestration, and event validation are separate source
  responsibilities. They consume schemas rather than copying constants.
- `nocter-task-runtime` retains generation-qualified task/registration lifecycle and cannot inspect
  process status or native records.
