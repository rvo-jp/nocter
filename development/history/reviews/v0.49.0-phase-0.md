# v0.49.0 Phase 0 Structured Process I/O Review

**Result: complete with no open design decision.** This review closes the process ownership and
runtime feasibility boundary before implementation begins.

## Findings Closed by the Contract

### Async convenience methods alone would preserve the wrong architecture

The current command-I/O session owns a blocking terminal operation. Wrapping it in `future T`
would either block the executor or duplicate launch and cleanup logic. v0.49.0 instead makes spawn,
child ownership, endpoints, and observation primary; closed status and output become compositions
over those authorities.

### The generated executor cannot currently observe child completion

Its wait mapping is built around `pollfd`, descriptor direction, and one separately calculated
deadline. `poll` has no child-completion subject. The runtime wait vocabulary must gain a process
variant and the native mapping must change as one design unit. A standard-library sleep or
`waitpid(WNOHANG)` loop is prohibited.

### Public Child destruction needs an owner after cancellation

An ordinary drop can occur through scope exit, error propagation, timeout, race cancellation, or
parent-future destruction. Requiring every caller to wait would make resource safety depend on
control-flow discipline. Blocking inside drop would violate executor safety. The contract therefore
requires a nonblocking, exact-owner transfer to a target abandonment service which terminates and
reaps the child.

### Pipe ownership and process ownership are different

An endpoint may be transferred while one `Child` retains the only process-observation right. Pipe
EOF can be delayed by descendants and cannot replace wait status. The design uses distinct owning
types and joins their futures explicitly instead of merging descriptor and child identity.

## Feasibility Evidence

- The active macOS SDK defines `EVFILT_PROC = -5`, `NOTE_EXIT = 0x80000000`, the 48-byte
  `kevent64_s` layout, `SYS_kqueue = 362`, and `SYS_kevent64 = 369`.
- The runtime contract already owns semantic wait variants, numeric record encoding, and readiness
  pointers in one schema.
- The task scheduler already gives registrations generation-qualified identities and removes a
  complete wait set before cancellation cleanup.
- Existing standard pipe code owns close-on-exec creation, descriptor normalization, local
  no-SIGPIPE writes, exact close, and typed syscall classification.
- Existing async interfaces and generic buffers need no process-specific compiler behavior.
- Existing structured `join`, `race`, and timeout operations can compose endpoint and child
  futures once their primitive waits are executor-safe.

## Responsibility Review

- The runtime contract owns the process-interest variant and ABI tag, not standard source or ARM64
  lowering.
- Reactors own native event registration and wakeup, not exit-status decoding or reaping.
- `std/process` owns public configuration, process and endpoint states, errors, and precedence.
- Target process operations own raw fork, exec, signal, wait, and native result facts, not public
  policy.
- MIR and machine layers consume frozen primitive roles and wait records; they cannot rediscover
  process semantics from declaration names.
- Editors consume checked declarations and semantic products; no process registry is added.

Phase 1 may begin without a source-language or public API decision from the user.
