# v0.50.0 Phase 2 Canonicalization Review

Date: 2026-09-14

## Result

The canonical and explicitly blocking filesystem surfaces now resolve existing entries to an
absolute owning UTF-8 path. The asynchronous operation is a typed bounded file-service job. Its
worker owns the input spelling, output storage, and temporary descriptor; caller storage is only
updated by completion consumption after the descriptor has been closed.

## Authority Review

- `DarwinFileOperation::Canonicalize` is the sole runtime operation identity. The job contract
  selects owned path input, worker-owned bounded output, no retirement input, and a transferred-byte
  result.
- The generated Darwin worker alone owns `open(O_EVTONLY | O_CLOEXEC)`, `fcntl(F_GETPATH)`, output
  termination validation, and temporary close. Standard source cannot construct an operation tag or
  inspect a worker record.
- `std/fs/path_output.nct` is the single allocation and UTF-8 construction policy shared by link
  target reads and canonicalization. Its capacity comes from the existing target `MAX_PATH_LEN`
  authority; no second path-size constant remains.
- `std/internal/io` maps the private primitive to the existing file completion and error contract.
  Public `std/fs` receives only a completion fact and an owning `Utf8Path`.
- The blocking twin uses the same target flags, path bound, UTF-8 conversion, and public error
  mapping without driving the executor or invoking the asynchronous surface.

## Failure and Ownership Review

Open and path-query interruptions may be retried because neither operation mutates filesystem
state. Close is attempted exactly once. A query failure remains authoritative if cleanup also
fails; a close failure after a successful query prevents publication of the path. Missing NUL
termination and undersized target buffers are rejected as invalid target progress. Non-UTF-8 target
bytes are rejected during the shared `Utf8Path` construction.

The worker never stores a caller pointer in a syscall-visible record. Job construction copies the
input path and reserves output bytes in the same allocation. Completion copies only the initialized
prefix after success. Cancellation and abandonment therefore reuse the existing job lifecycle with
no canonicalization-specific cleanup path.

## Verification

Focused verification covers the closed runtime job schema, generated ARM64 target family, host
conformance including undersized output rejection, complete native asynchronous symlink resolution,
complete native blocking canonicalization, authored standard-source checking, and semantic-editor
hover over the public contract.
