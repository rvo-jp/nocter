# v2.0.0 Parameter Defaults and Delegated Work

## Decision and Scope

On 2026-11-08 the user delegated the choice between default-read and default-value inputs, and
subsequent v2.0.0 design/planning/work, to the agent. **Select default read:** `value: T`,
`edit value: T`, `take value: T`. This reaffirms the basic S12 input policy after comparing the
alternative; it is not a decision to preserve it merely because it already exists. Public rules
belong to [Value Access](../../../spec/language/value-access.md#input-operations-and-receivers)
and [Callables](../../../spec/language/callables.md#future-direction-v2-0-0-value-access-callables).
The compiler still implements the pre-S12 private checkpoint. None of the examples below is
reported as compiled conformance or measured authoring/performance evidence.

The expanded delegation includes source alternatives and ordinary implementation sequencing.
Record and resolve them without waiting for approval of the next phase. Respect the user's
existing goals and later corrections. This does not authorize release publication, replacement
of qualified artifacts, or external messages.

## Alternatives Compared

| Operation | Selected default-read policy | Rejected default-value policy |
| --- | --- | --- |
| Observe | `func inspect(file: File): usize` | `func inspect(read file: File): usize` |
| Update caller storage | `func update(edit file: File): void` | Same |
| Receive a value | `func close(take file: File): void` | `func close(file: File): void` |
| Read receiver | `method self.len(): usize` | A uniform value-default would require `read self` |
| Read callback input | `func(File): usize` | `func(read File): usize` |
| Receive callback input | `func(take File): Product` | `func(File): Product` |

Both policies can encode the same three operations. Call sites omit assertions in both. Neither
policy alone improves generated code or lets a reader recover the input operation from an
ordinary call spelling. The actual operation belongs to the selected public declaration/type.

Choose the default by required reasoning, not by claiming an unmeasured keyword-frequency win:

1. An observational API should preserve a non-Copy input without constructing a separate value.
   Default read gives this contract directly. A type losing Copy cannot make that observation
   start receiving the caller's value; an explicit taking API instead advertises value supply.
2. Changed access is consequential API information. `edit` marks mutation of caller storage;
   `take` marks receipt of a value and its cleanup responsibility. Body inspection is unnecessary
   to learn either. Merely changing the body cannot silently strengthen the input operation.
3. Read semantics compose for unbounded generic T. A predicate/count/validation helper can read
   T without Copy evidence or extraction permission. A generic identity/storage helper genuinely
   needs a value and writes `take`; it cannot rely on a later Copy specialization to repair a body.
4. Use the same default for free functions, receivers, constructors, requirements and callable
   types. Constructor-specific or Copy-specific defaults would hide more rules and make abstract
   contracts depend on role/representation. Do not infer take from a name such as `close`.
5. Local value creation and callable input access are different boundaries. It is acceptable for
   `let x: T = source` to construct a value while `x: T` input reads one, provided the grammar and
   diagnostics teach that distinction explicitly. Type T itself is neither an alias nor an owner
   qualifier. The entire declaration, not the colon alone, selects the operation.

The cost is real: default-value would align ordinary inputs with local value initialization and
value results. Builders need explicit taking inputs in the selected policy, and a generic
`func identity<T>(value: T): T { value }` rejects without Copy. Read inputs also retain source
access during invocation; a permitted independent snapshot can support some overlapping-operand
uses that a read contract rejects. These are not defects the optimizer can erase from source
acceptance. We accept those costs to retain explicit value receipt and one stable input default.
There is no measured claim that observation dominates all workloads or that one policy is faster.

## Boundary Cases and Expected Contracts

| Case | Selected requirement |
| --- | --- |
| Observe a move-only file twice | Both calls preserve the caller's value |
| Close a move-only file | `take` transfers it; subsequent source use rejects |
| Supply a Copy scalar to `take` | Snapshot; source stays available |
| Read a large Copy aggregate | Read contract; no mandatory semantic snapshot merely due to Copy |
| Store unbounded T in a new owner | Taking input, or a proved Copy from read input |
| Constructor receiving a resource field | Explicit `take`; no constructor-role exception |
| Read T returned as independent T | Requires Copy at this source boundary |
| Change read input to take in implementation | Header mismatch/body failure, never inferred API replacement |
| Pass read input into a callback expecting take | Permitted snapshot only with Copy evidence |
| Concurrent overlap in one call bundle | Check selected operations and captures; no Copy/mode fallback |
| Anonymous callable input `func(T): R` | Read T, independently of environment invocation |
| Explicit `read value: T` input | Reject the redundant modifier form; a parameter named `read` remains possible |

### Anonymous Closure Completion

Keep contextual omission without body-selected access defaults:

```text
// A previously selected callback contract can supply missing operations.
func apply(take action: func(take File): File, take file: File): File
apply((value) { value }, file)

// Without a receiving contract, ordinary unmarked inputs default to read.
let invalid = (value: File) { value }        // rejects non-Copy extraction
let identity = (take value: File) { value } // delivers the received value
```

File and helper names are illustrative declarations. The first closure inherits its taking
input operation from the already selected callable type before its body is checked. An explicit
operation must agree. A data annotation supplies only data type. Without that context, an omitted
operation becomes read; the body may infer data/capture/environment/result facts but cannot choose
edit/take to make its own extraction valid. A later call cannot retroactively change a published
closure's operation. This tightens the earlier broad phrase "infer input requirements" so a bare
closure input does not have an unrelated body-dependent default.

Capture inference remains adopted. Capturing an outside owner by value is different from an
explicit parameter's default; name-only capture lists and checked body requirements retain their
selected capture rules. Environment `func`/`mut`/`once` is another independent contract.

## Work Chosen Under Delegation

Close the bounded value-binding private-unit grammar in its owning specification now, then derive
source cases from those rules. The intended replacement consumes the same internal private-module
goal, not a new user version switch. Scalar/unit/error data allow checking value/alias/input,
initialization, reservations, return and cleanup without waiting for the entire module/nominal/
async/library/ABI design. Full-language gaps do not justify more approval checkpoints.

The new source corpus is explicitly planned/unconsumed until the production parser/declaration/
typing/flow/access/resource boundary is replaced. Keep the old checkpoint evidence distinguishable.
Do not add a second parser or semantic oracle to "run" new expected cases. Freeze one new accepted
unit only after every definition validates under the replacement; then retire incompatible old
expectations. Independent projections/nominals/callables/outcomes/async extensions follow their
own owning contracts and proofs. Native work requires a closed executable consumer contract.

## Primary Evidence and Limits

- [Swift SE-0377](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0377-parameter-ownership-modifiers.md)
  separates borrowing/consuming/update conventions and explains why public convention matters.
  It also documents role-dependent defaults and ARC. Those choices are not imported into Nocter.
- [Hylo functions and methods](https://docs.hylo-lang.org/language-tour/functions-and-methods)
  describes its default immutable parameter convention and separate consuming/update conventions.
  Its explicit-copy and call-marker rules differ; it supplies a concrete design comparison, not
  evidence of Nocter's speed or a reason to copy its grammar.

These sources support separating operation contracts from transport strategy. No language's
existence establishes which spelling is easiest for Nocter authors. The selection above is a
reasoned design decision with explicit costs, not a user study or a general soundness proof.
