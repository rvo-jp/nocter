# v0.58.0 Phase 5 Binary Data Foundation Review

## Scope

This review closes the binary-data and protocol-foundation implementation milestone. It covers the
public scalar codec surface, package-private byte-order implementation, borrowed cursor composition,
fixed and dynamic storage, blocking and asynchronous writer composition, the runnable binary record
application, editor behavior, documentation, and clean-installation execution.

## Findings and Resolution

### Existing network code held a second byte-order implementation

The first implementation placed the new codecs behind one public module but left manual base-256
conversion in IPv6 values, address parsing, socket hashing, and the Darwin socket adapter. Those
operations were correct, but they made byte order a second authority outside the new foundation.
`std/internal/bytes` now owns the package implementation and the exact two-byte helpers required by
network representation. Public `std/bytes` delegates to that implementation, while network modules
depend only on its package-visible contract. A repository search leaves one unrelated base-256
operation in Darwin process wait-status decoding; that operation interprets an operating-system
status bitfield rather than a byte sequence.

The same review found a stale module comment claiming that the Darwin network adapter still owned
byte order. Its documentation now confines that adapter to native address and polling layouts,
socket constants, and syscall classification, and names `std/internal/bytes` as the byte-order
authority.

### The practical example initially bypassed two repository-wide gates

The new `binary-record` directory was discoverable as a public package but was absent from the
repository-owned process-contract catalog. The complete command test rejected that mismatch. The
catalog now fixes its usage failure, successful output, and exact 18-byte wire image. This protects
field order and endianness as observable behavior rather than merely checking that execution exits
successfully.

The example also contained a module comment unsupported by the current source formatter and had
not been normalized with `nocter fmt`. The repository-wide formatter test rejected both facts. The
comment was removed because `examples/README.md` already owns the example description, and both
source files now equal canonical formatter output. No formatter exception or test weakening was
introduced. These two failures were omissions in the focused implementation pass; the existing
discover-all gates detected them as designed.

## Authority Review

`std/internal/bytes` performs every integer byte-order calculation. `std/bytes` is the public
contract boundary and adds only IEEE bit-preserving projection through the existing `f32` and `f64`
bit APIs. It owns no cursor, allocation, or I/O state.

`scan.ByteCursor` remains the only borrowed forward-position authority. Scalar methods decode the
remaining slice, then call the cursor-owned `advance_exact`; short input changes no offset.
`fixed.ByteBuffer<N>` remains the only bounded staging authority. Scalar methods encode into its
initialized spare slice and commit the complete width only after success. `Vec<T>` performs one
complete reservation before copying a slice, and both writer interfaces consume that same encoded
slice without another codec or framing rule.

The public wrappers around the package implementation are intentional visibility boundaries, not
parallel algorithms. Compiler-side target serializers, hashes, and stable identities retain their
own explicitly specified binary formats and do not reinterpret Nocter semantic values or implement
the standard-library API. Review found no source-text reconstruction, host-native cast, duplicated
cursor, partial write exposure, compatibility fallback, or caller-maintained invariant.
