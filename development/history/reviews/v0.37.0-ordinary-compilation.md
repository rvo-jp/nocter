# v0.37.0 Ordinary-compilation Performance Review

**Result: complete (2026-09-06).** The ordinary single-file and package check paths are materially
faster without an on-disk cache, source-semantic shortcut, or compiler mode split. The work removes
three kinds of reconstruction from the shared command/LSP semantic path.

## Attributed Causes

The preceding performance work improved incremental finalization and repository verification, but
an ordinary command still rebuilt immutable compiler input and body-local interpretation data.
Inspection and alternating measurements identified three owned boundaries:

1. `DiscoveredUnit` retained normalized sources and parsed syntax, but reconstructed
   `CompileUnitInput` whenever a semantic consumer requested it.
2. Every reusable typed body rebuilt a `TypeId` map for the complete prepared-program prefix and
   scanned that prefix again during replay, although `TypeStore` is append-only persistent storage.
3. Name and body queries independently traversed the same current body to build
   `BodySyntaxProjection`; final lexical and typed materialization repeated that traversal again.

## Design Result

Discovery now constructs and retains one immutable `CompileUnitInput`. `SourceMapHandle` and
`SyntaxTreeHandle` let the input share discovery-owned storage while preserving borrowed
constructors for focused clients. Invalid shared syntax indexes are rejected at construction.

`TypeStore::cursor` identifies the immutable prepared prefix. Prefix compatibility is proven from
persistent allocation identity in logarithmic time, and a body recipe classifies only the dense
suffix after that cursor. It no longer builds a complete-prefix `HashMap` or compares every program
type during capture and replay.

`BodySourceCatalog` now owns one entry per `BodyId`. Each entry contains the syntax handle, body
identity facts, and its sole current-generation `BodySyntaxProjection`. The catalog is constructed
once when the current body context opens, then shared by name resolution, checking, recovery, and
canonical materialization. `CatalogedBodySource` keeps a body and its locator table inseparable;
callers cannot pair independently selected values.

These are authority changes rather than memoization layers. No invalidation key, semantic result,
diagnostic rule, target decision, ABI rule, or editor-only interpretation was added.

## Scope Decision

Remote-package HTTP initialization was inspected but not changed. The measured structural work
already produced a large improvement, while no isolated evidence showed transport setup to be the
remaining dominant cost. Making acquisition lazy without that evidence would widen error timing
and CLI policy solely for a speculative startup gain.

A persistent disk cache remains out of scope. It could reduce repeated fresh-process compilation
further, but requires artifact identity, eviction, compatibility, and corruption contracts that
are not justified by the current milestone.

## Review Conclusion

The optimized path has one immutable compile input, one append-only type-prefix identity, and one
current body-source projection authority. No later stage reconstructs those facts from syntax,
filesystem topology, or rendered identity. The changes reduce both latency and memory while making
the ownership boundaries stricter; no benchmark-specific path remains in production code.
