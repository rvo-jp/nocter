# v0.67.0 Phase 4 Source-neutral Configuration Review

**Result: complete with no open Phase 4 finding (2026-09-23).** The configuration core now owns one
typed overlay transaction without importing JSON, process-environment, command-line, filesystem,
service-lifecycle, or logging representations.

## Authority Review

`storage.nct` is the sole owned representation for field declarations, source candidates, builder
slots, normalized values, provenance, and finalized configuration. Public declarations expose only
opaque owners and typed operations. An adapter can construct a `Source`; it cannot inspect or mutate
builder slots, set provenance independently, bypass constraints, or publish a mutable finalized
value.

`schema.nct` owns field-name validity, uniqueness, kinds, and constraint construction. Consuming
field modifiers update the owned declaration in place, so adding representation fields cannot leave
a parallel reconstruction helper stale. `source.nct` owns source-name validity and source-local
uniqueness but deliberately has no schema knowledge.

`builder.nct` owns the only normalization and precedence decision. It first resolves every source
entry to a schema slot and an owned normalized value, then mutates slots in a separate pass. Thus an
unknown field, type mismatch, parse failure, or constraint failure cannot partly publish a source.
Application order is explicit call order; source labels carry no precedence. Finalization performs
required-field validation and consumes the builder, leaving no mutation path on `Configuration`.

`configuration.nct` owns typed observation, provenance borrowing, and presentation. Accessors return
none only for an absent optional field and return a named error for an unknown field or kind
mismatch. They do not claim `noalloc`: rich failure diagnostics allocate even though the ordinary
success path only borrows or copies. `display` redacts schema-classified secrets before inspecting
their value kind.

## Findings and Remediation

Review found two implementation-shape defects before qualification. Field modifiers initially
rebuilt every representation field and manually copied the constraint enum; owned local mutation now
eliminates that duplicate representation knowledge. Accessors initially declared `noalloc` despite
allocating field-specific diagnostics on failure; the false contract was removed rather than
weakening diagnostics or hiding the allocation in a helper.

Borrowed-loop early returns also exposed an ownership conflict during whole-library checking.
Source application now consumes its entry list after retaining one owned source label, and required
field discovery returns an owned name before consuming the builder. These are explicit ownership
transitions rather than compiler-specific escape hatches.

No second schema validator, precedence table, provenance writer, redaction path, or adapter-specific
configuration state remains. Linear schema lookup is intentional for this first core: introducing a
second index before application evidence justifies it would add synchronization authority without
changing the bounded application contract.

## Qualification

The complete bundled standard library crosses the target session. Seven configuration tests compile
to native images and execute through the native test runner, covering caller-order replacement,
typed text normalization, immutable observation, provenance, atomic source rejection, duplicate
schema and source names, required fields, modifier/constraint composition, typed-accessor failure,
and secret-safe diagnostics and presentation. Focused Rust formatting and Clippy, workspace-library,
documentation-generation, and repository-integrity gates complete the phase boundary.
