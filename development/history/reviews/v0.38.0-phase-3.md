# v0.38.0 Phase 3 Floating-Point Qualification Review

**Result: implementation and release-candidate qualification complete.** Floating-point values now
cross source syntax, semantic checking, constants, Machine ABI, ARM64 execution, standard numeric
text, formatting, interpolation, JSON, examples, and editor queries without a second value
authority. The final v0.38.0 identity also passed reproducible packaging and fresh installed-home
qualification.

## Authority Review

The review traced one value from authored decimal text to every observable boundary:

1. `nocter-syntax` owns the accepted token shape and publishes one value-free decimal/suffix
   projection.
2. Checking and constant planning map that shared suffix projection to `FloatFormat` and ask the
   target evaluator for exact IEEE bits. They do not call a host float parser.
3. `ConstantValue`, MIR, and Machine retain typed binary32 or binary64 bits. Machine layout owns
   stored size, alignment, transport class, argument-bank placement, stack placement, and result
   placement.
4. ARM64 consumes Machine scalar and transport contracts to select instructions and registers. It
   does not inspect semantic types or repeat callable dispatch.
5. `std/num` owns runtime decimal parsing and `std/fmt` owns shortest decimal generation. Type
   methods, `Format`, and interpolation are adapters over those implementations.
6. `std/json.Number` retains its exact validated token as its representation authority. Float
   conversion uses the numeric parser and formatter; it does not add a JSON-specific IEEE parser,
   formatter, or approximate stored value.
7. LSP features consume the ordinary checked semantic snapshot. No editor-only floating parser,
   type inference rule, or presentation identity exists.

## Findings and Remediation

The complete review found two concrete boundary gaps.

- Floating suffix decomposition was repeated in lexical validation, ordinary body checking, and
  constant planning. A future suffix change could therefore have made constants and runtime
  expressions disagree. `FloatLiteralSpelling` now makes syntax the sole decomposition authority;
  semantic consumers only map its typed suffix and evaluate its decimal component.
- Runtime float parsing allocated arbitrary-precision storage but exposed only an aborting API.
  `f32.try_parse` and `f64.try_parse` now preserve invalid text and range loss as inner optional
  absence while reporting temporary-storage allocation failure through the outer result. Ordinary
  `parse` invokes the same recoverable implementation with the current allocator and converts only
  allocation failure to the standard abort policy. `FloatBig` has one fallible mutation path based
  on `Vec.try_*`; no second parser was introduced.

The standard dependency review records the resulting `num -> internal/mem` policy edge. No stale
unsupported-float branch, compatibility fallback, semantic-type recovery below CheckedProgram,
ABI reclassification below Machine, partial/total-order conflation, host-dependent production
evaluation, or editor-only meaning remains in the reviewed implementation.

Native tests cover scalar and aggregate transport, independent general and floating argument
banks, stack arguments, returns, call-crossing spills, constants, arithmetic, comparisons, NaN,
infinities, signed zero, subnormals, integer conversion, and binary32 widening. Standard-library
tests cover exact parsing, ties-to-even boundaries, shortest round trips, recoverable allocation,
`Format`, interpolation, JSON conversion, and retained-token generation. One public single-file

output.

The editor qualification uses complete and recovering floating sources and exercises hover,
completion, signature help, definition, references, rename, semantic tokens, and inlay hints
through the same semantic authority. The source formatter preserves authored floating literal
spelling while formatting the surrounding expression.

Two complete disposable-target compiler gates verified repository metadata, Unicode table
reproduction, Rust formatting, warnings-denied all-target Clippy, all enabled locked workspace
tests, no-default-features checking, and warnings-denied Rust documentation. Public documentation
generation and repository whitespace validation also passed. Two independent optimized package
builds produced byte-identical archives and recursively identical installed homes. Fresh extraction
passed every public example, native execution, framed LSP analysis, home immutability, and compiler
and standard-library tamper rejection. The ignored public-HTTPS dependency-acquisition test passed
explicitly without an external Git executable.

## Conclusion

The implementation has one lexical spelling authority, one target-aware compile-time evaluator,
one Machine ABI decision, one runtime parser, one runtime generator, and one semantic editor path.
