# v0.51.0 Phase 5 Execution Contract Closure Review

Date: 2026-09-14

## Result

The implementation and architecture review is complete. The execution-contract area has one
syntax-to-guarantee projection, one checking-owned execution relation, one runtime-owned primitive
fact authority, and explicit temporal products for immediate invocation and deferred drive. No
current consumer reconstructs execution mode from `future T`, source names, or target operations.

## Findings and Remediation

### Duplicate callable-modifier projection

Declaration headers, declaration-level structural callable types, and body-local callable types
each inspected `NoAllocationModifier` and `BlockingModifier` independently. The semantic result was
currently equal, but adding another guarantee could have changed one path without changing the
others.

`nocter-declaration-lowering` now owns one exported, fallible
`project_callable_guarantees` operation. All three syntax paths consume it. The operation rejects a
non-callable syntax node instead of silently returning the default contract, removing a
caller-correctness precondition from the cross-crate API. Unit coverage proves declaration and
structural-type syntax produce the same contract and that an invalid node is rejected.

### Misnamed cleanup effect product

Ownership published `CleanupEffect`, although the value did not classify allocation or blocking.
It froze the exact drop declarations selected for a cleanup plus whether destruction remained
unknown. The old name obscured ownership authority and invited execution analysis to treat it as a
parallel effect summary.

The product is now `CleanupDependencies`, and its resolver is
`DestructionDependencyResolver`. Execution analysis consumes only those frozen dependencies; it
does not reopen type, declaration, copyability, or opaque-witness structure.

### Partial checked-call execution product

`CheckedCallExecution` stored a deferred output but required provenance and loan consumers to pass
the containing node's result separately for an immediate call. Correctness therefore depended on
each consumer pairing two related values correctly.

Immediate and deferred variants now both carry their execution-scope result. The semantic rebinder
updates either variant, and relation consumers ask the checked execution product directly without
supplying an independently recovered result identity. The containing node's invocation result
remains separate because a deferred call produces an outer future during invocation.

### Primitive roles could acquire implicit safe execution facts

The first closure review confirmed that primitive facts came from the runtime contract, but the
runtime contract itself used independent positive role lists for allocation, synchronous waiting,
produced computations, and hidden contexts. A newly added primitive omitted from those lists would
silently receive the most permissive profile: allocation-free, nonblocking, immediate, and without
ambient context. Exact-list tests did not close this hole because an omitted new role would not
change any positive list.

`nocter-runtime-contract` now owns one exhaustive `PrimitiveRole` projection to a typed runtime
profile. The profile assigns invocation facts, produced-computation classification, and hidden
contexts together. The match has no wildcard arm, so extending the closed role enum without making
the complete assignment is a compilation error. Target validation still consumes the same public
fact and context contracts; no downstream stage learns the profile representation.

## Repository-wide Boundary Review

Searches and call-site inspection confirmed:

- only syntax recognizes the modifier tokens, and only declaration lowering maps them to semantic
  callable guarantees;
- `ExecutionFactTable` is produced once during final checking and is not recomputed by analysis,
  target, MIR, machine, native, or editor code;
- checked operations and ownership-selected cleanup dependencies are the only source-body inputs
  to execution relation collection;
- missing callable, closure, drop, evidence, and body identities are integrity failures rather
  than conservative fallback facts;
- conservative facts enter only through the explicit `ExternalContract` edge for implementations
  unavailable by design;
- primitive execution behavior is keyed by closed runtime roles and compared with authored
  declarations at the target boundary;
- every primitive role is assigned one complete runtime profile by an exhaustive match, so an
  unclassified role cannot inherit permissive execution facts;
- target and MIR inspections of `future T` validate an already selected execution or
  representation contract and do not classify a callable as asynchronous;
- editor presentation consumes authored guarantees and declaration execution only; inferred
  implementation facts cannot synthesize source modifiers;
- executable and MIR execution products are stage-owned specializations or validated projections,
  not independent semantic discovery.

After reopening Phase 5 for the primitive-profile finding, no remaining old execution-effect table,
duplicate modifier mapping, temporal-scope guess, permissive primitive default, or
caller-correctness precondition with current impact was found in this area.
