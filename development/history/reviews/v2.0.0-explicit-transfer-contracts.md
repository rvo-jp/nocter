# v2.0.0 Explicit Transfer Contracts

## Status and Authority

The user adopted mandatory postfix transfer on 2026-11-09. The normative owner is
[Value Access](../../spec/language/value-access.md#explicit-transfer-sources), with syntax in
[Postfix Transfer Sources](../../spec/language/syntactic-grammar.md#postfix-transfer-sources).
This record explains consequences, alternatives and future qualification obligations. It does
not implement parser/checker support, executable cleanup, editor behavior or native performance.

This supersedes implicit movement of existing owners in S12–S23 and the name-only non-Copy
value captures selected in S13. Binding/input operations, ordinary data types, complete repeated
headers, source-context Copy evidence, dependencies and cleanup remain under their owning rules.
The released specification and product are unchanged.

## Source Retirement Is Worth Showing

```text
let file = open(path)?
consume(file^)              // retire this existing source
consume(open(other_path)?)  // no existing source to retire

var count = 10
let snapshot = count       // independent Copy value; count survives
let transferred = count^   // count is unavailable, even though i32 permits Copy
count = 20                 // var can restore its slot

let product = buffer^.finish()?
```

These are schematic uses with independently declared signatures. The caret identifies the
source that becomes unavailable. `take` identifies receipt at the destination. They do not
repeat the same fact: a fresh value or Copy snapshot can supply take without a caret; a marked
owner can instead supply a caller-owned temporary that lends read/edit access. The latter does
not promote the callee's access into ownership or let an escaping result retain a dead temporary.

The rejected alternative was permitting unmarked moves or making a caret on Copy data silently
copy. That would make availability depend on later type substitution and weaken the visible
meaning of the operator. Copy remains useful for ordinary unmarked supply; a written transfer
has one meaning across generic and concrete code. A caret does not authorize extraction through
read/edit aliases, user index/current projections or static storage, including Copy referents.
A fresh value/repeated transfer cannot take a redundant caret. No type/name/prefix alternative
or overloaded caret is introduced.

Postfix placement composes with chains. `record.field^` transfers the field, while `record^.field`
first acquires the whole record and then computes a component value, with normal remainder
cleanup. A direct `buffer^.finish(args)` retains a marked receiver through argument preparation.
`callback^(args)` similarly transfers the callable source without choosing its invocation view.
Exact token jointness, generic lists and suffix recovery still require parser qualification.

## Preserve the Existing Commit Protocol

```text
send(data^, load_options()?)
let pair = (file^, load_options()?)
```

For compatible declarations, the first direct transfer remains reserved until the whole call
bundle is ready. Later recoverable argument failure releases that reservation; data has not
moved. Marked Copy data follows the same protocol. An unmarked Copy taking argument instead
snapshots when prepared. Reads that finish during later operand evaluation can be valid, whereas
a surviving overlapping read input conflicts with retirement at invocation. No Copy fallback
repairs that conflict.

The second example constructs its first tuple component before the next operand. That transfer
has already committed on later failure. Nested calls, explicit outcome extraction and computed
field selection likewise retain their own earlier acquisition boundaries. Transparent grouping
alone does not change a direct call source into an eager transfer. Making every caret eager
would unnecessarily revoke the established interrupted-preparation guarantee.

Required backing and complete root/access validation precede invocation commit. No user callback,
destructor, recoverable failure or suspension may be inserted inside that commit. Async calls
receive values at creation, not drive; `await pending^` acquires the future at await start.
Pending cancellation preserves the actual state, without undoing completed transfers.

## Uniform Boundaries without Marking Synthesized Slots

An existing named owner requires its caret at value bindings, replacement, return/body result,
throw, outcome acquisition, await, taking branch/loop sources and explicit value capture. Named
take parameters, handler locals, pattern leaves and capture slots are existing owners again.
For example, `return value^`, `throw reason^`, `stored^?` and `(file^; path: Path) { ... }`
retire their respective sources. A caret inside a closure body cannot hide a formation-time
outside move; that requires the capture segment. Read/update/Copy capture inference remains.

Anonymous received/produced carriers can hand off internal components through their already
selected protocol without invented source tokens on compiler slots. Pattern decomposition and
intrinsic cursor delivery preserve cleanup and dependencies; they cannot use this rule to move
an unrelated named source. A fallible scoped projected `?` cannot implicitly extract the local
carrier's error: explicit carrier value acquisition or local recovery is required. Optional
absence propagation, which transfers no payload, remains distinct.

`...array^` transfers the whole array into the expansion evaluation owner, including empty/Copy
arrays. It does not leave partial holes in the original array. A direct intrinsic spread reserves
that acquisition through outer invocation preparation. An unmarked take spread needs component
Copy evidence. `pack^` is a sequence-only operation in captures, loop sources and expansion:
it transfers all owned components, including Copy keys/values, while original count metadata
remains. A read/edit pack cannot surrender caller components. `let value = pack^` does not
create a first-class pack data type. User-source acquisition remains an inner invocation.

Direct `drop name` and implicit cleanup require no caret: they dispose actual remaining state
rather than supply a complete value elsewhere. This distinction permits partial-container cleanup
while a complete transfer is invalid. Parent destructor preconditions and restoration checks
continue to apply, including recoverable failure and cancellation paths.

## Prototype Migration Boundary

The implemented private grammar/capture scope has moved from the normative chapters to the
[pre-S24 prototype snapshot](v2.0.0-pre-explicit-transfer-fragment.md). There is one current
language authority and one explicitly non-normative implementation record. The unchanged private
compiler's 283 cases (147 accepted, 122 checking rejections, 8 header rejections, 6 syntax
rejections) qualify that prototype only, not the new transfer syntax. This checkpoint changes
no compiler source or fixtures and does not claim current source conformance from those results.

Migration must replace implicit supply atomically through syntax, selected operations, direct
reservation, initialization, access and resource consumers. Record source retirement once, before
specialization, instead of inferring it again in lowering. Distinguish an unmarked Copy snapshot,
marked Copy transfer, fresh value and non-owning place. Captures need formation-source identity
separate from invocation slots. Preserve complete bundle validation, adapters, frozen witnesses,
known-but-unproduced contracts, partial cleanup, roots and actual invocation channels. No second
ownership ledger or selectable compatibility source mode is permitted.

Audit old accepted programs by their intended semantics before editing the source corpus: adding
carets mechanically could change Copy availability, capture timing and preparation failure paths.
Do not count unconsumed LSP/native tests as evidence for this private frontend migration. The
broader temporary-update protocol still needs coherent admission, separately from a direct
marked transfer to a taking input. Close both before claiming their composed behavior.

## Future Conformance Obligations

These are required tests, not passed production cases:

| Case | Required result |
| --- | --- |
| Existing non-Copy source, marked versus unmarked | Transfer versus local missing-transfer diagnostic |
| Copy source, marked versus unmarked, including generic substitution | Retired versus preserved; no later operation reselection |
| Fixed source versus mutable source after transfer | Reject restoration versus permit complete replacement |
| Read/edit alias, static, user index/current projection plus caret | Reject missing owning source, even for Copy data |
| Fresh value, repeated caret and prefix/type/name marker | Reject invalid source or retired syntax without reparsing |
| Field/array element versus marked whole owner selection | Exact selected source retirement and remainder cleanup |
| Missing component, dynamic overlap or complete-parent destructor | Preserve initialization/conflict/cleanup proof obligations |
| Direct input/receiver/callable transfer followed by failed preparation | Release uncommitted reservation, including Copy data |
| Completed later read versus simultaneously surviving overlapping input | Permit first when proved; reject second, without Copy repair |
| Nested construction/extraction followed by outer failure | Preserve committed inner transfers and exact cleanup |
| Marked source to read/edit and result retaining temporary storage | Caller-owned loan; reject escaping destroyed root |
| Explicit marked capture, unmarked Copy capture, missing non-Copy capture | Formation transfer, snapshot, rejection; no body-driven outside move |
| Captured slot transfer versus body-local transfer | Require owning environment only for the former |
| Named return/throw/catch/pattern/await source | Require caret; preserve ordinary success/failure/drive boundary |
| Anonymous pattern/cursor payload handoff | Preserve checked internal transfer without hidden named-source move |
| Fallible projected question mark on local owned carrier | Reject hidden failure extraction; explicit value acquisition remains available |
| Array spread: marked empty/Copy/non-Copy versus unmarked take | Whole-source retirement versus component snapshots with evidence |
| Pack capture/spread/loop: marked Copy keys and non-Copy values | Retire every owned component, retain original metadata |
| Read/edit pack marked acquisition | Reject caller-component retirement; ordinary Copy snapshots remain possible |
| User-source pull before outer failure | Preserve earlier acquisition/pull transfers and producer cleanup |
| Pending cancellation during preparation versus after receipt | Release reservation versus destroy actual received state once |
