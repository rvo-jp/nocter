# v0.64.0 Phase 4 Application Encoding and Identity Review

**Result: complete with no open Phase 4 finding (2026-09-20).** Strict byte codecs, incremental
SHA-256, canonical UUID values, cryptographic URL tokens, and their public example cross the
ordinary checked-source and installed-standard-library paths. Release preparation remains a
separate operation because version authorities and distributable artifacts have not changed.

## Reviewed Surface

The review followed hexadecimal digits, Base64 alphabets, SHA-256 state, UUID storage and text,
random-byte acquisition, public formatting and hashing, module dependencies, native-session tests,
and the complete public-example runner. It also searched compiler crates for similarly named host
operations and classified whether application code could observe or call them.

Historical release records and generated distribution copies were not treated as active source
authorities. They remain immutable evidence for their published versions.

## Authority Trace

| Responsibility | Sole application authority | Consumers |
| --- | --- | --- |
| hexadecimal digit classification and emission | `std/internal/ascii` | hexadecimal, URL, JSON, network, and HTTP source |
| complete-byte hexadecimal policy | `std/hex` | digest and UUID values plus applications |
| standard padded and URL-safe unpadded Base64 policy | `std/base64` | random tokens plus applications |
| incremental SHA-256 state and finalization | `std/digest/Sha256` | one-shot digest composition and applications |
| digest storage and canonical projections | `std/digest/Sha256Digest` | formatting, hashing, ordering, parsing, and applications |
| UUID storage and canonical projections | `std/uuid/Uuid` | formatting, hashing, ordering, parsing, and applications |
| target entropy adaptation and public failure | `std/internal/entropy` and `std/random` | UUID version 4, URL tokens, hashing, and applications |
| URL-token composition | `std/random` | applications |

The compiler retains host-side SHA-256 and hexadecimal operations for artifact integrity, package
identity, Mach-O signing, source syntax, and URI decoding. The CLI also retains a Base64 encoder for
its versioned JSON transport. Those operations cannot be imported by Nocter source and do not
select standard-library behavior; replacing one does not require changing an application
contract. They are therefore distinct tool responsibilities rather than duplicate public
authorities.

## Corrected Findings

HTTP request-target validation and decoding still contained a local case-insensitive hexadecimal
classifier after URL, JSON, and network source had moved to `std/internal/ascii`. The HTTP copy was
removed, leaving one package-internal digit decision for every standard consumer. `std/hex`
deliberately layers its stricter lowercase-only byte-sequence policy over that narrower authority.

The first complete verification run found that the new nondeterministic public example had not
been registered in the exhaustive CLI output-contract table. The example already passed its
focused native test, so this was not an execution defect. The runner now checks the stable content
digest, canonical lowercase UUID shape and version/variant bits, and exact URL-safe token width and
alphabet. It still rejects every discovered example without an explicit observable contract.

The next complete run found that the native codec target still expected the six cases that existed
before the final hexadecimal boundary case was added. All seven generated cases had executed
successfully before the stale completeness assertion failed. The expected total now matches the
three hexadecimal and four Base64 cases, retaining the guard against silently omitted native test
roots.

The v0.63.0 review described entropy acquisition as `blocking`. The implemented Darwin operation
is a bounded system call that does not wait for caller-controlled external progress, so current
`std/random` and `std/uuid` guidance now records the actual nonblocking effect. The published
v0.63.0 review remains unchanged as historical evidence rather than becoming a second mutable
statement of current behavior.

## Behavioral Evidence

Codec tests cover RFC 4648 vectors, both explicit Base64 profiles, impossible lengths, mixed
alphabets, noncanonical unused bits, insufficient output, and transactional caller-owned output.
Digest tests cover published empty, short, and long SHA-256 vectors; every 55–65 byte padding and
block boundary; arbitrary chunking; canonical parsing; and shared equality, ordering, formatting,
and hashing. UUID tests cover strict parsing, nil and arbitrary byte values, canonical rendering,
version and variant observation, value contracts, and entropy-backed version-4 construction.

Focused native-session tests cross each public contract through checking, lowering, executable
materialization, and execution. The public example crosses the installed standard library and its
nondeterministic output is validated structurally rather than compared with one accidental sample.
Documentation generation is deterministic and produced 350 pages outside the repository.

The complete compiler gate covers metadata licensing, performance invariants, Unicode-data
reproducibility, formatting, Clippy, all workspace tests, CLI and JSON-RPC editor behavior,
standard-library native tests, public examples, no-default-feature compilation, and warning-free
Rust documentation. Its first restricted run reached the expected sandbox denial for a loopback
socket. The unrestricted run passed that socket test and exposed only the missing example contract;
the next run passed the exhaustive example contract and exposed the stale codec-case total. A final
complete run after both corrections is the closing evidence.

## Conclusion

No compiler or editor special case was added for these standard types. Application source sees one
checked contract per representation; implementation modules depend on narrower package contracts
instead of inspecting compiler state. Parsing, formatting, equality, ordering, and hashing derive
from the bytes owned by each value rather than retaining parallel text state. v0.64.0 feature
implementation is ready for release preparation.
