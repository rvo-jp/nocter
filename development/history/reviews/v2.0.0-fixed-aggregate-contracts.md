# v2.0.0 Fixed Aggregate Contracts

## Status and Ownership

Adopted on 2026-11-09 under the user's delegated v2.0.0 design/work authority. This review
records rationale, counterexamples and future qualification obligations. The normative owner is
[Tuples and Fixed Arrays](../../spec/language/tuples-and-arrays.md); the
[grammar](../../spec/language/syntactic-grammar.md#fixed-aggregate-construction) owns recognition.
This is source closure, not parser, checker, evaluator, executable, ABI or native qualification.
The existing 283-case production corpus and bounded private compiler are unchanged.

## Why Close Structural Aggregates First

The assembly draft grouped fixed arrays, typed sequence literals, expansion and variadic inputs
under similar punctuation without closing their distinct schemas. A fixed array already owns a
known number of structural component slots. A dynamic sequence, pack or user expansion needs
separate received/accessed-element, backing, cleanup and retained-dependency contracts. Reusing
an unclosed `[T]` or a released container API would manufacture those contracts implicitly.

Move only tuple/fixed-array productions now. Leave typed sequence/string entries, pack receipt,
expansion, coercion and iteration explicit next subjects. A coherent small owner is preferable
to a purportedly complete literal chapter whose dynamic parts still depend on guesses.

## Selected Consequences and Alternatives

### Construction Does Not Reserve Deferred Moves

```text
let pair = (file, compute()?)
```

Assuming move-only file and a fallible compute, the first component's transfer has happened before
compute executes. Failure cleans that received component. Treating the tuple as a delayed argument
bundle would leave file available and contradict ordinary aggregate/value construction. A caller
can still reserve a directly supplied owning component for a selected take input; the separate
call-preparation protocol owns that commit point.

Tuple arity/array length and component data remain structurally checked on interrupted paths,
without claiming their runtime payloads were produced. Completed components and live evaluation
temporaries keep their own cleanup order; no blanket rollback is introduced.

### Exact Empty Array Types Carry No Element Resources

The previous foundation sentence required element Copy independently of length. It is replaced
by the structural rule: an exact zero-length array is Copy without evidence for T. Its type
differs from every positive length, so this does not infer Copy from a runtime active tag or
revise a generic operation after specialization. A symbolic count remains insufficient unless
the body's own checking context establishes zero or element Copy, including an established
zero-count branch fact.

```text
func snapshot_empty(value: [File; 0]): [File; 0] { value }
```

This can snapshot an empty array through read input, assuming File is a declared storable type.
Requiring File Copy here would demand a capability for a value that cannot be present. Giving
all `[File; N]` Copy would instead duplicate real positive-length resources and is invalid.
The exception grants neither File Copy nor eligibility for never as a stored type.

Zero also removes an actual by-value containment edge. A field `[Self; 0]` does not recursively
contain a Self instance; a positive/unproved length cannot use that argument. Ordinary validity
of named types and cycles in required count evaluation still need their normal checks. This is
an exact cardinality proof, not implicit boxing or permission to ignore a malformed declaration.

```text
let empty = [file; 0]
```

This still receives and destroys file. Skipping element evaluation would preserve file and
erase acquisition/destruction/failure effects. Repetition is not a repeated producer call or a
clone loop. At a known count of one it transfers once; a possible count greater than one needs
the checking context's Copy evidence. Zero-sized resource values with positive counts remain
real logical resources; byte size is not the emptiness proof.

### Owning Subplaces Are Different from Lent Index Projections

```text
func pick(take files: [File; 2], index: usize): File {
    files[index]
}
```

For a valid index this stages the selected complete File, cleans the other element, and delivers
the answer. The fixed-array owner has a known structural schema, so recording a missing component
is the same ownership operation as moving a record field. A custom index operator instead
returns read/edit access under its projection contract. It cannot transfer its receiver's
element just because the caller wants a value. The source spelling alone is not the category.

Restricting owning extraction to literal indices would reject this safe pattern without a
semantic reason. Dynamic extraction instead freezes one evaluated index; later reads/moves need
proof they do not select a hole. Lowering may retain that index for exact remainder cleanup.
It cannot guess disjointness from different source spellings, reevaluate a side-effecting index,
or repair a conflict with an implicit copy/runtime fallback. This model imposes proof obligations;
it does not claim that the current analysis can discharge them.

An out-of-range fixed-array index traps before selection. The ordinary source does not gain an
implicit optional/fallible layer. Required CTFE reports the evaluated operation as a compilation
error. Treating the index as unchecked would invalidate safe-source guarantees; always rejecting
an index that is not a literal would prevent ordinary dynamic computation. Proven bounds may
remove the physical branch while preserving source behavior.

Partial cleanup is distinct from a complete-value read. A present owning array can end with
missing elements; a complete transfer/alias requires them all. A writable array can restore an
element with RHS-first replacement. A wholly moved parent cannot be rebuilt by an element store.
An enclosing user destructor still requires complete-self entry on every relevant exit.

## Future Conformance Obligations

These are required cases, not passed compiler tests:

| Case | Required observation |
| --- | --- |
| `(1, true)`, `(1, true,)`, `(1)` and `()` | Tuple, tuple, grouping and void remain distinct |
| `(value,)` | Reject the unsupported single-element tuple form |
| Expected `[T; 0] = []`; uncontextualized `[]` | Context supplies T; no arbitrary element type is guessed |
| Array expected length differs from listed count | Structural mismatch, without padding/truncation |
| `[true, none]` with no context versus expected `[bool?; 2]` | Require context for none; expected payload permits ordinary injection |
| Array element order with distinct independently inferred data types | Exact mismatch, not first-element-driven coercion |
| Tuple/array mismatched element or interrupted known shape | Diagnose the component contract without fabricating a value |
| Non-Copy first component followed by failure/suspension/cancellation | Preserve the completed move and reverse-prefix cleanup |
| `[effect(); 0]` and `[file; 0]` | Run producer once; clean seed; no resulting element resource |
| Repetition seed from non-Copy read input at count zero | Reject missing seed value-supply rights despite empty result |
| `[non_copy; 1]` versus `[non_copy; 2]` | Transfer once versus missing Copy evidence |
| Generic unproved count with non-Copy T, later instantiated at zero/one | Reject the generic repetition; no specialization repair |
| Body-local proven zero/one branch before repetition | Use that checked path proof; caller specialization supplies no new body evidence |
| `[T; 0]` read snapshot with no T Copy | Accept the exact empty structural proof |
| Symbolic `[T; N]` read snapshot without evidence | Reject; a known zero caller cannot change body selection |
| Positive-count zero-sized resource elements | Preserve separate initialization, dependencies and cleanup |
| Nominal recursion through exact zero versus positive/unproved array count | Zero contributes no element edge; require a finite payload schema otherwise |
| Tuple `.n` out of range or a non-usize array index | Diagnose invalid selection/data without coercion |
| Array index equal to count, including zero count | Trap before access; evaluated required CTFE instead fails compilation |
| Computed-array selection supplied as a value | Supply selected component and clean the remainder once |
| Scoped alias/edit input from computed-array selection | Reject lack of existing writable/readable storage |
| Move non-Copy element through array owner versus read/edit input or custom projection | Only eligible owning subplace transfers |
| Enum take test on an owning array element, including false path | Apply pre-test receipt and retain that array's actual hole/remainder |
| Dynamic owning extraction | Freeze one evaluated index and clean remaining initialized indices in reverse order |
| Index variable changes after extraction | Cleanup still skips the original frozen position, not the variable's new value |
| Later index proven distinct, equal, or possibly equal to a hole | Accept initialized disjoint selection; reject missing/unproved initialization |
| Copy-valued selection followed by source mutation | Preserve prepared snapshot value |
| Read/edit/take element operand followed by preparation failure | Release reservation without an uncommitted transfer |
| Nested value construction inside a later failed call | Preserve its already executed transfers/effects |
| RHS replacement fails after an earlier element move | Do not identify target/install; retain and clean actual remaining elements |
| Reinitialize moved element versus absent whole parent | Restore present writable container only |
| Present partial/all-elements-moved array explicitly dropped | End container, skip transferred components, forbid second drop |
| Incomplete array inside a complete-self destructor owner at failure/cancellation | Reject missing restoration proof |
| Live component access through parent transfer/replace/relocation | Retain conflict/root evidence through last demand/cleanup |
| Copy descriptor elements or discarded fallible repetition seed | Retain dependencies and ordinary failure-loss warning |
| Joint index versus spaced typed literal; spread in fixed array | No type-driven reparse or draft-family admission |
| Large count/required evaluation cycle or budget exhaustion | Distinguish resource/constant errors; no guessed length/runtime fallback |

Before compiler admission, freeze normalized component positions, evaluated dynamic selections,
source-context supply choices, conditional initialization and cleanup paths under the checked
program's authority. Exercise failure, loop backedges and cancellation before executable/ABI
realization. LSP tests on an unconsumed private path cannot establish these semantics.
