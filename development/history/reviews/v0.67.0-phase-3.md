# v0.67.0 Phase 3 Incremental-journal Review

**Result: complete with no open Phase 3 finding (2026-09-23).** Store commits now publish bounded
atomic mutation batches, deterministic checkpoints close every configured-capacity boundary, and
the published v0.66.0 format crosses one explicit migration path.

## Authority Review

`journal_format.nct` exclusively owns outer magic, versions, flags, sequence continuity, record
bounds, checksum validation, and interrupted-tail classification. It returns explicit legacy
snapshot, checkpoint, or mutation record kinds. Neither the journal file owner nor Store recovery
guesses record meaning from payload bytes.

`journal.nct` owns descriptor lifetime, append synchronization, durable replacement, record and byte
capacity, and the next commit sequence. It cannot inspect Store entries, snapshots, or mutation
operations. A failed write, synchronization, or replacement leaves its owner terminal instead of
allowing a caller to retry an indeterminate operation.

`mutations.nct` owns the staged-operation representation and its deterministic payload encoding.
The batch is bounded: crossing the record limit releases accumulated operation copies and records
only that checkpoint publication is required. It never answers current-state queries. `StoreState`
remains the sole authority for retained entries, insertion order, exact-key identity, and lookup.

`store.nct` alone translates state changes into publication intent and replays explicit payload
kinds. It selects mutation append or checkpoint replacement from typed journal outcomes. Snapshot
encoding always traverses the authoritative state; no parallel persisted-state model or
caller-maintained journal invariant exists.

## Migration and Recovery

Version `1` is decoded only as the v0.66.0 zero-flag snapshot journal. Every complete record is
framing-validated, only the final snapshot is retained, and opening immediately replaces it with a
version `2` checkpoint at the same sequence. The writer cannot append version `2` data to a legacy
journal, and mixed-version input is rejected.

Version `2` replays a checkpoint and following mutation batches, or a sequence-one mutation batch
over the empty state. Each outer checksum is validated before its batch is exposed. An incomplete
final record is truncated; a complete malformed record is corruption. Compaction and bound-driven
checkpoint fallback use the same durable replacement operation and checkpoint encoder as migration.

## Qualification

Standard-library native tests cover current record classification, mixed-version rejection,
incomplete-tail recovery, sequence continuity, checksum and bound failures, authored-order mutation
replay, and bounded staging. The complete Store application covers incremental commit, record-limit
checkpoint fallback, restart replay, interrupted current-format tails, and compaction. A dedicated
native migration test constructs a version `1` file independently, verifies recovered data and
sequence through the public API, and then verifies the durable version `2` checkpoint and checksum.
Formatting, focused Clippy, workspace-library, documentation-generation, and repository-integrity
gates complete the phase boundary.
