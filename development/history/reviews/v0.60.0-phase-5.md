# v0.60.0 Phase 5 Review

## Scope

This review covers the bounded `archive-inspect` application, its process and declared-test
contracts, the release qualification hook, and the source formatter correction exposed by the new
generic reader adapter. It also rechecks the ownership boundary between application policy,
compression representation, archive representation, transport, and filesystem publication.

## Findings Resolved

### Report publication initially lacked a complete application gate

Unit-level gzip and tar composition proved state-machine behavior but did not prove that an
ordinary package could open a real file, apply policy, and publish a useful result. The new public
example crosses package discovery, the installed standard library, native compilation, file I/O,
the complete gzip/tar pipeline, and process output. Its declared tests are now explicit release
qualification inputs rather than documentation-only examples.

### Resource limits needed an input authority outside gzip

Neither gzip nor tar owns application resource policy. `LimitedSource` is therefore a package-local
`BlockingReader` adapter and the sole accepted-compressed-byte counter. Its reusable buffer limits
transport reads and permits exactly one rejected sentinel byte when distinguishing an exact-limit
EOF from an excessive stream. Gzip and tar remain unaware of the application's chosen limits.

### Streaming events could have leaked an unverified prefix

Tar entries and bodies are observable before the outer gzip trailer is available. Printing each
event immediately would publish a report that later integrity failure could invalidate. The
application instead retains bounded entry metadata and returns `ArchiveReport` only after
`TarStream.finished`; Phase 4 makes that event depend on outer source EOF and gzip trailer
validation. File publication is absent from this inspection application, so it creates no partial
filesystem state.

### Formatter spacing depended on the inside of a completed generic list

The source formatter treated a closing generic `>` as permanently attached to its following
token, producing `Source<R>where`. Spacing now considers the transition out of the generic node,
with a focused idempotence regression. The example corpus remains the executable canonical-format
gate.

## Boundary Review

- `std/compress` still owns only compressed representation and integrity.
- `std/archive` still owns only tar framing, metadata, normalized relative paths, and body ranges.
- `std/io` remains the only byte-reader contract used by the application.
- `archive-inspect` alone owns limits, accepted entry kinds, duplicate policy, retained metadata,
  and the point at which observations become public.
- The application calls public contracts only; it does not inspect gzip, tar, file, or collection
  representations.
- No second checksum, path normalization, decoder, tar parser, or transport loop was introduced.

## Evidence

- all three declared `archive-inspect` tests pass through native compilation and execution;
- the repository-owned process contract validates usage and a real `.tar.gz` file;
- the complete runnable-example formatter gate passes;
- gzip and tar composition tests from Phase 4 remain unchanged; and
- documentation generation and repository-wide checks are deferred to the Phase 6 qualification
  gate rather than being represented as Phase 5 evidence.

## Result

Phase 5 is complete. No unresolved defect in the application or its responsibility boundaries was
found. Phase 6 may proceed to whole-repository editor, documentation, installation, packaging, and
release qualification.
