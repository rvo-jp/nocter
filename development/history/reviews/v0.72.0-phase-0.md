# v0.72.0 Phase 0 Safety-Disposition Boundary Review

## Scope

This review covers the first v0.72.0 design unit: direct fixed-array bounds proof from checking
through checked execution facts, MIR, Machine, and ARM64. It asks whether one responsibility owns
the source-visible conclusion and whether a later stage can repeat or strengthen it.

## Findings and Remediation

### Closed — Machine was a second bounds-proof authority

The previous Machine optimization resolved constant indexes and changed a required check into
`ProvenInBounds` or `ProvenTrap`. That made a backend-adjacent representation pass the semantic
owner of a source-visible safety result. Checking's `notrap` analysis could not consume the same
conclusion, and future control-flow facts would have required a second proof implementation.

The checked place now carries one `IndexBoundsCheck`. Direct fixed-array literal indexing selects
the disposition during checking, and checked execution analysis consumes that exact value. MIR has
a mechanical transport representation. Machine constant propagation may replace an SSA index with
its constant representation, but it preserves the disposition and rejects a contradiction against
a closed fixed length.

The obsolete Machine optimization counters for checks elided and traps proven were removed. The
remaining counter records only representation resolution, so telemetry no longer claims semantic
ownership for Machine.

### Closed — Current documentation still named Machine as proof owner

The Machine storage contract and architecture guide described the disposition as Machine-owned.
They now distinguish checking-owned source proof from Machine-owned representation validation.
Historical v0.68.0 records remain unchanged because they accurately describe that released design
at the time.

## Authority Audit

- **Checking** reads typed values and the fixed-array length and is the sole producer of a
  source-visible bounds disposition.
- **Execution analysis** reads the checked disposition. It does not evaluate constants or inspect
  target layout.
- **MIR** maps and validates the carrier. It cannot strengthen `Required`.
- **Machine** resolves value representation, preserves the carrier, and rejects contradictions. A
  generic structural index remains `Required` even when constant propagation discovers its value.
- **ARM64** already switches exhaustively on the closed Machine disposition and performs no range
  proof.

No consumer needs checking's internal constant table, body checker, or control-flow implementation.
The cross-stage contracts expose only the decision each consumer requires.

## Evidence

- checking tests cover required, in-range, and proven-trap dispositions;
- a `notrap` test proves execution analysis consumes the frozen disposition;
- a MIR test covers lossless transport of all three states;
- Machine tests prove direct safe/trapping states, retain `Required` for generic structural
  indexing, and reject contradictory fixed-bound dispositions;
- the complete compiler workspace library-test gate passes in an environment that permits its
  network service fixtures, including the 38-test CLI, 118-test LSP, and 126-test native-session
  suites; the restricted sandbox failure was reproduced as host permission denial, not compiler
  behavior;
- Clippy with warnings denied, formatting, diff validation, documentation generation tests, and an
  out-of-tree 373-page documentation build pass.

## Result

No open Phase 0 finding remains. This boundary is suitable for Phase 1's control-flow fact domain:
that phase can add proof producers inside checking without changing execution, MIR, Machine, or
ARM64 ownership.
