# v0.51.0 Phases 0–1 Execution Authority Review

Date: 2026-09-14

## Result

Phases 0 and 1 are complete. The audit rejected a flat effect record as the final model because it
would erase the boundary between invoking an asynchronous producer and later driving its body. The
adopted model instead keeps authored promises, checked invocation plans, deferred-body execution,
and destruction roots distinct under one relation authority.

## Findings and Corrections

### Inferred facts were named as callable contracts

The checking product used `CallableEffects` and `EffectTable` even though its entries are inferred
implementation facts. For an immediate callable an entry describes body execution during
invocation; for an asynchronous callable it describes execution while the future is driven. The
old names did not communicate that temporal distinction.

The product is now `ExecutionFactTable`, containing `ExecutionFacts`, `AllocationFact`, and
`SynchronousWaitFact`. `CheckedProgram` exposes that authority explicitly. Authored promises remain
`CallableGuarantees` and cannot be replaced by successful inference.

### Missing identities silently became conservative facts

An execution edge referring to a missing callable, closure, or drop identity previously became
`MayAllocate + MayBlock`. That preserved rejection safety but disguised a broken checked graph as
ordinary conservative analysis. All such lookups now produce a semantic integrity failure.
Conservative conversion remains available only through the explicit `ExternalContract` edge used
when an implementation is unavailable by design.

### Direct allocation was a special field

Root collection previously stored one optional direct-allocation locator alongside call edges.
This would require a new bespoke field and solver path for every later guarantee axis. Roots now
retain a list of typed direct `ExecutionFacts` plus typed execution edges. The same monotonic join
handles both, and diagnostic locators remain attached to the fact that introduced them.

### Current design documentation had two authorities

`blocking-effect-design.md` and the new execution-contract document both claimed ownership of the
same compiler boundary. The former also retained a v0.45.0 migration inventory as current design.
It was removed, all live references now point to `execution-contract-design.md`, and historical
milestone and review records remain unchanged.

## Preserved Correct Foundations

- `CheckedCallExecution` already freezes immediate versus deferred invocation during checking, so
  relation analysis does not infer async behavior from `future T`.
- One `BodyRelationCatalog` already supplies exact body coverage to provenance, execution, and loan
  analysis.
- The existing least-fixed-point graph already includes callable, closure, and ownership-selected
  destruction roots and is independent of source order.
- Semantic presentation already renders authored guarantees rather than inferred facts.

The implementation retained these contracts instead of replacing sound boundaries merely to make
the refactor larger.

## Evidence

- checking unit tests, including async construction, recursive propagation, callable erasure, and
  implicit destruction;
- execution-fact lattice tests for independent allocation and synchronous-wait axes;
- workspace all-target checking;
- documentation link and generated-site verification.

No public language behavior changed in these phases.
