# v0.70.0 Trap-Free Callable-contract Review

**Result: complete with no open implementation finding (2026-09-25).** `notrap` is now one
independent structural callable guarantee, proved by the checked execution graph and reproduced by
tools from semantic declarations. It is not inferred into public API presentation and is not
reconstructed by a target backend, standard-library name, or source-text pattern.

## Authority Review

The review traced the guarantee through its complete ownership chain:

- `nocter-language` owns the modifier vocabulary, spelling, canonical order, and syntax-category
  admission;
- syntax preserves an admitted `notrap` token without interpreting its meaning;
- declaration lowering projects that token once into `CallableGuarantees`;
- `CallableGuarantees` owns structural identity and directional weakening for callable values,
  interface methods, and erased callables;
- checking computes one `TrapFact` dimension beside allocation and synchronous waiting over direct
  operations, selected calls, callable values, closures, and implicit destruction;
- the closed primitive-role registry supplies target-verifiable facts for bodyless primitive
  declarations; and
- formatter, completion, hover, highlighting, and generated source indexes consume the shared
  vocabulary or semantic contract instead of maintaining a second language rule.

No later stage repeats the trap decision. Machine lowering receives already validated primitive
identity and checked execution; it does not classify source operations or decide whether an API may
claim `notrap`.

## Closed Findings

Four concrete design defects were found and closed during implementation:

- callable and closure contract validation initially repeated three nearly identical checks; one
  shared execution-requirement validator now compares every independent fact and retains the exact
  checked cause;
- `DropValueAtPointer` was initially treated as merely allocating, although it can dispatch to an
  arbitrary destructor; its closed runtime profile is now both allocating and source-trapping;
- process termination was initially exempted by reclassifying the complete `process.abort` and
  `process.exit` wrapper bodies, which could have hidden an earlier safety trap; dedicated
  `ProcessAbort` and `ProcessExit` roles now prove only the primitive edge, while ordinary body
  traversal proves the wrappers; and
- the public process roles did not validate the complete callable shape; their shared validator now
  requires the exact function kind, visibility, parameters and positions, `never` result, absence
  of generic requirements and receiver, and authored `notrap` contract.

Regression coverage demonstrates that a process-termination wrapper containing prior integer
arithmetic is rejected, while the direct validated termination edge remains permitted. There is no
checker name or path match for either operation.

## Deliberate Limits

`notrap async` remains invalid because `future T` does not retain a drive-time trap guarantee.
Runtime-value reasoning is intentionally conservative: ordinary checked integer arithmetic,
bounds indexing, postfix `!`, and exact-size spread invariants count as potentially trapping even
when a particular constant input could prove safe. Recoverable `T!` propagation is not a trap.

Generic structural equality, ordering, indexing, coercion, and expansion requirements cannot yet
state `notrap`, so execution through those requirements remains conservative. Extending their
contract syntax is separate language design work; weakening the proof or recognizing selected
implementations would create an unsound compatibility shortcut.
