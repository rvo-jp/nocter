# v2.0.0 Owned-Capture Producers

## Scope

The owning [callable contract](../../spec/language/callables.md#bounded-owned-capture-producers)
selects one explicit ordinary value capture with complete ordinary input/result data annotations.
This review records source/flow implementation and verification, not full closure, execution or
performance conformance. Multiple/nested/inferred captures, contextual completion and callable
results inside closure bodies remain outside this first source scope.

```text
func observe(input: error): void {}
func example(take input: error): void {
    let action = (input;): void { observe(input) }
    action()
    action()
}
```

The environment is owned and non-Copy, but invocation reads it and can repeat. Updating an
owned counter instead infers mut; extracting or explicitly dropping the captured value infers
once. Explicit parameter read/edit/take operations remain independent of environment invocation.
Copy follows the exact environment schema, so a Copy environment can supply separate consuming
instances. There is no call-site marker or implicit clone.

## Authority Audit and Implementation

- Named-header parameter identities were embedded in private access roots. Roots now use their
  body-local input slot, shared by named parameters, anonymous inputs and the captured environment.
  Source projection directly resolves that local's locator instead of reverse-searching parameter
  declarations. Formal callable witness identities retain their declaration-level meaning.
- A lexical owner/slot key identifies closure code without a source range or environment address.
  Body type construction publishes the ordinary environment data and complete callable contract
  under that key. The same canonical replay merges application and closure keys/schemas while
  preserving the immutable header prefix. `body_types` is the single construction authority;
  `closures` projects the immutable schema. No header/body type-store fallback exists.
- Closure checking uses the existing Checker with a separate local/return/loop scope. A common
  constructor/finalizer handles named and closure bodies; source bytes and locator projection are
  shared. Unlisted outside names cannot acquire access or silently become moved captures.
- Provisional environment authority serves demand collection only. The control graph is prepared
  once; reached moves/drops/transfer inputs require once, reached updates/delegations require mut,
  and otherwise func suffices. Unreachable moves cannot force once. The selected environment input
  kind freezes before the same graph enters normal initialization, access and resource validation.
  Every closure body is validated before Unit publication, even an uninvoked or unreachable one.
  Named and closure bodies use one flow-admission and diagnostic procedure.
- The resource ledger's atomic Capture transition transfers one complete environment obligation
  into its closure value. OwnedCapture disposal retains the exact environment cleanup schema.
  Consuming body inputs use the ordinary partial-move, staged-return and remaining-field cleanup
  rules. Read/edit body inputs do not acquire independent ownership. No closure-specific owner
  registry, lifetime extension or allocation policy is introduced.
- Reachable closure formation establishes a captured-code producer in the existing finite result
  equations. Factory results and static callback supply preserve it; signatures cannot substitute
  another lexical producer. Closure metadata and nested bodies share the Unit's one final type
  authority. Source reuse remains guarded by the complete enclosing body and producer byte evidence.

The first environment domain contains only the already closed builtin/record payloads. Its empty
outside D/S is evidence from those schemas. General capabilities, callable captures and retained
outside state require further proof; ownership, Copy and invocation kind do not prove independence.

## Target Boundary

An uninvoked closure's data maps to its existing payload and environment-data obligations without
creating a code instance. A reached captured-code call or formal binding returns the explicit
UnsupportedCapturedCode boundary. It does not report an invalid accepted Unit or invent a named
callee, runtime-erased function pointer or executable closure layout.

Next extend the existing instance authority to select a named or captured body, preserve explicit
environment/input placement and specialize frozen witness edges. Taking adapters must retain their
own post-call environment cleanup even when the original closure body only reads. Nested closures
and callable-result applications inside closures require code-scoped operation identities before
source admission; the enclosing named function's application identity domain is not reusable there.
ABI, physical environments, executable cleanup, MIR and native execution remain separate work.

## Source Evidence

Twenty new source inputs bring the corpus to 283: 147 accepted units, 122 checking rejections,
8 header rejections and 6 syntax rejections. All 277 syntax-valid inputs have reviewed lossless
parser snapshots; declaration tests validate 269 header-valid inputs. Existing snapshots are
unchanged. Recognition tests distinguish closure heads, grouped expressions and unit, and keep
retired symbolic capture/access forms rejected.

Source-backed body tests inspect repeated read invocation of non-Copy captures, inferred mut/once,
Copy snapshot supply, distinct code owners, partial record extraction/cleanup, source invalidation,
returned environments, callback forwarding, unreachable moves and interrupted prepared-prefix
cleanup. Rejections cover read extraction, non-writable invocation, consumed/source reuse,
heterogeneous code joins, invalid unused bodies, outer-loop control, unlisted captures and view
upgrades. Declaration tests exercise coinciding branch-local type IDs with different owner/schema
projections. Target tests distinguish uninvoked payload projection from unsupported captured-code
invocation.

Verification covers the checking library (731 tests, including 98 private value-access tests),
declarations (51), declaration lowering (144), model (43), syntax (145) and target (64, including
22 private instance tests). The affected library suites and complete source corpus pass.
Warnings-denied workspace all-target Clippy, formatting and whitespace checks pass. Documentation
generator tests and an external build at `/tmp/nocter-v2-owned-capture-site` pass with 376 published
pages; adopted development contracts remain outside publication/search. LSP/native runtime tests
were not used as feature evidence because they do not consume this private product.
