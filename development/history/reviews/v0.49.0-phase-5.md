# v0.49.0 Phase 5 Review

Phase 5 migrates every closed child-process operation onto the structured process foundation and
removes the earlier terminal session. This review covers the changed process source, compiler
native and editor regressions, examples, behavior documentation, and direct searches for the old
authority.

## Result

No release-blocking issue remains in the Phase 5 scope.

The implementation now has one launch transition. It returns either a typed pre-child preparation
failure or `LaunchedChild`, which pairs one public child owner with the exact close-on-exec fact.
Public spawn selects its error and returns the child. Closed operations retain both facts, complete
endpoint transfer and exact observation, then apply their documented failure precedence. Launch
does not know which closed operation called it, and the blocking coordinator cannot launch or wait.

The asynchronous output path owns four child computations under two nested structured joins:
finite input, stdout collection, stderr collection, and exact child observation. Join preserves all
outcomes until the parent selects `wait`, launch, capture, then input failure. Cancellation destroys
all child computations, closes their endpoint owners, and transfers the still-unobserved child to
the existing abandonment authority.

The blocking output path uses one group readiness adapter because sequential blocking transfer can
deadlock on finite pipes. It advances at most one write and one read per ready direction before the
next readiness observation. Actual bytes still cross `PipeEndpoint`'s sole read/write attempt
classifier. The adapter owns neither a raw descriptor copy nor a second child identity.

## Removed Design

The following obsolete path is absent after migration:

- `CommandIoSession` and its combined launch, pipe, buffer, progress, and cleanup ownership;
- separate closed-operation input and capture pipe construction;
- duplicate command-specific read and write syscall classifiers;
- the separate `CommandFork`, `execute_command`, `run_command`, and `output_command` wrappers;
- synchronous `status` and `output` names without the `_blocking` suffix.

Repository searches found no remaining source reference to the removed session or its transition
names. Historical documents remain unchanged records of earlier releases.

## Contract Review

- `Command` is the sole unlaunched request owner. Closed operations remove finite input through one
  explicit internal contract before shared launch prepares stable child addresses.
- `LaunchedChild` is the sole post-fork handoff. A caller cannot receive a launch fact without the
  exact child owner or a child owner without that fact.
- `ChildOwner` remains the only wait, cache, and abandonment authority. Neither output path stores
  or interprets a raw PID.
- `PipeEndpoint` remains the only descriptor owner and read/write result classifier. The blocking
  readiness source observes liveness only.
- `complete_closed_status` and `complete_closed_output` are the only closed-operation public
  failure selectors. Both examine wait before launch; output then examines capture before input.
- Missing internally required endpoints become typed closed-operation failures. Correctness does
  not rely on an unchecked caller promise about a `ProcessIo` configuration.

## Qualification

The focused complete-native-session matrix passes for canonical async status and output, blocking
configured output, lifecycle control, launch errors, output larger than pipe capacity, simultaneous
stdout and stderr, empty and early-closed input, nonzero and signal termination, and repeated
launches. Standard process native tests cover the remaining pipe readiness and endpoint facts.
Editor contract tests resolve the renamed blocking declarations and their new implementation
source through ordinary checked identities.

The final `cargo test --lib --quiet` gate passed with loopback access enabled. The exact process
matrix, three LSP contract tests, standard-module dependency review, private implementation
reference review, documentation generation for 276 pages, `cargo fmt --check`, and
`git diff --check` also passed. The dependency review exposed the new intentional
`process -> task` edge, and the implementation-reference review exposed two old session-only pipe
queries; the reviewed graph now records the former and the latter definitions were removed.
