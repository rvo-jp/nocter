# v0.50.0 Phase 1 File and Local-storage Review

**Result: complete with no open Phase 1 defect.** The canonical file API is executor-safe, its
blocking twin is explicit, and ownership remains closed from source construction through generated
worker execution, completion, cancellation, retirement, and process shutdown.

## Findings Corrected During Implementation

### Runtime-owned storage lost its physical category before destruction

Machine layout previously represented compiler-owned storage as an empty source struct. Deferred
destruction could therefore no longer prove that `FileOwner` bytes belonged to the runtime or that
its selected drop matched that role. Runtime storage now remains an explicit closed category in the
executable environment, MIR destruction plan, Machine layout, Machine destruction plan, and their
validators. Neither MIR nor Machine projects target fields or reconstructs native offsets.

### Owner transfer used an implicit scratch register

The first generated completion adapter loaded the returned owner into `x8` and then reused `x8` to
clear its source slot. It returned zero while leaking the live retirement owner. Storage helpers now
require an explicit non-aliasing scratch register, and an exact instruction test fixes load, clear,
and return order.

### Instruction selection duplicated generated adapter call shapes

Instruction selection carried a second role-to-register-shape table and had already assigned wrong
shapes to flush, truncate, seek, and positioned operations. Each generated adapter now owns one
direct-register call contract. Selection resolves the adapter and validates the frozen Machine ABI
against that contract without reconstructing it from the primitive role.

### Standard source could manufacture target selector tags

The initial standard implementation copied numeric open-access and seek-origin tags and passed
arbitrary `usize` values to generated primitives. This contradicted the runtime contract's sole
authority and made correctness depend on each caller. Separate semantic primitive roles now
represent read-only open, create, append, absolute seek, end-relative seek, and cursor-relative
seek. Only generated adapters translate those roles into runtime-owned tags.

### Asynchronous construction was parsed but rejected as an attachment

Construction validation inspected the outer `future` result instead of the deferred callable's
produced output. It now validates immediate and deferred construction through the callable execution
contract. Parser, declaration, complete native pipeline, and editor tests cover the same checked
declaration rather than introducing an editor-only interpretation.

### File synchronization leaked into borrowed standard streams

The first `BlockingFile` cutover sent every `flush_blocking` call to `fsync`, including borrowed
stdout and stderr wrappers. Buffered output therefore failed when a process stream was a pipe.
Flush policy now follows the existing ownership state: an owning file requests target
synchronization, while an open borrowed stream with no retained user-space buffer completes as a
no-op. The public package-example suite exercises buffered stdout through this boundary.

## Authority Review

- `std/io` owns public `File`, `BlockingFile`, `SeekFrom`, portable errors, and partial-progress
  policy. `std/fs` composes those contracts for whole-file operations.
- Private raw primitive declarations are exposed to other standard modules only through typed
  package-visible operations. Standard source cannot observe worker records, queue state, wake
  transport, retirement identity, or access/seek tags.
- `nocter-runtime-contract` alone owns file operation vocabulary, generated job layout, completion
  layout, lifecycle states, capacity, access modes, seek origins, and failure encodings.
- MIR retains the selected runtime-storage role; Machine consumes its layout and never reinterprets
  the source nominal declaration. ARM64 consumes frozen primitive targets and exact runtime ABI
  schemas.
- Generated jobs own path and write bytes. Read workers own their output region and cannot access
  the consumer destination. Cancellation clears the consumer pointer before detaching a worker.
- Explicit close and implicit drop use the same pre-reserved retirement authority. No source caller
  repairs capacity, polls worker state, or performs a fallback close.

## Qualification Evidence

- physical `development/std` package analysis with a freshly built compiler and synchronized
  installation image;
- complete native public `File` lifecycle covering open, create, append, sequential and positioned
  I/O, flush, all seek origins, truncate, target-error mapping, terminal-state rejection, explicit
  close, implicit drop, and root shutdown;
- generated lifecycle and host-service tests for bounded admission, cancellation before claim,
  abandonment while running, completion without a waiter, retirement, and shutdown;
- native asynchronous construction, public hover, definition, and implementation navigation;
- workspace library tests, Clippy, documentation generation tests, and repository whitespace
  validation recorded at Phase closure.

Phase 2 may add filesystem operations only through the same semantic-operation, owned-input,
typed-completion, and explicit execution-surface boundaries.
