# v0.73.0 Phase 0 Review: Relational Fact Domain

**Result: complete with no open finding (2026-09-30).** Checking now owns one normalized order
domain for relationships between stable scalar values and semantic borrowed-view lengths.

## Changed Boundary

The previous flow state had two unrelated representations:

- numeric intervals for comparisons with constants; and
- a two-state `index < length` / `index >= length` set used only by bounds checking.

That split could not retain `start <= end`, could not derive transitive order, and forced arithmetic
and bounds checking to understand different fact shapes. Phase 0 preserves numeric intervals for
the domain they model well and replaces the length-only set with `OrderRelations`. Its symbols are
stable parameters, immutable locals, and lengths selected by validated standard semantic roles.

`OrderRelations` owns normalization and transitive closure. A strict edge also supplies its implied
non-strict edge. Equality supplies both non-strict directions. A contradiction creates a strict
self-edge and makes the branch unreachable. Control-flow join intersects already closed facts, so
two paths retain the same conclusion even when one derived it transitively and the other stated it
directly.

## Authority Review

- Syntax and lowering do not interpret relationships.
- Body checking is the only producer of order facts and arithmetic dispositions.
- Standard length methods are selected by `StandardDeclarationRole`, never by source spelling.
- Checked execution continues to consume the stored arithmetic or bounds disposition for
  `notrap`; it does not query `OrderRelations`.
- MIR, Machine, and ARM64 remain unchanged and cannot strengthen the checking result.
- Mutable locals, captures, statics, arbitrary calls, and projected places remain inadmissible in
  this phase. No missing invalidation rule is hidden behind optimistic alias assumptions.

## Proved Operations

For unsigned integer operations, checking can now prove:

- `upper - lower` when the path establishes `lower <= upper`;
- `cursor + 1` when the path establishes a strict upper bound of the same checked integer domain;
  and
- either conclusion through transitive order relationships.

Signed subtraction remains conservative because ordering alone does not exclude signed overflow.
Larger increments remain conservative because a strict upper bound does not supply the required
distance. Runtime checks remain whenever proof is incomplete.

## Remaining Work

Phase 1 must introduce stable writable-place identity and explicit invalidation before facts about
fields or mutable locals are admitted. Phase 2 must compute loop facts across back edges. Phase 0
does not simulate either capability and therefore leaves current mutable traversal conservative.
