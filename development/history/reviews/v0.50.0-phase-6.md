# v0.50.0 Phase 6 Complete Application Review

Date: 2026-09-14

## Result

Phase 6 is complete. `examples/async-file-report` is a native runnable package that combines the
Phase 0–5 contracts into one bounded local-data application without primitives, target imports, or
application-owned resource workarounds.

## Application Flow

The program accepts an input directory and report path. `WalkDir` owns bounded depth-first
discovery, lazy `filter` excludes non-regular entries, and `enumerate` derives the completed file
count without collecting paths. Each regular file is opened as an asynchronous `File` and consumed
through 8 KiB `ByteChunks`; only the aggregate file and byte counts survive an iteration. A 4 KiB
`BufWriter<File>` writes the report to a sibling temporary path.

Successful publication requires `BufWriter.finish`, explicit `File.close`, and `fs.rename` in that
order. No partial final report exists before rename. The complete build future is owned by
`task.with_timeout`; timeout destroys the walker, active chunk source, and output graph before the
caller removes the temporary path. A recoverable discovery or I/O failure follows the same cleanup
path and returns status 1. Invalid invocation returns status 2 without opening an endpoint.

## Boundary Review

- The application knows only `AsyncIterator`, `Reader`, `Writer`, filesystem, task, and duration
  contracts. It does not inspect executor, blocking-job, descriptor, target, or completion state.
- Recursive traversal, asynchronous file access, chunk publication, buffering, and timeout each
  retain one authority in the standard library or runtime. The application does not reproduce any
  of their state machines.
- Memory use is independent of total input bytes and entry count: retained state consists of the
  bounded traversal stack, one directory entry, one 8 KiB chunk, one 4 KiB output buffer, and scalar
  aggregates. The traversal depth is bounded by the shared filesystem policy.
- Final-path visibility is controlled by one rename after every fallible buffered write and close.
  Failure cleanup is explicit because removal itself is recoverable, but endpoint retirement is not
  delegated to caller discipline.
- The public-example harness now owns reusable filesystem postconditions rather than teaching the
  compiler test about this application. It can assert exact files and absent paths for later
  examples through the same contract.

## Evidence

The public package contract compiles and runs every repository package example. For this example it
materializes a nested input tree, checks the exact `files\t2` and `bytes\t17` report, then exercises
a missing root and proves that neither its final path nor either temporary path remains. Existing
native lifecycle tests provide deterministic cancellation-at-suspension coverage; the application
adds the complete composition and publication boundary rather than another synthetic cancellation
mechanism.

No endpoint-specific copy loop, unbounded collection, hidden blocking call, duplicated cleanup
authority, or compiler/platform escape hatch remains in the Phase 6 scope.
