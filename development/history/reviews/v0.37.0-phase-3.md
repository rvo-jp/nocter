# v0.37.0 Phase 3 Incremental Finalization Review

**Result: complete (2026-09-06).** Whole-program relation analysis is now independently reusable
across body edits that change only scalar literal payloads. Exact-current body replay and source
projection still execute for every changed body generation.

## Design Result

The former finalization query combined four different lifetimes: canonical body replay,
source-coordinate projection, provenance/effect/loan analysis, and final checked-program assembly.
Any body text change invalidated the complete value. Phase 3 replaces it with four explicit query
contracts:

1. `ProgramMaterializationQuery` replays source-neutral body recipes into current canonical type
   and closure identities, completes ownership and cleanup, and closes the current source
   projection.
2. `ProgramRelationInputQuery` projects a structural fingerprint from that materialization. The
   syntax-owned projection retains declarations, identifiers, operators, node shape, and string
   interpolation expressions while eliding only scalar literal payloads.
3. `ProgramRelationQuery` computes source-neutral provenance, allocation effects, and loans.
4. `ProgramFinalizationQuery` joins those reusable relation facts to the independently demanded
   exact-current materialization.

Relation failures retain `BodyId`, `BodyNodeId`, and `BodyRule`, never `SourceDiagnostic` or source
coordinates. Finalization projects a reused failure through the current materialization's origin
arena. A regression test changes the byte length of an earlier literal, verifies relation-query
reuse, and compares the resulting diagnostic and source snapshot with a fresh analysis.

The first implementation exposed the correct invalidation boundary but deeply cloned the cached
materialization during final assembly. Its edit latency met the target, but process memory grew by
11–13 percent. The corrected design closes semantic completion, body arenas, source access,
source index, witnesses, and relation tables as immutable shared authorities. The materialization
and `CheckedProgram` share those values; downstream getters retain their existing borrowed
contracts, and owned extraction clones only at the existing ownership boundary when sharing
prevents an unwrap.

## Review Conclusion

The relation query does not retain syntax or source projection, and the finalization query does not
recompute relation semantics. The syntax layer is the sole owner of structural equivalence; the
computation layer owns invalidation; checking owns semantic construction and failure projection.
No editor-only parser or semantic path was added. The measured dominant path exceeds the 15%
milestone target without a major-path latency regression above 5%. Phase 3 is complete.
