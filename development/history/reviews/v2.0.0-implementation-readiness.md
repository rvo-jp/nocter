# v2.0.0 Implementation Readiness

## Status

This records the pre-implementation closure pass on 2026-11-07. The
[milestone](../milestones/v2.0.0.md) owns adopted scope. Detailed autonomous Value Access Model
decisions are recorded in [semantic closure](v2.0.0-value-access-semantics.md); human-facing
alternatives are isolated in [source design](v2.0.0-source-design-decisions.md). No v2.0.0 compiler
implementation, formal soundness proof, performance improvement, or release qualification is
claimed. Current `spec/` and checked standard-library contracts remain authoritative.

The user has selected all six principal source directions. S2 adopts result-mode prefixes on
callable identifiers and derives result permission at unmarked calls/bindings, retaining ownership
when supplied. Earlier I-only ordinary bindings and redundant result assertions are not selected.
The `throw` operand's explicit `^`, explicit optional-presence construction, and the unit literal
remain separate unresolved source choices. The user rejected result-side `view`/`&view` and `yield`.
The [pending syntax recommendations](v2.0.0-source-design-decisions.md#remaining-syntax-recommendations)
prefer `throw reason`, ordinary generic `some(...)`, and `()` as the `void` literal; none of
these three spelling recommendations has been adopted.

The semantic basis no longer needs approval for every internal alternative. Specification
migration, pending source design, implementation contracts, and conformance remain real gates.
Neither a successful documentation build nor the bounded model check closes those gates.

at a destroyed owner, or an async output's permission is confused with ownership of its future.
Define each boundary once before lowering, and derive cases that distinguish those errors.

Use minimal examples covering an owned factory, reader/update accessor, consuming receiver plus
owned output, generic identity/forwarding, an indirect callback, fallible read/update output,
nested optional output, and a suspended operation with cancellation. Add contrasting rejection
cases for strengthening I to U/X, returning local access, overlapping access, duplicate ownership,
and mismatched interface/result contracts. The existing root-place model check does not cover
those result protocols and must not be presented as evidence that they are already verified.

Then migrate the owning language/platform/tooling rules, establish adjacent compiler product
contracts, and derive executable conformance cases. Specifications precede implementation of
each affected boundary. Optimizer pass selection can continue afterward; no universally optimal
optimizer or Rust comparison is a prerequisite.

The explicitly reserved source decisions are the existing `throw` operand marker and optional/
unit construction spellings. Do not request approval for internal algorithms or mechanically
derived consequences of S1–S6. If closure exposes another materially different human-facing

finished or block independent internal work waiting for it.

## Conservative Optimization Boundary

Use the following proof conditions without broadening observable-behavior permission:

| Observation | Required condition on a transformation |
| --- | --- |
| Returned values, outcome tags, failure codes/causes | Preserve them; no branch flattening or failure reclassification |
| User callbacks and destructors | Preserve reachable invocations, arguments, and specified order |
| Recoverable allocation failure or aborting allocation boundary | Preserve the specified possibility/effect unless the owning contract explicitly permits elision or a proof removes it |
| Allocator calls, budgets, region release, reported capacity | Treat as observable wherever the selected API exposes them |
| Address or identity observation | Preserve supported observations and stability while access is live |
| Size/alignment and stored representation | Use one authoritative materialized layout for each observable type/ABI instance |
| Checked arithmetic, bounds, validation, floating point | Preserve exact required behavior; no unchecked access or fast-math assumption |
| Nonreturning trap/termination | Do not add unwinding or pretend cleanup completed |

An inferred allocation fact is not a declaration that allocation has no observable effects.
In particular, removing an explicit recoverable allocator call just because its successful buffer
is unused can change the returned failure or a budget. Preserve that boundary or prove it inert.
Do not manufacture a fictitious allocation probe and call that allocation elimination.

Compiler-selected transport, dead scalar storage, and proven nonescaping frame/environment
representation can be changed when no supported observation distinguishes them. There is no
requirement to materialize an implementation-only address solely because an earlier IR did so.
Where the current allocation/failure contract makes even that storage observable, keep the
obligation until it is discharged; future permission to weaken allocation observations is not
silently adopted in this pass.

Source cleanup points remain authoritative. Physical memory can be reclaimed earlier only when
resource destruction, allocator visibility, and all outstanding accesses remain equivalent.
Smaller representations are candidates to measure, not a proof of faster execution.

## Conditional Effect Inference

Separate facts for storage requests, possible recoverable failure, traps, immediate termination,
external synchronous waiting, suspension, resource effects, callbacks, and cleanup. Preserve
allocation-context requirements and result-storage origins as separate relations. Read access
does not certify purity or constant-evaluation eligibility.

1. Each selected operation contributes a conservative effect summary. Trusted bodyless operations
   obtain facts from exact registered roles; ordinary declarations cannot self-certify them.
2. Generic summaries contain conditions on selected operation/destructor witnesses, not a guess
   based on Copy or a new source-level effect parameter. Specialization substitutes those witnesses.
3. Solve mutually recursive callable groups monotonically. A closed group with no waiting seed
   and only proved nonwaiting outgoing operations can establish absence of waiting; unknown
   outgoing targets remain possibly waiting. Divergence is a separate fact, not assumed absent.
4. Structural/erased calls join every available selected target summary. Missing target evidence
   means unknown, not nonblocking. Carry required closed effect evidence across erasure, without
   changing the authored parameter modes. Do not inspect source names at runtime.
5. Every async drive and cancellation path, including implicit destruction, must exclude external
   synchronous waiting. Unknown evidence rejects that use; it does not insert a worker thread.
6. Unknown redundancy of an ordinary runtime safety check retains the check. Unknown memory
   safety, initialization, ownership, or nonblocking-drive validity is a different issue and must
   not be accepted by merely emitting an unrelated check.

Treat effect evidence as revision/target/specialization-bound compiler data. Adding a waiting
operation in a private body can invalidate a future use and must report the selected call path.
It cannot change the meaning of the public input/update/transfer contract. This is an internal
protocol to specify and verify, not a new mandatory authored modifier.

## Constant Evaluation and Type Dependencies

Use one dependency graph with separate query identities for declaration headers, required closed
constant values, type/array construction, checked callable bodies, and target serialization.
The graph may request one authority's product from another without letting a later owner
reinterpret syntax or resolve a call again.
These are semantic-construction dependencies, not permission for a lowered target/MIR product to
call back into checking or for crates to form a cycle. Specify and freeze the required early
header/typed-evaluation products before their consumers; change the owning architecture contract
coherently when that replaces a current stage edge.

- Reserve nominal and callable identities and generic schemas before evaluating constants that
  use them. Header availability does not imply that a body or recursive layout is available.
- A request for an in-progress required value/layout is a dependency cycle and has a source-backed
  diagnostic. Ordinary recursive callable evaluation is instead governed by evaluator limits.
- Evaluate resolved, typed operations with the same value-access, initialization, failure, and
  destruction semantics as runtime code. Keep required-constant evaluation separate from optional
  optimizer folding, which must preserve effects and runtime behavior.
- Admit only operations with checked evaluator capability, including the adopted local mutation,
  loops, repeated arrays, and supported nominal aggregate construction. A `const` body cannot
  smuggle runtime I/O, arbitrary allocation, or resource cleanup into evaluation through a helper.
- Temporary evaluator storage may not escape. Retained final aggregates must have supported
  serializable components and no live resource, unresolved access, or evaluator address. Static
  references, where already permitted, refer only to validated static identities.
- Canonicalize a structural `usize` argument by its checked target value, not spelling or the
  function used to compute it. Target arithmetic and floating-point serialization are explicit.
- Work, memory, and depth accounting is deterministic and part of evaluator diagnostics. Budget
  exhaustion in a required constant is an error, not fallback runtime initialization. Exact
  budgets are compiler resource policy, not a reason to ask the user to design the evaluator.

Qualify with loop-generated CRC data, nominal parser-table entries, repeated arrays, floating-point
tables, equal-value type identities, negative cycles, target overflow, and retained-resource
rejection. Acceptance alone is insufficient: inspect emitted static data and startup operations.

## Contract and Implementation Joining

Give each public declaration one semantic identity before joining its bodies. Root declarations,
inherent operations, interface-owned operations, and associated bindings are distinct domains.
Target selection chooses applicable bodies before uniqueness validation. Missing or duplicate
applicable bodies are diagnostics, never file/import-order selection.

For an opaque result, the public contract and matched implementation share one opaque identity.
Determine one concrete witness per specialization from the implementation and check the declared
interfaces, modes, origins, and cleanup. Private witness properties do not silently become public
Copy or method capabilities. Diagnose recursive witness/layout dependencies through the shared
query protocol instead of inventing an adapter or a second opaque type.

For interfaces, use interface/member identities for mappings and associated types. Defaults are
selected only by the explicit conformance decision; an unrelated inherent method cannot replace
them. Qualification selects an existing interface operation, not a general UFCS conversion.
The named mapping and qualified-call forms are selected by S5; final recognition and boundary
cases remain specification migration work. S2, S4, and S6 are also selected; the `throw` operand
marker remains open. The rejected result qualifiers and `yield` are not implementation targets.
Construction availability comes from public `func`/`literal` entries, not private fields.

Derive module identity from directory/package identity. Treat root `use` as deliberate re-export
and implementation `use` as local. Preserve direct, non-transitive `see`; do not use it as a
compiler input inventory or optimization barrier. Root item forms and private representation
need a complete source inventory before migration, not publication of formerly private helpers.

## Implementation Boundaries and Entry Gates

The following is an order of authority replacement, not permission to implement unselected
grammar behind an old checker. Work may use isolated changes, but a completed boundary must
have no competing old producer or silent compatibility fallback.

| Boundary | Work that must precede compiler implementation | Required evidence afterward |
| --- | --- | --- |
| Source recognition | Select relevant source-review forms; update owning grammar and formatting rules | Name/type-independent parsing, canonical formatting, invalid-form recovery |
| Declarations/contracts | Specify module roots, `impl`, interface mapping, exact body matching | One identity per operation; missing/duplicate/inaccessible cases |
| Values/access | Migrate ownership, initialization, parameters, projection and capture rules together | Valid/conflicting/failed-preparation cases; no hidden copying |
| Deferred execution | Specify retained dependencies, cancellation, effect evidence | Child-before-owner cleanup and stable suspension storage |
| CTFE/type construction | Specify the dependency and serialization protocol | Cycles/limits/target arithmetic and emitted tables |
| Specialization/IR | Specify owned uses, access transitions, cleanup, and outstanding proof obligations | Validators reject invalid ownership/access graphs; later proofs retain selected identities |
| Representation/backend | Specify observable layout/identity/failure contracts | Correct transport/drop plus measured storage/operation elimination |
| Standard library/tooling | Migrate checked declarations, behavior guides, examples, diagnostics and editor contracts | Public APIs and all presentation surfaces reflect the same selected model |

Migration owners include `spec/language/{ownership,bindings-and-initialization,callables,
generics-and-interfaces,errors-and-optionals,values-and-types,sequences-and-text,
asynchronous-computations,memory-and-regions,constants,modules,construction,syntactic-grammar}.md`,
the relevant platform chapters, and tooling contracts. This is a work index, not duplicate semantics.
Use explicitly labeled future sections while the current released contract remains active, then
switch each coherent selected contract and its implementation together at the v2.0.0 boundary.

## Verification Already Performed and Remaining Obligations

The root-place model check was run with:

```sh
python3 development/history/reviews/v2.0.0-value-access-model-check.py
```

It explored 3,456 reachable states and checked 14,144 allowed transitions. Four intentional invalid
state mutants were rejected. Named scenarios cover preparation failure retaining a source,
post-invocation failure consuming it, duplicate transfers, disjoint updates, retained-read conflicts,
and nested read versus nested update during a reservation.

This is exhaustive only for its finite abstraction: two roots, two calls, two operands each.
It does not verify compiler behavior, projections, dependency-bearing aggregates, reinitialization,
reborrowing, suspension, effects, or preservation of arbitrary program traces. The semantic case
matrix and proof obligations in [semantic closure](v2.0.0-value-access-semantics.md) remain required
inputs to formal specification and implementation conformance, not claims of completed proofs.

Before declaring implementation-ready, close every source form needed by the first boundary,
write its owning specification and negative/boundary cases, and document its adjacent compiler
products. Before declaring v2.0.0 complete, run the full compiler gates, installed-product checks,
standard-library/example migration, learning tasks, and correctness/performance measurements from
the milestone. No Rust-relative gate or deadline is added.
