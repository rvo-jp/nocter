# v0.49.0 Phase 3 Public Spawn and Pipe Review

**Result: complete with no open Phase 3 defect.** Canonical asynchronous spawn and its explicit
blocking twin now share launch preparation, target transitions, ownership, exec reporting, public
failure selection, and endpoint implementations.

## Findings Closed During Implementation

### A blocking launch could not be wrapped by an executor-safe future

Calling `spawn_blocking` from an async body is correctly rejected by the language effect contract.
The launch path was separated by progress semantics instead of hidden behind a wrapper. Operations
that create or configure local kernel resources, fork, or run child-only setup now cross exact
source-private primitive roles. Only the parent report read can wait for external progress, so the
async path suspends that descriptor through the existing reactor.

### Raw syscall vocabulary could bypass the ownership proof

The endpoint read/write roles already require standard source to establish nonblocking and
no-SIGPIPE state, but launch preparation still used generic Darwin syscall declarations marked
`blocking`. Closed roles now own pipe creation, close-on-exec duplication, status-flag access,
broken-pipe suppression, null opening, fork, descriptor installation, directory change, and exec.
ARM64 selection validates each exact ABI before materializing its target transition.

### Async and blocking exec confirmation could diverge

The launch-report pipe is now nonblocking before fork. Both readers consume one raw-attempt
classifier and one complete-payload decoder. The async reader awaits descriptor readiness; the
blocking reader calls the synchronous readiness adapter. Clean EOF remains the sole exec-success
proof, and a complete failure payload remains the sole staged rejection proof.

### The old generic pair-syscall escape hatch became dead infrastructure

After pipe creation and fork gained exact roles, `syscall_pair0` had no cross-module caller. Its
public package visibility, runtime role, target contract, ARM64 instruction, materializer, and
self-test were removed together. Multiword results remain supported through the exact pipe and
fork operations rather than a caller-selected syscall number.

## Responsibility Review

- `std/process` owns command preparation, stream policy, every temporary and public owner, launch
  failure decoding, public errors, and endpoint transfer.
- `nocter-runtime-contract` owns closed operation meanings and effect facts, not source spellings.
- `nocter-standard-profile` maps each role to one exact private declaration.
- `nocter-target-program` validates target-independent signatures and target availability.
- `nocter-arm64` validates machine ABI shapes and owns Darwin syscall identities and conventions.
- the reactor owns readiness only; it cannot decode exec reports or reap children.

No compiler stage recognizes `Command`, `ProcessIo`, `Child`, `Stdio`, or any public process error.
No source caller must remember cleanup: future cancellation and ordinary destruction retain or
transfer every child and descriptor obligation.

## Evidence

- runtime-role effect, uniqueness, profile-location, primitive-contract, and ARM64 selection tests;
- complete bundled-standard discovery, checking, target validation, and native materialization;
- generated native async spawn with stdin/stdout/stderr transfer, exact child observation, and exec
  rejection;
- generated native blocking spawn and exact-once endpoint transfer;
- existing generic future cancellation, endpoint destruction, and live-child abandonment tests;
- complete compiler, documentation, formatting, and repository gates.
