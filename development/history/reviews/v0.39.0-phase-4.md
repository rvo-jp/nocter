# v0.39.0 Phase 4 Network-timeout Review

**Status: complete with no open Phase 4 finding (2026-09-07).** Phase 4 adds finite synchronous
network timeouts without exposing native socket timeout state or creating a second retry policy.

## Reviewed Contract

The exact public declarations remain owned by `development/std/net/index.nct`. `TcpStream` exposes
a timeout-bounded constructor plus readable and writable timeout configuration. `TcpListener`
exposes accept timeout configuration. `UdpSocket` exposes receive-side and send-side timeout
configuration. Absence consistently means unlimited waiting, and observation returns the exact
portable `Duration?` retained by the socket owner.

The review rejected a general socket-option bag. IPv6-only behavior remains a constructor invariant,
and reuse-address is not public because no v0.39.0 use case defines portable semantics for it.

## Deadline Authority

`std/internal/net/deadline.nct` is the sole time-accounting authority. It samples monotonic `Instant`
once at an operation boundary, retains that fixed origin with the requested `Duration`, derives a
remaining interval for each wait, rounds positive sub-millisecond intervals upward, and caps one
Darwin poll request without extending the logical deadline. No TCP, UDP, or Darwin implementation
reconstructs the original duration.

The descriptor layer owns the complete retry decision. Connection establishment, acceptance,
stream reads, whole-buffer stream writes, datagram connection, datagram sends, and datagram receive
all create or receive one operation deadline. Interruptions and partial write progress consult the
same value. Each operation gets one immediate syscall attempt, including with a zero duration; a
subsequent need to wait after expiration returns the internal `timed_out` category.

The Darwin adapter owns only poll timeout encoding and raw outcome classification. It accepts an
optional already-bounded millisecond interval, uses the target `-1` sentinel only for absence, and
returns a closed `timed_out` outcome when poll reports zero descriptors. It cannot sample a clock,
restart a timeout, choose a public error, or mutate descriptor policy.

## Error and Ownership Review

`NetworkFailure.timed_out` is independent of raw `errno`, because a shared monotonic deadline can
expire without a native error. `std/net/errors.nct` is still the only conversion to the stable
`std.net.timed_out` code. Native timeout errno classification remains available for direct target
failures and maps to the same public category.

Adding timeout fields does not change descriptor ownership. Partial constructors still close on
failure, accepted descriptors start with no inherited policy, explicit close remains terminal and
idempotent, and destruction closes one still-open descriptor at most once. Timeout configuration
contains no descriptor, allocation, pointer, or target-native record.

## Verification

The native network gate compiles and executes 18 cases. New cases verify:

- finite listener accept expiration and stable error mapping;
- timeout configuration observation and clearing;
- timeout-bounded loopback TCP connection and finite stream-read expiration;
- finite UDP receive expiration; and
- successful receipt of already-queued data under a zero timeout.

The implementation was also traced for the nondeterministic branches that a portable loopback test
cannot inject reliably: EINTR recomputes remaining time from the same deadline, partial stream
writes check that deadline before every later attempt, long durations are issued as bounded poll
chunks, and an early or spurious poll timeout is rechecked against monotonic elapsed time.

Phase 4 passes the native network gate, the full compiler library suite, Rust formatting, generated
documentation stability, and whitespace validation. No compatibility alias, duplicated deadline
state, wall-clock dependency, raw timeout leakage, or open Phase 4 remediation remains.
