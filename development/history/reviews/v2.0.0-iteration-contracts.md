The bounded private fragment and its 283 production cases remain unchanged.

## Values and Existing Places Stay Distinct

Using ordinary next(): T? for every traversal would require T itself to encode read/update
access, or would copy/move elements during a supposedly reading loop. Letting ordinary methods
return either values or aliases would contradict the selected value-access foundation.

The selected protocols separate current-place cursors from value iterators. Read/edit cursors
advance, then project their current place through the fixed zero-input `[]` operator family.
Taking iterators return ordinary optional Item values. No yield, borrow type qualifier, dummy
unit argument or arbitrary named alias-returning method is introduced. Current projection reuses
the index projection's validity, origin and cleanup contract; it is not a second place system.

```text
for file in files { inspect(file) }
for edit file in files { update(file) }
for take file in files { submit(file) }
```

These are separate schematic uses under compatible helper declarations. The first does not
consume a non-Copy File; changing the body to require ownership does not change the loop mode.
The second needs writable source/current access. The third receives values and cleans unused
items at their defined points. A cursor's mutable control state is separate from the source's
element authority, so a read traversal can advance without mutating the original collection.

The fixed source families match read/edit/take receiver operations. An existing stream needing
incremental mutation while retaining its descriptor can expose an ordinary checked view/iterator
API, which is then consumed as a source value. A loop cannot silently upgrade a read source to
edit or take merely because the implementation needs those rights. Concrete source/API names
and async/fallible-step contracts are separate library migration, not invented here.

## Explicit Evidence, One Selection

### Produced Values Can Lend Update

The source-composition audit also removes the earlier blanket ban on edit input/receiver
temporaries. For a declared `touch(edit value: Buffer): void`, `touch(build_buffer())` can
own that produced Buffer in the caller's evaluation frame, lend update for the call, and clean
it afterward. A traversal over a freshly produced view/collection uses its explicit loop frame
the same way. Requiring a var merely to name that existing scoped owner added writing without
creating a safety distinction.

The expression remains a value. Local alias initializers and assignment still require places;
direct fixed/read sources are never snapshotted or implicitly wrapped to repair edit rights.
A computed component keeps its earlier Copy/move before temporary lending, while a direct
existing component updates original storage. Explicit construction and its already active
capabilities are not converted into delayed reservations. Wrapper construction from produced
values follows ordinary context; a direct edit place cannot be converted by implicit copying.

Returned capabilities/futures cannot escape a temporary they still need. Immediate await can
retain its normal evaluation frame; no lifetime extension or hidden promotion is introduced.
The bounded private frontend still has direct-place-only edit preparation, so these formerly
rejected programs require a coherent owner/preparation/access/cleanup admission before being
counted as accepted. This is adopted source closure, not an implemented relaxation. Earlier
future conformance rows are corrected to distinguish scoped aliases from temporary edit inputs.

### Operator and Cursor Evidence

An expansion operator is an explicit declaration, unlike a same-spelled next/advance method.
Its result needs the exact nominal cursor protocol. The three source interfaces bundle these
facts and associated cursor choices for generic use. Direct declared operator evidence and
interface-required evidence normalize to one selected operator identity, without fallback
ranking or member-name duck typing. Fixed arrays/packs have their own checked structural evidence.

Interface expansion requirements bind an associated cursor type. They do not introduce a new
opaque result identity or allow an operator to hide an incompatible result. Existing named
opaque factories remain available under their own contract; public nominal cursors may also
hide fields. Each public/body header still repeats completely.

## Sequential Use Does Not Imply Accumulation

A cursor can overwrite one private buffer whenever it advances. A for body can read its current
place and finish before the next advance. A variadic read/edit expansion instead prepares every
entry before invoking the recipient, so earlier roots must survive later steps and final
exhaustion. That same buffer-reusing cursor can be unsuitable for expansion. Copy element data
does not authorize an implicit snapshot of a declared read input to repair it.

Conversely, a cursor projecting separate stable outside elements can support accumulation when
its checked root/write/cleanup schema proves those relationships. Logical ordinals alone do
not imply disjoint actual roots. An outside guard can remain necessary even after the cursor's
position field is no longer used; dropping that guard cannot be postponed invisibly.

Finer root/footprint facts used by callers are exported checked public schema, not hidden-body
lookup. Generic bodies freeze operations under declared capabilities and export symbolic
root/write/cleanup conditions. Actual schema/witness binding discharges them without retyping,
granting a missing trait/Copy/right, or changing the selected operation. A known contradiction
is rejected at the definition; a failed actual-root condition is diagnosed at its use. This
reuses capability evidence rather than adding a blanket authored stable/noalloc modifier.

## Acquisition and Cleanup Are Observable

A taking array loop acquires the whole array before stepping. Non-Copy source storage becomes
unavailable; early break cleans unused received elements. Pack take acquisition uses the same
per-component value-sequence formation as pack captures. The original metadata count remains,
but moved components are unavailable. Copy evidence belongs to the source context.

Direct built-in argument expansion remains component preparation, with transfers reserved until
outer call commit. A user taking expansion operator is an inner invocation that may already
consume its source before later outer arguments are ready. Both use the same value/preparation
rules; they are different established producers, not permission-selected alternatives. Earlier
executed source/pull effects are not rolled back on later failure.

The count audit generalizes S22's known-length contribution check to each prepared logical entry,
including pulled entries. Check target-usize overflow before another entry/step/contribution.
No outer callee body runs before complete enumeration; fusion requires proof preserving the
source schedule, first failure, roots, allocator effects and destruction.

Body/owning-item cleanup runs before the next step. Break causes no extra pull; return/throw
protects the result before iteration/cursor/source cleanup. Disposing a cursor does not drain
an unevaluated producer. Intrinsic arrays/packs clean remaining elements in reverse order;
custom cursor destruction retains its checked lifecycle. Synchronous loops can suspend inside
an async body only with their complete frame/root/effect evidence; this is not for-await.

Item? uses only its outer absence as the end marker. Nested optional/fallible items keep their
layers; error data never becomes failure by type name. Discarded fallible items keep the normal
failure-loss warning. Current/index place-result data containing ! does not give the operator
an ordinary callable failure envelope or permission to throw.

## Grammar and Contract Audit Corrections

One tuple pattern handles both keyed and ordinary pair-valued sources. Retire the assembly-only
colon-key loop binder. Range generation belongs to an ordinary library source rather than a
special `..<` branch in for headers; no range API/export is selected by that simplification.
For-await stays a separate draft gate. The current projection is joint `cursor[]`, not spaced
typed construction or a synonym for one-input `cursor[()]`.

The integrated origin audit also makes the already recognized read/take incoming from relation
explicit in its memory owner. It bounds carried input provenance, unlike edit post-state.
S22's no-input-state wording must not be read as deleting that separate incoming contract.
Tuple/pack clauses cover every supplied component; direct descriptor access duration remains
separate from carried roots, and Copy cannot remove them. Earlier future conformance rows are
updated to use this precise obligation rather than an ambiguous state-clause description.
