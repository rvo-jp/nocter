# v0.72.0 Phase 1 Flow Fact Domain Review

## Scope

This review covers the checking-owned control-flow fact domain, its first fixed-array bounds
consumer, and every checker construct that can split, suppress, or merge execution paths.

## Design

`SafetyFlowState` maps stable parameter and immutable-local identities to conservative integer
ranges. It never stores syntax nodes, source spans, MIR values, or machine representation. The
normalized primitive relation is owned by `CheckedComparison`; compile-time projection and safety
flow consume that one meaning instead of independently decoding comparison plans.

An `if` clones one entry state, refines the true and false branches, and joins only continuations
whose checked type is not `never`. `match`, recovery expressions, short-circuit operators, loops,
and nested closures explicitly isolate or join state according to their execution shape. A join
keeps only identities present on every reachable incoming path and forms the conservative interval
envelope. Loop facts do not escape a potentially zero-iteration loop.

Mutable locals, captures, statics, value temporaries, and projected places are not admitted. This
is a semantic boundary, not a missing invalidation call: aliasable storage will enter the domain
only with an explicit checking-owned mutation model.

## Findings and Remediation

### Closed — Machine contradiction checking lost path context

The Phase 0 Machine pass initially compared a frozen disposition with a constant index and fixed
length. Path-sensitive proofs demonstrate that this check is invalid: constant propagation may
discover an out-of-range value inside a branch that checking proved unreachable for that value.
Machine sees neither the comparison nor its incoming path.

Machine now resolves only `Value` versus `Constant` representation and preserves the disposition
verbatim. A regression test lowers a constant-false guarded access and proves that optimization
does not reject checking's path result.

### Closed — Comparison meaning had two interpreters

Compile-time projection previously decoded `CheckedComparisonPlan` locally. A second decoder in
flow analysis would have created two semantic authorities. `CheckedComparison::primitive_relation`
now owns normalization, including reversed and inclusive relations, and both consumers use it.

### Closed — Branch state could leak through non-`if` control

A single mutable checker environment is safe only if every nested control construct restores or
joins it. The audit covered `if`, pattern branches, exhaustive `match`, `catch`/`otherwise`, logical
short-circuiting, loops, regions, unreachable tails, and nested closures. Tests reject facts that
escape a join, a loop body, or mutable storage.

## Authority Result

- Checking alone creates and joins path facts and freezes `IndexBoundsCheck`.
- Checked execution consumes the frozen disposition for `notrap`.
- MIR transports it mechanically.
- Machine may optimize index representation but cannot prove, strengthen, or contradict it.
- ARM64 consumes the closed disposition.

No consumer knows the flow environment's representation or recreates its comparison semantics.
Phase 2 may add view-length relations as another fact kind, but must use this same authority and
control-flow join model.
