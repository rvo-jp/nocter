# v2.0.0 Nominal Payload Schema Checkpoint

Date: 2026-11-09. Scope: declaration metadata for the next value-binding extension.
This record is implementation evidence, not a language authority or full-language conformance.

## Contract and Implementation

The owning language contracts are [nominal value payloads](../../../spec/language/structs-and-enums.md#future-direction-v2-0-0-nominal-value-payloads)
and [value construction and Copy](../../../spec/language/value-access.md#value-construction-and-copy).
The [declaration crate](../../compiler/crates/nocter-declarations/README.md#future-value-declaration-boundary)
owns exact APIs and construction invariants.

The existing private declaration program now owns closed record schemas in the same type
authority as its builtin callable data. Records reserve nominal identities before definition;
fields receive their own semantic identities and retain declared order, data types and owner.
A frozen field namespace performs member selection without rescanning definitions. No source
coordinates enter semantic identity, and no released-declaration adapter is involved.

Finite-containment and Copy validation operate over a shared graph, not an expanded tree. A
bottom-up worklist counts every containment field, including repeated uses of the same child
type. Invalid cycles retain a concrete field/type witness. Copy opt-in is checked against every
component; an ordinary record remains move-only even when empty or made entirely of Copy fields.

## Evidence

Focused declaration tests cover definition-order independence, nominal identity, repeated child
fields, nested Copy, empty and ordinary records, opaque error payloads, invalid Copy, self/mutual/
containing cycles, missing/double definitions, unknown references and symbols, duplicate names,
callable collisions, field-local names, and a 4,096-record shared graph. The shared graph has two
references to the preceding record at each level: validation must not expand its exponentially
large conceptual payload or recurse through host stack frames.

## Remaining Admission Work

The production `V2CoreUnit` parser and callable headers still admit the four builtin types only.
This checkpoint adds no accepted nominal source case, CLI mode, native realization or performance
claim. The builtin-only body resource classifier is intentionally unchanged; it cannot silently
classify a record as trivial scalar storage.

Next connect selected field places, partial initialization and payload disposal to the existing
shared control/access/resource authority. Prove whole/partial moves, disjoint and overlapping
accesses, replacement cleanup, surviving-field destruction and dependency survival before
accepting nominal source operations. Preserve schema sharing when tracking selected subplaces;
do not expand the full conceptual payload tree to represent initialization or cleanup state. Dynamic indexing, generic/container/capability/outcome
schemas and user destructors require their own contracts and proofs; four-leaf independence is
not a general payload inference rule.
