# v2.0.0 Module and Operation Contract Closure

## Status and Evidence

This is a design/migration checkpoint, not compiler qualification. The owning unreleased contracts
are [modules](../../spec/language/modules.md), [type behavior](../../spec/language/type-behavior.md),
[interfaces](../../spec/language/interfaces.md) and
[file/declaration syntax](../../spec/language/syntactic-grammar.md#files-and-declarations).
This review records rationale and adversarial examples without becoming another editable rule.
The published product and bounded private compiler fragment are unchanged.

The user requested a whole-source design audit before resuming executable lifecycle work.
The existing v2.0.0 delegation permits normal source/model decisions. No missing requirement or
external authorization blocks this checkpoint. The consequences below were selected by the
delegated designer, not presented as additional user approvals.

## Audit Findings and Dispositions

1. **An associated declaration had no conformance-binding production.** The assembly admitted
   `type Item` and associated bindings in requirements, but inner conformance allowed only
   named operation maps. Consuming an associated-binding block as part of InterfaceApplication
   also left a second optional mapping block. One comma-delimited conformance block now carries
   `.Item = T` and `read = read_bytes`. Their prefixes determine parsing without type lookup.
2. **Module decisions were distributed across the milestone and historical source checkpoints.**
   Contract-only roots, root-use exports, `see`, audience paths and definition pairing now have
   one current owning chapter. The source assembly imports the migrated productions rather than
   keeping an editable duplicate. Unmigrated generic/package/expression families remain labeled.
3. **Visible fields did not say who owns the complete schema.** A structural grant now explicitly
   closes a braced root field schema. That root owns a simple public record without a second
   private field-list copy. Without a grant, a public struct requires one private complete
   definition and the root lists only its selected visible fields. Schema ownership never depends
   on whether a same-name file happens to be discovered. This preserves hidden representation
   without a `...` notice and makes full public structural construction an actual promise.
4. **Directive attachment did not settle capability members.** Visibility cannot decorate an
   outer impl or selectively hide an interface requirement/conformance. Named APIs, fields,
   structural grants and root-use exports can have an audience; operation mappings inherit
   their interface/owner contract. No file/block mode or hidden public conformance is introduced.
5. **Default replacement and automatic matching were easy to conflate.** Required operations use
   a unique same-name binding; defaults retain their own body until explicitly mapped. Same-name
   maps are rejected when redundant but required for a genuine explicit default override.
   Private helper names remain implementation details; caller selection names interface identity.
6. **Header repetition lacked a name-resolution check.** Canonically equal authored headers
   must also resolve to the same contract in their own sources. Equal spelling with different
   import bindings cannot form a pair. Interface compatibility instead translates parameter
   identities and validates the substituted semantic contract; it is not text matching.

The separate complete representation for an opaque/public-partial struct repeats any exposed
field declarations. This is deliberate local readability, like complete callable implementations.
A closed public structural record needs no such repetition. No optional short implementation
form, generated public constructor alias or hidden field completion is introduced.

## Complete Source Reading Exercise

The following three sources form a design example within an assumed selected package. They are
not runnable compiler fixtures: public modules/interfaces/defaults are not admitted by the bounded
private frontend. Package/target/entry configuration is deliberately not inferred from the example.

```text
// index.nct
see ./counter.nct
see ./measure.nct

interface Measure {
    method self.value(): i32
    default method self.is_zero(): bool
}

struct Counter
impl Counter {
    func create(initial: i32): Self
    method edit self.increment(): void
    impl Measure
}

func exercise(): bool
```

```text
// counter.nct
see ./index.nct

struct Counter {
    total: i32
}

impl Counter {
    func create(initial: i32): Self {
        Self { total: initial }
    }

    method edit self.increment(): void {
        self.total += 1
    }

    method self.value(): i32 {
        self.total
    }
}

func exercise(): bool {
    var counter = Counter.create(0)
    counter.increment()
    counter.is_zero()
}
```

```text
// measure.nct
see ./index.nct

interface Measure {
    default method self.is_zero(): bool {
        self.value() == 0
    }
}
```

An API reader opens the root, not the hidden total field or default body. An increment-body edit
needs only counter.nct for its complete signature/representation; the direct root link explains
the public identity. A default-body edit needs its own source plus its explicit interface
dependency. The interface has no access to Counter.total. An outside caller can use the public
Measure operations through the contracted conformance; it cannot construct Counter by fields.
Compiler inventory still checks all three sources. No empirical learning-cost or timing result
is claimed from this reading exercise.

## Adversarial Source Obligations

These are specified outcomes for future compiler fixtures, not passed tests. Each row must be
consumed by the actual source path when that feature is admitted; documentation checks cannot
qualify it.

| Case | Required outcome |
| --- | --- |
| Root function body, constant initializer, test or destructor | Reject forbidden file role |
| Root authored use whose signature use later disappears | Re-export remains until authored use is removed |
| Root namespace alias | Export the alias; preserve module/member identity and audience |
| Source-folder helper without a direct see | Inventory/check it without granting the caller visibility |
| A sees B; B sees C; A names a C helper | Reject missing direct visibility |
| Mutual same-module see | Accept direct set visibility without recursive loading |
| see crosses child module or nested package | Reject even if the physical target exists |
| Matching body reached through only a transitive see or use | Do not pair; diagnose missing exact definition relation |
| Contract/body differ only in read versus edit, origin, data constructor or generic names | Diagnose the header difference at both locations |
| Equal authored type spelling resolves to different imported types | Reject resolved-contract mismatch |
| Two directly linked bodies | Reject duplicate definition without first-match selection |
| Package-only target re-exported externally | Reject widening, not silently narrow the re-export |
| ../ above root, named visibility path, package alias | Reject invalid audience syntax/boundary |
| Visibility on outer impl or an interface requirement | Reject unsupported subject, not a scoped default |
| Closed Point root with literal { x, y } and no implementation copy | Admit one complete schema and synthesized initialization |
| Private representation completion added to that Point | Reject second schema owner |
| Partial/opaque root struct without a complete definition | Reject missing representation |
| Hidden field is non-Copy behind a copy struct contract | Reject Copy conformance at the complete definition |
| Structural grant misses/duplicates/reorders a field or exposes a restricted field too widely | Reject at the grant/schema relation |
| Interrupted initializer after an earlier moved field value | Clean only produced components in reverse production order; do not restore the move |
| Interface impl contains .Output and parse mapping in one block | Parse independently of type-name lookup; validate each distinct binding |
| Missing, duplicate, unknown or cyclic associated binding | Reject the owning declaration's failed obligation |
| Same named helper with an incompatible operation | Reject selected helper compatibility; do not search other signatures |
| Different private helper names implement same-name operations on two interfaces | Freeze each distinct interface binding without exporting helper aliases |
| Same-name inherent method added beside a default | Preserve selected default; do not override implicitly |
| Inherent-only candidate collides with a different interface body | Rename it or make an intentional implementation binding; an interface selector cannot select the inherent-only member |
| Explicit same-name default replacement map | Check/freeze the intentional override |
| Redundant same-name required-operation map | Reject duplicate style |
| Two generic bounds expose distinct read identities | Require interface selection even if both signatures match |
| Unique operation unnecessarily qualified | Reject redundant selector |
| Interface default accesses a concrete private field | Reject absent interface capability |
| Derived prerequisite lacks its separate explicit implementation | Reject; no synthesized base conformance |
| User destructor consumes a non-Copy field without replacement | Reject incomplete-self transition |
| Destructor throws, waits or suspends through a helper | Reject inferred forbidden cleanup effect |
| Destructor traps/diverges | Do not claim normal component cleanup or invent unwind semantics |
| Conformance law says bounds are valid without proof | Do not eliminate a memory-safety check from that assertion |

## Remaining Work

This checkpoint closes selected declaration/source-role semantics. It does not close full generic
solving, associated-projection collision spelling, opaque result witnesses, enum exposure and
patterns, CTFE/effects, typed literals/packs/coercions, outcomes, async or platform/package tooling.
Their remaining grammar stays in the explicitly non-normative assembly. Do not use the published
specification or a historical example as a fallback.

Next close those owning subjects and test the integrated source design before extending compiler
acceptance. The already frozen private invocation graph still needs executable environment and
cleanup realization; this documentation work supplies no runtime evidence for it.
