# v0.73.0 Phase 5 Review: Qualification

**Result: complete with no open implementation finding (2026-09-30).** The qualified candidate
closes the relational-safety milestone without adding a second proof authority or claiming
guarantees beyond validated source bodies.

## Proof-authority Audit

Checking remains the sole owner of source-level bounds and arithmetic proof. Each checked
operation freezes a closed disposition. MIR converts that disposition one for one and validates
its placement. Machine converts it one for one, may rewrite only the index representation, and
retains the disposition unchanged. Its effect classifier uses the frozen value only to avoid
removing a potentially trapping operation. ARM64 emits the specified runtime check, omits it for a
proved-safe operation, or emits an unconditional trap for a proved-trapping operation.

Search and call-site review found no relation graph, interval reconstruction, source-expression
inspection, semantic-name fallback, or backend rule that can strengthen a checking-owned result.
Compiler-generated arithmetic retains its separate `InternalInvariant` state and cannot be
mistaken for source proof.

## Contract and Presentation Audit

Primitive execution facts remain owned by `nocter-runtime-contract`; target-program validation is
the only boundary that admits a source declaration against those facts. Standard declarations and
their physical bodies are checked together. The language server consumes checked callable
guarantees through analysis queries and presents authored `notrap`; it does not infer guarantees
from body text or native behavior.

The standard adoption remains deliberately incomplete where a generic callback, selected decoder,
comparison, destruction path, or private-invariant abort can trap. The base iterator interfaces
therefore stay effect-neutral even though selected concrete iterators are `notrap`.

## Verification Reliability Finding

The first complete gate exposed a verification-resource defect rather than a compiler failure.
The native-session suite ran eight full compiler and generated-process tests concurrently while
local TLS cases exercised one-second source deadlines. One ALPN rejection case consequently
observed timeout instead of the intended TLS failure; the same test passed in isolation.

The gate now applies its existing four-worker heavy-suite limit to both language-server and
native-session tests. This preserves every assertion and source deadline while bounding compiler,
generated-process, and local-service contention. The complete 132-test native-session suite then
passed under the selected limit, including the formerly failing ALPN case.
