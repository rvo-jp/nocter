# v2.0.0 Enum Schemas and Pattern Operations

## Status and Owners

The normative owners are [enum schemas](../../spec/language/structs-and-enums.md#enum-schemas-and-construction),
[patterns](../../spec/language/patterns.md),
[branch syntax](../../spec/language/syntactic-grammar.md#patterns-and-enum-branches) and
[compile-time values](../../spec/language/generics-and-constants.md#constants-statics-and-final-values).
This review records decisions, counterexamples and future source/proof obligations. It does
not implement enum/pattern parsing, initialization, resource analysis, evaluation or native code.
Published contracts, library declarations and the 283-case private corpus are unchanged.

These decisions are made under the user's delegated design authority. No further permission,
new reserved word, type-side access qualifier or caller-mode assertion is required. Copy enum
reuses the existing Copy declaration vocabulary; edit/take bind pattern inputs rather than
restating a selected callable contract.

## Decisions and Rejected Alternatives

### Observe by Default, Request Update or Receipt Once

The former assembly specified a match header but not whether its payload names owned or accessed
values. Select the same unmarked-read/edit/take vocabulary as inputs. The operation applies
uniformly to the whole pattern and is fixed before tag/authority/body checking. A default match
can inspect a move-only enum without destroying it. A receiving branch must say take rather
than silently upgrading from a later use of a payload.

A value-receiving default, analogous to let, was rejected because ordinary inspection could
consume and destroy ignored resources. Inferring the operation from body use would make a
later edit change earlier source availability. Repeating operations on each leaf would add
duplicate authoring choices. The selected words express distinct operations unavailable from
the variant's ordinary data types; no explicit-read alternate is added.

These complete design functions assume the Message schema in the owning chapter and are not
currently runnable compiler fixtures:

```text
func number(message: Message): i32 {
    match message {
        Message.empty { 0 }
        Message.number(value) { value }
        Message.report(_) { -1 }
        Message.pair((left, right)) { left + right }
    }
}

func increment(edit message: Message): void {
    match edit message {
        Message.number(value) { value += 1 }
        _ { () }
    }
}

func receive(take message: Message): i32! {
    match take message {
        Message.report(reason) { throw reason }
        _ { 0 }
    }
}
```

Number reads the caller's payload; increment updates existing payload storage; receive acquires
and disposes the carrier while transferring a selected error explicitly to the failure output.
The raw error data variant does not select failure by its type or name. A take parameter and
a take branch are different boundaries: owning the parameter does not force every use to
consume/decompose it.

### One Complete Schema and Stable Copy Policy

A braced public enum publishes its complete alternatives and their construction entries. It
needs no private duplicate. An opaque root instead hides all variants and has one directly
linked complete definition. No hidden extra variant is added to an exhaustive public contract,
and no rest notice is needed. Payloadless alternatives omit parentheses; payload alternatives
declare/accept their exact nonzero arity.

A complete payloadless declaration has scalar Copy/equality. Payload families remain move-only
unless copy enum opts into the same conditional component proof as copy structs. An opaque root
without the grant remains move-only even if its private completion happens to be payloadless.
This selects one family policy at the declaration, rather than exposing hidden representation
as accidental source Copy or giving providers a second whole-type Copy rule. A Copy grant
alone exposes neither variants nor hidden scalar equality. Generic Copy conditions belong to
the checked advertised contract; their change is an API change, not an invisible optimization.

There is no fixed eight-bit tag/256-case language ceiling. Representation proofs may choose
compact tags, niches or eliminated tag storage. They cannot expose a numeric variant ordinal,
silently create structural equality for payloads or turn one known tag into whole-type Copy.
Finite by-value schemas are the selected scope; inferred recursive indirection still needs
its own allocation/cleanup contract, rather than an implementation-shaped tag limit.

### Tuple Paths Are Not Extra Inputs

The common tuple pattern reuses one enclosing binding/input operation. One parameter remains
one input position; names identify its semantic component paths. When every eligible source slot
belongs to that one input, a conservative whole-input bound can be elided; decomposing it does
not add a from annotation. The bound does not equate independent slots; an explicit leaf origin
can narrow it. Multiple eligible inputs still need an explicit public choice. Whole edit
postconditions cover ignored components too. Contract/body patterns repeat canonically, while abstract callable and
interface compatibility compare normalized positions/paths rather than parameter spellings.

### Discard Has a Lifecycle Position

Acquire a value once, stage named leaves using the common component supply rule and then clean
the remaining carrier before entering the body/continuation. Read/edit underscores instead leave
their original components intact. Named owners later follow ordinary scope cleanup. An ignored
resource needed by a surviving view cannot be retained invisibly as a repair.

A user-destructible carrier must stay complete: Copy leaves can be snapshotted, but a non-Copy
extraction is rejected. Dispose that complete carrier once before entering the branch. Parameter
pattern entry on a lazy producer occurs when driven; capture receipt occurs at construction,
and unstarted cancellation cleans the intact received inputs. These phases must not be conflated
when a destructor has effects.

### Constant Data Needs Its Active Variant, Not Phantom Resources

Finite enum construction, matching and tuple patterns join the single checked const evaluator
domain. Final eligibility inspects the actual active payload. For example a resource-free
Message.number constant contains no error graph merely because Message also has a report case.
This is fresh constant construction, not Copy for arbitrary Message values. An enum-owned
destructor always applies and prevents final admission; actual resource payloads remain invalid.
No general outcome/view serializer or host-layout encoding is implied.

## Future Source and Proof Cases

These are required future cases, not passing production tests.

| Case | Expected behavior |
| --- | --- |
| Braced public enum and another private full definition | Reject a second schema owner |
| Bare public enum without/with two linked completions | Diagnose missing/duplicate definition independently of file order |
| Hidden variant added to a purported exhaustive root | Reject; no partial public enum schema |
| Opaque completion not directly visible to a helper | No private variant access through root/transitive see |
| Opaque enum is matched outside with its private cases | Reject inaccessible variants; a fallback cannot legalize naming them |
| Opaque enum outside uses a final catch-all | Cover the opaque remainder without knowing its private cases |
| Payloadless private completion behind an unmarked opaque root | Preserve move-only policy; do not infer Copy/equality from hidden tags |
| copy enum has an error or other unconditional non-Copy payload | Reject Copy request across the whole family |
| Known resource-free tag of a move-only payload enum | Do not grant whole-type Copy |
| Distinct scalar enums have equal names or physical tags | Reject cross-type intrinsic comparison |
| More than 256 finite variants | No invented source limit or mandatory tag width |
| Direct by-value recursive payload with a terminating alternative | Reject this scope's non-finite payload representation; no silent boxing |
| Enum constructor used as a function value | Reject; use an ordinary helper/closure |
| Payloadless variant() or omitted payload patterns | Reject the noncanonical/wrong-arity form |
| Interrupted later payload argument | Dispose only completed earlier payload values; no whole-enum destructor or rollback |
| Default match on non-Copy payloads | Bind read access and retain original owner |
| Edit match on a fixed owner or read input | Reject missing authority even if the variant would not match |
| Take if-is on a non-Copy source, then false branch | Source already unavailable; cleanup precedes fallback |
| Take of Copy enum | Snapshot; original remains available |
| Copy take branch changes the original and later uses its bound payload | Keep the snapshot's earlier value; do not alias the original |
| Default read branch changes the parent before a later bound-payload use | Reject the live projection conflict rather than silently snapshotting |
| Take requests a non-Copy indexed element | Reject a hole in the container; require checked removal/exchange |
| Read scalar leaf returned as value | Copy the selected data under source evidence, not the entire carrier |
| Read non-Copy leaf returned/thrown | Reject unavailable transfer; do not infer take from the body |
| Live payload alias while parent variant is replaced | Reject invalidation |
| No remaining payload demand, writable parent replacement | End the access and invalidate old tag facts without an artificial arm-long borrow |
| Duplicate variant arm or catch-all after complete coverage | Reject structurally redundant coverage |
| Known current tag but missing other arms | Still require source coverage; optimize execution separately |
| Match/if result used as a scoped alias | Reject ordinary value-result escape, not silently select a place |
| Taking a user-destructible carrier and extracting a non-Copy leaf | Reject incomplete-self transition |
| Taking one Copy leaf from that carrier while ignoring other payloads | Snapshot leaf; destroy complete carrier once before body |
| User destructor changes a copied field before branch entry | Keep the leaf's pre-cleanup snapshot, not a later reread |
| Ignored owned field carries a fallible value | Preserve failure-loss warning; underscore is not catch suppression |
| Ignored read/edit field | Retain the original component; no ownership loss at that pattern |
| Ignored owner is needed by a surviving dependent binding | Diagnose discard boundary and later need, without lifetime extension |
| Tuple parameter with two names | One argument/ABI input; aliases point to distinct component paths |
| Different component names normalize to the same interface relation | Compare semantic paths, not text |
| Same type leaf names swapped under a from bound | Preserve distinct paths; reject changed dependency relation |
| All eligible slots belong to one tuple input | Elide a conservative whole-input bound; do not guess a particular leaf or require repeated from |
| Another eligible input also exists | Require a stable explicit public bound; do not infer it from private body use |
| Edit tuple from static leaves a discarded component dependent | Reject incomplete post-state proof |
| Async take pattern with ignored user-destructible component | Discard on drive entry or intact cancellation, never eagerly at construction |
| Joint take(value) versus separated take (value) header | Preserve identifier-call versus contextual mode; no type-name reparse |
| Grouped identifier arithmetic starts with a contextual mode word | Preserve its expression reading and formatter grouping |
| Constant enum has an inactive resource-bearing case | Validate only the actual payload; no phantom resource |
| Constant enum's active payload owns a runtime resource or family has a destructor | Reject final eligibility |
| Non-Copy static enum is inspected by a read pattern | Preserve static owner; no move or update |

## Verification and Remaining Work

Checkpoint verification uses the documentation-generator tests and an explicit external build
at `/tmp/nocter-enum-pattern-site`, preserving the 376-page publication boundary. A read-only
inventory across the owning grammar and remaining draft finds 153 V2 productions with no
duplicate definitions or unresolved V2 references. Whitespace/local links are checked as well.

Verify documentation generation, an external site build, links/whitespace and the combined owning
grammar/remaining assembly's named-reference inventory. These checks cannot prove an unambiguous
parser, correct flow/resource plans, const emission or executable cleanup. No tests for an
unconsumed private-language path or a language server count as enum implementation evidence.

Future source integration must freeze the enum/variant identities, input operation, component
paths, supply choices, tag refinements and remainder cleanup under one authority. Consumers must
not recover them by source text, type layout or another overload search. Generic/capability schemas,
async cancellation, target data and actual source cases need qualification together.

Next close literal/pack/expansion and iteration contracts, then the remaining lexical/control/
expression and package/platform subjects. Keep recursive schema/indirection and general
capability/erasure rules explicit gates rather than inheriting released syntax or representation.
