# v0.50.0 Phase 7 Integration and Release Qualification Review

Date: 2026-09-14

## Result

Phase 7 is complete. The v0.50.0 local-data and asynchronous-streaming area now crosses the same
source, semantic, editor, native-execution, and installed-toolchain boundaries used by ordinary
Nocter applications. No release-only adapter or compiler-internal escape hatch is required.

## Findings and Corrections

The review found two current integration defects.

First, the exact reviewed standard-module dependency set had not been advanced when `io` gained
time contracts and `io/stream` gained its generic I/O, buffering, asynchronous-iteration, string,
and vector dependencies. The discovery test correctly rejected those otherwise valid edges. The
reviewed set now records them explicitly; the test still compares the complete actual graph in both
directions, so an unreviewed new edge and a stale exception both fail.

Second, the complete application compiled and ran but had not been rewritten by the current source
formatter. The repository-wide runnable-example formatter contract detected the divergence. The
source is now canonical, and the existing global gate—not an application-specific exception—owns
future enforcement.

## Boundary Review

- Installed qualification builds the application only through the packaged compiler and packaged
  standard library. It verifies exact output and the absence of temporary or failed final files on
  the recoverable failure path.
- The LSP test opens the checked-in application rather than reproducing a smaller source string. It
  exercises hover, definition, implementation, completion, semantic tokens, and inferred types
  from one workspace semantic snapshot.
- Standard-module dependency policy remains in discovery tests. Standard source does not know the
  allowlist, and downstream compiler responsibilities do not reconstruct the graph.
- Application execution continues to depend only on public filesystem, iterator, stream, task,
  time, process, string, and generic I/O contracts. It does not know target jobs, descriptors,
  executor queues, or completion encodings.
- The qualification script owns observable installed-artifact behavior. It does not implement
  semantic validation or duplicate the compiler's application checks.

## Residue Review

Repository searches and exact graph tests found no retained public asynchronous filesystem alias,
endpoint-specific byte-iteration interface, public wrapper around a blocking filesystem operation,
or second target operation selected by source spelling. File completion roles remain internal ABI
declarations and are not user-visible compatibility paths. Network-local `read_async` identifiers
are internal transport attempts, not alternate standard-library surface names.

No caller must know how to retire a blocking job, directory stream, asynchronous iterator, file,
buffer, or timeout operation. Cleanup authority remains with each owner and its ordinary
destruction path. No new reverse dependency, semantic recomputation, or source-text inference was
introduced by the application or its qualification.

## Evidence

- the runnable-example formatter contract;
- exact standard-module dependency and declaration-boundary tests;
- the real-application language-server reference test;
- compiler workspace tests, clippy, formatting, and repository integrity gates;
- installed release qualification for successful and recoverable-failure application runs.

Phase 7 introduced no compatibility layer. v0.50.0 can proceed to release-candidate preparation.
