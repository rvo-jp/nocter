# v2.0.0 Generic, Constant and Opaque Source Closure

## Scope and Status

This records selected source-design consequences and adversarial obligations. The normative
owners are [generics and constants](../../spec/language/generics-and-constants.md),
[opaque results](../../spec/language/opaque-results.md),
[nominal Copy schemas](../../spec/language/structs-and-enums.md) and the
[generic grammar](../../spec/language/syntactic-grammar.md#generic-arguments-and-requirements).
The whole-source assembly imports migrated productions without retaining editable copies.
The [previous checkpoint](v2.0.0-module-and-operation-contracts.md) owns its own migration evidence.

These are decisions under delegated design authority, not additional user approvals, compiler
conformance, an implemented evaluator, an opaque-result ABI or native performance evidence.
Published specifications, libraries and the bounded private compiler are unchanged.

## Decisions and Counterexamples

### Generic Names Do Not Choose the Parse

`decode<Config>(bytes)` remains the selected explicit callable argument form. A type argument
and a value argument can both look like `Name`; arrays and groups overlap too. Resolving that
name as a type to decide syntax would make a declaration/import change alter parsing. The
selected declaration's ordered parameter kind instead directs elaboration of one neutral
source tree. Wrong-kind arguments fail checking, without fallback parsing or another target.

Owner and member arguments stay independent, as in
`Table<Key>.from_entries<Entry>(entries)`. Each list is complete or fully inferred; partial
argument lists, `_` holes and a second call spelling are not added. A requirement validates
the inferred substitution instead of searching interfaces for a convenient unknown type.

Generic delimiter rules now have one owner. Closers terminate ungrouped value arguments; a
right shift or comparison involving a closer uses an ordinary parenthesized expression.
This keeps `Fixed<u8, (WIDTH >> 1)>` distinct from nested generic closers without name lookup.
Actual parser ambiguity/recovery still needs source fixtures when the feature is admitted.

### Associated-Type Collisions Need an Owner

The source design already selects an interface operation as `value.(Reader.read)()`. The same
shape now selects a colliding associated type as `T.(Reader.Item)`. This avoids a new punctuation
family or extra type parameters merely to name an existing declaration. Unique lookup stays
`T.Item`; redundant qualification is rejected. The selector does not prove an absent interface
bound or merge two declarations whose normalized types happen to be equal. This closes the
previous module/operation checkpoint's type-position spelling gate; solver qualification remains.

### Constant Evaluation and Final Data Are Different Domains

Loops, local mutation, fixed arrays and finite record construction can execute in a checked const
body without allowing a local address, file handle or exclusive capability into an emitted value.
Final eligibility is checked separately from temporary operations. This provides generated tables
without treating arbitrary runtime resources as serializable bytes.

`const` is a storage-independent named value recipe, while `static` has one immutable place.
A constant reference constructs a fresh eligible value, even for an ordinary move-only record;
it does not copy an existing runtime owner or make the type Copy. For example, an ordinary
private source may contain:

```text
struct Entry {
    code: i32
}
const ENTRY: Entry = Entry { code: 7 }

func example(): i32 {
    let first = ENTRY
    let second = ENTRY
    let transferred = first
    // first is unavailable; Entry has not acquired Copy.
    transferred.code + second.code
}
```

The alternative of requiring all final constant types to be Copy was rejected: it would force a
public runtime duplication capability merely to name reproducible resource-free data. The
selected recipe cannot contain a user destructor, runtime-owned resource or evaluator-local
identity. Its fresh-value behavior is intentional constant construction, not a hidden clone
repair. `static ENTRY` instead permits read access but no move of that non-Copy record.

Array repetition also stays an ordinary value operation: evaluate the element once, require
Copy for multiple elements, and evaluate/clean the element even for a zero count. This does not
permit repeating a move-only resource or removing effects because the final length is zero.

### One Evaluator Serves Value and Type Positions

A closed `usize` returned from a const loop is eligible for a fixed-array length or const
argument. Its typed value, not its source spelling, enters type identity. Unknown symbolic
arithmetic such as `N + 1` remains outside the selected type-identity domain. Expanding ordinary
closed evaluation is not a claim to solve arbitrary symbolic equalities.

Constant/type dependency queries cannot use unfinished results. Pure callable recursion may be
valid within deterministic evaluation limits; a declaration-value cycle is a different failure.
Required evaluation cannot become runtime initialization after exhaustion. Optional optimization
can decline folding without altering source validity. Runtime primitive registration does not
implicitly provide an evaluator implementation.

### Opaque Witnesses Belong to the Callable, Not Its Source File

A bodyless root result `some Source { .Item = i32 }` and its complete matched implementation
share one opaque identity. The implementation establishes one finite witness per specialization;
clients use only the advertised contract. No hidden Copy capability, heterogeneous branch
representation or separate caller-generated witness is inferred.

Required interface operations use an associated type rather than an implementation-specific
opaque identity. A contracted default can have an opaque result because it has a uniquely
matched body. Missing/failure-only/unanchored producers cannot invent the witness needed for
layout. Generic witness and native realization are still implementation/proof work.

An opaque default override is an explicit conformance boundary: its selected helper establishes
one witness under the operation's instantiated opaque identity. Without that rule an override
would need to name an inaccessible opaque return type. No new source spelling or general type
equality is required, and an inherent same-name addition still cannot override implicitly.

## Future Conformance Obligations

These are design cases, not newly passing compiler tests.

| Case | Required outcome |
| --- | --- |
| Explicit callable list decode<Config> after its name | Select the declared type slot and check it once |
| Same path syntax in a usize constant slot | Elaborate as a value, without reparsing based on the name |
| Literal in a type slot or type-only form in a value slot | Local kind-mismatch diagnostic |
| Partial list, named argument or underscore hole | Reject unsupported generic form |
| Empty result inference with several possible substitutions | Require a local expected type or explicit complete arguments |
| Requirement could be satisfied by several unrelated concrete types | Do not use it to guess a substitution |
| T.Item from two distinct interfaces | Require T.(Interface.Item), irrespective of equal normalized results |
| Prerequisite diamond reaches the same owning declaration | Preserve one identity without a false collision |
| Selector names an interface absent from the capability environment | Reject missing evidence |
| copy struct Box<T> with value: T | Derive conditional Copy; do not rewrite a generic move at a concrete caller |
| copy struct with an unconditional error field | Reject invalid structural Copy request |
| Closed const function result determines an array length | Evaluate through the same checked value authority |
| Equal array lengths 4 and 2 + 2 | One semantic array type |
| Bare N versus unresolved N + 1 in a type | Preserve N identity; reject unsupported symbolic arithmetic |
| const loop mutates evaluator-local data | Admit only through ordinary initialization/access checks and budgets |
| Const body contains a runtime-only call on an unused branch | Reject the promised evaluator-domain violation |
| Temporary record returned with a local view/address | Reject final-value escape |
| Repeated references to a resource-free move-only record constant | Construct distinct fresh values; do not grant Copy to ordinary bindings |
| Attempt to alias/drop a constant name | Reject absent place/owner |
| Attempt to take a non-Copy static or edit immutable static storage | Reject operation on the existing immutable place |
| Array repetition count zero or one | Evaluate once; zero cleans the produced element; no multiple-copy requirement |
| Array repetition count greater than one without Copy | Reject, without implicit cloning |
| Constant references itself through a const body or a type length | Diagnose the actual declaration/type dependency cycle |
| Terminating recursive const function | Evaluate under deterministic budgets, not reject merely for a recursive call edge |
| Required evaluation exhausts memory/work/depth | Diagnose that limit, without runtime fallback or a nontermination claim |
| Host width/rounding/layout differs from the selected target | Use target semantics or reject unclosed target support |
| Bodyless public opaque result with one matched producer | One opaque identity and checked private witness |
| Two reachable witnesses or an unanchored recursive producer | Reject rather than synthesize runtime erasure |
| Private witness Copy changes | Preserve the opaque boundary's source availability contract |
| Unrelated opaque declarations share an interface and witness | Keep distinct declared identities |
| Opaque result required directly by an interface | Reject; use an associated type contract |
| Explicit override of an opaque default result | Establish one selected helper witness under the operation/conformance identity; do not equate distinct opaque types |

## Verification and Remaining Work

Documentation-generator tests, an explicit external site build and whitespace/link checks qualify
the documentation boundary. No generic/CTFE/opaque source admission or executable data emission
was added here. Source corpus counts and compiler/runtime qualification remain unchanged.

A read-only inventory of grammar fences across the owning syntax chapter and remaining assembly
finds 151 V2 productions, no duplicate definitions and no unresolved V2 references. Lexical/common
notation imports and semantic gates remain explicit. This inventory is not a proof of parsing
unambiguity, error recovery, type soundness or full-language implementation.

Remaining source work includes lexical completeness, full expressions/control/patterns/enums,
literal/pack/coercion operation contracts, outcomes, async, effects and capability/library schemas,
package/target/primitive/foreign contracts. Then audit the integrated grammar and reading examples
before resuming executable lifecycle work. Full generic solving, evaluator dependency scheduling,
target serialization and opaque witness validation need implementation evidence beyond this design.
