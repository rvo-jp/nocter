# v0.53.0 Phase 2 Dynamic Structured Task-group Review

## Scope

This review covers the public `TaskGroup<T>` contract, its standard-library ownership model, the
private dynamic-readiness primitive, Machine output placement, ARM64 lifecycle lowering, and
terminal future polling required for readiness observation followed by owning consumption.

## Findings and Resolution

### Child ownership remains in one ordinary source value

`TaskGroup<T>` owns exactly one `Vec<future T>`. The native readiness primitive receives only a
readwrite slice view and cannot remove, consume, or cancel a child. `next` removes the selected
future with the package-internal constant-time dense-storage operation before awaiting it, and
ordinary Vec destruction cancels every retained element. There is no detached handle or duplicate
cancellation authority.

### Readiness observation required a complete lifecycle contract

The initial implementation exposed a latent mismatch: a readiness scan could observe a completed
child, but a subsequent owning await rejected a second poll of that completed frame. Treating only
the group wrapper as exceptional would have created two future protocols. The shared native
lifecycle now defines completed polling as idempotent until consume or cancel; source async frames,
fixed-pair compositions, and interest futures obey the same rule.

### Machine placement is result-shaped, not child-shaped

The first draft reused a dependency named `AsyncPair` for the group's `(bool, usize)` output even
though the group is not a two-child composition. The contract is now `AsyncTuple`: Machine freezes
the two physical result offsets, and ARM64 consumes them without reopening semantic types. Pair
composition ownership stays confined to the ARM64 pair lifecycle.

### Dynamic wait storage has one temporary owner

The borrowing wait frame owns child metadata and combined-interest capacity for its complete
lifetime. It reuses both across polls, grows interest capacity only when required, and releases
them on cancellation or output consumption. The published count names exactly the copied records,
which retain each child's readiness-cell identity. No scheduler or executor representation enters
the public or standard-library contract.

The compiler-recognized primitive remains private to its implementation source. A small
`group_ready` adapter is retained because it changes authority: the wrapper is visible across the
standard package while the raw primitive cannot be called by another source. Collapsing them would
broaden primitive visibility, and the target-program contract rejects that change.

## Evidence

- runtime-contract, standard-profile, target-program, and Machine contract tests;
- complete bundled-standard-library target-session checking;
- native execution with empty, three-child completion-order, and nested `task.join` cases;
- existing join, race, timeout, source-async, and interest-future lifecycle tests;
- formatting, diff-integrity, compiler, documentation, and package checks recorded with the phase
  commit.

## Result

No open Phase 2 finding remains. Dynamic ownership, readiness observation, output placement,
cancellation, and destruction each have one authority, and no consumer depends on another
responsibility's private representation.
