# v0.73.0 Phase 1 Review: Place-Sensitive Mutation

**Result: complete with no open finding (2026-09-30).** Flow facts now admit writable scalar places
without assuming that callers, assignments, or aliases leave their values unchanged.

## Place Identity

`SafetyValue` is now a structural place identity: a parameter or admitted local root followed by
field and tuple projections. Borrow dereference is an access step rather than an identity step.
Dynamic index projections remain inadmissible because their identity depends on a runtime value.

Two identities overlap when they share a root and either projection path is a prefix of the other.
Writing a field therefore invalidates that field and its descendants without discarding facts about
a sibling field. Writing a whole root invalidates every projected fact below it.

An immutable local initialized from a scalar place retains its numeric range and is equated with
the source in the order domain. A local reborrow records an alias identity instead. Every later
field access and invalidation through that local is canonicalized to the original place before it
touches the fact state. This prevents a mutable call through a temporary alias from leaving facts
about the original root alive.

## Mutation Contract

Assignment invalidates its checked target after the right-hand side is checked and before later
source operations are checked. This matches source evaluation order and lets the right-hand side
use facts that are still true before the store.

Every checked call crosses one centralized invalidation hook when its `CheckedCall` is added:

- a direct readwrite receiver or argument invalidates its canonical place;
- a callable value with readwrite or owned invocation authority drops all value facts because its
  captured aliases are not represented as body places;
- an owned argument or receiver whose type may hide mutable aliases drops all value facts;
- an optional, fallible, array, slice, or tuple carrier is inspected recursively; and
- readonly receivers, readonly borrows, and built-in scalar values preserve facts.

When an alias-capable value cannot be reduced to an exact place, checking discards facts instead of
requiring a caller to have used an internal helper correctly. Alias identities remain structural
metadata when facts are cleared; they do not claim that a value is unchanged.

## Standard Validation

`MutableViewIter.next` now authors `noalloc notrap`. Its implementation establishes
`next_index < view.len()`, copies the cursor into an immutable local, advances the field, and indexes
with the copied value. Copy equality derives the copied bound; invalidating `next_index` preserves
the independent copied bound. The complete physical standard-library target validates this body.
The general `Iterator.next` interface remains unqualified, so generic code does not receive a
guarantee that every iterator implementation cannot trap.

## Remaining Work

The current loop model deliberately does not feed body exit facts into a back edge. Phase 2 must
replace that one-pass assumption with an explicit conservative loop invariant before facts about
mutable cursors may survive across iterations. Phase 1 does not infer nominal alias transparency;
opaque or generic carriers clear facts conservatively.
