# v0.53.0 Phase 1 Effect-Neutral JSON Generation Review

Date: 2026-09-15

## Result

Phase 1 is complete. Compact JSON spelling now has one effect-neutral encoder. In-memory String
generation no longer acquires `blocking` from a destination abstraction, while writer generation
retains the exact same token and escaping authority behind an explicitly blocking driver.

No remaining defect with current impact or an obvious near-term failure mode was found in this
area.

## Findings and Remediation

### A generic sink leaked its broadest effect into every caller

The former `ByteSink` contract required a blocking `emit` operation because one implementation
adapted `BlockingWriter`. Generic traversal therefore made `stringify` and `try_stringify` blocking
despite using only memory. Adding a second nonblocking sink interface would have duplicated either
traversal or adapters and left spelling ownership ambiguous.

The sink abstraction, its two adapters, and the separate escaping source are removed. One pull
encoder owns traversal, separators, exact number text, and string escaping. String and writer
drivers only consume complete UTF-8 chunks.

### Borrowed output and allocation failure shared an unusable provenance contract

A direct `&[u8]?!` step result made successful chunks depend on the input Value and conservatively
gave the failure path the same provenance. Returning such an allocation failure from
`try_stringify` violated its allocator-only result contract.

The encoder now retains its current borrowed chunk. Construction and advance results contain only
state or allocation failure; a chunk is observed separately after the `chunk` transition. This is
one private state-machine boundary inside `std/json`, not a public protocol. The two drivers are its
only consumers, and semantic visibility prevents application code from calling it.

### Writer buffering changed a fixture's assumed token boundaries

The old destination-failure fixture failed after a specific number of punctuation writes. Those
writes were private implementation detail, so buffering correctly changed the boundary. The test
now uses a value larger than the driver buffer and proves the actual contract: large content is not
materialized as one complete intermediate String, an observable prefix may be accepted, and the
destination's exact failure identity is returned unchanged.

### Removed modules remained in reviewed dependency and editor-leakage fixtures

The exact standard-library dependency relation and JSON LSP tests named the old output module and
private types. Those records now describe the current encoder boundary. Historical v0.22.0 reviews
remain unchanged because they accurately record the design shipped at that time.

## Boundary Review

- `EncodingFrame` is the only traversal state; neither driver walks `Value`.
- Escape spelling exists only in `Encoder.escape`; neither driver recognizes JSON punctuation or
  control bytes.
- Encoder code imports no I/O module and cannot invoke a destination operation.
- The String driver carries no blocking operation. The BlockingWriter driver is the only blocking
  generation layer.
- Allocation and destination failures remain distinct without comparing public error-code text.
- Map, String, Vec, allocator, and writer representations remain behind their owning contracts.
- The obsolete `std/internal/json/output` module, adapters, imports, and active documentation are
  gone.
- Public hover, signature help, completion, and diagnostics expose the root declarations but no
  encoder or failure-classification type.
