# v0.67.0 Phase 5 Configuration-source Adapter Review

**Result: complete with no open Phase 5 finding (2026-09-23).** JSON, current-process environment,
structured command-line results, and authored defaults now enter one source-neutral configuration
transaction without gaining a second policy path.

## Dependency Direction

The `config` root remains independent of JSON, CLI, process, filesystem, and service modules. Each
adapter is a child module with a one-way dependency on the core's public `Source` contract and its
own input contract. No adapter sees `Schema`, `Builder`, slot storage, normalization helpers,
constraints, secret flags, or finalized configuration internals.

`config/json` consumes public JSON variants plus package-visible semantic map traversal. It copies
strings and exact number tokens as text and copies Booleans as typed values. This preserves the JSON
document exactly while leaving the configuration schema as the sole authority for signed versus
unsigned interpretation and bounds. Container and null members are rejected without rendering
candidate values.

`config/environment` performs only an explicit field/variable selection through the public process
environment view. It introduces no prefix, case, separator, or fallback convention. An absent
variable adds nothing. `config/arguments` consumes `ParsedArguments` observations and never sees raw
tokens; flags add a caller-selected Boolean only when present, scalar options and positionals add
text, and repeated options fail rather than silently selecting a value.

## Authority and Failure Review

Adapters mutate only an uncommitted `Source`. `Builder.apply` remains the sole normalization,
unknown-field, constraint, precedence, and provenance authority, and its Phase 4 two-pass commit
keeps every adapter application failure-atomic. The caller still authors source labels and apply
order. Authored defaults require no adapter and use `Source` directly.

Adapter errors use stable codes and never contain candidate bytes. JSON map iteration order has no
configuration meaning because object names are unique and the completed source is applied
atomically. The first diagnostic among multiple independently invalid JSON members is intentionally
not an ordering contract. Environment and argument helpers add no candidate when the selected input
is absent, preserving earlier overlays.

Review rejected a shared adapter mapping representation: it would have duplicated configuration
name validation and introduced storage whose only purpose was delaying explicit calls. The chosen
functions keep mapping visible at the application call site and rely only on owner contracts.

## Qualification

Four standard test targets compile twelve core and adapter cases to native images. The Rust harness
supplies exact present and absent environment variables. A separate complete native application
applies defaults, JSON, environment, and command-line sources in order and verifies final typed
values plus source provenance. Bundled-standard compilation, reviewed module dependencies, focused
Clippy and formatting, workspace-library tests, documentation generation, and repository integrity
complete the phase boundary.
