# v2.0.0 Input-dependent Callable Results

## Scope

The private front end now preserves a taking callback through an owning result. Each selected
call application substitutes its own actual witnesses into the established result relation.
Named and generic forwarding, recursive input anchors/permutations, invocation adapters,
local joins/replacement and value-invoked factories use the existing accepted-unit and instance
products. No new source syntax, erased dispatch, ABI, MIR or native admission is added.

The sole source rules are [callable results](../../spec/language/callables.md#statically-witnessed-callable-results)
and the [bounded grammar](../../spec/language/syntactic-grammar.md#bounded-value-binding-fragment).
The [private stage contract](../../architecture/pipeline/value-access-declarations.md) and crate
READMEs own current responsibilities; this record preserves findings and qualification.

```text
func increment(value: i32): i32 { value + 1 }
func decrement(value: i32): i32 { value - 1 }
func forward(take action: func(i32): i32): func(i32): i32 { action }
func run(): i32 {
    let first = forward(increment)
    let second = forward(decrement)
    first(second(10))
}
```

`forward` returns its own formal witness without Copy evidence. Its body transfers the received
environment. The two applications in `run` establish different named results; exact producer
schemas can separately justify caller-side Copy. A currently Copy caller never changes the
unspecialized body's transfer, read-input capability or symbolic destruction obligation.

## Authority Review

A per-function result TypeId cannot represent both applications above. Body typing now reserves
one application from caller, selected semantic operation and callee identities. Source
coordinates, names and sibling type-allocation order do not enter that key. A construction-only
reservation prevents selecting two callees for one operation.

Application types are a controlled extension of the immutable header prefix. Branches share
immutable declaration/namespace/record facts. Canonical replay validates metadata identity,
persistent prefix identity and body ownership, then rewrites every body's data slots through its
exact suffix projection. Raw suffix TypeIds may coincide between bodies; the replay test proves
that their canonical application identities remain distinct. Every accepted body shares one final
program/type authority. The retained header handle validates source reuse and supplies no type
lookup fallback. An extended program cannot be reopened as a fresh header base.

One body data visitor serves canonical replay and result closure. It covers locals, selected
places, expressions, blocks, declared result evidence and deferred equalities. Selected call and
binding origins contain semantic identities and require no suffix-TypeId rebinding. Result
projection supplies its expression-specific witness/supply transformation to that same visitor.

One positive-equation solver owns witness unions and selected application substitution. The
analysis separates two obligations:

- Reachable result summaries come from actual staged values and argument producers captured at
  preparation. Strong replacement and conditional forwarding preserve actual producer flow.
  Each summary establishes one named or own-input witness. Recursive equations stay finite and
  require a reachable return anchor.
- Typed applications instantiate those established summaries through frozen actual bindings.
  This retains known types on interrupted paths without inventing runtime values. Exact deferred
  join/replacement equalities must hold after substitution; identical signatures cannot erase
  different actual code or input identities.

Declared argument types cannot establish a return anchor. This distinction prevents a dead named
branch or overwritten local, passed through another factory, from falsely closing an otherwise
unanchored recursive result. Type compatibility still applies to structurally checked branches.

The preceding [supply checkpoint](v2.0.0-deferred-value-supply.md) supplies the ordering needed for
move-only generic environments: pending supply closes after witness projection and before
initialization. Access/resource validation then consumes the same control graph. Code-origin
facts prove neither availability nor retained-access safety. Dropping a returned owner with a
live alias and reusing a consumed generic environment still reject.

The target owner substitutes the closed named/caller-formal result data through its existing
instance binding and payload maps. It does not inspect source, search signatures, infer result
relations, retype bodies or create another call graph. Only reachable invocation commits create
instances. Formal cleanup stays symbolic until concrete instance projection supplies its exact
payload; source moves remain selected even for a concrete named Copy environment.

## Regression Evidence

The production corpus contains 263 sources: 136 accepted units, 113 checking rejections,
8 header rejections and 6 syntax rejections. All 257 syntax-valid inputs have lossless parser
snapshots; header tests independently validate 249 header-valid inputs.

This extension adds 28 sources, evenly split between acceptance and checking rejection. The
former `r90-callable-result-dependent-input` becomes accepted
`a122-callable-result-dependent-input`, retaining its source and parser shape. Its previous
rejection was the explicitly recorded bounded limit. Other prior verdicts and snapshots stay
unchanged; earlier reviews retain their original evidence.

Accepted cases cover distinct applications, composed relays, input-anchored recursion, mutual
position permutations, same-witness joins/replacement, read-alias Copy from an exact named result,
generic once transfers, view weakening, second-input return and cleanup, higher-order input
supply, value-invoked factories, update views and known-witness interruption.

Rejected cases cover different application/formal joins and replacement, read extraction,
source/once reuse, unanchored recursion, dead input/argument anchors, overwritten argument
anchors, unknown-shaped required input, invocation upgrade and retained aliases. In particular,
a caller supplying the same named function twice does not excuse a body whose unspecialized
return relation joins two independent formals without an equality contract or erasure.

Five new source-backed checking tests inspect separate application identities, the single
canonical authority, generic result transfer/symbolic cleanup, formal-position substitution,
selected return staging and interrupted known types. A declaration replay test checks coinciding
raw suffix IDs, canonical separation, immutable headers, source ownership and fixed call target
selection. Three additional target tests close independent/permuted applications through the same
instance arena and exclude interrupted calls.

Affected library checks pass: checking 716 (83 private value-access tests), declarations 50,
model 43, declaration lowering 144 and syntax 144. The 18 private target tests and warnings-denied
workspace all-target Clippy pass. Formatting, documentation generator tests, an external site
build and whitespace checks pass. LSP/native runtime suites do not consume this product and are
not feature evidence. No speedup follows from front-end acceptance or static instance closure.

## Remaining Boundary

An unknown-shaped terminating input still cannot establish a witness required by a dependent
result (`r110-dependent-result-unknown-input`). The fragment currently rejects that application
with E0370, while independent results and interrupted inputs with known witnesses retain their
types. Signature-only result evidence must be represented without fabricating a producer or
runtime owner before this limit is removed.

Captured producers, general retained-state/write footprints and R/D/S, destruction, physical
argument/environment realization, ABI, executable cleanup, MIR and native output remain separate
work. The [handoff](../../TODO.md) owns the next task. No publication is authorized by this change.
