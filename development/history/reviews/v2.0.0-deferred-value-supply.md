# v2.0.0 Deferred Value Supply

## Scope and Reason

The private front end now resolves result-dependent Copy-versus-move before initialization.
It keeps one selected control graph, one place-supply decision and the existing immutable type
authority. No source syntax is added. Input-dependent callable results remain the next extension.

The [preceding result checkpoint](v2.0.0-callable-result-witnesses.md) selected conditional Copy,
ran initialization, and later proved that the exact result producer was a capture-free named
function. That proof was valid for its admitted producer domain. Extending the same ordering to
move-only environments would require replacing availability facts already computed under Copy.
The new boundary removes that dependency before admitting a wider producer domain.

The language authority remains the [value model](../../../spec/language/value-access.md) and
[callable results](../../../spec/language/callables.md#statically-witnessed-callable-results).
The checking README owns the mechanism; the
[cross-stage contract](../../architecture/pipeline/value-access-declarations.md) owns its handoffs.

## Authority and Ordering Review

1. Body typing selects ordinary input operations and known supply actions. One `supply::select`
   serves value construction and call inputs. An unresolved result records `PendingValue`, never
   provisional Copy; an unknown data identity is an integrity rejection.
2. The private control product builds only the selected evaluation graph. Result-producer flow
   follows reachable graph successors directly, including the builder's literal-Boolean pruning.
   It does not consume initialization or guess an anchor from a provisional expression type.
3. Result closure establishes existing witness identities and proves exact join/replacement
   equalities. During the same body projection traversal, the supplier resolves pending place
   operations against the exact data and source access. There is no second expression-arena
   traversal, body retyping, new type store or control reconstruction.
4. Only the closed query enters initialization, then access/resource analysis. Each runs once over
   the same graph. Known formal transfers remain transfers even when a concrete caller later
   supplies a Copy environment. Pending operations cannot acquire availability semantics.
5. Accepted units and the existing target instance graph consume these frozen operations.
   Source rebinding retains the preceding checkpoint's producer-body dependency proof.

The control graph has the same shape for pending direct input supply, Copy and transfer. Copy
uses `CopyPlace` to identify the exact selected place. Preparation checks initialization and read
permission and constructs one snapshot; it creates no child place-read expression or retained
source access. A later argument may update or destroy the original after that snapshot. Non-Copy
transfer keeps the existing reservation and atomic commit semantics.

Ordinary pending value construction likewise becomes a Copy boundary or a place move at its
existing evaluation point. Only unresolved operations are completed by this step. The result
relation still admits named producers; full source support for move-only returned environments
requires the remaining witness/dependency work.

Reusable-body rejection projection is shared by result closure and pending supply. Its source
binding remains separate from semantic decisions; supplier diagnostics do not depend on the
result solver's internal diagnostic construction.

## Source and Regression Evidence

The added accepted sources cover a taking scalar snapshot before a later argument updates the
same place, and a returned `once` environment snapshot before a later argument drops its original:

```text
func increment(value: i32): i32 { value + 1 }
func make(): once(i32): i32 { increment }
func run(): i32 {
    let action = make()
    action(if true { drop action
        1
    } else { 1 })
}
```

Two additional sources reject taking Copy input supply after destruction, for scalar and returned
function values. They retain `E0378` at the attempted preparation. Copy evidence never restores
an unavailable source.

Three integration tests inspect pending supply before closure, exact graph equality afterward,
successful initialization/access validation, one snapshot at input preparation, absence of a
child read and ordering before later update/destruction. The existing dead/overwritten-anchor,
recursive-result, alias, partial-record, interruption, cancellation and generic-transfer cases
continue to pass.

The production corpus now contains 235 sources: 121 accepted units, 100 checking rejections,
8 header rejections and 6 syntax rejections. All 229 syntax-valid sources have parser snapshots;
declaration tests validate all 221 header-valid units independently of body acceptance. Previous
verdicts and snapshots are unchanged. The four additions use the production parser, declaration
query and complete Unit constructor.

Checking's 711 library tests pass, including 78 value-access tests; the 15 private target instance
tests, parser corpus and header corpus also pass. Warnings-denied workspace all-target Clippy,
formatting, documentation generator tests, an external site build and whitespace checks pass.
LSP/native runtime suites do not consume this private product and are not feature evidence.

## Next Boundary

Later extension: [input-dependent callable results](v2.0.0-dependent-callable-results.md) implements
canonical application types and own-input substitution. This checkpoint's verification remains
its original evidence; current work belongs to the handoff and owning contracts.


Input-dependent results still require canonical application identities and witness substitution.
`forward(first)` and `forward(second)` cannot share an undifferentiated per-function result
identity. Recursive result equations must remain finite, while exact selected invocation views,
source-level capabilities and cleanup/dependency evidence survive substitution. The new supplier
ordering is a prerequisite; it does not establish those relations or captured-environment safety.

The [handoff](../../TODO.md) owns next work. ABI, physical environment/argument realization,
executable cleanup, MIR and native output remain separate from private front-end acceptance.
