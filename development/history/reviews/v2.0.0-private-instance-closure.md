# v2.0.0 Private Instance Closure

Date: 2026-11-09. Scope: root-driven concrete instances for the existing private value-binding
language, including statically witnessed callback inputs. This extends the
[callable input checkpoint](v2.0.0-callable-input-witnesses.md). No language syntax, public CLI,
ABI, released target admission or native execution is added.

## Boundary and Work Order

Callable results must preserve code identity through returns, input-dependent forwarding and
recursive relationships. They cannot be realized by treating their structural signatures as erased
runtime datatypes. Before extending that source boundary, this change closes the existing checked
binding recipes into one target-owned instance authority. Result relations can then extend that
same authority rather than create another dispatch graph or a body-rechecking path.

The production path now includes:

```text
private source -> declarations -> checked bodies/flow/resources -> accepted Unit
  -> explicit root -> private InstanceProgram
       concrete witness keys + reachable call edges + concrete payload projection
       paired with the same accepted Unit and checked bodies
```

The new instance product belongs to `nocter-target-program`, which already owns executable
specialization. Checking keeps body validity and preparation selection. No released-program
conversion, native fallback, layout guess or independent checking-side specialization graph exists.

## Implemented Contracts

Each key contains a callable identity and concrete witnesses for exactly its callback formals.
Argument plans supply the selected formal-to-actual edges; formal substitution preserves invocation
views and named identity. Keys are reserved before following calls. Repeated keys share one
instance, recursive edges refer back to it, and different witnesses never merge merely because
their signatures match. With only finite named producers and invocation views, this instance
domain is finite. Runtime scalar arguments are not specialization arguments.

Only checking-reachable invocation commits add instance edges. A named value that is never invoked,
a false/unreached path, or a callback input that terminates before producing a witness does not
force an uninvoked callee into the graph. Upstream Unit acceptance still checks all definitions;
root reachability cannot excuse an invalid unused body. A root with externally unbound callbacks
rejects without publishing a partial graph.

One table maps source data identities to concrete payload obligations in the same declaration
TypeAuthority. The checking-owned schema classifier remains the cleanup authority. A symbolic
formal environment resolves to its exact named-code contract, with trivial destruction, while
record schemas retain their schema cleanup. Shared record schemas close iteratively by data ID;
the algorithm does not enumerate their conceptual field-path trees.

The source body's selected Copy/move, reservations, preparation order and control graph remain
unchanged. A concrete named witness's Copy evidence cannot repair a generic body that lacked Copy
at source checking. Original bodies are shared through the Unit's sole exact-ID catalog; no typed
body, source generation, signature lookup or access proof is recreated during specialization.
Construction indexes are discarded when the one immutable instance arena is frozen.

## Review Findings

Review found that direct and value calls were distinguishable only indirectly through their input
bundle: value calls prepend an environment, while direct calls do not. A later ABI consumer could
otherwise infer this from counts and repeat an earlier decision. Typed calls now record the kind
explicitly. Transparent grouping of a named direct callee remains direct; named higher-order
values retain value invocation and the separate environment slot.

The resource schema projection is now an exported checking contract. It describes an obligation
without creating an initialized owner, acceptance proof or native capability. Target projection
uses that contract instead of maintaining another cleanup classifier. The shared test-support
fixture creates source and production syntax only; integration tests must still run normal
declaration and complete Unit validation.

## Verification

Twelve source-backed target-program tests validate exact named targets after forwarding, finite
recursive instance sharing and binding permutations, distinct equal-signature positions,
repeated versus distinct keys, checking-proven unreachable calls,
view/payload specialization with source moves preserved, interrupted invocation exclusion,
upstream rejection of unused invalid definitions, unbound-root rejection, explicit direct/value
shape, and a 64-level shared record schema without expanding its 2^64 conceptual leaves.

The existing 70 value-access checking tests pass, including the production corpus of 189 sources
(96 accepted, 81 checking rejections, 6 header rejections and 6 syntax rejections). No manifest
expectations or parser snapshots changed. Model library tests pass; warnings-denied workspace
Clippy checks the shared API and all targets. Formatting, documentation generator tests and an
external site build pass. LSP/native runtime suites do not consume this private path and are not
feature evidence.

This is concrete instance/call/data closure. It does not materialize ABI arguments or environment
storage, lower executable cleanup, construct MIR, emit machine code, or establish a speedup.
