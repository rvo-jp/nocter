# v0.36.0 Wall-clock and UTC Calendar Final Review

**Result: implementation complete with no open v0.36.0 finding (2026-09-05).** The reviewed change
adds wall-clock observation, validated UTC calendar conversion, strict RFC 3339 interchange,
filesystem modification times, one runnable package example, and semantic-editor qualification.
Release packaging and independent installed-home qualification remain release-preparation work.

## Authority Result

- `std/internal/os/darwin` owns syscall numbers, errno facts, stat offsets, and generic syscall
  primitives. It does not construct public time values or implement calendar policy.
- `std/internal/time` owns Darwin wall-clock and timeout layouts, validates target subsecond values,
  and publishes only normalized target-neutral observations or closed attempt states.
- `std/time` owns `Duration`, `Instant`, `SystemTime`, `UtcDateTime`, Gregorian conversion, public
  errors, and the complete RFC 3339 profile.
- `std/fs` owns filesystem metadata policy. Its Darwin adapter reads the OS-owned stat offsets and
  publishes the modification field only after `SystemTime` validation.
- compiler and LSP crates consume checked declarations and semantic identities. They contain no
  calendar, RFC 3339, stat-layout, or wall-clock interpretation.

The review initially found timeout `timeval` layout and validation in `std/internal/os` while the
new wall-clock `timeval` lived in `std/internal/time`. That split made target-time ABI ownership
depend on which syscall used the structure. The timeout layout and validation moved to
`std/internal/time`; the OS module now exposes only the generic `syscall5` boundary and
`SYS_SELECT` fact needed by that owner. This removed the old `wait_timeout_once` wrapper and its
duplicate policy boundary.

## Computation and Invariant Result

One private Gregorian implementation converts in both directions. RFC 3339 parsing constructs a
validated `UtcDateTime`, applies its numeric offset once in the `SystemTime` domain, and reuses the
same UTC range check. Generation obtains one validated UTC projection and never repeats calendar
arithmetic. Filesystem timestamps enter through `SystemTime.from_unix_parts`; no second normalized
instant representation exists.

The parser checks every byte boundary before indexing, accepts one through nine fractional digits,
normalizes numeric minute offsets, and rejects unknown `-00:00`, leap seconds, and results outside
the UTC year range. The generator reserves the exact maximum canonical length and shares one write
core between ordinary and recoverable allocation entry points.

Private unchecked constructors remain inside the single `std/time` module owner and are reached
only after public validation or from the inverse Gregorian conversion. No cross-module caller must
know their representation preconditions.

## Tooling and Practical Result

The `wall-clock` package example uses only public `std/time`, `std/fs`, `std/io`, and `std/process`
contracts. The public-package registry makes it part of complete target compilation and exact
usage-path execution. Standard filesystem tests execute Darwin stat decoding and UTC/RFC 3339
projection.

The focused semantic-editor test covers signature help and definition for parsing, completion,
hover, and implementation navigation for generation, and typed metadata hover. The full 92-test
language-server suite confirms that these results use the existing semantic snapshot and do not
introduce a source-text fallback.

## Remaining Scope

Local time zones, daylight-saving rules, locale presentation, leap-second preservation, async
timers, scheduling, `noblock`, and `realtime` remain explicit non-goals. They are not represented by
hidden fallback behavior in this implementation.
