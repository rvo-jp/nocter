# v0.73.0 Phase 2 Review: Loop Invariants

**Result: complete with no open finding (2026-09-30).** A loop can no longer reuse a mutable fact
that only happened to hold before its first iteration.

## Previous Risk

The v0.72.0 loop checker copied the incoming flow state into the body. That was sound while mutable
locals and projected fields were excluded from the fact domain. Phase 1 admitted those places with
write invalidation, which exposed a repeatability problem: an operation before a later assignment
was checked with the first-entry fact even though the assignment could make that fact false before
the next iteration.

This was a model boundary, not an isolated bounds-check bug. Arithmetic in a repeated condition,
body indexing, and facts retained after normal loop exit all shared the same optimistic entry.

## Repeated Invariant

Checking now derives one conservative repeated invariant before checking a loop body:

- built-in scalar value parameters and immutable locals remain stable;
- readonly borrows remain stable;
- fixed arrays, tuples, optionals, fallibles, and slices remain stable only when their recursively
  inspected element types cannot carry mutable aliases;
- mutable locals, readwrite borrows, generic values, opaque values, pointers, callables, futures,
  and nominal values are removed conservatively; and
- relational facts survive only when every referenced value and view length is stable.

Alias canonicalization happens before facts enter the state, so an immutable reborrow of mutable
storage does not masquerade as an immutable loop root. Numeric ranges and relational edges use the
same stability decision.

For `while`, the repeated condition itself is checked from this invariant because it executes on
every iteration. The state after evaluating the condition is branched into true and false paths.
The true path checks the body; the false path contributes the normal exit. A condition such as
`index < values.len()` therefore re-establishes the bound for every entered iteration even when
`index` is mutable.

Infinite, range, ordinary iterator, argument-pack, and asynchronous iterator bodies begin from the
same invariant after their one-time source acquisition is checked. Explicit `break` paths retain
their exact checked state. All reachable exits join through `SafetyFlowState::join`.

## Why This Is Not a Speculative Fixed Point

No body is checked twice, no checked nodes are discarded, and no syntax prepass guesses which
places a later call may mutate. The invariant is defined by semantic place and type stability, then
the condition adds facts known on every entered iteration. This is deliberately less powerful than
general abstract-interpretation convergence, but it is complete for guarded cursor traversal and
cannot depend on first-iteration optimism.

## Regression Evidence

- `cargo test -p nocter-checking --lib --quiet` — 633 tests passed.
- `cargo clippy -p nocter-checking --all-targets -- -D warnings` — passed after the final format
  correction.
- `cargo test -p nocter-native-session bundled_standard_library_crosses_the_complete_target_session --quiet`
  — passed.
- `cargo fmt --all -- --check` — passed after formatting.
- `git diff --check` — passed.

Focused tests prove a guarded mutable cursor can index and advance in a `notrap` loop, reject a body
that relies on a pre-loop mutable bound, and reject a post-loop index that would otherwise retain a
fact invalidated by an earlier iteration.

## Remaining Work

Phase 3 must close borrowed range construction. Pointer offset construction still uses arithmetic
whose validity is not represented by the current relation domain, and raw projection primitives
must not gain `notrap` merely because their callers usually validate inputs.
