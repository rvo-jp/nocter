# v0.63.0 Phase 3 Cryptographic-randomness Review

**Result: complete with no open Phase 3 finding (2026-09-20).** The public random contract crosses
the complete native pipeline, while target entropy, adaptation, public failure, byte decoding,
bounded selection, and element exchange each retain one authority.

## Reviewed Surface

The review traced every repository occurrence of entropy acquisition, random generation, seeding,
bounded reduction, and shuffling. It then followed the selected primitive from its runtime role
through target validation and ARM64 emission, and followed both standard-library consumers from the
internal adapter to their public or fail-stop policy.

Generated output, frozen historical records, and unrelated uses of the ordinary word `seed` were
not treated as active authorities.

## Authority Trace

| Responsibility | Sole authority | Consumers |
| --- | --- | --- |
| target operation identity | `nocter-runtime-contract::PrimitiveRole::EntropyFill` | standard profile and target contracts |
| primitive source location | `nocter-standard-profile` | discovery and checking |

| rejection threshold and remainder selection | `std/random/sampling.nct` | bounded public generation |
| raw initialized-value exchange | `std/internal/ptr` | slice sorting and random shuffling |
| Fisher–Yates permutation policy | `std/random/shuffle.nct` | public callers |
| collection seed retention and failure policy | `std/hash/HashState` | private table storage |

The compiler chain contains several representations of one selected operation, but no layer repeats
the standard library's retry, distribution, cleanup, or collection policy. The runtime role names a
capability; the target contract validates its ABI; machine lowering carries the already selected
operation; ARM64 selection chooses one target instruction; emission encodes that instruction. A
change to sampling or shuffling therefore cannot require a compiler change.

## Corrected Findings

The runnable example initially omitted `blocking` from `main`, although operating-system entropy is
a blocking effect. The ordinary checker rejected the example with `E0417`; declaring the actual
entry contract fixed the source rather than weakening effect enforcement.

The documentation generator rejected the first random behavior guide because it did not link its
compiler-checked `index.nct` contract. The guide now names that contract directly, preserving the
repository-wide rule that declaration documentation and longer observable behavior have a
bidirectional, mechanically checked relationship.

The public-example runner assumed every successful example had one exact stdout byte sequence.
Random output made that hidden assumption observable. Its contract is now an explicit sum of exact
output and validated output; `random-choice` validates both the sampled range and the set of values
that a permutation may place first. The runner still rejects every discovered example without a
declared output contract.

The map behavior guide still claimed that hashing source received only a `u64` seed. That described
the implementation before shared entropy adaptation. The guide now records the actual boundary:
`HashState` consumes the package-internal completion fact, owns fail-stop conversion and seed
retention, and table storage receives only the initialized state.

The complete editor suite found one test that still searched slice sorting for the local raw-swap
implementation removed in Phase 2. The test now follows the checked call from slice ordering to the
shared package-internal `swap_slice_values` contract. This removes an old-structure assertion while
increasing coverage of the new responsibility boundary.

No obsolete hash-specific entropy primitive, alternate operating-system random source, remainder-
only bounded sampler, second Fisher–Yates loop, or second raw element-swap implementation remains.
The test-support `fill_for_test` wrapper exposes the selected primitive only inside a synthetic
standard package used to prove the native ABI; it is not an application or standard-library
authority.

## Behavioral Evidence

Deterministic standard tests cover failed-output clearing, preserved successful bytes, canonical
little-endian scalar decoding, biased-prefix rejection, zero-bound rejection before entropy use,
Fisher–Yates boundaries, and entropy-free empty and singleton shuffles. Native-session tests cover a
request larger than Darwin's single-call limit, full-width and bounded values, a move-safe in-place
shuffle, and the public example through executable materialization.

The complete compiler verification matrix covers compiler libraries, CLI behavior, JSON-RPC editor
behavior, standard-library native tests, examples, no-default-feature compilation, warning-free
Rust documentation, installation-model tests, and package-layout metadata. Documentation
generation is deterministic and produced 340 pages outside the repository. Release preparation
remains responsible for the versioned archive and installed-archive qualification because those
artifacts must be built only after version authorities change from v0.62.0 to v0.63.0.

## Conclusion

No active implementation recomputes entropy adaptation, integer sampling, or permutation policy.
Consumers depend on explicit contracts rather than inspecting another responsibility's internal
representation. v0.63.0 feature implementation is ready for release preparation.
