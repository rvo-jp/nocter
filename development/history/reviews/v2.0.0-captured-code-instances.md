# v2.0.0 Captured Code Instances and Input Channels

## Scope

The bounded owned-capture producer now closes through the existing private instance graph.
No new source syntax or data domain is introduced. The 283-source corpus retains its existing
147 accepted units, 122 checking rejections, 8 header rejections and 6 syntax rejections.
This checkpoint closes logical code/input/result/adapter obligations; it does not grant ABI,
physical environment layout, executable cleanup, MIR or native output.

## Finding and Authority Changes

The previous target key admitted named declarations only. Replacing that ID with a union was
necessary but insufficient: a closure's named source owner is not its code body, a named function
value has a code token without a body environment, and caller preparation order alone does not
identify the callee's local inputs. A taking adapter also owns environment cleanup when the
original body only reads or updates it.

The model now owns a named/captured code identity independently of invocation view. Typed queries
retain that code identity and derive the named source owner only for their existing byte/locator
reuse guard. The accepted Unit selects the exact body by code kind, without names or a header/body
fallback. Source checking still rejects nested closures and factory-result applications inside
closure bodies; their operation identities have not silently become code-scoped.

Checking publishes one body input layout: an optional environment channel and an ordered explicit
sequence of local slots with their selected operations. Its validator closes exact input coverage,
roles, order, data and operation consistency against the selected contract. Root scope cleanup
consumes that same sequence. Closure demand freezes the environment operation alongside its local
kind before final contract/flow admission. Code identity, source ownership and input-slot role
cannot substitute for one another.

## One Instance Graph

The existing key now pairs selected code with concrete formal witnesses; witnesses retain supplied
views. The code instance is shared across invocation views and runtime environment contents.
Recursive keys are reserved before following their edges. Only reached invocation commits add
instances: formation, uninvoked references/bindings and interrupted argument prefixes do not.

The existing data map substitutes named/captured/formal witnesses and includes captured environment
payload obligations even through formal bindings. Its symbolic source moves and snapshots remain
unchanged. Result witnesses arrive from checking's finite closure; target does not infer them again.
The former UnsupportedCapturedCode boundary and its special projection bypass are removed.

Each reached invocation retains its concrete target, direct/value kind, prepared-bundle to explicit
body-input bindings, exact carrier/environment schemas and concrete input/result obligations. The mappings consume the
checking-owned layout, not local allocation order, source names or an enclosing named header.
Final graph freeze compares each edge's input and answer payloads against its selected concrete
body's projections. This is identity/coverage closure over established facts, not a second signature match.

## Normal Environment Exits

The supplied invocation view and original body input operation remain distinct:

| Supplied instance | Body environment | Normal environment exit |
| --- | --- | --- |
| Read access | Read input | Retain caller responsibility |
| Update access | Read/update input | Retain caller responsibility |
| Received value | Read/update input | Adapter disposes post-call environment before answer delivery |
| Received value | Taking input | Body owns remaining-payload cleanup |

Named function values supply a code token without a body environment. A received token retains its
trivial normal disposal obligation. Direct named calls have no environment channel. A Copy supply
refers to the committed prepared snapshot; it cannot destroy the original source owner. A consuming
body's partial cleanup is not repeated by an adapter. The returned value remains protected through
normal environment cleanup. This bounded result domain cannot expose access into that environment.
No unwind or cancellation guarantee follows from a normal-exit recipe; interrupted prefixes keep
their existing caller-owned resource steps and acquire no invocation edge.

## Verification Scope

Source-backed target tests close all ten accepted owned-capture corpus additions. Additional cases
inspect explicit edit/take inputs independently of the environment, one body shared across
func/mut/once views, owned read/update adapter cleanup, full/partial consuming bodies, runtime
capture values sharing code, distinct lexical producers, returned callbacks, named/captured
recursion, recursive formal forwarding and uninvoked bound captures.

Input-layout mutation tests reject equal-data reordered/duplicate/missing slots, a coherent local
kind/operation change conflicting with a named contract, an explicit slot substituted for the
environment, a source owner substituted for closure code, and an inferred environment contract
changed before flow admission. Existing source and graph tests retain their assertions, with
call edges now exposing the complete invocation product rather than a bare target ID.

The next owner must realize the same graph's pack/unpack, prepared inputs, staged answers,
conditional resource steps and normal adapter exits as executable lifecycle operations before
physical layout/ABI or native admission. Broader captures, dependencies and source grammar still
require their own contracts. No speedup or full-language safety claim follows from this graph.
