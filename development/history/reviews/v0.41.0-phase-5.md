# v0.41.0 Phase 5 Structured Asynchronous I/O Review

**Result: implementation and source-tree qualification complete with no open practical v0.41.0
finding (reviewed again 2026-09-09).** Lazy single-use computations, consuming suspension,
structured two-child joins, cancellation, timers, and nonblocking TCP now cross language checking,
executable lowering, native ARM64 execution, the public standard library, examples, and semantic
editor queries through one set of contracts.

## Practical Boundary

`async T` is a lazy owning computation. Calling a deferred function constructs it, moving it into
`await` consumes it, and destroying an unfinished computation cancels it. No operation starts a
hidden process-global executor. An asynchronous program begins at an explicit asynchronous root,
whose generated process adapter drives the same opaque resume, wait-interest, cancel, and consume
contract used by nested computations.

Public time and TCP operations reuse the existing monotonic, descriptor, resolver, and error
authorities. `task.join` owns exactly two heterogeneous children, starts them in argument order,
allows either wait set to progress, retains completed outputs until both are available, and returns
them in argument order. Cancellation destroys both unfinished children exactly once. Recoverable
failure values remain ordinary child outputs and are not a second scheduler failure channel.

`examples/async-loopback` is the complete integration program. It resolves and connects to a local
listener, concurrently accepts the peer through `task.join`, exchanges bytes with asynchronous
stream operations, and compares exact status, stdout, and stderr through the sole shared public
package-example registry. The same source is also required to remain canonical under the recursive
formatter and visible through generated documentation.

## Semantic Tooling

Focused language-server coverage opens ordinary source using the public asynchronous APIs and
verifies declarations, calls, await expressions, inferred values, definition navigation,
references, rename, completion, signature help, hover, semantic tokens, and inlay hints. These
features consume the checked semantic snapshot and capability-based analysis queries shared with
ordinary source. The editor neither parses a second async language nor inspects MIR states,
Machine frame placement, runtime records, or ARM64 code-generation data.

## Final Authority Audit

The complete asynchronous path has these single authorities:

1. The checked program owns deferred callable classification, `async T`, consuming `await`, loan
   legality across suspension, output provenance, and ordered cancellation obligations. Later
   stages cannot infer these decisions from source spelling.
2. MIR owns the explicit suspension control-flow graph, continuation states, frame liveness,
   initialization facts, and validated cleanup transitions. It publishes a closed executable
   lifecycle instead of checker state.
3. Machine owns dense identities, closed stored layouts, callable ABI transport, destruction
   targets, and structured-join tuple placement. It consumes MIR facts and does not repeat source,
   borrow, or ownership analysis.
4. `nocter-runtime-contract` owns the opaque async handle header, lifecycle entry signatures,
   status and state encodings, wait-interest record, register assignments, and target ABI numeric
   schema. Machine planning and ARM64 lowering select that schema by `RuntimeAbiIdentity`; neither
   redeclares its offsets or tags.
5. ARM64 lowering owns physical heap-frame placement and emitted constructor, resume, cancel,
   consume, executor, and Darwin wait code. It consumes frozen Machine products and the selected
   runtime schema; it cannot inspect source syntax or reconstruct semantic selection. A separate
   backend-local Darwin kernel ABI owner supplies system-call numbers, supervisor-call encoding,
   native `pollfd` layout, errno, and native process constants to all emitters.
6. The target-independent scheduler owns generation-qualified task lifecycle and runnable order.
   Its reactor contract exposes only opaque descriptor and timer interests. The Darwin reactor
   owns native registration and readiness observation, but cannot mutate task lifecycle or inspect
   computation frames.
7. `std/time`, `std/net`, and `std/task` own public policy and compose the lower contracts. They do
   not expose raw monotonic counters, descriptors, readiness records, executor handles, or native
   event representations.

The Rust task runtime and Darwin reactor are a deterministic reference and native conformance
harness. Generated executables use independently qualified ARM64 lifecycle and Darwin wait code
rather than linking those Rust crates. This is deliberate dual implementation of one shared
behavior and numeric runtime contract, not two authorities active in one program.

## Findings Corrected During Qualification

The final review and its follow-ups corrected ten classes of practical defect:

- MIR async validation had grown into large functions that mixed lifecycle, initialization, and
  cancellation checks. Dedicated helpers now expose explicit validation results while keeping
  checker state out of the MIR contract.
- Machine lowering copied the complete runtime ABI schema and returned loosely related function
  data. It now retains the selected ABI identity and consumes one `FunctionSource` contract,
  leaving numeric layout solely in `nocter-runtime-contract`.
- ARM64 resume emission accepted an over-wide raw parameter list and repeated readiness-pointer,
  join-layout, and child-initialization checks. One `Arm64AsyncResumeResources` boundary and shared
  validation and initialization helpers make invalid combinations harder to construct.
- The new public example initially sat outside the shared execution contract, omitted the `net`
  namespace required by its calls, relied on an implicit ownership move, and contained comments
  the source formatter cannot preserve. The sole public-package registry now owns its process
  contract, and the example follows the same namespace, ownership, and formatter-safe rules as the
  existing corpus.
- Three obsolete Cargo dependency edges survived earlier responsibility moves because the compiler
  workspace rejected forbidden directions but did not reject unused edges. Workspace Rust lints
  now deny unused crate dependencies, with narrowly documented binary-target exceptions for
  Cargo's package-wide dependency exposure.
- The top-level semantic query cached its reusable semantic result together with the discovery
  snapshot. An identical-text editor revision could therefore return the previous document
  version. The query now owns only the reusable semantic branch; the compiler-computation entry
  seals that branch with the exact current discovery unit outside the cache.
- Fixed async wait and join computations repeated numeric lifecycle tags inside ARM64 lowering.
  The runtime contract now closes a complete state-tag sequence from the computation's suspension
  count, and generated frames and compiler-owned computations consume the same authority.
- Compiler source revision tokens carried only an owner and semantic revision number, so a public
  caller could pair a token admitted from one overlay with an independently observed overlay whose
  explicit bytes happened to have the same fingerprint. `SourceOverlay` now owns an opaque exact
  generation identity. Compiler tokens, computed syntax, discovery requests, and semantic mutation
  validation all consume that one identity, while content fingerprints remain independently
  responsible only for safe query reuse.
- Darwin syscall emitters independently repeated the supervisor-call immediate and compiler-owned
  syscall numbers, while memory, diagnostic, and wait emitters privately retained related native
  constants. A backend-local Darwin kernel ABI module now owns those values and the syscall-number
  register transition; individual emitters retain only operation-specific code generation.
- The source owner's normalized-input comparison combined source-name identity with byte
  normalization even though the caller must distinguish identity and content failures. The source
  contract now exposes name identity through `name()` and normalized byte comparison through a
  separate `matches_source_bytes()` operation, so neither validation rule is repeated or skipped
  by an unrelated early return.

Searches over production compiler and runtime sources found no hidden executor singleton, second
async ABI schema, second ARM64 Darwin kernel-value table, source-derived backend decision,
async-specific editor parser, or actionable compatibility fallback. Machine `TypeId` values
identify entries in its closed runtime type and layout tables; ARM64 consumes the resulting Machine
representation and does not reinterpret the semantic type system.
