# v0.65.0 Phase 3 HTTP Application-data Review

**Result: complete with no open Phase 3 finding (2026-09-21).** Forms, media types, and request
cookies now cross one checked `std/http` contract, bounded owned representations, native execution,
and current behavior guidance. Phase 4 may consume those values without defining another decoder.

## Reviewed Surface

The review followed public declarations through application limits, form decoding, media-type
canonicalization, request-cookie parsing and rendering, request-target query iteration, URL
normalization, stable errors, module discovery, native test materialization, and generated
documentation. Existing HTTP framing, routing, client, and server code was checked for competing
application-data representations.

## Authority Trace

| Responsibility | Sole authority | Consumers |
| --- | --- | --- |
| hexadecimal digit meaning inside a percent triplet | `std/internal/percent` over `std/internal/ascii` | URL normalization, request targets, forms |
| URI query split and plus preservation | `RequestTarget` and `QueryIter` | routers and applications |
| form split, plus-to-space conversion, UTF-8 validation | `Form` | applications |
| item, component, and aggregate application-data bounds | `ApplicationLimits` and its checked-size helper | forms, media types, cookies |
| media type and parameter canonicalization | `MediaType` | applications |
| request-cookie grammar and pair ordering | `Cookie` and `Cookies` | applications |

The shared percent authority performs only byte-level triplet interpretation. Each consuming
grammar still owns whether plus is data or space, which separators have meaning, which UTF-8 or
token rules apply, and which stable public error is returned. This keeps reuse below the point
where URI queries and form values intentionally differ.

## Corrected Findings

The first implementation duplicated percent bounds and hexadecimal conversion between the
existing query iterator and the new form decoder. Moving that operation into
`std/internal/percent` also let URL normalization consume the same digit interpretation. No HTTP
module reaches into URL representation or treats URL parsing as a form parser.

Initial form storage used the encoded source-component length as its capacity even when the caller
selected a smaller decoded-value bound. Capacity is now capped before allocation. A shared checked
size operation owns overflow and aggregate-limit decisions for all three application parsers, so
callers cannot accidentally perform wrapping addition before the limit check.

Syntax and resource failures were separated. Malformed percent input, invalid UTF-8, invalid media
grammar, and invalid cookie octets keep format-specific codes; item and decoded-byte exhaustion use
limit-specific codes. Duplicate media parameters are rejected after lowercase canonicalization.
Form and cookie duplicates instead remain ordered and are exposed through `first`, `count`, and
indexed access.

## Behavioral Evidence

The HTTP native target now executes 57 cases. Phase 3 cases cover nonzero limit construction, form
plus and percent decoding, UTF-8 rejection, empty items, duplicate ordering, media token and quoted
values, case-insensitive canonical lookup, duplicate rejection, cookie optional whitespace,
quoted wrappers, forbidden octets, rendering, and all three finite limit dimensions. Existing
query tests prove that URI query plus signs remain literal.

The authored standard-library graph test accepts the new package-only percent module and its exact
dependencies. The URL native target still passes its 11 canonicalization and resolution cases,
showing that the shared decoder did not change URL behavior. Documentation generation validates
the checked contract and current behavior guide rather than a copied API table and produced 355
pages outside the repository. The complete fast compiler gate passed from a disposable clean Cargo
target, including warnings-denied compilation, all workspace tests, and native execution.

## Conclusion

No compiler or editor special case was added. Each new application-data value retains one owned
semantic representation, and borrowed projections remain tied to that owner. The pre-existing
lending query iterator deliberately decodes a component while advancing so unescaped text can
remain zero-copy; it consumes the same percent authority and cannot revise construction-time UTF-8
validation. Phase 3 leaves no duplicate percent-triplet authority or unbounded syntax-controlled
allocation in its reviewed scope.
