# v2.0.0 Access Typing and Specification Migration

## Status and Authority

Subsequent [S8](v2.0.0-source-design-decisions.md#s8-place-access-qualifiers-on-types) adopts type-side
qualifiers and reopens the local-inference policy. The recipe and finite check below remain the
explicitly pre-S8 binding baseline. They are not validation of a full qualified type system or the
proposed inference replacement; migrate both with the owning future rules before implementation.

This is a delegated internal typing/validation design, not a second source of language rules.
The explicitly future [Value Access Model](../../../spec/language/value-access.md) now owns the
migrated operation, Copy, binding, call, and return semantics. Related future sections own
[callable modes](../../../spec/language/callables.md#future-direction-v2-0-0-value-access-callables),
[origin bounds](../../../spec/language/memory-and-regions.md#future-direction-v2-0-0-value-access-origins),
[unit](../../../spec/language/values-and-types.md#future-direction-v2-0-0-storable-void), and
[syntax fragments](../../../spec/language/syntactic-grammar.md#future-direction-v2-0-0-access-syntax).
The released contract remains unchanged. This is partial specification migration, not a complete
v2.0.0 grammar, compiler implementation, mechanized proof, or release qualification.
The subsequent S7 source decision fixes local I/U/X with `let`, `let &`, and `let ^` and removes
`var`. It supersedes the earlier initializer/Copy-derived local category; the recipe below follows S7.

## 1. Judgment Inputs and Evidence

The following is specification metalanguage, not source syntax:

```text
Gamma  = declaration identities, types, generic capabilities, expected result contract
Delta  = owned places, initialization states, writability, and cleanup obligations
Lambda = access identities, place paths, permissions, and delegation parents

Gamma; Delta; Lambda |- e => (T, K, R, D, S); Delta'; Lambda'
```

K classifies the checked expression as an existing owned place, fresh owned value, read access,
update access, or independent Copy answer. It is not inferred from an optimizer's chosen storage.
R is the access needed to read/update the particular referent, D contains dependencies carried
inside the payload, and S contains allocator/region validity requirements. R and D remain distinct
even if they ultimately name the same outside owner. A scalar Copy answer has no R; a Copy closure
can still have D. Delta and Lambda describe the continuing path after expression evaluation.

Retain source-selected callable identities and substituted contracts. Later analysis consumes
them; it does not redo lookup, treat display names as identities, or reinterpret a token as a
different operation after type checking.

## 2. Copy Materialization

Let `Copy(Gamma, T)` mean capability evidence available at this source checking boundary. It is
not merely the fact that a particular later specialization happens to have a Copy representation.
One materialization operation produces:

```text
copy_materialize(T, source, R, D, S) -> owned(T, new_place, {}, D, S)
    requires Copy(Gamma, T) and readable initialized source
```

The source ownership/availability is unchanged. A source access can remain live for its own later
uses; copying it does not globally release every lease on its referent. The destination no longer
needs R, but D and S must be preserved. Source types prohibit copying exclusive update captures;
a structural Copy of a value does not duplicate a U access capability.

This accounts for a generic read accessor without changing its body when specialized. With no
Copy requirement, its checked return forwards caller-owned access. A caller whose own source
context knows the result is an integer can materialize an independent answer. The access ends
only if no other source use/cleanup retains it. A caller copying a dependent closure instead
retains its captured-data access through the new closure value.

I result normalization may copy before return cleanup when the declaration proves Copy. Without
that evidence it must supply a valid outside access. The checked result protocol and origin bounds
remain attached to generic forwarding. A receiving Copy operation can discharge its own source
access; neither monomorphization nor function-value erasure can simply delete it.

An I-result callable witness can cross an I-result Copy-answer boundary using the same explicit
checked materialization operation. Keep environment, parameter, and result modes exact; validate
the copied payload's D/S against the receiving contract, and record any adapter operation before
erasure. This permits a generic accessor specialized to an integer to supply an ordinary integer
callback without rewriting its generic body or pretending its original origin bound never existed.
It is not U-to-I or X-to-I callable subtyping. Implementations may inline/eliminate empty transport
only after the copied-value semantics and retained dependencies have been established.

## 3. Context-Specific Obligations

Use the canonical binding rules in the owning future chapter, rather than one universal
"convert to whatever permission is needed" operation:

| Boundary | Evidence to produce |
| --- | --- |
| `let name` from an existing place/access | Read relationship and R/D/S, regardless of Copy |
| `let name` from an independent read answer | Read-only answer, no new X authority or outside referent |
| `let &name` from owned writable storage or U | Update relationship and original R/D/S |
| `let ^name` from fresh/explicit-transfer value | Ownership destination and preserved D/S |
| `let ^name` from existing readable value | Proved structural Copy or missing explicit-transfer diagnostic |
| I/U binding from a fresh X temporary | Reject invisible owner/lifetime extension |
| X call from an existing owner | Invocation-time transfer; source unavailable afterward |
| X call from I/U access | Materialize a separate Copy during preparation when proved; otherwise reject |
| X return from existing Copy place | Structural copy, or explicit transfer if authored |
| I/U return | Copy answer or eligible outside access, protected through normal cleanup |

A freshly computed independent Copy answer can be materialized as an owned temporary; this is
not extracting ownership from an I/U place. The checker must not confuse those categories merely
because both display the same T. Direct X arguments consume existing Copy owners as well as
move-only owners. An I/U actual cannot supply that owner, but declared Copy evidence permits
preparing a new owned snapshot without a user-written intermediate binding. This is a recorded
materialization operation, not transfer or permission strengthening of the original referent.

Take the snapshot during left-to-right preparation, retaining D/S. Later preparation failure cleans
that owned temporary without consuming the referent. Any other live source access remains live.
An existing owned X actual is instead reserved and transferred at invocation even if Copy. The
checker selects these operations from the actual's category and source capability evidence,
not a callee body or optimizer preference.

Requiring a named Copy temporary for every read-to-owned forwarding would add source with no
additional safety fact. Conversely, silently copying an existing owned X actual would violate
uniform source invalidation. The selected category-specific rules avoid both problems.

The binding mode is source input to checking, not inferred from initializer capabilities. Copy
evidence can decide whether an X destination is constructible; it cannot turn I into X or make a
U binding a detached snapshot. `let &editable = accessor()` retains update to the original, while
`let ^snapshot = accessor()` can request a separate permitted Copy. Their meanings differ and do
not become optional assertions. No `with` alternative is adopted.

Assignment target checking follows the binding category: a U name denotes its original writable
place, not a replaceable reference cell. Whole assignment replaces that referent; an I name is
not writable. X owns a writable replaceable/reinitializable slot. No `var` or independent local
immutability bit remains. This prevents the same `editable = value` statement from switching
between updating the original and rebinding an alias after inference.

`let ^next = ^previous` separates destination ownership from source transfer. Without `^previous`,
an existing source can supply only a permitted Copy to that owning initializer. Keep the deferred
implicit-return/storage transfer proposal deferred; S7 did not adopt it. Call-directed X transfer
remains invocation-time transfer of an existing owner, a different boundary with an already
selected parameter mode.

## 4. Transfer and Escape

An explicit transfer requires a definitely initialized owned place and no incompatible live access.
It consumes that place in Delta and creates exactly one destination obligation, preserving D/S.
The rule is identical with and without Copy evidence. A fresh result does not need another `^`.

For return, first stage the result, then check every normal cleanup edge with its dependencies
protected. The escape check is against the state after that cleanup, not the state at the written
`return` expression. Removing R with Copy does not repair a D dependency on a destroyed local or
an S dependency on an ending region. Return staging must not delay their cleanup to pass the check.

An owned output must account for exactly one owner after handoff. An I/U output must account for
live initialized roots and an appropriate delegated permission. A consumed invocation parent is
retired/reparented atomically; it cannot be restored alongside a conflicting escaping child.
Suspension points additionally preserve child-before-owner cancellation obligations.

## 5. Control-Flow Joins and Delegation

Keep separate initialization facts and alternative access worlds at a join:

- Definite initialization is the intersection of initialized incoming places; disagreement yields
  maybe initialized state and conditional cleanup, not permission to read the place.
- Possible D/S requirements are unioned for an unrefined result. Tag/path proofs may narrow the
  alternatives before a use. Do not treat the most convenient predecessor as authoritative.
- Mutually exclusive U accesses are alternatives. They do not conflict merely because the union
  mentions both, but an operation after the join must be safe in every possible world.
- Result/binding modes must already agree after contextual checking. An owning path and an access
  path cannot be merged into a newly strengthened mode by downstream demand.
- A delegation edge records its parent access identity and restricted subplace. The dependency
  graph must be acyclic, roots live, and child permission no stronger than the parent. Ending a
  child restores only the surviving parent's rights, and only if its other children permit that.

Compute loop facts to a conservative fixed point over canonical place/access identities. A
transfer on a continuing backedge needs valid reinitialization before the next iteration's use.
Do not infer reinitialization from a branch that exits the loop. Preserve correlations where
needed to accept a disjoint or tag-refined case; an unproved relationship remains conservative.

The finite checks do not yet implement general joins or reborrowing. A full declarative/algorithmic
correspondence, termination account for the chosen abstraction, and preservation/progress argument
remain required. Stating a judgment is not a proof of that judgment's safety.

## 6. Distinguishing Cases and Check Scope

| Case | Required evidence or rejection |
| --- | --- |
| `let ^snapshot` copies an integer reached through I | New owner, no source-place R, source still available |
| `let read` refers to Copy or move-only storage | I in both; retain referent R rather than auto-owning |
| Copy an I closure result into an X local | Remove header R; preserve captured-data D and S |
| Copy then destroy a source still used through another access | Reject conflicting destruction |
| Copy closure captures a local, then return it | Reject D escape even though header R was removed |
| Copy region-backed payload into an escaping result | Reject S escape |
| `let &edit` binds a Copy integer | Retain U relationship; do not snapshot |
| Assign to I, or retarget U | Reject; permissions do not change with initializer type |
| Reinitialize moved `let ^owner` after RHS success | Initialized X slot; no old-value destruction |
| Reinitialization RHS fails | Preserve prior initialized/uninitialized state |
| Forward Copy I/U access to X | Prepare an independent snapshot; preserve source and payload D/S |
| Forward move-only I/U access to X | Reject; no callee-directed owning clone |
| Transfer existing Copy owner into X | Source becomes unavailable |
| Specialize unbounded T to Copy | Retain previously checked operation category |
| Copy proof at caller but not generic callee | Caller materialization permitted, callee body unchanged |
| I-access callback supplies an I Copy-answer boundary | Checked Copy adapter; preserve modes and payload D/S |
| One branch initializes a place, the other transfers it | Maybe initialized; reject unguarded use |
| Branches return different U places under one declared origin bound | Check alternative worlds; do not invent simultaneous U |
| Return reference-free header carrying dependent data | Validate D/S, not merely absence of a pointer in transport |

The [typing boundary check](v2.0.0-access-typing-check.py) enumerates a finite set of operand
categories, source Copy proofs versus concrete substitutions, origin/dependency combinations,
and explicit binding/call/return operations. Its invariant checker inspects source availability,
written permission, Copy evidence, separate R/D/S handling, and escape. A separate initialized-slot
check covers assignment, X transfer/reinitialization, and failure before replacement is ready,
assuming place/conflict validation already succeeded. Intentional invalid-result/assignment mutants
check dependency loss, wrong modes, implicit ownership extraction, and invalid old-value cleanup.

It does not parse or compile Nocter, verify arbitrary type constructors, run destructors, check
general CFGs, or prove the full language sound. It supplements the existing reservation and result
handoff explorations rather than replacing implementation conformance.

Recorded run:

```sh
python3 development/history/reviews/v2.0.0-access-typing-check.py
```

The S7 run enumerated 4,864 boundary attempts, checked 860 accepted results, 3,072
specialization-stability comparisons, and 1,152 comparisons showing Copy cannot change I/U binding
permission. It rejected 11 invalid-result mutants. Six accepted assignment cases and one initialized
X-slot transfer were checked, rejecting four invalid-assignment mutants. These counts describe
the finite abstraction, not supported Nocter programs or compiler tests.

## 7. Migration Boundary

The migrated future rules are linked above. Current grammar and standard-library declarations
remain the released authority. Outcome/async composition, captures, full type/precedence grammar,
modules and construction, effects/CTFE, platform layout, and tooling still need their coherent
owning future/current migration before v2.0.0 can be implemented as a complete replacement.
Do not create a compiler accepting a mixture of old borrow types and selected new access forms.

New source choices are required only if that work exposes materially different human-facing
forms. All currently recorded S1–S7, R1–R3, and structural callable result-marker choices are
already selected; algorithm/proof obligations are not reasons to ask for their approval again.
