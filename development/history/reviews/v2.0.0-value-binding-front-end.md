## Scope and Authority

The production `V2CoreUnit` parser and its declaration, typing, initialization, access and resource
consumers now implement the adopted S12–S16 four-type private-unit fragment. They replace the
incompatible type-qualified/result-access checkpoint, rather than adding a second source mode.
The owning [grammar](../../spec/language/syntactic-grammar.md#bounded-value-binding-fragment)
and [value semantics](../../spec/language/value-access.md) remain normative. The broader
[implementation design](v2.0.0-value-binding-implementation.md) retains full-language obligations;
this record owns bounded implementation and verification evidence.

The supplied unit contains private functions over `bool`, `i32`, `void` and opaque `error`.
There is no CLI language switch, package discovery, public module join, native/code-generation
consumer or conversion to the released checked-program product. Released language behavior and
qualified release artifacts remain unchanged. This is neither full v2.0.0 qualification nor a
soundness proof or performance result.

## Implemented Behavior

Input operations are independent of data type: unmarked read, explicit `edit` and `take`. Calls
omit operation markers. `let` and `var` construct values under the same Copy-or-move rule; only
`var` allows ordinary replacement/update. Both owning bindings may transfer or drop their values.
`read` and `edit` construct scoped aliases to existing storage, with no invisible temporary owner.
A take input is locally writable. Type annotations constrain data without changing these rules.

```text
func restore(take value: error): error {
    var slot = value
    let temporary = slot
    slot = temporary
    slot
}

func touch(edit value: i32): void { value += 1 }
func inspect(value: i32): i32 { value }
```

Every ordinary result delivers a value. An eligible Copy source supplies a copy; an eligible
non-Copy owner supplies a move. A read/edit alias to move-only data cannot manufacture an owner.
Fixed `let` storage cannot be reinitialized after transfer/drop. Mutable storage can be restored
by complete RHS-first replacement. Explicit drop invalidates a Copy local too; copying elsewhere
does not restore that named slot. Branches, early exits, short-circuiting and loop backedges share
one initialization/control graph. Literal Boolean branches do not invent loop exits: a dead
`break`, or a break after an always-selected `continue`, cannot require a fictitious result.
Reachable exits still require results and unreachable declarations retain their type checks.

Copy taking arguments snapshot before later operand evaluation; they do not reserve or consume
the original scalar. Read arguments reserve the original place. Non-Copy taking arguments reserve
an owner until all operands finish and the complete call bundle validates atomically. Conflicting
bundles and modifications during preparation are rejected. Interrupted preparation cancels
reservations and cleans only resources already created. Fresh values supplied to read inputs
retain one temporary owner until the enclosing evaluation ends or unwinds, after staging its result.

The exact data contracts admit Copy/trivial `bool`, `i32` and `void`; opaque move-only `error` owns
an immutable snapshot graph. All four have empty external dependency/state sets by these exact
contracts. This is not generic D/S inference, a runtime error-storage implementation, or evidence
that any owning/Copy value necessarily has empty dependencies.

## Authority Audit and Retired Paths

- Semantic data remains `TypeId`. Independent input operations and binding kinds select transient
  operation access; access is not a source type constructor.
- Declaration results store data only. The old result mode/referent set and read-result
  normalization algorithm are removed. Typing never reconstructs an input operation from body
  text, a type annotation or later use.
- Syntax retains one future private-unit goal. Old access-type, update/transfer-prefix nodes and
  direct-call marker assertions are removed. Contextual input/binding words are recognized from
  grammar position. Future lexical names are separate from the released keyword inventory.
- Canonical declarations are selected once. Reusable typed/flow products share that exact authority;
  source recipes project current diagnostics and cannot participate in semantic selection.
- Flow, permission demands, referent alternatives, resource survival and cleanup share one graph
  and one set of worlds. No independent owner-survival index was added.
- Ordinary return proof requires all evaluation frames closed and exactly one staged value with
  the declared result data type. Return survival uses that resource ledger alone; the old staged
  referent state, update demand and diagnostic witness branch are removed. No borrowed-result
  fallback remains.
- The old [fixture directory](../../compiler/tests/fixtures/v2-access/README.md) is a retirement
  notice. Its incompatible sources, shape expectations, manifest and registration-only checker
  are removed. Historical [contract evidence](v2.0.0-access-checkpoint-contracts.md) remains clearly
  distinct from current conformance.

## Production Evidence

The [source corpus](../../compiler/tests/fixtures/value-bindings/README.md) contains thirty cases,
all consumed by production tests. Fourteen accepted cases construct a sealed whole-unit result;
twelve fail checking (seven typing, three initialization and two access conflicts); four fail
syntax. The twenty-six syntax-valid sources also freeze declarations and have parser shape
snapshots. The parser checks lossless source projection as well as shapes.

Focused tests cover Copy versus move/drop, fixed versus mutable storage, writable take inputs,
scoped alias weakening/reparenting, last-use conflicts, Copy take snapshots versus read reservations,
duplicate non-Copy arguments, pending-call modification, interrupted preparation, fresh temporary
cleanup, edited error replacement, branch joins, loop restoration, whole-unit membership and exact
source/authority rebinding. Resource mutants reject duplicate ownership, double destruction,
missing results and wrong result data. Every definition is validated, including unused functions;
intermediate reports cannot publish a partial accepted unit.

The focused five-crate library run passed 1,019 tests, including all 27 value-access checking
tests and per-case diagnostic assertions. Another 52 diagnostic/source-tooling tests passed.
A grouped eight-scenario sealed-unit regression first reproduced the dead-break missing-result
error, then passed after the literal-control correction. It also retains reachable-exit result
requirements and dead-branch type errors. Final checking/all-target Clippy passed with warnings
denied.

On 2026-11-09, `development/verification/verify-compiler.sh` passed on the final source in its
explicit disposable target. This includes repository metadata, benchmark and Unicode checks,
formatting, workspace/all-target Clippy with warnings denied, all workspace test groups, the
38 CLI tests, 62 command tests, 132 native-session tests, 118 language-server tests, the
no-default-features workspace check and warning-free Rust API documentation. The initial sandbox
run could not create a local TCP listener; the complete qualification ran with local socket
permission. Native and public editor coverage here exercises the existing released-language
pipeline. It does not create a native or editor consumer for this private future goal.

Documentation generator tests passed. The explicit external build produced 377 HTML pages at
`/tmp/nocter-binding-site`; generated website output is not committed. A corpus inventory check
confirmed thirty unique registered sources, twenty-six exact shape registrations, UTF-8/LF input
and explicit checking-rejection codes. These inventory/document checks do not replace production
compiler tests.

## Remaining Boundaries

Extend place projections and nominal payload schemas next. Their closure must establish partial
move/replacement behavior, disjoint versus overlapping places, cleanup ordering and dependency
survival, rather than extrapolating the four built-in contracts. Capability/callable/generic/
interface evidence, outcomes, async, public contracts and module joining remain separate tasks.
Target layout, ABI, physical storage, executable error graphs and native cleanup require a closed
executable consumer before native qualification. Full-language editor/formatter migration is also
outside this internal checker. No measured speedup follows from front-end acceptance.
