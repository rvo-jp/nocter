# v2.0.0 Callable Input Witnesses

Date: 2026-11-09. Scope: flat structural callable parameters, symbolic invocation targets and
formal-to-actual bindings in the private front end. This extends the
[named-function checkpoint](v2.0.0-function-witnesses.md). The owning
[callable input semantics](../../../spec/language/callables.md#statically-witnessed-callable-inputs)
and [bounded grammar](../../../spec/language/syntactic-grammar.md#bounded-value-binding-fragment)
remain normative.

## Source and Implementation Boundary

```text
func increment(value: i32): i32 { value + 1 }

func apply(action: func(i32): i32, value: i32): i32 {
    action(value)
}

func forward(action: func(i32): i32, value: i32): i32 {
    apply(action, value)
}

func run(): i32 { forward(increment, 1) }
```

The call in `run` binds a formal witness to `increment`. Forwarding records the original formal
as the actual witness of `apply`'s input. Invocation inside `apply` targets that formal identity;
it does not search the program for a function matching the signature. Recursive forwarding retains
finite identity edges, without expanding a recursive string/type term or recursively rechecking
bodies. Different inputs and different named functions keep distinct identities even when their
contracts match. Calls through a named higher-order local value freeze the same binding facts.

A structural callback parameter has no Copy evidence. Receiving the named Copy function above
does not make `let copy = action` valid in a read formal's body. An owning formal can move its
value or supply an invocation adapter; a read alias can invoke without constructing a value.
`edit` and `take` on the parameter remain independent of `func`, `mut` and `once` invocation.
A consuming invocation transfers its environment once. Early return or explicit drop retains the
formal environment's symbolic cleanup obligation instead of classifying it as trivial.

This is a typed template and argument-binding product. It is not executable witness specialization.
The admitted concrete producer domain is named code; formal forwarding preserves that domain.
Anonymous/captured producers, callable results, nested callback contracts, erased storage, hidden
capture overlaps, general D/S and write-footprint solving, ABI/layout and native invocation remain
outside this boundary. Symbolic cleanup is an obligation for later specialization, not evidence
that an arbitrary environment is independent or destruction-free.

## Authority Review

- The model owns one witness origin: named declaration or formal input, paired with invocation
  view. Named keys remain concrete and storage-independent. Formal keys remain symbolic and may
  carry storage, including after type projection. Neither origin contains source coordinates.
- Declaration publication freezes canonical parameter identities, normalized structural contracts
  and permitted views in the same TypeAuthority. Contracts and witness identity are different
  facts. Definition order and body annotations cannot create another type domain or change input
  modes. The existing signature matcher and invocation-adapter policy apply to both origins.
- One lowering-owned type-syntax projection serves parameter headers and local annotations. It
  uses the same input-operation decoder and data namespace. Header reuse rejects changed callback
  operations and preserves the exact program authority through body/trivia edits.
- Checking separates callee selection from input preparation. The preparation plan alone stores
  the receiving formal and selected actual witness. It keeps the actual value's identity rather
  than relabeling it as the callee formal. No parallel binding registry is maintained.
- Environment and explicit inputs use ordinary reservations, atomic commit, cancellation and
  resource cleanup. Access commit no longer reopens the declaration target merely to validate a
  call already selected by typing. Initialization, ownership and liveness consume the same plans.
- Formal environment destruction is explicit in the existing resource ledger. Adapting its view
  transfers that obligation atomically and preserves origin. Source-level Copy is not inferred
  from a currently named caller. Released admission still rejects private witness keys; shared
  property visitors treat symbolic storage/destruction conservatively.

Review caught an interruption boundary: a callback input that always returns before producing a
value has no witness to bind. The ordinary interrupted input plan now represents that path;
no environment, invocation or result is invented. A known scalar result on an interrupted path
still fails a callable contract, so termination cannot hide structural type errors.

## Verification

The production corpus has 189 sources: 96 accepted whole private units, 81 checking rejections,
6 header rejections and 6 syntax rejections. All 183 syntax-valid sources have lossless structural
snapshots; declaration tests independently freeze 177 header-valid units. The 40 added sources
exercise callback binding, read/edit/take forwarding, view adapters, recursive edges, equal-signature
identity separation, records/errors, interruption, cleanup, missing Copy, live aliases, unavailable
owners, incompatible contracts and complete-bundle conflicts. The former callback-header syntax
rejection now rejects a nested callback contract; existing valid parser snapshots remain unchanged.

Seven additional source-to-unit tests inspect binding edges and positions, recursive identity,
consuming-environment transfer, adapter origin/cleanup, early-return destruction and absence of
unreachable bindings/invocation. A declaration-lowering test checks header identity/reuse and
lack of Copy; a model test checks symbolic storage and projection. Invalid unused bodies are
checked even with a known Copy caller. This evidence does not rely on fabricated semantic inputs
or a second parser.

Affected library suites pass: model 42, declarations 48, declaration lowering 144, syntax 144 and
checking 703 tests. Warnings-denied workspace Clippy checks shared consumers. Formatting,
documentation generation tests and an external site build pass. LSP/native runtime suites do not
consume this private path and were not run as feature evidence. No runtime or speed claim follows.

## Next Boundary

Callable results need checked witness relations over named/formal producers and coherent
return/control joins, together with executable substitution of already selected targets. Recursive
result dependencies must terminate or reject without order-dependent guesses. That work cannot
reuse a callable signature as if it were an erased runtime datatype. Captured environments then
need carried R/D/S, retained-state/write footprints, alias conflict and destruction proofs before
source admission. The [handoff](../../TODO.md) owns current work order; crate READMEs and the
[cross-stage contract](../../architecture/pipeline/value-access-declarations.md) own current
implementation responsibilities.
