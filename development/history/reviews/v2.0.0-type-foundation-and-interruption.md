# v2.0.0 Type Foundation and Interrupted Callable Results

## Scope and Finding

The adopted [type foundation](../../spec/language/values-and-types.md#type-system-foundation)
separates data identity, boundary compatibility, operation authority and value-production evidence.
This review records the implementation audit and the bounded interruption fix; it does not own
language rules or establish a complete v2.0.0 type system.

The audit found that locals and inputs already keep their operations separate from data TypeId.
Annotations constrain data; they do not choose FixedValue/MutableValue/ReadAlias/EditAlias or
Read/Edit/Take. Callable contracts additionally retain input operations and invocation views.
Concrete named/formal witnesses remain distinct from equal structural signatures. Copy evidence
comes from the source checking context, independently of local mutability and later specialization.

One boundary was incomplete: result closure demanded an actual witness for every typed callable
application, even when argument evaluation returned before any invocation could commit. The
control graph correctly represented interruption, but application closure still rejected E0370.
This was a compiler limitation, not a reason to change source syntax or weaken access safety.

## Implementation

The existing application identity now closes to either a selected witness or explicit Unproduced
evidence. Missing producers qualify only when the application's invocation commit is unreachable
in the already selected graph. A reachable application still needs its witness; heterogeneous or
unanchored returned relations still reject. Result closure uses the same finite equations and
canonical type authority without retyping, alternate lookup or a second graph.

Unproduced applications retain their structural contract and selected invocation view. Dead local
bindings, aliases, adaptations and taking supplies can therefore be checked without inventing
Copy, transfer, environment ownership or cleanup. Pending supplies become explicitly unproduced,
rather than remaining pending or acquiring a provisional move. Initialization and access analysis
reject such actions if reached.

The additional admission proof traverses the same graph before initialization. It rejects a
reached evaluation, prepared input, binding, forwarding, value consumption or call commit carrying
unproduced data. Starting an evaluation that subsequently exits is permitted. Scope exit still
cleans only initialized holders. No return anchor is inferred from absent data.

An adversarial recursive-return test also exposed a conditional typing issue: when the first
branch retained an interrupted application shape and the other produced a named function, the
conditional retained the first branch's provisional identity. Conditional typing now checks both
known shapes, then takes the continuing value identity from a normally producing branch when the
other cannot produce a value. Existing compatibility constraints remain checked.

The accepted Unit's DataEvidence is the single payload-versus-unproduced projection boundary.
Raw cleanup projection now rejects result/application identities instead of assigning a symbolic
environment destructor. Private instance projection consumes DataEvidence and preserves absent
contracts in its existing data map, without payloads, witness specialization or executable edges.
Named/formal payloads keep their existing specialization and source-selected operations.

## Evidence and Limits

The source and parser snapshot previously named `r110-dependent-result-unknown-input` are unchanged
and renamed `a137-dependent-result-unknown-input`. The manifest now expects acceptance. Its 263
cases comprise 137 accepted units, 112 checking rejections, 8 header rejections and 6 syntax
rejections. The syntax-valid/header-valid totals remain 257/249.

Additional source-backed tests cover absent chained applications; dead locals, read aliases,
invocation adapters, replacements and pending supplies; anchored recursion; structural arity,
data and annotation rejection with source locations; and absence of runtime environment steps.
A typed-product mutation attempts to use absent data as a reached scalar result and must fail
admission. Target tests verify that absent contracts and adapted dead locals close into a single
root instance with no calls and no callable payload.

Verification passed:

- Checking library: 722 tests, including 89 private value-access tests.
- Target library: 62 tests, including 20 private instance tests.
- Declaration, declaration-lowering, model and syntax library suites passed; parser snapshots and
  the complete 263-source acceptance catalog passed through their production consumers.
- Warnings-denied workspace all-target Clippy and workspace formatting passed.
- Documentation generator tests and an external build at `/tmp/nocter-v2-type-foundation-site`
  passed with 376 published pages; unreleased contracts remain outside site navigation/search.

LSP and native runtime suites do not consume this private product and were not used as feature
evidence. Workspace Clippy checks the changed API against their compilation boundaries.

The foundational specification also identifies the open boundaries: full generic/interface
requirement solving, associated types, erased joins/representations, general capability schemas,
effects, outcomes and recursive data representation need their own closed contracts. Existing
limited acceptance is not a complete implementation of those subjects. Captured environments,
general R/D/S and retained-state proofs, physical realization, ABI, MIR and native execution
remain outside this checkpoint. No performance claim follows.
