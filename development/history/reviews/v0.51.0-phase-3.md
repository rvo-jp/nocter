# v0.51.0 Phase 3 Semantic Consumer Review

Date: 2026-09-14

## Result

Phase 3 is complete. Compiler consumers use authored contracts, checked execution plans, inferred
execution facts, and target primitive facts only for their respective responsibilities. No target,
MIR, machine, native, or editor path rewalks a checked body to classify allocation or synchronous
waiting.

## Findings and Corrections

### Result mapping repeated deferred-execution interpretation

Provenance and loan analysis each matched `CheckedCallExecution` to recover the result produced by
the actually executed target. Both also reopened `CallableExecution` to recover a declaration body
result even though `CallableDeclaration::body_result` already owned that mapping.

`CheckedCallExecution::executed_result` now owns the call-level temporal mapping, and
`CallableDeclaration::body_result` remains the declaration-level authority. The relation passes no
longer duplicate those decisions. `is_deferred` similarly centralizes the temporal branch used for
future captures and invocation allocation.

### Structural-dispatch execution was hidden behind a wildcard

Execution relation collection treated every non-callable `StructuralRequirement` predicate as an
unrestricted allocation, nonblocking contract through one wildcard branch. Structural dispatch
legitimately also carries equality, ordering, indexing, coercion, and expansion predicates, so
rejecting every non-callable predicate would be incorrect. The classifier now enumerates those
executable predicates explicitly. Interface, copy, and binder-refinement evidence cannot denote an
operation and produces a semantic integrity failure if it reaches this edge. Adding a new predicate
therefore requires an explicit execution decision.

### Current documentation retained stale vocabulary

The checking module, error variant, test module, and current design text still used the old effect
table name after the authority replacement. They now use execution terminology. Historical records
retain their original release vocabulary.

## Consumer Review

- Declaration presentation reads only authored `CallableGuarantees` and `CallableExecution`.
  A source-backed body proven allocation-free does not gain a displayed `noalloc` modifier.
- Completion reads incomplete syntax only to propose legal authored modifiers; it does not publish
  semantic execution facts.
- Target specialization maps the declaration's already resolved immediate/deferred identity into
  an executable representation. It performs no body analysis.
- MIR checks future representation coherence around already selected async operations. These are
  structural validation checks, not callable-effect inference.
- Machine and ARM64 consume executable/MIR execution variants and cannot access declaration or
  checking bodies.
- Primitive target validation compares two supplied authorities: the resolved source declaration
  and closed runtime role. It does not infer behavior from source spelling or emitted code.

## Evidence

- workspace all-target checking;
- checking, runtime-contract, target-program, and analysis tests;
- an editor test proving that only an authored `noalloc` guarantee appears in presentation;
- repository searches for superseded effect products and modifier inference outside their owners.

No public language behavior changed in this phase.
