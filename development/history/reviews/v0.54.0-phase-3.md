# v0.54.0 Phase 3 Sequential Persistent-connection Review

## Scope

This review covers request connection-token interpretation, retained transport input, response
policy generation, fixed and chunked completion, explicit server closure, operation deadlines,
public examples, native execution, and editor projection. It searches for reparsed connection
headers, loose retained-input fields, reusable authority published before both framing directions
complete, and hidden pooling or pipelined execution.

## Findings and Resolution

### Retained input must transfer as one owner

Passing a pending vector, offset, and scratch vector independently would permit a later adapter to
mix state from different exchanges. Private `ConnectionInput` owns all three. It moves intact from
a completed body cursor to `ServerConnection`, then initializes the next request-head decoder and
body cursor. When unread bytes remain, they are compacted once into the other reusable buffer; when
none remain, the consumed buffer is cleared directly. The prior request is never rescanned, both
allocations stay under one owner, and partial pipelining cannot retain an ever-growing consumed
prefix.

### Persistence is a parsing result, not a response-driver inference

The request-head decoder validates all comma-separated values of every `Connection` field and
records one private `ConnectionDisposition`. It does not stop after finding `close`, so malformed
later tokens still fail the request. The response planner consumes that decision and conditionally
generates `Connection: close`; neither the writer nor the server loop inspects raw header text.

### Server policy needs an explicit terminal transition

Request policy alone could not express a graceful service choosing to finish one response and then
retire its connection. `Responder.close_after_response` monotonically changes reuse to closure
before the response plan is frozen. Applications still cannot provide reserved framing or
connection headers directly, and no operation can reverse a request-selected close decision.

### Reuse must be represented by ownership, not a Boolean

`ResponseWriter.finish` and the complete response convenience return `ServerConnection?` only
after request-body completion and complete fixed or chunked response framing. A close plan returns
`none` after closing the stream. Failure and timeout return no continuation and destruction owns
the remaining close path. The next request therefore requires possession of the exact capability
returned by the prior response.

### Connection ownership changes the close effect contract

`ServerConnection` now owns retained vectors. Its consuming `close` can run generic destruction,
so retaining the previous `noalloc` declaration would make a false public guarantee. The contract
and implementation now omit `noalloc`; transport closure itself remains exact-once.

### Large frame addressing must not borrow an undeclared scratch register

The larger fallible async result exposed an ARM64 defect below HTTP: large stack-address formation
silently borrowed `x16` after its caller had selected `x17` specifically to preserve an `x16`
store source. The emitted store consequently wrote the numeric offset in place of an error-node
function pointer. Address formation now materializes a non-encodable offset in its destination
register and therefore has no hidden scratch effect. A direct instruction test fixes that register
contract, and a native test exercises a fallible async result large enough to cross the affected
offset boundary. The temporary request-state wrapper used while isolating this fault was removed;
the server retains only the decoder state that actually changes across reads.

## Result

No open Phase 3 finding remains. Persistence is selected once from validated semantics, retained
input has one owner, response completion is the sole publisher of reusable authority, and later
requests remain sequential even when their bytes arrive early. Phase 4 may compose graceful
application-owned draining without reopening HTTP framing or connection ownership.
