# v2.0.0 Outcome Construction and Payload Access

## Scope and Status

The owning contracts are [outcomes](../../spec/language/outcomes.md),
[the ordinary prelude constructor](../../spec/library/prelude.md) and
[outcome syntax](../../spec/language/syntactic-grammar.md#outcome-elimination-and-recovery).
This review records design rationale and future source obligations, not another specification or
compiler qualification. No bounded frontend, library source, runtime or released contract changes.

## Closure Findings

**Success must not depend on payload type.** The adopted throw decision now has one current
owner alongside exact whole-outcome forwarding and ordinary injection. `return reason` succeeds
for an error payload, including through a generic result; `throw reason` selects failure. The
error-type special case from the published contract is deliberately not inherited.

**Repeated optional layers require stable constructor identity.** Exact forwarding precedes new
injection. An existing inner optional can be made present without lifting its own absence to the
outer layer. The ordinary prelude some function adds exactly one layer under the same checked
generic operation before substitution. The one-fallible-layer boundary remains explicit rather
than assuming arbitrary fallible nesting from the optional extension.

**Value elimination alone cannot support read access to non-Copy payloads.** A read parameter
containing an optional resource cannot surrender it merely to inspect it. The selected extension
reuses scoped read/edit projection, analogous to indexing, instead of requiring ordinary borrow
types, a second pattern language or a mandatory wrapper conversion at every inspection:

```text
struct Item {
    code: i32
}

func inspect(candidate: Item?): i32 {
    read item = candidate otherwise { return 0 }
    item.code
}

func increment(edit candidate: Item?): void {
    edit item = candidate otherwise { return }
    item.code += 1
}

func inspect_result(candidate: Item!): i32 {
    read item = candidate catch _ { return 0 }
    item.code
}
```

These are complete design functions over a move-only record, not runnable private-fragment
fixtures. Inspect preserves the caller's optional; increment keeps its payload/tag initialized;
inspect_result intentionally handles failure without copying or taking the caller's error.
The existing binding operation says whether a payload is extracted or accessed. A call's already
selected input operation supplies that distinction for a direct projected argument as well.

**Projection does not supply an owned failure for propagation.** `read item = candidate?` may
propagate absence, but propagation of failure still needs ownership of its error. An owned local
carrier can transfer on that exiting path; a read input cannot, and an edit input cannot leave
its caller's carrier uninitialized. Explicit catch recovery is available without pretending that
error is Copy. A projected catch aliases its error, while an ordinary value catch owns it. This
context comes from the same enclosing operation that governs tuple leaves and index projections;
it is not another optional catch-binding spelling.

**Read input injection must not hide a move.** Wrapping a direct non-Copy File into File? to
satisfy a read parameter would consume the source despite the selected input operation. Require
intentional value construction there. Exact existing outcomes, Copy injection and fresh values
remain usable. Edit inputs never manufacture wrapper places from values.

**Failure loss needs a diagnostic without becoming a new safety type system.** Select a
default-enabled warning rather than a language error. Scope cleanup is memory-safe even when an
application forgot to handle an operation's failure. Warn on actual loss, including named locals,
replacement/drop and aggregates; do not treat `let _` as failure acceptance or warn merely because
an outcome is retained for later use. Catch suppression and forwarding remain meaningful distinct
operations. No warning-only analysis may change runtime cleanup or require handling flags in data.
Complete conditional handling analysis, opaque payload schemas and async cancellation still need
source-backed qualification; an unstarted future is not a produced source outcome.

## Future Source Obligations

| Case | Required outcome |
| --- | --- |
| error returned as error! success data | Success, without payload-type failure selection |
| Same error supplied to throw | Failure, with eligible transfer and normal exit cleanup |
| Complete failed outcome returned at its exact type | Preserve failure tag rather than inject success |
| Generic succeed<T> checked before T = error | Preserve its selected success construction |
| none at i32?? versus some<i32?>(none) | Outer absence versus present inner absence |
| Existing i32? injected at i32?? | Present complete inner optional, without lifting/flattening |
| Bare unit completion at void? | Present unit, not absence |
| Repeated fallible layer after alias/substitution | Reject unsupported chain |
| Failure propagation into (T!)? | Presence containing failure; preserve constructor order |
| Absence propagation into T??! | Success with the outermost declared optional absent |
| Ordinary elimination of stored move-only carrier | Move before tag selection; source unavailable on every continuation |
| Read projection of stored optional/fallible success | Preserve owner and access active payload |
| Edit projection followed by parent tag replacement while access is live | Reject invalidation |
| Read/edit alias initialized from a fresh temporary | Reject hidden owner retention |
| Ordinary read argument over an evaluation-owned temporary | Keep that owner through the bounded call, then clean it |
| Projected catch name | Alias error under the selected read/edit operation; do not invent a second owner |
| Projected catch underscore | Accept encountered failure without destroying its retained source |
| Value catch underscore | Destroy the received error before fallback |
| Projected fallback returns a handler-local place | Reject escape through cleanup |
| Projected fallible question mark from a read input | Reject unavailable error transfer |
| Projected fallible question mark from an owned local | Transfer failure on exit; preserve payload owner on success |
| Ordinary catch result has the wrong payload type | Reject without recursive recovery/flattening |
| Forced extraction of failure/absence | Safety trap, without synthesized unwinding/output/status |
| let underscore, unused name, drop or replacement loses unhandled failure | Default-enabled warning; preserve actual cleanup |
| Outcome still retained or transferred to a handler/recipient | No premature loss warning |
| Producer proven to yield only success or ordinary error data | No failure-loss warning merely because error is a payload type |
| Zero-byte unit output or error snapshot optimized away | Preserve effects, tags and logical cleanup obligations |

## Verification and Remaining Work

Documentation-generator tests, an explicit external site build, local-link and whitespace checks
qualify this documentation boundary. The grammar-name inventory finds 151 V2 productions with
no duplicate definitions or unresolved V2 references across the owning syntax and remaining
assembly. That is not parser ambiguity or type/resource soundness evidence. No planned source
case in this review counts toward the production corpus or proves native execution.

The same audit makes private automatic conformance selection respect direct source visibility;
an explicit mapping resolves a helper in its own fragment, without leaking its private dependencies
into the root. Inventory and source-level lookup remain separate authorities.

Complete async/cancellation and conditional effect/handling schemas before admitting their
cross-boundary cases. Full control/enum patterns, literal/pack/coercion contracts, lexical and
package/platform source remain separate migration work. Actual source integration must preserve
the same value/projection, ownership and cleanup decisions through checking and native execution.
