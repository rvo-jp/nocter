# v2.0.0 Value Binding: Grammar and Implementation Design

## Status and Authority

On 2026-11-08 the user adopted the value-binding foundation after the
[44-case audit](v2.0.0-value-binding-candidate.md), then selected name-only value captures,
post-state origins after an edit parameter's type, environment origins immediately after `mut`,
the index projection declaration form, and mandatory keyed-pack names in callable types. [S12](v2.0.0-source-design-decisions.md#s12-separate-values-binding-operations-and-capabilities)
records the foundation; subsequent S13–S15 entries record its source extensions. This document
owns replacement design, reasoning, adversarial requirements
and entry gates, not normative language semantics or current crate-internal structure.

Owning future chapters now specify values/aliases, input operations, Copy-or-move supply,
capability preservation, result/edited-state origins, callable contracts, access-syntax productions,
assignment/flow, complete headers and tooling requirements. Current released behavior is unchanged.
The subsequent [bounded front-end implementation](v2.0.0-value-binding-front-end.md) replaces the
pre-S12 private-unit checkpoint. This broader design document does not claim native execution,
full-language grammar closure or speedup. Its algorithmic design has not been mechanized or
proven sound.

The subsequent [S16 default-input decision](v2.0.0-parameter-defaults.md) retains default read,
fixes uncontextualized closure inputs to that default, and expands the user's delegation to source
choices and normal work sequencing. Its owning bounded grammar and source corpus define the
implemented four-type private-unit scope. The front-end record owns implementation qualification;
the verification record at the end of this document remains the earlier design checkpoint.
Projections, nominals, capabilities, callable schemas and other full-language subjects below still
require their own implementation and proofs.

## 1. Source Boundary and Remaining Grammar Work

The future [grammar](../../spec/language/syntactic-grammar.md#access-syntax)
owns exact productions; do not implement this example as a separate mini-language:

```text
func inspect(buffer: Buffer): usize
func append(edit buffer: Buffer, value: u8): void
func enqueue(take job: Job): void
func open(path: Path): File!
func remember(edit holder: Holder from buffer, buffer: Buffer): void

impl Buffer {
    method self.len(): usize
    method edit self.append(value: u8): void
    method take self.finish(): Product!
}

var buffer = Buffer.create(64)?
read inspect = buffer
// The read must finish before an overlapping edit.
edit working = buffer
working.append(42)
let product = buffer.finish()?
```

The last call is valid only after all conflicting uses/cleanup of `working` end. It transfers
non-Copy Buffer. These are schematic signatures/examples, not runnable library packages. Capability
names in this review are likewise illustrative APIs, not new standard-library declarations.

## 2. Checked Representation

Keep one data-type identity and separate operations. The following are design records, not public
Rust API names or source syntax:

```text
BindingKind       = FixedValue | MutableValue | ReadAlias | EditAlias
InputOperation    = Read | Edit | Take
InvocationKind    = ReadEnvironment | EditEnvironment | TakeEnvironment
ExpressionClass   = Place(place_id) | ConstructedValue(value_id)
ResultProtocol    = ValueResult | IndexPlaceResult(Read_or_Edit)
PlaceAuthority    = Readable | Writable | Owning(readable_or_writable)
DependencyShape   = direct-place slots + carried-access slots + external-storage slots
CallableContract  = invocation + input schemas + value result schema
                    + result-origin relation + edited-state relations + reachable write footprint
                    + effects/cleanup
```

A binding kind is not a type qualifier. A type can describe a read/edit capability intrinsically;
its allowed operations and Copy evidence remain in its data contract. Alias holder identity and
referent identity are different; assigning through an alias cannot replace its referent identity.
`take` input slots are locally writable; fixed local slots are not. Fixed owners can transfer/drop.
A data type alone neither grants update permission nor proves freedom from outside dependencies.

Resolve every header before bodies. Canonical callable/input/type/slot identities are independent
of source coordinates and traversal order. Parameter names project to positions/subpaths before
origin equality/matching. Tuple input patterns bind projections of one input, not separate input
calls. A complete contract/body header assertion retains the selected canonical source agreement;
erasure/type equality uses semantic identities, not those display names.

Replace the old result-permission field with a value-result schema. Do not keep a default X field
and old I/U-result adaptation under a new parser. There is no read-result-to-Copy-result adapter
in S12: ordinary results already deliver values. Ordinary returned access is carried in a capability value. Index operators have a separate
place-result protocol; do not disguise that protocol as a qualified ordinary result.
Retire semantic dispatch based on old standalone transfer/update nodes. Keep type constructors,
input operations and dependency slots intact through generic substitution and target lowering.

## 3. Value Supply Algorithm

A value-producing boundary consumes one checked expression and a destination data schema:

```text
supply_value(expression, destination, source_evidence):
    if expression is ConstructedValue:
        transfer its logical value and cleanup obligation
    else if Copy(source_evidence, expression.data_type):
        require initialized readable source
        create a snapshot; preserve carried D/S and capability identities
    else:
        require initialized owning extraction source
        require no conflicting access/reservation and a valid partial-parent transition
        move the value; mark source part unavailable
    validate destination schema and retained dependencies
    record selected operation exactly once
```

No layout-size threshold, future use, runtime tag, private-body lookup or specialization chooses
another operation. A read/edit alias cannot supply a non-Copy referent to this algorithm. An
existing update-view *value owner* can move its non-Copy descriptor; that is different from
extracting an ordinary value through an edit alias. A Copy read-view descriptor retains the exact
outside access identities. Copy never duplicates an exclusive capability.

The destination's mutability is irrelevant to value supply. Copying known `i32` into a `var`
constructs an independently writable slot. Moving a fixed File into a `take` operation is allowed;
the receiving slot can be updated without updating the now-unavailable source slot. A generic
body's declared evidence fixes its own supply operations. A known-Copy caller can supply a copy
to a generic taking input whose body still moves that received value.

Apply this single algorithm to local/storage/component initialization, ordinary return/final block
results, replacement and taking inputs. Direct read/edit call inputs use place access instead.
Computed conditional expressions construct branch values first; a read call cannot retroactively
make branch moves into aliases. Tuple/discard leaves account for every constructed part and its
cleanup. A discard of a Copy place leaves its source; explicit drop destroys the named owner.

## 4. One Flow and Resource Authority

Reuse the source-neutral selected-operation/control graph principle, not the old source rules.
Each checked transition carries:

```text
State = initialized owned parts + binding writability
        + access/delegation/reservation graph
        + dependency alternatives + external storage requirements
        + logical resource responsibility and evaluation frames
```

The resource ledger alone decides owner existence/survival. An access graph names those owners;
it must not maintain an independent root-alive bitset. State alternatives describe feasible paths,
not simultaneously live copies of exclusive authority. At joins require validity in every admitted
alternative. Loop headers compute a finite conservative fixed point with summarized identities;
do not retain an unbounded execution history. The chosen finite abstraction and convergence/widening
proof are implementation work, not already established by this record.

Backward demand includes ordinary uses, invocation, post-state requirements and destructor accesses.
Release an alias only when its own and dependent needs end. Reparent surviving children without
upgrading read to edit, duplicating exclusive access, dropping a pending reservation, or reviving
a destroyed owner. An ordinary edit declaration activates immediately; an edit call reservation
activates only at invocation. Borrowing memory and keeping a guard's semantic permission valid
are both dependency obligations.

Construct replacement values before identifying assignment destinations. Save their resources and
D/S through target evaluation/old cleanup. If RHS moved the target owner, no old owner is destroyed
at install; if RHS failed, do not evaluate/install the target. An edited external place cannot be
left invalid on an outward failure. A ready exchange replacement can make an extraction safe.
Partial-parent moves need proof that every path reaching a complete-self destructor restores the
needed state; otherwise reject. Conditional cleanup never bypasses that destructor obligation.

## 5. Calls, Atomic Commit and Unwind

Prepare environment/receiver before explicit arguments, all left to right:

| Operand | Preparation record |
| --- | --- |
| Direct read place | Stable place reservation; activate read at invoke |
| Direct edit place | Writable place reservation; activate edit at invoke |
| Direct Copy take place | Snapshot now; prepared owner carries exact D/S |
| Direct non-Copy take place | Reservation for a later ownership transfer |
| Constructed take value | Prepared owner |
| Constructed read value | Evaluation temporary surviving the entire evaluation frame |
| Already computed edit alias/capability | Preserve active access restrictions, not a new inactive reservation |

A later operand may complete a compatible temporary read, such as `buffer.len()` before
`buffer.append(...)`; it cannot destroy/replace/update a reserved place incompatibly. Snapshotting
a Copy take operand does not create snapshot semantics for ordinary read operands. Primitive
scalar operands preserve their prepared payload before later effects.

After all preparation succeeds, check the complete access/capture bundle and all post-state
requirements. All required backing and validity checks precede commit. Commit contains no user
code, destructor, allocation or fallible step between transfers. The callee then owns its taking
inputs even if its execution fails. Failure before commit releases named reservations; it destroys
already constructed owned preparations in reverse order. Earlier nested value constructions/moves
have already happened and are not rolled back.

Stage return value/dependencies, execute normal callee cleanup, then hand off. A staged capability
cannot depend on storage/permission revoked by that cleanup. Evaluation temporaries die at their
stated frame boundary; successful move-to-destination transfers their obligation out of that frame.
Cancellation unwinds actual nested frames and dependent values before roots they need. Terminal
traps without unwind remain distinct from recoverable failure/cancellation.

## 6. Dependency Schemas and State Relations

For every stored type publish a machine-checked schema of potentially dependent components,
access strengths and external-storage slots, including private fields. A generic schema is
parametric in the corresponding argument schemas. Its existence is not a new public field list or
permission to instantiate a hidden representation. Checked API metadata must expose sufficient
bounds for an abstract consumer without searching an inaccessible method body. The exact binary
metadata representation and library capability declarations remain implementation/design work.

A public relation names source slots, not just address values or type names. It distinguishes:

- direct storage of an input/environment, invalid if that slot dies;
- dependencies already carried by an input/environment value, which can survive forwarding;
- storage/allocator requirements, which do not themselves grant read/edit rights;
- semantic guard dependencies that revoke access even if backing bytes survive.

Result relations and edited-state relations are separate. An explicit edited-state clause bounds
the entire resulting value on completed success/failure; a clause without the destination origin
cannot retain its old outside dependencies. `from holder | buffer` admits both; `from static`
proves absence of caller-dependent roots, including when the operation returns `void`.
These are upper bounds: they do not promise that every named source is actually retained.
Deferred cancellation instead permits the incoming state union that completion bound, with
ready-output cleanup composed separately, under the owning
[phase rules](../../spec/language/memory-and-regions.md#deferred-completion-and-cancellation-bounds).

The omitted edit clause preserves incoming dependency slots plus compatible dependencies already
carried by supplied input values. It excludes new direct references into other inputs. This makes
ordinary `push(edit items: Vec<T>, take item: T)` possible without another source annotation while
preventing `remember(edit holder: Holder, buffer: Buffer)` from silently retaining a new direct
buffer view. Unknown direct retention is rejected, not inferred from a caller's current long life.
Default transport does not bypass value supply, component types, or exclusive-capability movement.

At each abstract call apply the selected conservative relation to resulting edited state, including
recoverable exits. Body checking must prove each actual transition is covered. A body can be more
precise internally without changing what an abstract caller is allowed to assume. An explicit
independence/clear contract can release old dependencies only after its completion-path proof succeeds.
A failing clear that leaves the old dependent value intact cannot promise `from static`.

An alternative relation is not a set of simultaneously active exclusive loans. If a result/state
can select one of several edit roots, preserve alternatives; each later operation is checked
against every possible choice. No type erasure or dependency-schema substitution launders uniqueness.
No old payload certificate is extended from scalars/errors to arbitrary types by inference from
Copy or value ownership.

Track state effects on reachable referent owners as well as local descriptors. A closure capturing
edit access to an outside holder can store an input view there; destroying the closure must not
release the dependency now belonging to the holder. Similarly, a guard can update a protected
owner's dependent payload and then release the guard while that payload remains. The complete
contract carries a write-footprint relation from capability/capture slots to actual referent-state
identities. Instantiate it with the caller's current graph, conservatively update affected owners
on each successor, and retain the result independently of the descriptor's later cleanup. Do not
use descriptor liveness as target-state liveness. Read invocation of an explicit shared-state
protocol is not an empty-footprint proof; checked protocol metadata must preserve these changes.
Unknown writes cannot be treated as local effects to make erasure or an adapter pass.

For example, an inferred edit capture of `holder` in
`var action: mut from self | input (input: Buffer): void = (input) { holder.remember(input) }`
can update the outside holder. After `action(buffer)` and `drop action`, the holder's new
buffer dependency still constrains `buffer`. The environment's capture lease and the stored
view's dependency are different graph edges. This example is a design requirement, not a
compiled test or a declaration of the illustrative Holder API.

## 7. Closures, Interfaces and Deferred Execution

The callable type stores invocation kind independently of explicit argument operations, result
origins and environment state. `func(edit Buffer): void` can update an argument while reading its
environment. A `mut` environment requires writable authority; a fixed holder cannot supply it.
`once` receives a value instance under ordinary Copy-or-move supply. Exact input operations and relations survive witnesses/generics/erasure. Boundary adaptation
permits `func` to `mut`, and `func`/`mut` to `once`, only after the complete relation is checked.
For `func` to `mut`, the unchanged environment must satisfy the receiver's post-state bound.
Taking adaptation constructs its own environment value, delegates read/edit invocation, stages the
answer, destroys that environment normally, and then hands off. Direct environment-backed answers
fail; independent answers and properly forwarded carried dependencies can pass. Unknown abstract
bounds must themselves suffice; a hidden body cannot repair them. Reject `mut` to `func` and all
consuming-to-repeatable conversions. Freeze one checked adapter operation before later consumers;
this is not type equality, permission-based overload fallback or repeated target selection.

Every callback invocation introduces fresh symbolic extents for abstract inputs. Verify universally
valid uses against that contract. A retention-free callback cannot keep an invocation-local root
for a later call. A retention-capable `mut from input (...)` contract updates the caller's
obligations; `mut from self | input (...)` also preserves earlier environment dependencies.
The result's independent `from` clause remains after its type. Taking the environment cannot
return a capability into dying capture storage, but can return a moved capture or forward a
surviving carried descriptor.

Name-only `(file; args) { ... }` capture entries construct values at formation using the common
Copy-or-move algorithm. Ordinary captures are inferred from checked operations, never upgraded
from read to move merely to satisfy a later escape. An expected callable supplies missing input
operations before body validation; explicit modes must agree. Without context, unmarked closure
inputs default to read; checked uses infer data/capture/environment/result facts, not a stronger
input operation. Private later call sites cannot change that published contract.

Deferred frames own captured/moved values and retain borrowed roots for the duration required by
drive, output and cancellation. A ready-but-unconsumed output is still a value with cleanup/deps.
Apply relation updates at the owning async contract's specified operation point; do not move a
post-state effect to frame construction merely because it was inferred during compilation.
Complete async update-lease, drive/cancellation and output ownership migration before accepting
such source in the new checker. Frame placement/fusion does not discharge semantic dependencies.
The [async/effect review](v2.0.0-async-and-effect-contracts.md) records subsequent source/model
closure and the correction to earlier same-bound cancellation, without executable qualification.

### Index Projection Completion

An index operator identifies an existing place, stages read/edit authority, completes its own
normal cleanup and hands off the projection. It does not suspend. `return place`/a final place
result is checked under this operation's declared place protocol, never under ordinary Copy-or-move.
A local guard invalidated by cleanup cannot protect that handoff. Read/edit index identities are
selected from the source operation before checking available authority; failed authority never
selects another implementation. A value use subsequently supplies a value from the read projection;
non-Copy container extraction needs a valid removal/exchange operation. Ordinary functions keep
value results, and built-in owning field/tuple projections retain their distinct subplace state.

These are design cases, not 36 compiled fixtures. A fixture must include actual declarations,
source spans, selected operation expectations and cleanup assertions; inventing a Python source
oracle or counting IDs is not executable language validation.

Required proof obligations:

1. **Preservation:** selected transitions preserve data schemas, definite initialization and one
   cleanup responsibility per initialized owned part.
2. **Access soundness:** every read/edit/extraction has authority; active/reserved accesses and
   dependent cleanup cannot conflict on potentially overlapping places.
3. **Dependency preservation:** Copy/move/wrapping/substitution/erasure preserve all carried and
   storage dependencies, including state changes in reachable outside owners; successful clear/independence discharge is justified by its relation.
4. **Exit soundness:** staged results survive ordinary cleanup; updated external values satisfy
   every outward post-state contract; unwind destroys exactly the initialized resources in order.
5. **Abstract-call soundness:** a verified body refines its public relation for arbitrary eligible
   inputs and fresh invocation extents, independent of private-body availability at the caller.
6. **Analysis correspondence:** the finite CFG abstraction conservatively simulates these
   transitions, including loop convergence, alternatives, partial state and nested evaluation.
7. **Lowering refinement:** executable/native lowering realizes the already selected operations
   without redispatch, changed failure timing, hidden copies/sharing or earlier logical cleanup.

A bounded state enumerator can find counterexamples to a finite model; it cannot establish these
claims for the full language. Document the model's admitted assumptions and excluded features.

## 9. Replacement and Verification Order

1. Complete remaining owning grammar/semantic subjects before their parser/checker extensions.
   This checkpoint migrated the access foundation; it did not declare modules/async/ABI complete.
2. Before editing crates, read each owning README. Replace qualified local/result metadata with
   binding/input operations and value-result/dependency schemas. Preserve canonical declaration
   identities and one reusable exact-source binding authority.
3. Replace the private goal's parser, declaration lowering, typed selected operations, flow/init,
   access validation and resource transitions as one coherent acceptance boundary. Derive changed
   source fixtures from S12; retire old expectations that a plain binding aliases or that Copy
   taking arguments invalidate their source. No CLI compatibility flag or released-program adapter.
4. Keep accepted-unit publication sealed: check every definition, even unused/recursive ones;
   no partial product survives sibling failure. Rebinding checks the same frozen declarations and
   every current body. Do not add separate root-survival or post-state authorities.
5. Run authoritative focused production tests, then the disposable complete compiler gate. Old
   passing tests are historical regression evidence, not S12 conformance. Qualification records
   identify the exact changed source/certificate boundary.
6. Extend projections/nominals, generic/callable/interface schemas, outcomes/async and modules
   only after their corresponding specification/fixtures are closed. Then freeze the native
   consumer/ABI contract and qualify lifecycle/failure/cancellation end to end.
7. Evaluate realistic reading/writing tasks and inspect generated operations. Measure compile
   time/memory as well as runtime/allocation/code size. Spelling does not prove performance;
   source-level Copy permits physical elimination, not a requirement to materialize every snapshot.

Do not change qualified release artifacts, tags, or publication status as part of S12. The previous
checkpoint is preserved as engineering evidence, not a semantic fallback. Under the later expanded
delegation, resolve internal and source alternatives with concrete examples and recorded reasoning;
do not wait for approval of ordinary design or work sequencing. Missing requirements outside the
available session/repository and actions outside authorization remain separate questions.

## 10. External Evidence and Limits

- [Swift SE-0377](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0377-parameter-ownership-modifiers.md)
  illustrates distinguishing input ownership conventions from caller spelling. It does not justify
  importing Swift's ARC, defaults or all parameter rules.
- [Swift SE-0446](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0446-non-escapable.md)
  distinguishes escape restrictions from copyability. Its existence is evidence against treating
  Copy as independence, not a Nocter proof or an assertion that every experimental lifetime feature
  is a stable Swift contract.
- [Hylo bindings](https://docs.hylo-lang.org/language-tour/bindings) separates fixed/mutable values
  from mutable projection. Its explicit-copy policy differs from S12's evidence-driven implicit
  Copy policy; no performance comparison follows.

Research informs counterexamples and proof obligations. The owning Nocter future chapters select
Nocter behavior; neither a related language nor documentation generation validates this design.

The [Hylo subscript specification](https://github.com/hylo-lang/specification/blob/main/spec.md)
provides a contrasting place/projection design whose accessors can suspend at `yield`. S14 selects
normal completion instead; it does not import suspended accessor cleanup, a coroutine ABI, or a
new `yield` spelling. The comparison identifies a cleanup obligation, not a Nocter soundness proof.
