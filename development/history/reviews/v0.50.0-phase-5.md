# v0.50.0 Phase 5 Cross-I/O Composition Review

Date: 2026-09-14

## Result

Phase 5 is complete. Local files, child pipes, TCP, TLS, and HTTP response bodies compose through
the same `Reader`, `Writer`, and `io.copy` authority. Timeout-aware endpoints retain their explicit
capability without forcing timed copies of every generic algorithm.

## Shared Timeout Capability

`TimedReader` requires `Reader` and adds one `read_with_timeout` operation. `TimedWriter` likewise
requires `Writer`. `TcpStream` and `TlsStream` implement both refinements; HTTP `Response` implements
the reader refinement. `TimeoutReader<R>` and `TimeoutWriter<W>` retain only mutable endpoint borrows
and a copyable `Duration`. Their ordinary `read` or `write` implementation delegates to the timed
operation, so existing algorithms select no endpoint-specific branch.

The duration is intentionally per operation. A multi-read collection or transfer receives a new
relative interval for each operation. A whole-pipeline wall-clock deadline remains structured task
composition through `task.with_timeout`; the byte-stream interfaces do not conflate those policies.

## Transfer and Failure Precedence

`io.copy` remains the sole asynchronous generic transfer loop and `io.copy_blocking` its explicit
synchronous twin. One iteration reads, validates the reported count, observes EOF, writes the valid
prefix, and only then commits that chunk to the returned total. Consequently:

- a read failure wins before the destination is invoked;
- `std.io.invalid_read_count` wins before the destination is invoked;
- after a valid nonempty read, a writer failure wins and any already-observable writer prefix
  remains observable;
- the successful byte count is returned only at clean EOF and excludes a chunk whose writer failed;
- cancellation destroys unpublished scratch storage and delegates subsequent endpoint usability to
  each endpoint's own cancellation contract;
- generic copy does not close or flush either borrowed endpoint.

The native contract fixture proves these rules with instrumented sources and destinations. It also
cancels a pending transfer before the source publishes bytes, then successfully reuses both memory
endpoints. Timeout projections prove that only timed methods are selected while the generic copy
loop remains unchanged.

## Cross-Endpoint Evidence

- Filesystem copy performs its same-file identity check and truncation policy, then calls `io.copy`.
- One native process pipeline copies a file into `ChildStdin` and concurrently copies `ChildStdout`
  into another file. Both directions use `io.copy`; concurrent draining prevents pipe deadlock.
- One fragmented local HTTP response is borrowed through `TimeoutReader` and copied into `File`.
  The result is reopened and verified after explicit close.
- HTTP `read_to_end_with_timeout` now creates the same timeout projection and calls the shared
  `Reader.read_to_end` collector. Its former scratch allocation and collection loop were removed.
- Process closed-output capture already calls the shared `Reader.read_to_end` defaults. The separate
  blocking closed-process pump is retained because it must service input, stdout, stderr, and child
  progress simultaneously; it is lifecycle coordination, not a duplicate sequential copy loop.
- Remaining HTTP read loops own protocol framing and response-head state. Remaining pipe loops own
  target partial-syscall handling. Neither reconstructs generic stream transfer.
