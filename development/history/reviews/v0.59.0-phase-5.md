# v0.59.0 Phase 5 Integrity-Checked Record Review

## Scope

This review closes the integrity-checked binary-record milestone. It covers the canonical scalar
and variable-width codecs, CRC-32, borrowed cursor and owning storage adapters, the practical
append-only record package, blocking and asynchronous transport composition, editor projection,
and whole-repository qualification.

## Findings and Resolution

### The reviewed standard-library graph omitted two authored dependencies

The whole-workspace gate rejected `checksum -> internal/safety` and `vec -> bytes` as unexpected
standard-library dependencies. Both edges are intentional. CRC-32 uses the package invariant abort
only after proving its finalized value fits `u32`; it does not acquire allocation, transport, or
platform authority. The byte-vector adapter delegates canonical width and encoding decisions to
`std/bytes`; it does not reproduce them. The exact reviewed dependency catalog now contains both
edges, and its closed-graph test rejects future unreviewed or stale edges.

### The editor qualification initially exceeded the repository test-size rule

The first end-to-end editor test put every request in one function. Clippy correctly rejected that
shape. The test now keeps one scenario entry and separates decode, prefix-codec, checksum, and
source-projection assertions into named helpers. No lint suppression or larger global limit was
introduced.

### The native standard-library inventory retained the previous test count

The full native-session suite successfully executed the new signed bit-conversion test, then
rejected its own obsolete total of 31 selected standard-library cases. The selected modules and all
case results were correct; v0.59.0 intentionally adds the signed-representation case to that closed
inventory. Its expected total is now 32. The assertion remains exact, so an unintentionally omitted
or newly admitted case cannot silently weaken this cross-module failure-atomicity run.

### The practical package bypassed canonical source formatting

The implementation sources carried descriptive comments even though the current formatter rejects
all comment-bearing input rather than risking comment loss. Their descriptions duplicated the
package entry in `examples/README.md`, so the implementation comments were removed instead of
adding an example-specific formatter exception. The package root contract and the remaining
sources were then normalized to formatter output, including declaration spacing and multiline
condition indentation. The discover-all runnable-example gate now formats every file successfully.

## Authority Review

`std/internal/bytes` owns unsigned fixed-width byte-order calculation. Public `std/bytes` owns the
Nocter scalar contract, signed and floating bit projection, canonical ULEB128 and ZigZag encoding,
and prefix-decode classification. `std/scan` alone owns borrowed cursor position;
`std/fixed.ByteBuffer<N>` owns bounded committed length; `Vec<u8>` owns dynamic growth. Their
adapters consume codec results and do not repeat scalar representation decisions.

`std/checksum` independently owns ISO-HDLC CRC-32 state transition, its reproducible lookup table,
and finalization. The binary-record package calls that contract and owns only record magic,
version, payload layout, declared-size policy, checksum placement, and valid-prefix retention.
Neither standard-library layer knows the record format.

The blocking and asynchronous readers collect transport fragments into dynamic byte storage and
then call the same `decode_log`. They own no framing or checksum branch. Wire construction and
parsing are separate source responsibilities behind the package root contract, but share the
single constants and codec authorities visible within that module. Review found no second endian,
prefix classification, CRC table, cursor offset, framing decision, or transport-specific decoder.

The editor scenario starts from the real public package rather than a reduced fixture. Hover,
definition, and implementation requests resolve the package decode contract, canonical ULEB128
contract, and CRC-32 contract to their public declarations and implementation sources. Completion
uses the checked `ByteCursor` members; semantic tokens cover the application, parser, and wire
sources; and inlay hints use retained checked body types. The language server consumes the normal
semantic query surface and has no record-specific projection path.
