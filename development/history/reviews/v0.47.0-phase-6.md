# v0.47.0 Phase 6 Compiler Convention Authority Closure

## Scope

This review covers compiler-known source spellings and physical conventions across language,
syntax, package decoding, discovery, declaration lowering, checking, semantic presentation,
command presentation, installation, acquisition, and LSP registration. It asks whether each
decision has one owner, whether consumers receive typed results instead of repeating recognition,
and whether any contract succeeds only because its caller previously performed an undocumented
check.

## Findings and Remediation

### Source spelling was classified in multiple semantic consumers

Contextual names such as `Self`, `self`, `static`, `copy`, and `_` were cataloged by syntax, but
several lowering, checking, and presentation paths still compared or emitted independent string
literals. Function and provenance labels, package directive names, and the intrinsic argument-pack
member `len` had the same problem.

The language layer now owns closed package-directive and argument-pack-member vocabularies. Syntax
continues to own contextual and reserved keywords. Semantic consumers classify through those
contracts, and the canonical presentation renderer emits their spellings rather than maintaining a
parallel source vocabulary.

### Module-segment validation had two authorities

`nocter-compile-input` and `nocter-package` independently implemented the same lowercase module
segment grammar and keyword exclusion. A newly reserved keyword could therefore be accepted by one
path and rejected by the other.

`nocter-syntax` now owns both general source-name validation and portable module-segment validation
in one `name` responsibility. Compile input re-exports that contract for existing topology clients;
package decoding calls the same function directly. No consumer maintains another keyword list.

### Package schema and exact-selection validation relied on caller discipline

Package header, dependency, and target field sets were repeated as raw map keys. Exact dependency
decoding separately checked hexadecimal text and then called a crate-visible constructor that
assumed validation had already occurred. Resolution later reconstructed the exact lock from the
trusted text.

One package-private schema now classifies every compiler-owned field while leaving dependency
aliases authored. `DependencyExactSelection` stores both its source-bearing authored value and an
`ExactDependencyLock` produced by the lock type's public validating constructor. The unchecked
constructor is private, and later graph and resolution stages clone the retained validated value.

### Physical source layout was repeated across filesystem responsibilities

Discovery, command input, workspace analysis, package cache, acquisition, installation, formatter
qualification, and watched-file registration embedded independent `index.nct`, `.nct`, or glob
spellings. The language crate now derives the extension, suffix, module-root name, and recursive
glob from one declaration. Filesystem decision points consume those constants.

The protocol-only `nocter-lsp` crate does not depend on this language policy. It accepts a watched
file glob as input; `nocter-language-server` supplies the language-owned value. This preserves the
dependency direction instead of moving a Nocter-specific decision into the protocol codec.

### CLI presentation reclassified command text

Argument parsing had already selected a typed command but converted it back to text. CLI JSON
presentation compared that text with `test` to choose its response schema. The command layer now
publishes the narrower typed `DiagnosticCommand`; its spelling derives from the command schema, and
the CLI branches on the enum.

## Resulting Authority Flow

```text
nocter-language ── vocabulary and physical source layout
       │
       ├── nocter-syntax ── parsed structure and canonical name grammar
       │         │
       │         ├── package/discovery ── validated package and topology facts
       │         └── lowering/checking ── semantic identities and checked behavior
       │                                  │
       │                                  └── analysis presentation
       │
       └── language-server ── Nocter source glob
                                  │
                                  └── nocter-lsp protocol encoding

command schema ── typed DiagnosticCommand ── CLI JSON presentation
```

No later responsibility scans standard declarations by public API name. The standard profile still
maps exact bundled declarations to compiler roles once; checking and machine construction consume
those resolved roles and semantic identities.

## Review Conclusion

No remaining production path was found that makes semantic selection from a raw compiler-known
source identifier, revalidates an exact dependency selection, or independently decides the Nocter
source extension or module-root file name. Remaining textual names belong to authored symbol
lookup, diagnostics, test fixtures, external protocols, installation-manifest keys, or command
schema declarations at their owning boundary.

The review found no compatibility fallback or obsolete `#lock` parser path. `#lock` remains only in
negative tests, current specification text that declares it invalid, and historical records.
