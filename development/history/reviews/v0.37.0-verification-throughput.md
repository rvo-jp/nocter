# v0.37.0 Verification-throughput Review

**Result: complete (2026-09-06).** The complete clean compiler gate retains its coverage while
finishing 46.3 percent faster on the measured Apple M1 host.

## Attribution

The existing `development/verification/verify-compiler.sh` gate took 569.31 seconds in a fresh
disposable target. Cargo spent 24.66 seconds on warnings-denied Clippy and then 50.99 seconds
building a distinct unoptimized test profile. Test execution dominated the remainder:

| Test executable | Elapsed before change |
| --- | ---: |
| `nocter-cli` library | 27.48 s |
| `nocter-analysis` | 32.04 s |
| `nocter-command` | 79.78 s |
| `nocter-language-server` | 143.19 s |
| `nocter-native-session` | 95.26 s |
| `nocter-workspace-analysis` | 37.99 s |

These are not ordinary unit-test workloads. They repeatedly run the Nocter compiler, standard
library analysis, LSP queries, native lowering, and produced executables inside Rust test
processes. The workspace test profile nevertheless used Cargo's unoptimized default.

The native-session suite also compiled every public single-file and package example after the
command suite had already compiled those same inputs, emitted native executables, run them, and
checked their complete process contracts. The lower test added only nonempty-image and selected-
identity assertions already covered by focused native-session and target-program tests. The one
unique package-catalog completeness assertion now precedes the command-boundary execution loop.

## Selected Change

The test profile now uses optimization level 1 for workspace packages. A wildcard package override
keeps third-party dependencies at optimization level 0, because they are support code rather than
the repeatedly executed compiler workload. This balance completed a clean all-target workspace
test in 217.73 seconds during isolated comparison. Optimizing dependencies as well took 284.54
seconds; optimization level 2 took 344.24 seconds. Both alternatives spent more time compiling
without materially reducing the dominant integration-test execution.

The two subsumed whole-example native-session tests were removed. The command suite remains the
single owner of full public-example compilation and execution coverage. Focused native-session
tests continue to cover standard APIs, ABI transport, cleanup, primitive behavior, target sets, and
native image construction.

## Rejected Shortcut

Running the six heavy test executables concurrently with one test thread each did not help. It made
the language-server executable take 569.15 seconds instead of 143.19 seconds and the experiment
took 569.28 seconds overall. Cargo's normal per-executable execution allows each heavy suite to use
the host cores efficiently; the problem was unoptimized compiler code and duplicated semantic
coverage, not a missing outer scheduler.

No tests were globally serialized around a mutable shared compiler. Such a fixture would make test
results depend on cleanup and execution order and would hide isolation faults behind test-only
state. No production cache or semantic contract was changed for test speed.

## Verification

After the change, the same clean disposable-target compiler gate completed in 305.55 seconds. It
passed repository metadata, benchmark-helper and Unicode reproducibility checks, formatting,
warnings-denied workspace Clippy, every all-target workspace test, no-default-feature checking, and
warnings-denied Rustdoc. The gate creates and removes one external target exactly as before.

The measured reduction is 46.3 percent. Test optimization affects only Rust binaries built under
the test profile; released compiler artifacts, Nocter-generated programs, source semantics,
diagnostics, LSP behavior, and native ABI are unchanged.

## Review Conclusion

The change removes duplicated responsibility instead of weakening verification. Full public
examples have one strongest owner at the command boundary. Lower layers keep focused contracts.
The Cargo profile expresses the actual workload: the workspace compiler is code under execution,
while external dependencies remain cheap to build. No new wrapper, cache authority, alternate
semantic path, or caller-discipline contract was introduced.
