# v0.37.0 Performance Closure Review

**Result: performance work complete (2026-09-06).** The final candidate improves every measured
compiler and checked-editor path targeted by the milestone. No semantic shortcut, editor-only
meaning, persistent artifact cache, generated-program optimization, or duplicated compiler
authority was introduced. Versioned release packaging remains a separate release-preparation gate.

## Review Scope

The review covered every change after v0.36.0, including the external measurement runner, query
decomposition, reusable relation analysis, immutable compile-input retention, persistent type
prefixes, shared body-syntax projection, test-profile configuration, and removal of duplicated
whole-example tests. It specifically checked for stale wrappers, repeated computation, multiple
sources of truth, reverse dependencies, caller-disciplined contracts, changed diagnostics, and
benchmark-specific production behavior.

One measurement-authority gap was found and closed before the final comparison. Benchmark schema
2 records each compiler binary, its installed manifest, the manifest's standard-library tree
identity, and exactly the `.nct` sources belonging to each fixed scenario. It no longer treats
package documentation as compiler input or omits the LSP package root. An unused
`DiscoveredUnit::into_sources` conversion was removed because retained compile input made its
apparently consuming operation clone the complete source map. Two relation comments left behind by
the source-neutral failure split were corrected.

## Final Alternating Comparison

The released v0.36.0 home and candidate revision
`5ab91d83fa1442981f2e931584504eda5aa2c37b` were measured in one alternating run on the recorded
Apple M1 host. Both installed manifests select the same standard-library tree
`f47d380844347bd024ad268fd2224526fe5b99b101b8ed18819ca75768cbd5d7`. Process scenarios used two
warmups and seven samples. Editor scenarios used five sessions, two warmup edits per session, and
fifty measured edits per session.

| Scenario | v0.36.0 median | Candidate median | Change |
| --- | ---: | ---: | ---: |
| Single-file cold check | 1,090.821 ms | 833.481 ms | -23.6% |
| Representative package cold check | 1,190.302 ms | 908.939 ms | -23.6% |
| LSP open plus first checked hover | 884.481 ms | 636.842 ms | -28.0% |
| Body edit plus checked hover | 301.920 ms | 203.068 ms | -32.7% |
| Fifty-edit session total | 15,261.019 ms | 10,190.879 ms | -33.2% |

Median peak resident memory fell by 9.2 percent for the single-file check and 7.8 percent for the
package check. The first five-session run reported a noisy 12.1 percent initialize increase even
though initialization performs none of the changed semantic work. A separate fifteen-session
confirmation measured 189.057 ms for v0.36.0 and 189.781 ms for the candidate, a 0.4 percent
difference. Its minima were 188.582 and 186.103 ms respectively. The candidate therefore has no
substantiated initialization regression.

## Boundary Review

- Discovery constructs one immutable compile input. Source and syntax handles share its exact
  storage rather than rebuilding topology or copying normalized sources.
- A `TypeCursor` identifies the append-only prepared prefix. Body recipes classify only their
  suffix and cannot publish source-branch type or closure identities.
- One body-source catalog owns each current body/syntax association and locator projection. Name,
  type, recovery, and canonical materialization consumers cannot independently reconstruct it.
- Program materialization remains exact-current. Reusable provenance, effect, and loan results are
  source-neutral, and failures regain spans only through the current relation projection.
- Query fingerprints are owned by the computation layer; syntax owns structural body equivalence;
  checking owns semantic construction. No layer interprets another layer's private representation.
- Full public-example execution remains at the strongest command boundary. Native-session retains
  focused ABI, runtime, cleanup, and image-construction coverage rather than recompiling the same
  corpus.
