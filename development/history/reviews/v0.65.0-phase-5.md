# v0.65.0 Phase 5 Sessions-and-observability Review

**Result: complete with no open Phase 5 finding (2026-09-21).** Session identity, HTTP transport,
structured event construction, JSON projection, and application state each have one explicit
owner. The complete HTTP service composes those contracts without a global session table, ambient
request context, hidden clock, or logger registry.

## Authority Trace

| Responsibility | Sole authority | Consumers |
| --- | --- | --- |
| 256-bit session identity and canonical spelling | `std/session.SessionId` | HTTP and applications |
| cryptographic entropy | `std/random` | `SessionId.issue` |
| request-cookie syntax and finite decoding | `std/http.Cookies` | `SessionCookie` and applications |
| session-cookie attributes and ambiguity policy | `std/http.SessionCookie` | HTTP applications |
| event field ownership and redaction | `std/log.Field` | applications |
| event shape and timestamp ownership | `std/log.Event` | applications and sinks |
| JSON escaping and number spelling | `std/json` | structured log projection |
| shared event retention | application-selected `Mutex<Vec<Event>>` | HTTP service handlers |

`SessionId` stores exactly one 32-byte identity. URL-safe Base64 encoding is generated only when
transport text is explicitly requested. Equality examines all bytes instead of returning at the
first mismatch; hashing and ordering consume the same byte identity. The type does not implement
generic formatting, preventing ordinary interpolation or structured-field conversion from
revealing a bearer value accidentally.

`SessionCookie.read_headers` examines the complete field sequence and rejects multiple `Cookie`
fields. It delegates field syntax and bounds to `Cookies` and identifier spelling to `SessionId`.
The lower-level `read` remains available for an application that has already applied an explicit
multi-field combination policy. Set and clear operations share one attribute renderer, so path,
HttpOnly, SameSite, and Secure policy cannot diverge.

`Field.redacted` accepts no secret value and stores only a fixed marker. Redaction therefore cannot
be disabled later by a renderer. `Event` accepts its `SystemTime` and output destination explicitly;
it neither reads a clock nor discovers process state. JSON values and output delegate to `std/json`,
including the newly exposed direct integer constructors, so logging does not duplicate escaping or
number-token rules.

## Corrected Findings

The initial HTTP adapter accepted an already parsed `Cookies` value but did not own the ambiguity
decision for multiple request fields. Adding `read_headers` closed that transport gap while keeping
`Cookies` as the sole syntax authority. The initial session equality returned on the first unequal
byte; it now performs the complete fixed-width traversal appropriate for a bearer identity.

Running the completed service with a real timestamp exposed an older ARM64 target defect rather
than a logging defect. Darwin's kernel `gettimeofday` entry has a third optional
`mach_absolute_time` output pointer that is absent from the public two-argument C declaration. The
wall-clock emitter left that argument register ambient, so an async executor pointer could be
mistaken for writable output. The target ABI now records all three arguments, passes null for the
unused output, and a native async-entry regression test proves that an indirect wall-clock result
cannot corrupt the surrounding executor frame.

The service records an event through a short helper so its mutex guard is destroyed before response
I/O begins. This prevents the example from normalizing a lock held across an unrelated suspension.
The router still owns exact application state and lends only its declared readonly borrow.

## Evidence

Focused native execution covers session parsing, issuance, hashing, logging projection, redaction,
duplicate fields, HTTP set/clear policy, duplicate cookie values, and duplicate request fields. The
HTTP-service editor test analyzes the complete composition through ordinary package and semantic
queries. The 62-case HTTP native contract, the structured-log and session suites, the async
wall-clock regression, and all installed-standard-library system examples pass. The documentation
builder generated 359 pages outside the repository. Full repository qualification belongs to
Phase 6.

## Conclusion

No compiler primitive recognizes sessions, logging types, route state, or redaction. Every layer
depends on the preceding public contract rather than its representation. The remaining milestone
work is application and qualification closure, not another foundational model.
