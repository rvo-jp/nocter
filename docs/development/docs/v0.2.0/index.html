use std/io.print

func greet(user: User): void! {
    let name = user.display.name() otherwise { "guest" }

    let tone = match user.presence {
        Presence.online { "hello" }
        Presence.away { "welcome back" }
    }

    print("${tone}, ${name}\n")?
}
interface Writer {
    pub method &+self.write(bytes: &[u8]): void!
}

func save_log(output: &+Writer, events: &[Event]): void! {
    for event in events {
        output.write(event.message().bytes())?
        output.write("\n".bytes())?
    }
}
pub struct Session {
    id: SessionId
    user: User
    expires_at: Time
}

pub func Session.start(user: User, clock: &Clock): Session {
    return Session {
        id: SessionId.new(),
        user: move user,
        expires_at: clock.now().plus_minutes(30),
    }
}

    return Profile {
        ...user.summary(),
        ...move stats,
        visits: 0,
    }
}

Nocter v0.2.0 Development Contract

Purpose

v0.2.0 は Nocter で所有する可変長データを安全に扱い、同じ意味情報をエディタから 利用できる状態を作るリリースである。終了時には String と Vec<T> がデモ用の 限定実装ではなく、Allocator と所有権の共通基盤上で通常のプログラムに使える。

この文書が唯一の現行マイルストーンを定義する。v0 は曖昧なのでリリース名の 略称に使わない。過去リリースの記録は Git と release metadata に残し、現行の 設計文書へ混在させない。

対象は arm64-darwin、リリース版は 0.2.0 である。公開言語規則は spec に従う。

Completion Definition

次の四領域をすべて満たしたときだけ v0.2.0 を完了とする。

1. Allocator

  • Layout が size、alignment、overflow、zero-sized allocation の規則を一元化する。
  • allocation、growth、deallocation が同じ Allocator 契約を通り、String と Vec<T> が OS page primitive を直接呼ばない。
  • growth は新領域の確保と内容移送に成功してから旧領域を解放する。失敗時に元の値を 保持する。
  • RawBuffer は allocator provenance と実際の allocation layout を失わず、公開 API から不正な値を構築できない。
  • capacity の加算・乗算 overflow、過大 alignment、確保失敗、empty 値の解放を 実行時テストで固定する。
  • allocator は明示的に渡す。v0.2.0 のために暗黙の global allocator を導入しない。

詳細は Allocator and Ownership に記す。

2. Ownership and Destruction

  • struct、fixed array、payload enum の再帰的な部分初期化状態を表現できる。
  • fixed array の「完了済み prefix」と「構築中の現在要素」を別々に追跡し、現在要素の ネストした field 初期化に失敗しても取得済み資源を一度だけ逆順に破棄する。
  • Vec<T> は [0, len) を所有済み要素として扱い、非 copy 要素を逆順に drop する。
  • push は要素の構築完了後だけ len を公開し、clear と drop は各要素を一度だけ 破棄する。
  • pop は末尾要素の所有権を返り値へ移し、vector 側の所有範囲を一要素縮める。
  • 正常 return、早期 ?、分岐、loop exit、replacement、部分初期化失敗で同じ drop 規則が働く。
  • 未対応の所有権形状は IR や backend へ到達する前に source-backed diagnostic で 拒否する。

3. Standard Library Runtime

  • String の empty、from/copy、reserve、push、clear、view、drop が共通 Allocator 上で 動作する。
  • Vec<T> の empty、with_capacity、from_slice、reserve、push、pop、clear、view、drop が copy / non-copy の両要素で動作する。
  • 少なくとも Vec<String>、Vec<File>、Vec<Vec<String>> を build/run テストし、 growth、early return、clear、scope exit を通して二重解放・未解放・use-after-move を 起こさない。
  • 配布 .nocter/std と repository-local development/std の公開動作が一致する。
  • runtime primitive は pub(nocter) の狭い trust boundary に留め、通常 API を コンパイラ固有名で special-case しない。

詳細は Standard Library に記す。

4. LSP

  • diagnostics、semantic tokens、definition、references、document symbols が open document と imports に対して同じ compile-unit facts を使う。
  • hover が宣言種別、完全な型または signature、generic specialization、documentation、 ownership capability を source-backed range とともに返す。
  • completion が global、local、import、member、enum pattern、struct field、keyword の 文脈を区別し、型・visibility・現在位置で候補を絞る。候補には kind、detail、必要な insert text を含める。
  • call position で signature help が parameter、active parameter、return type、 documentation を返す。
  • 編集途中の不完全な source でも server が落ちず、回復可能な範囲で hover と completion を返す。
  • LSP 自身が名前解決、型推論、visibility、ownership を再実装しない。

詳細は LSP に記す。

Acceptance Programs

リリース判定には小さな unit test だけでなく、配布 home を使う次のシナリオを含める。

  1. 1. Vec<String> を空から成長させ、複数回 reserve し、pop した文字列を vector の drop 後にも使用する。
  2. Vec<File> を途中で clear し、残りを scope exit で閉じる。失敗経路でも各 handle が一度だけ閉じられる。
  3. Vec<Vec<String>> を構築し、growth が失敗した後も内側の値を回収できる経路と 正常終了を検証する。
  4. String を empty から複数回成長させ、view と clear 後の再利用を検証する。
  5. 複数ファイルの標準ライブラリ利用例で diagnostics、hover、completion、signature help の JSON-RPC 応答を固定する。

Explicit Non-goals

次は v0.2.0 の終了条件に含めない。基盤を壊す暫定実装も入れない。

  • collection literal、map literal、... spread / variadic syntax
  • string interpolation の暗黙 allocator 選択
  • interface runtime dispatch と embedding
  • vector の任意 index から所有値を抜く remove、sparse live-element tracking
  • allocator の暗黙既定値、複数 allocator family の公開設計
  • workspace-wide package index、rename、code action、formatter request
  • arm64-darwin 以外の native backend

pop は末尾 prefix を縮めるだけなので v0.2.0 に含める。任意位置の remove は sparse ownership state を必要とするため後続設計とする。

Work Order

順序は依存関係で固定する。

  1. 1. recursive drop obligation に fixed-array current-element staging を追加する。（完了）
  2. Layout、RawBuffer、Allocator allocation/grow/free 契約を完成させる。（完了）
  3. Vec<T> の initialized prefix、non-copy push/clear/drop を実装する。（完了）
  4. ownership transfer として Vec<T>.pop を実装する。（完了）
  5. String を共通 Allocator 契約へ移し、growth failure invariants を固定する。（完了）
  6. hover 表示を typecheck facts の安定した presentation model に統合する。（完了）
  7. context-aware completion と signature help を compiler analysis に追加する。（完了）
  8. distributed-home acceptance programs と全検証を通し、文書の未達項目をゼロにする。（完了）

Release Gate

以下を全て満たすまで version と release metadata を安定版へ変更しない。

  • ./development/compiler/scripts/verify.sh
  • cargo fmt --manifest-path development/compiler/Cargo.toml --check
  • git diff --check
  • 上記 acceptance programs の build/run/LSP integration tests
  • development/docs/ と development/TODO.md に未解決の v0.2.0 必須項目がない
  • 配布物を package-local-release.sh で生成し、生成した .nocter home だけで再検証する
