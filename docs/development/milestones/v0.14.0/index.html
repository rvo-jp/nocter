use std/io.print

func greet(user: User): void! {
    let name = user.display.name() otherwise { "guest" }

    let tone = match user.presence {
        Presence.online { "hello" }
        Presence.away { "welcome back" }
    }

    print("${tone}, ${name}\n")?
}
interface Writer {
    pub method &+self.write(bytes: &[u8]): void!
}

func save_log<W>(output: &+W, events: &[Event]): void! where W: Writer {
    for event in events {
        output.write(event.message().bytes())?
        output.write("\n".bytes())?
    }
}
pub struct Session {
    id: SessionId
    user: User
    expires_at: Time
}

construct Session {
    pub default func start(user: User, clock: &Clock): Self {
        return Self {
            id: SessionId.new(),
            user: move user,
            expires_at: clock.now().plus_minutes(30),
        }
    }
}
func consume(values: Vec<String>): void! {
    for value in move values {
        print(&value as &str)?
    }
}
construct NonEmptyList<T> {
    pub default literal [](...items: T): Self from items {
        var list = Self.new()

        for item in items {
            list.push(move item)
        }

        return move list
    }
}

v0.14.0: Specification-First Compiler Rewrite

Goal

Build a new Nocter compiler from the public specification without consulting, executing, copying, or behavior-matching the previous compiler. v0.14.0 is not released until the specification is closed, the new architecture has one authority for each semantic decision, and the required public language, standard-library, CLI, editor, and native-runtime contracts are implemented.

Rewrite Rules

  • spec/ is the sole source of public behavior.
  • A missing observable rule blocks implementation and requires a user decision.
  • The archived compiler, its tests, its diagnostics, and released behavior are not oracles.
  • Existing standard-library implementation details are not bootstrap semantics.
  • New responsibilities receive new files or crates with acyclic dependencies.
  • Compatibility adapters, fallback selection, reverse semantic lookup, and duplicate program indexes are prohibited.
  • A phase cannot complete while its superseded authority remains active.

Phase 0: Isolation and Specification Audit

Status: complete. The archived implementation is isolated, the observable specification audit is complete, and the lexical/syntactic grammar gate is closed with a derived conformance plan.

Phase 0 removes the previous compiler from the active tree, establishes the rewrite rules, and audits every specification chapter. Each gap is classified as:

  • derivable from an existing normative rule
  • an internal implementation freedom
  • explicitly deferred scope
  • a user-visible ambiguity requiring a decision

The phase stops for each user-visible ambiguity. The decision is written to the owning chapter and receives valid, boundary, and invalid conformance cases before the audit continues.

Grammar Gate

Before compiler code begins, the specification must define complete lexical and syntactic grammar for source files, directives, declarations, types, requirements, statements, expressions, patterns, operators, literals, construction, instances, conformances, and tests.

Phase 1: Source and Syntax

Status: complete (2026-08-16). Normalized source storage, lexical projection, the complete G001-G033 parser, syntax diagnostics, immutable syntax arenas, and lossless source projection are implemented and qualified.

Introduce source storage, tokenization, parsing, syntax diagnostics, immutable syntax trees, and source projections from the closed grammar. No semantic crate exists in this phase.

Completion includes accepted node-shape snapshots, syntax-rejected fixtures, semantic-boundary fixtures, exact token-projection checks, a 256-level recursive-delimiter limit, and non-recursive stress coverage for 5,000-layer prefix and left-associative syntax. Parsing decisions use only tokens, jointness, delimiters, and the normative newline rules; no semantic crate or archived implementation participates.

Phase 2: Declarations and Structural Types

The syntax-independent semantic ID, canonical symbol, normalized callable provenance, structural type interner, immutable declaration-program spine, normalized module and visibility model, complete typed declaration arenas, freeze-time graph-integrity validation, and separate node/token-level bidirectional source projection are implemented. The explicit compile- unit lowering boundary now canonicalizes and validates package, module, and physical-source topology independently of discovery order. Every authored import now requires an explicit discovery-owned source or module edge; source reachability/cycles and module acyclicity are checked without path reinterpretation. Canonical declaration-surface traversal now retains exact nested ownership and enforces the root-source-only public surface. Semantic identity reservation and header resolution remain. Public callable contracts and private implementation bodies are coalesced by canonical authored header, and all recursively referenceable declaration IDs are now reserved deterministically. Exact declaration names, visibility boundaries, declaration sites, namespace collisions, and token-level definition projections are resolved. Generic binder identities, inherited lexical scopes, declaration-pattern reuse, contract/body identity sharing, and exact binder projections are resolved. Authored module namespaces now resolve direct declarations, selected aliases, module imports, visibility, and non-widening chained re- exports in dependency order; source composition creates no semantic import. Synthetic prelude fallback is now a separate shadowable, non-reexporting namespace layer selected by exact module identity; standard-package modules receive no fallback and source imports of that module are rejected. Both authored and fallback layers are retained in the immutable declaration program, so body checking never reconstructs lookup from declaration/import iteration. Block imports remain a checked lexical-scope responsibility rather than declaration imports. Header type syntax is now bound once into a flat syntax-independent arena with exact module, imported/prelude, generic, arity, Self, fixed-array, and structural-callable provenance resolution. Alias applications and associated selections deliberately remain bound nodes until requirement-aware normalization. Declaration target patterns share the same name, arity, and exact source-projection authority and now refer directly to their allocated bare binders. Nominal interface and structural callable capabilities reuse the same resolver and bound type arena. Every where predicate and associated-type bound is now bound into a closed semantic requirement shape, including the directed distinction between pattern refinement and general equality. The syntax tree also represents mandatory interface-member pub through the common visibility node. The structural type store now represents interface-owned Self by its declaring interface identity rather than forging an implicit generic parameter. Requirement-aware normalization is complete: aliases expand with canonical generic substitution and cycle rejection, associated selections resolve to exact declaration identities, declaration patterns and requirements share one evaluator, callable type origins normalize to parameter positions, opaque results retain exact interface and associated-binding contracts, and 5,000-layer type lowering remains non-recursive. Complete header definition now allocates every non-recursive leaf identity, defines every reserved declaration domain, and freezes the declaration program and source index as independent immutable values. Authored from contracts remain distinct from provenance that body checking must infer. Joined public contracts and private bodies share callable and parameter identities while retaining separate source roles. Freeze-time validation is the sole authority for declaration shape, ownership, construction and drop attachment, complete associated bindings, opaque-result placement, and exact compiler-selected authority over built-in surfaces. Standard authority is stored as package and module IDs rather than recovered from a textual std prefix. Complete-input ordering permutations produce the same declarations, types, and source index.

The source-backed semantic diagnostic boundary is complete. Integrity failures retain an exact semantic subject that the separate source index projects without recreating declaration rules in lowering. Freeze-time declaration rules distinguish authored violations from compiler graph-integrity faults, carry stable E0200-E0212 identities, and project primary and related declaration sites through SourceIndex. Callable-contract violations carry stable E0250-E0253 identities and project their exact syntax subjects before reservation. Both use one source-diagnostic envelope without merging rule selection into presentation. Authored module- surface violations use that envelope for E0230-E0232, while malformed syntax snapshots and inconsistent discovery inputs remain internal errors. A production facade now owns the complete declaration pass sequence. Header name and visibility violations now preserve exact syntax subjects and project shared namespace rules E0240-E0242; import processing reuses those rules and adds E0260, E0261, and E0412 for its own selected-name contracts. Import namespace bindings retain exact local-name tokens, including aliases. Authored source-composition and module-cycle failures now project E0270-E0271; each module edge retains its exact use node and cycle witnesses are stable under input reordering. Generic binder rules now project E0280-E0282 from exact stored declaration tokens, distinguishing explicit duplicates from inherited shadowing while preserving declaration-pattern reuse. Header type binding projects E0290-E0302 from retained path segment, argument, duplicate-name, provenance, opaque-binding, and requirement subjects; malformed bound input remains internal. Prelude composition now reuses import rule E0262 and the module-path origin retained during authored import preparation; compiler-selected authority failures remain internal. Type normalization consumes a temporary origin side index and projects E0310-E0313 and E0320 for canonical complete alias cycles, associated selections, ambiguous callable provenance, and projection-free general equalities after alias expansion. Definition completion projects E0314-E0319 from retained subjects. Every production-facade failure variant is classified as either an authored rule or a compiler/discovery integrity error. Declaration-owned G006-G010, G012-G013, and G015-G018 semantic fixtures produce identical complete diagnostics when package and module input order is reversed.

Introduce package, module, declaration, callable, generic-parameter, body, and structural type identities. Resolve headers into one compile-unit declaration graph and type store. Source ranges and rendered names cannot enter semantic identity.

Phase 3: Checked Program

Status: complete (2026-08-17). Every body-owned grammar form now constructs closed checked HIR, and ownership, loans, provenance, destruction, and region semantics consume the same immutable identities and cleanup edges.

Implement name resolution, type checking, generic requirements, conversions, dispatch contracts, ownership, borrowing, provenance, regions, destruction, outcomes, and compiler-generated semantic operations in body-owned checked HIR.

Current implementation includes the syntax-independent body spine, lexical identity, normalized instance/conformance/copy/drop/construction authorities, expected-type and generic-call planning, field/index places, ownership and cleanup flow, primitive and source-selected operators, direct and structural callable calls, construction functions, receiver methods, named-field struct and enum variant construction, fixed-array literals, exact generic typed-literal selection for fixed sequence elements and decoded strings, explicit typed-literal allocation-context selection through validated standard semantic roles, static borrowed string literals, outcome propagation/forced unwrap, and catch/otherwise recovery. Method calls freeze inherent, concrete conformance/default, or lexical interface dispatch and at most one explicitly selected borrow coercion. Cleanup events distinguish statement, control-header, propagation, store, and transfer edges; call/aggregate staging and branch-conditional temporaries share the ordinary ownership state. Pattern control, closures, non-lexical loan escape, callable result provenance inference, owned interpolation, exact-size typed-sequence spread, collection iteration, authored binding annotations, and executable regions are complete. A region has one typed context binding, one retained parent operand, one lexical body, and one ordered release target. Normal and early exits destroy body-owned values before release; never termination does not invent cleanup. The same identity controls current allocation provenance, storage escape, and the parent loan lifetime.

Sequence literal bodies now receive a compiler-owned, non-escaping checked-HIR pack rather than an ordinary element-typed parameter. Only pack length and consuming iteration are representable; ordinary value use projects E0409. Executable signatures retain the pack's specialized element type and parameter identity outside the ordinary runtime input list. Each reachable call site also freezes its dense constructor item, specialized result, fixed/spread producer order, concrete spread types, retained iteration selections, allocation selection, and per-segment residual destruction as one executable sequence plan. Required user drop bodies enter the executable closure before MIR. Phase 4 now lowers both caller-side pack materialization and the literal body's consuming input.

Phase 4: Target Program, Executable Program, and MIR

Status: complete (2026-08-18). Target and executable-program construction and checked-body lowering into validated MIR are complete. The closed target/toolchain snapshot validates the standard primitive registry and selected package targets before executable construction. Entry-driven specialization closes a deterministic graph of callable, closure, drop, and test items, freezes concrete runtime signatures and types, and resolves every reachable static selection without exposing a requirement to MIR. Composite comparison and index dispatch retain named operand lanes rather than relying on step order. MIR lowering now covers scalar and aggregate values, ordinary places, branches, direct and primitive calls, receiver and operand coercions, comparisons, index places, outcomes, cleanup, loops, patterns, closures, regions, callable bounds, typed strings, and static opaque results. Opaque construction and method invocation retain one explicit representation lane from specialization through exact MIR witness aggregates and projections, including owned, readonly, readwrite, and collection-iteration receivers. Literal bodies now consume one dedicated MIR pack input through typed length and next operations, and all returning paths explicitly destroy the unconsumed suffix. Callers now preserve specified evaluation order, checked exact length, fixed/spread ownership, selected iteration, and dense deferred destruction in one validated hidden pack argument. Interpolation now lowers through the frozen standard owned-String constructor, text appender, and per-expression formatter selections without a string-specific MIR operation. Its partial output uses canonical value storage, so propagation and explicit return run ordinary cleanup while a forced trap does not. Callable functions and compiler-owned roots share one MirBody CFG schema without synthetic items. Process roots materialize all six accepted result contracts through root-only exit and allocation-free error-reporting operations. Test targets retain one independent root per case in declaration order and preserve empty targets. Test executable signatures are fixed to void!, and void! success uses no fictional payload value.

Validate one target/toolchain program as the shared success boundary for check, build, and run; no public check-only language subset exists. Then instantiate one entry-driven monomorphized program graph, resolve concrete conformance dispatch once, and lower it to validated MIR with explicit control flow, calls, moves, loans, regions, and cleanup. Library-only checking stops at the target program and does not invent an executable entry.

Phase 5: Machine Program and Native Target

Project MIR through the specified ABI into target-independent machine operations, deterministic linkage, ARM64 encoding, and Mach-O output. Code generation cannot access syntax, resolver state, or runtime names as semantic input.

Status: complete (2026-08-20). nocter-machine owns the complete target-independent program consumed by native lowering: recursive stored layouts, the immutable Nocter ARM64-Darwin ABI plan, name-independent function linkage, content-addressed static data, concrete primitive roles, allocation-context requirements, and validated per-function dataflow. Dense machine bodies close all MIR storage, addresses, values, operations, packs, blocks, switches, cleanup, and terminal behavior without retaining semantic or MIR passthrough nodes.

nocter-arm64 owns typed instruction encoding, local branch relaxation, physical register roles, deterministic linear-scan allocation, fixed frames, function/data fixups, and complete materialization of the currently selected operation set. Constants, scalar operations, structural comparisons, static and dynamic addresses, checked indexing, aggregate construction, exact memory movement, direct and indirect callable transport, allocation-context transport, pointer/view and memory primitives, Darwin syscalls, process termination, direct user destruction, drop flags, and all machine terminators now execute without consulting source or semantic identities. Direct and memory-valued block arguments each have cycle-safe parallel-copy authorities. Value switches retain their one- or two-word subject; stored-tag switches consume the exact layout-owned byte offset.

Arm64Program resolves the completed function and data domains into typed fixups. The independent Mach-O writer owns deterministic section/VM layout, native and dynamic-loader commands, content-derived UUIDs, SHA-256 ad-hoc signing, and final bytes without invoking an assembler, linker, or signing tool. Cross-crate conformance tests execute source-authored constants, calls, arithmetic, comparisons, direct and memory block joins, optional tag switches, static text, large aggregate transport, checked indexing, pointer and memory primitives, Darwin syscalls, process exit, conditional user destruction, and compiler-generated recursive pointer destruction natively on ARM64 macOS.

Fixed literal packs now cross the native boundary through a caller-owned four-word descriptor and source-ordered state. Stable target functions implement consuming-next with the exact direct or caller-owned Optional<T> result ABI and reverse residual cleanup through the common generated destruction functions. Function-pointer and static-data address pairs are both relocated only after Mach-O fixes the final section virtual addresses.

Spread segments now use those same target functions and state cursors. Their callbacks call the frozen direct iterator function through its ordinary ABI, stage direct or caller-owned results, support direct and copied-borrow contributions, skip exhausted segments, propagate inherited allocation contexts, and destroy iterator state exactly once. Early exhaustion that contradicts the exact-size count reaches a dedicated compiler-owned runtime trap.

Lexical regions now lower as non-movable compiler-owned resources instead of source-layout SSA values. MIR freezes the innermost region on ordinary calls, literals, and authored destruction and validates the ordered region stack across the complete CFG. ARM64 assigns one closed frame layout containing the ordinary context header, independent mapping-list head, and selected parent header; release advances and unmaps that list through a checked target syscall loop.

Independent test-root execution is complete. Machine lowering closes declaration-order names and dense test identities, ARM64 shares one immutable code/data payload while selecting one entry per case, and Mach-O can serialize each entry as its own process image. Fallible process and test roots now construct and report the built-in error payload without allocation through the ordinary ABI.

Process-entry state is complete. One shared machine fixed-point authority now derives independent allocation and process capability plans across ordinary calls, destruction, and literal callbacks. ARM64 roots capture argc, argv, and envp before other entry initialization, store the environment count once, propagate the context through a dedicated hidden lane, bounds-check indexed queries, and return program-lifetime argument/name/value views. Native conformance launches the generated Mach-O image with controlled arguments and environment across an ordinary nested call.

The native I/O boundary is complete. Seven redundant open/read/write/close primitive roles were removed; generic syscall results are the sole file-descriptor target boundary. Ordinary std/io source owns Darwin constants, path preparation, interruption retry, partial-transfer completion, zero-progress detection, count validation, errno mapping, and close-once behavior. Native conformance writes exact bytes and opens, reads, verifies, and closes a temporary file through that generic ABI. No backend name lookup, private error ABI, or target-owned retry policy remains.

The executable, MIR, and machine layers now preserve pointer destruction as one explicit semantic dependency containing the concrete subject and optional destruction plan. Recursive user-drop reachability, layout translation, validation, and hidden allocation-context propagation are closed before target selection. Machine lowering now interns pointer and pack plans deterministically, appends name-independent generated linkage after the stable source-function domain, and gives them one compiler-owned (byte_pointer, byte_offset) ABI. Nonempty pointer primitives become ordinary direct calls, while pack segments retain only the same generated function identities. Generated CFG handles reverse fixed arrays without unrolling and delegates authored drops through normal function calls; ARM64 receives no recursive destruction semantics. Fixed and spread pack callbacks execute those closed dependencies through the same function authority when advancing or destroying their retained state.

Phase 6: Tooling, Packages, and Standard Library

Implement formatting, JSON structures, package commands, testing, LSP snapshots, semantic presentation, and newly authored standard-library source from their specification contracts.

Status: in progress (2026-08-21). The production package/source and exact toolchain-profile boundaries are complete. nocter-compile-input now owns the neutral lowering handoff, nocter-target-selection supplies one shared target-gate decision, and nocter-discovery turns an exact resolved package graph into a canonical immutable source graph without semantic path reopening. It resolves source folders, directory modules, dependency aliases, nested imports, source cycles, module candidates, and inactive target gates; rejects source/module ambiguity and ownership escapes; preserves filesystem failures; and is deterministic under request ordering.

The discovery request now carries one exact standard-package profile. Discovery validates and loads the selected prelude and built-in attachment modules, resolves each compiler-owned standard semantic role to one declaration-name token, and freezes those identities in CompileUnitInput. Declaration lowering and body preparation consume that profile directly; neither stage infers standard authority from package, module, or declaration spelling. Toolchain-specific discovery failures form a separate typed error domain.

Primitive roles now use the same identity path. The role enum belongs to the syntax-independent declaration layer, the bundled toolchain profile maps every closed role to a source locator, discovery freezes each locator as an exact primitive declaration token, and target construction resolves those tokens through SourceIndex into one complete canonical PrimitiveRegistry. Production target construction does not search the checked graph for primitive names.

The independent nocter-session crate is now the production ownership boundary from a syntax-clean DiscoveredUnit to TargetProgram. It consumes declaration lowering, body preparation/checking, primitive resolution, target capability selection, and target validation in one fixed order. No mutable or partially assembled pipeline state escapes; the successful result contains only the target-validated program and its independent source index.

Discovery now accepts an explicit sum of declared-package and single-file layouts. File mode canonicalizes exactly one .nct source into a synthetic package identity, supplies only the compiler-selected std dependency, rejects local source/module expansion, and then converges on the ordinary compile-unit representation. Every public single-file example passes the complete nocter-session target boundary with the authored standard library. Qualification also closed the specified error.code and error.message surface through one syntax-independent built-in field identity carried by field selection, source projection, provenance, loans, MIR validation, and machine-layout offset selection; no synthetic struct declaration or backend name lookup is used.

For declared packages, discovery now parses target module selectors once, validates their segments through the same compile-input authority used by lowering, and pairs every selected root with its exact package-directive node and ModuleIdentity. Declaration lowering consumes those frozen edges without decoding a path. The public package example and all public single-file examples now pass the same complete nocter-session target boundary with the authored standard library.

nocter-session now also owns executable-root requests. A request selects either the sole process target or one declared executable name, converts that presentation choice to one exact PackageTargetId, and consumes TargetProgram into its closed ExecutableProgram. Missing, multiple, unknown, and cross-root ambiguous selections are distinct typed failures. Every public example now passes this executable-closure boundary; command code cannot scan target names or assemble specialization stages independently.

The native session now consumes that selected executable through MIR, machine lowering, ARM64 selection, and Mach-O construction. Every public single-file and package example reaches a complete native image through this one boundary. Qualification closed three representation gaps: void! success has no fictional payload place, unsized slice/string reborrows retain an explicit pointer-plus-length address extent, and lossless integer widening preserves source signedness in ARM64 selection.

nocter-command now owns the post-session executable effects. Persistent build output uses a same-directory private file followed by permissions, synchronization, and atomic rename. Run uses a private temporary directory, inherited standard streams, exact child status, and explicit cleanup. The command crate depends on the native session and cannot import individual semantic or backend stages. Discovery now also freezes the exact command-root package identities before dependency traversal, and declaration lowering retains their translated PackageId values in the immutable semantic graph. Executable selection is restricted by that authority instead of mistaking dependency targets or matching display names for command roots. Public argument parsing, package-wide build selection, dependency resolution, and diagnostic presentation remain open Phase 6 work.

The complete authored development/std tree now parses, discovers, and passes the declaration pipeline and full checked-body pipeline through that production boundary. Qualification removed obsolete destruction spelling and invalid same-line statement sequences, broke the str/string and iter/vec module cycles at their responsibility boundaries, fixed generic projection for separately implemented construction patterns, and closed the missing generic inference, conversion, dispatch, ownership, outcome, provenance, and loan cases exposed by real standard source. Callable-boundary provenance now separates authority carried by an input value from the temporary place loan created only for invocation. Command orchestration, diagnostics, formatting, and editor snapshots remain Phase 6 work.

Completion Definition

v0.14.0 is complete only when:

  • every implemented public behavior traces to one normative specification section
  • no unresolved observable ambiguity remains
  • the complete grammar and semantic conformance suites pass
  • public examples and newly authored standard-library packages check and run
  • check, build, and run agree on accepted programs for the same target and toolchain snapshot
  • CLI and editor contracts pass protocol-level tests
  • native ABI and runtime behavior pass target conformance tests
  • source and declaration ordering cannot change semantic or machine results
  • later phases cannot import representations owned by earlier phases to repeat decisions
  • no archived implementation source, test, output, or compatibility path exists in the active tree
  • clean builds are deterministic and full verification passes

Publication and release qualification require separate explicit authorization after this milestone is complete.
