struct Point {
    x: i32
    y: i32
}

instance Point {
    impl Format
    method &self.try_format_into(output: &+String): void! {
        output.try_push_str("(")?
        self.x.try_format_into(output)?
        output.try_push_str(", ")?
        self.y.try_format_into(output)?
        output.try_push_str(")")?
        return
    }
}

    let message = "point = ${point}\n"

    return 0

use std/io
use std/vec.Vec

struct Point {
    x: i32
    y: i32
}

instance Point {
    operator (&self == other: &Self): bool {
        return self.x == other.x && self.y == other.y
    }
}

func main(): i32! {
    let first = Point { x: 3, y: 4 }
    let same = Point { x: 3, y: 4 }
    let other = Point { x: 5, y: 6 }
    if first != same || first == other {
        return 1
    }
    let points = Vec [move first, move other]
    if points[0] != same {
        return 1
    }
    var values = Vec [1, 2, 3]
    values[1] = 4
    if values[0] + values[1] + values[2] != 8 {
        return 1
    }
    io.print("equality found the point\n")?
    return 0
}
struct Buffer {
    values: [i32; 3]
}

instance Buffer {
    operator (&self[index: usize]): &i32 {
        return &self.values[index]
    }

    operator (&+self[index: usize]): &+i32 {
        return &+self.values[index]
    }
}

func at<C>(container: &C, index: usize): i32 where (&C[usize]): &i32 {
    return container[index]
}

func main(): i32 {
    var buffer = Buffer { values: [3, 4, 5] }
    buffer[1] = 9
    if at(&buffer, 1) != 9 {
        return 1
    }
    return 0
}

v0.14.0: Specification-First Compiler Rewrite

Status: published (2026-08-23). The implementation and review evidence is recorded in the v0.14.0 implementation qualification, and candidate work is recorded in the release preparation.

Goal

Build a new Nocter compiler from the public specification without consulting, executing, copying, or behavior-matching the previous compiler. v0.14.0 is not released until the specification is closed, the new architecture has one authority for each semantic decision, and the required public language, standard-library, CLI, editor, and native-runtime contracts are implemented.

Rewrite Rules

  • spec/ is the sole source of public behavior.
  • A missing observable rule blocks implementation and requires a user decision.
  • The archived compiler, its tests, its diagnostics, and released behavior are not oracles.
  • Existing standard-library implementation details are not bootstrap semantics.
  • New responsibilities receive new files or crates with acyclic dependencies.
  • Compatibility adapters, fallback selection, reverse semantic lookup, and duplicate program indexes are prohibited.
  • A phase cannot complete while its superseded authority remains active.

Phase 0: Isolation and Specification Audit

Status: complete. The archived implementation is isolated, the observable specification audit is complete, and the lexical/syntactic grammar gate is closed with a derived conformance plan.

Phase 0 removes the previous compiler from the active tree, establishes the rewrite rules, and audits every specification chapter. Each gap is classified as:

  • derivable from an existing normative rule
  • an internal implementation freedom
  • explicitly deferred scope
  • a user-visible ambiguity requiring a decision

The phase stops for each user-visible ambiguity. The decision is written to the owning chapter and receives valid, boundary, and invalid conformance cases before the audit continues.

Grammar Gate

Before compiler code begins, the specification must define complete lexical and syntactic grammar for source files, directives, declarations, types, requirements, statements, expressions, patterns, operators, literals, construction, instances, conformances, and tests.

Phase 1: Source and Syntax

Status: complete (2026-08-16). Normalized source storage, lexical projection, the complete G001-G033 parser, syntax diagnostics, immutable syntax arenas, and lossless source projection are implemented and qualified.

Introduce source storage, tokenization, parsing, syntax diagnostics, immutable syntax trees, and source projections from the closed grammar. No semantic crate exists in this phase.

Completion includes accepted node-shape snapshots, syntax-rejected fixtures, semantic-boundary fixtures, exact token-projection checks, a 256-level recursive-delimiter limit, and non-recursive stress coverage for 5,000-layer prefix and left-associative syntax. Parsing decisions use only tokens, jointness, delimiters, and the normative newline rules; no semantic crate or archived implementation participates.

Completion Definition

v0.14.0 is complete only when:

  • every implemented public behavior traces to one normative specification section
  • no unresolved observable ambiguity remains
  • the complete grammar and semantic conformance suites pass
  • public examples and newly authored standard-library packages check and run
  • check, build, and run agree on accepted programs for the same target and toolchain snapshot
  • CLI and editor contracts pass protocol-level tests
  • native ABI and runtime behavior pass target conformance tests
  • source and declaration ordering cannot change semantic or machine results
  • later phases cannot import representations owned by earlier phases to repeat decisions
  • no archived implementation source, test, output, or compatibility path exists in the active tree
  • clean builds are deterministic and full verification passes

Publication and release qualification require separate explicit authorization after this milestone is complete.
