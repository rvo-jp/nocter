use std/io.print

func greet(user: User): void! {
    let name = user.display.name() otherwise { "guest" }

    let tone = match user.presence {
        Presence.online { "hello" }
        Presence.away { "welcome back" }
    }

    print("${tone}, ${name}\n")?
}
interface Writer {
    pub method &+self.write(bytes: &[u8]): void!
}

func save_log<W>(output: &+W, events: &[Event]): void! where W impl Writer {
    for event in events {
        output.write(event.message().bytes())?
        output.write("\n".bytes())?
    }
}
pub struct Session {
    id: SessionId
    user: User
    expires_at: Time
}

construct Session {
    pub func start(user: User, clock: &Clock): Self {
        return Self {
            id: SessionId.new(),
            user: move user,
            expires_at: clock.now().plus_minutes(30),
        }
    }
}
func consume(values: Vec<String>): void! {
    for value in move values {
        print(&value as &str)?
    }
}
construct NonEmptyList<T> {
    pub literal [](...items: T): Self from items {
        var list = Self.new()

        for item in items {
            list.push(move item)
        }

        return move list
    }
}

v0.20.0 Phase 0 Interface-Prerequisite Review

Result: passed (2026-08-28). This review covers the interface-prerequisite language contract, compiler capability authority, concrete dispatch, editor projection, and the standard iterator migration. Hashing and associative collections remain outside Phase 0.

Review Criteria

The review traced:

  • every authored interface-header predicate from parsing through declaration identity, closure, specialization, implementation validation, body evidence, concrete dispatch, and editor query;
  • direct, transitive, generic-argument, structural, and inherited-associated-type prerequisites;
  • cycles and effective member collisions independently of declaration and source order;
  • the distinction between entailed generic capabilities and separately authored concrete implementation facts;
  • stale compatibility syntax, duplicate prerequisite traversal in later compiler layers, source inference, repeated selection, redundant standard-library bounds, and unchecked caller obligations.

Findings and Remediation

Structural prerequisites were limited to generic parameter identities

Equality, ordering, indexing, and expansion requirements previously stored only generic-parameter IDs. Their declaration model now stores semantic type IDs, so contextual interface Self and ordinary generic parameters share one requirement representation. Callable, copy, and binder refinement retain their narrower domains.

A root requirement could not identify an entailed dispatch predicate

One authored requirement can entail several specialized predicates. Checked body assumptions now freeze a distinct CapabilityEvidenceId for each exact predicate while retaining the authored RequirementId for diagnostics and source provenance. Static dispatch carries both identities; concrete dispatch specializes the evidence and never reinterprets the authored root as the entailed predicate.

Generic-argument prerequisites were omitted by the first closure implementation

The first review pass retained only predicates targeting interface Self. That would have admitted impl Derived<Argument> without proving a header requirement such as Argument impl Base. The declaration-owned capability now retains every interface-header predicate. Only Self impl Base edges contribute inherited methods and associated names. A focused rejection test prevents the two roles from being conflated again.

Derived associated bindings needed one original declaration identity

Construction-time type binding follows only Self interface prerequisite edges and resolves an inherited name to its original associated declaration. The accepted declaration graph rejects ambiguous effective names and freezes that identity. Checking propagates a derived application's binding into the corresponding prerequisite predicate without creating an alias declaration.

Explicit implementations did not validate prerequisite capability

Checking now validates every admitted implementation pattern against its specialized interface and structural prerequisites after the interface and instance-operation tables are complete. Missing evidence reports E0358. A derived implementation does not synthesize a prerequisite implementation or associated binding.

Exact-size iterator users repeated the base iterator requirement

ExactSizeIterator now declares Self impl Iterator. Generic standard-library APIs state only the strongest meaningful bound, while concrete iterator types still explicitly implement both interfaces. No ABI or runtime iterator representation changed.

Final Boundary Assessment

  • Parsing records ordinary where predicates and does not infer inheritance from member names.
  • Declaration lowering owns construction-time associated-name binding. The declaration graph owns the accepted prerequisite topology, effective member identities, and cycle/collision rejection.
  • Checking owns specialized proof evidence and implementation validation. It consumes declaration contracts rather than source ranges or syntax nodes.
  • Target lowering consumes frozen CapabilityEvidenceId values and performs concrete candidate selection once. It receives no source or editor inputs.
  • LSP hover preserves authored headers. Navigation for inherited associated names uses the original semantic declaration identity through ordinary analysis queries.
  • No compatibility spelling, implicit conformance, duplicate associated declaration, or redundant Iterator plus ExactSizeIterator standard-library bound remains.

No unresolved correctness or responsibility-boundary finding remains in Phase 0 scope.

Verification

The complete workspace all-target test suite passed with zero failures and one intentional ignored test. Warnings-denied workspace all-target Clippy, formatter checks, generated documentation, and repository diff integrity checks passed. Focused coverage includes parsing, direct and transitive generic substitution, generic-argument prerequisites, structural equality, inherited associated bindings, cycle and collision rejection, unsatisfied explicit implementations, concrete target dispatch, hover rendering, and inherited-definition navigation.
